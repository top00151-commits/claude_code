## 1. 원칙 네 가지 (대표 확정)

1. **사용자가 고른 줄만 바꾼다.** 화면에서 고친 그 줄(그 수주·그 호기·그 칸)만 저장한다.
2. **다른 줄에 퍼뜨려야 하면 바뀔 줄을 먼저 보여 주고 확인받는다.** 「이 3개 수주의 납기도 같이 바꿀까요? M-…, M-…」 → 사람이 고른 것만.
3. **화면을 여는 것만으로는 아무것도 저장하지 않는다.** 다시 계산한 값(합계·자가치유·동기화)은 **보여 주기만** 하고, 고칠 필요가 있으면 「맞추기」 단추로 사람이 누르게.
4. **자동으로 바뀌는 것이 꼭 남는다면 반드시 이력을 남기고 되돌릴 수 있게 한다.** 누가(사람·시스템)·무엇을·전→후·왜.

## 2. 자주 틀리는 자리 (만들기·고치기 전에 확인)

| 모양 | 왜 위험한가 | 대신 |
|---|---|---|
| 대표값(프로젝트) → 자식(수주) 퍼뜨리기 | 수주마다 고객·통화·형태가 다른 관리번호가 많다(웍스 206곳 중 고객 48·통화 43·형태 35) | 자식이 2개 이상이면 고른 자식에만 · 퍼뜨림은 2번 원칙 |
| 자식 → 대표값 맞추기(「첫 수주 = 대표」) | 첫 수주를 고치면 대표값이 바뀌고, 빈칸 자식들 화면이 따라 바뀜 | 자식 2개 이상이면 대표값 안 바꿈 |
| 자식 칸이 비면 대표값을 대신 보여 주는 구조 | 대표값이 바뀌면 이력 없이 여러 자식이 바뀐 것처럼 보임 | 그런 화면은 「(대표값)」 표시 · 대표값을 바꾸는 저장은 1번 원칙 |
| 화면 열 때(GET) 고쳐 저장 · 서버 시작 때 백필 UPDATE | 연 사람 이름으로 자료가 바뀌고, 사람은 모름 | 보여 주기만 · 「맞추기」 단추 · 백필은 대표 승인 .ps1 |
| 이름으로 자동 연결(같은 이름 첫 곳) | 이름이 같은 다른 회사·옛 자료에 붙음 | 후보가 하나로 분명할 때만 · 아니면 사람이 고르게 |
| 엑셀 올리기가 기존 값 덮기 | 사람이 고친 값이 사라짐 | 바뀔 칸을 보여 주고 확인 · 원본↔저장 대조 |
