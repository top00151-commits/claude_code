## 1. 네 입장 — 설계할 때 한 번, 만든 뒤 시뮬레이션으로 한 번

| 입장 | 누구(예) | 묻는 것 |

## 2. 반드시 검증할 변수

1. **문제** — 오류·먹통 단추(스크립트 문법)·느림·권한 구멍
2. **빠진 것** — 연결된 화면 전부(목록·상세·수주 카드·작업일정표·전사일정표·보고서·엑셀)에 같은 값이 보이는가
3. **더 개선할 것** — 쓰는 사람 입장에서 더 쉬운 길이 있으면 만들어 보여 준다(선택지로 적어 두기만 하지 않는다)
4. **사람이 쓰기 힘든가** — 글자·단추 위치·좁은 화면·설치 앱·폰
5. **데이터 연결이 정확한가** — 같은 관리번호에 고객사·통화·형태가 여러 개인 실제 자료로 확인 · 사람이 고른 줄만 바뀌는가(`knk-no-silent-change`)
6. **허상이 없는가** — 빅터가 스스로 가정하거나 지어낸 값(「첫 수주 = 대표」·「프로젝트 값 = 모든 수주 값」·추측한 환율·짐작한 날짜·이름으로 짝지은 고객사)으로 자료를 채우거나 계산하지 않았는가. 숫자는 실측·원본에서만, 모르면 「모름 · 확인 필요」로.

## 3. 시뮬레이션 하는 법

- **실제 운영 자료 사본**(운영 DB 읽기 전용으로 꺼낸 것)에서, **실제 직원 계정**(같은 권한)으로, **화면 단추를 직접 눌러**(서버 직접 호출로 대신하지 않음) 해 본다.
- 네 입장마다 하는 일 순서대로: 올리기 → 취소 → 수정 → 연결 화면 확인 → 금액·값이 다르면 알림이 뜨는지 → 같으면 안 뜨는지 → 화면 열기만 해서 자료가 바뀌지 않는지(전후 비교).
- 결과는 **입장별 · 단계별 표(통과/실패)** + 화면 사진으로 남긴다. 못 해 본 것은 「못 함 · 이유」로 정직히.
