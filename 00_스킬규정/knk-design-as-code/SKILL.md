## 1. 규칙 — 한 줄로

**디자인은 그림 파일이 아니라 코드(HTML · CSS · SVG, 값은 JSON)로 만든다. 그래야 그대로 화면에 쓰고, 값 하나만 고쳐 전부 바꾸고, 테마·화면 폭·언어가 바뀌어도 깨지지 않는다.**

## 2. 왜 코드인가

| 그림 파일로 만들면 | 코드로 만들면 |
|---|---|
| 시안을 화면으로 옮길 때 다시 만들어야 하고, 옮기다 색·간격이 달라진다 | **시안이 곧 화면** — 그대로 붙여 쓴다 |
| 글자를 고치려면 그림을 다시 그려야 한다 | 글자·숫자만 바꾸면 된다 · 한국어·베트남어·영어 바꿔 끼우기 |
| 다크 테마·폰 폭에서 흐리거나 잘린다 | CSS 이름(색 변수)·폭 규칙으로 테마·폭에 맞춰 저절로 바뀐다 |
| 확대하면 흐려지고 파일이 무겁다 | SVG 는 아무리 키워도 또렷하고 가볍다 |
| 무엇이 바뀌었는지 비교가 안 된다 | 깃허브에 글자로 남아 바뀐 곳이 보이고 되돌릴 수 있다 |
| 회사 색을 눈대중으로 맞춘다 | `brand.json` 값을 읽어 늘 같은 색 |

## 3. 무엇을 어떤 코드로

| 디자인 | 코드 |
|---|---|
| 화면 시안·목업·화면 꾸미기 | 실제 HTML + CSS(가능하면 그 화면의 공용 틀·공용 클래스 위에) |
| 단추·표시·작은 그림 문자(아이콘) | SVG 또는 CSS · 그림 문자(이모지)는 글꼴에 따라 달라지니 꼭 같은 모양이 필요하면 SVG |
| 도표·흐름도·조직도·안내 그림 | SVG 또는 HTML(글자는 그림이 아니라 글자로) |
| 배너·안내판·공지 머리·표지 | HTML + CSS(회사 색·패턴은 `knk-brand.css`) |
| 양식 머리(견적서·발주서 등) | HTML + CSS · 로고는 `knk-brand` 원본 SVG |
| 발표 화면 | HTML 슬라이드 또는 코드로 만드는 도구 — 글자를 그림으로 굳히지 않는다 |
| 색·글꼴·간격·모서리 값 | `brand.json` / CSS 이름(`--knk-brand-red` 등)에서 읽기 · 숫자를 손으로 다시 적지 않기 |

## 4. 그림 파일을 써도 되는 것 (예외)

- **사진**(직원 얼굴·현장·제품 사진) — 코드로 만들 수 없는 것
- **회사 로고** — 다시 그리지 말고 `knk-brand\assets\` 의 원본 파일을 쓴다(SVG 먼저, 꼭 필요할 때만 PNG)
- **바깥으로 내보내야 하는 결과물**(카톡·문자에 붙일 그림, 인쇄소 파일 등) — 이때도 **원본은 코드로 두고 그림은 코드에서 뽑아낸다.** 그림만 따로 고치지 않는다.
- 대표가 「그림으로」를 직접 말씀하신 경우

## 5. 만들 때

1. **먼저 있는 것을 쓴다** — 그 화면의 공용 틀·공용 클래스·`knk-brand.css`. 새 색·새 간격을 만들기 전에 이미 있는 값부터 찾는다.
2. 값은 이름으로 — 색은 CSS 이름(색 변수), 크기는 한 기준(`knk-even-layout`).
3. 글자는 글자로 — 그림 안에 글자를 굳히지 않는다(검색·번역·확대가 안 됨).
4. 테마·폭을 함께 — 라이트·다크(`knk-text-contrast`), PC·폰 폭에서 실제로 띄워 본다.
5. 시안을 보여 드릴 때도 **실제로 띄운 화면**(코드로 만든 것의 화면 캡처)을 보여 드리고, 그 코드를 그대로 반영한다.

## 6. 확인 (완료 전)

- [ ] 새로 만든 그림 파일(PNG·JPG)이 4절 예외(사진·로고 원본·코드에서 뽑은 결과물) 말고는 없나
- [ ] 색·글꼴 값이 `brand.json` / CSS 이름에서 왔나(손으로 적은 색 번호가 없나)
- [ ] 그림 안에 굳힌 글자가 없나
- [ ] 라이트·다크, PC·폰 폭에서 깨지지 않나
- [ ] 시안과 실제 반영된 화면이 같은 코드인가
