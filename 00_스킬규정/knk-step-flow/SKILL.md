## 1. 규칙 — 한 줄로

**여러 단계로 된 기능은 화면 맨 위에 「전체 순서 + 지금 위치 + 지금 하실 일 하나」를 늘 보여 준다.** 사용자가 묻지 않고 화면만 보고 다음 행동을 알 수 있어야 한다.

## 2. 순서의 기본 모양

**진행(준비) → 실행 → 수정 또는 다시 실행 → 완료**

- 기능마다 실제 단계 이름으로 바꿔 적는다. 예: 「1 번호 만들기 → 2 PC 에서 실행 → 3 가져오는 중 → 4 다시 실행 → 5 끝」
- **「수정 또는 다시 실행」 칸을 반드시 둔다.** 필요할 때만 쓰는 칸이면 점선 + 「(실패·멈춤 있을 때만)」.
- 지난 단계 = ✓ 초록 · 지금 단계 = 강조색 · 남은 단계 = 흐리게.

## 3. 「지금 하실 일」 칸 — 단계 줄 바로 밑

- 첫 줄은 `knk-done-status` 머리말(✅/⏳/👉) **하나**.
- **할 일은 하나만**: 어디서 · 무엇을(단추 이름 그대로) · 그 뒤 무엇이 보이면 다음 단계인지.
- **그 일을 하는 단추를 그 자리에** 둔다 — 위로 올라가 다시 고르게 하지 않는다(예: 「🔁 실패한 것만 다시 하기」 = 앞 설정 그대로 바로 진행).
- 화면 밖에서 하는 일(PC · 폰 · 아웃룩 · 엑셀)은 **그 창을 생김새로** 적는다 — 예: 「명령을 붙여 넣은 PowerShell 창(파란·검은 창)」. 「PC 창」 같은 말 금지.

## 4. 금지 — 실제로 헷갈리게 만든 것들

1. **완료와 남은 일을 한 칸에 같이 쓰지 않는다.** 「✅ 완료」 밑에 「👉 실패 2통」 ❌ → 남은 일이 있으면 ✅ 가 아니라 👉.
2. **멈춤 · 기한 지남 · 중간 끊김을 ✅ 로 쓰지 않는다.** 다 못 했으면 「👉 끝나지 않았습니다 — 이어서 하려면 ○○」.
3. **지금 단계에서 의미 없는 단추를 보이지 않는다**(예: 이미 끝난 번호의 「멈추기」). 단추는 누를 수 있고 필요한 단계에서만.
4. **화면에 없는 것을 가리키지 않는다**(예: 새로 열면 사라지는 ② 명령인데 「②의 명령을 실행하세요」 ❌) → 사라졌으면 다시 만드는 단추를 준다.
5. **다시 실행할 때 옛 방법이 안 통하면 미리 알린다**(예: 「새 명령입니다 — ↑ 키로 옛 명령을 쓰면 안 됩니다」).
6. **정상인 조용한 구간을 미리 적는다**(예: 「처음 몇 분은 목록을 읽느라 숫자가 안 올라갑니다 · 기다리시면 됩니다」).

## 6. 검증 (`knk-four-view-verify` 와 함께)

- 상황표 **모든 줄**을 시험 화면에서 실제로 만들어 사진으로 남긴다(한 줄도 빼지 않음).
- **처음 쓰는 사람처럼** 화면만 보고 묻지 않고 끝까지 가 본다 — 중간에 「이제 뭐 하지?」가 한 번이라도 생기면 실패.
- 일부러 **중간에 끊고**(창 닫기 · 서버 재시작 · 기한 지남) 다시 이어지는지 본다.
- 대표가 그 기능에서 「어떻게 해?」 · 「끝났어?」를 물었다면, 그 물음이 화면에서 답해지게 고쳤는지 확인한다.
