## 1. 기준 — 화면이 넘어가도 이것은 움직이지 않는다
1. **왼쪽 메뉴(폴더) 칸의 스크롤 위치** — 누른 그 자리 그대로. 방금 누른 항목을 「잘 보이게」 끌어올리지 않는다.
2. **위 띠·도구 줄의 높이** — 처음 그린 높이와 숫자가 채워진 뒤 높이가 같아야 한다.
3. **목록의 시작 위치** — 위 칸이 늦게 커져서 목록이 밀려 내려가면 안 된다.
4. **아이콘·글자 폭** — 그린 뒤에 그림 문자→아이콘 바꾸기, 접기·펼치기, 글자 크기 적용으로 줄이 출렁이면 안 된다.
5. **번쩍임** — 하얀 빈 화면·반쯤 그린 화면이 보이면 안 된다. 겹쳐 바뀌는 움직임(크로스페이드)도 넣지 않는다(멀미). **준비되면 한 번에 바뀐다.**

## 2. 흔들림의 원인 다섯(메일 11-27 실측) — 새 화면에서 먼저 이것부터 본다

| ① 화면 뜬 뒤 **숫자·안내 띠를 서버에서 받아 채움**(0.2초 뒤) | 위 띠가 두 줄로 늘어 아래 전체가 밀림(77px) | 마지막으로 받은 값을 `sessionStorage` 에 기억 → 다음 화면 **그리기 전에** 먼저 채움 · 새 값이 오면 숫자만 바뀜 · 기억값으로 채울 때는 「새 메일」 판정 등 부수 동작 안 함 |
| ② 왼쪽 칸 **스크롤이 새 화면에서 맨 위** | 위로 올라갔다 다시 내려옴 | 누르는 순간 스크롤 값 저장 → `</nav>` 바로 뒤 인라인 스크립트에서 되돌림 + **칸 높이가 정해진 뒤 한 번 더**(높이 계산 전엔 값이 잘림) |

| ⑤ 높이 계산(`setH`·`fillH`)을 **그린 뒤 load 에서 다시** | 칸 높이가 바뀌며 스크롤이 잘림 | 위 ①·④를 끝낸 직후 `resize` 이벤트를 한 번 보내 다시 재고, 그다음 스크롤 되돌림 |

## 3. 만들 때 붙이는 기본 틀
```html
<!-- 머리(head) -->
<style>
  @view-transition{ navigation:auto; }                 /* 같은 사이트 화면끼리: 준비될 때까지 옛 화면 유지 */
  ::view-transition-old(root),::view-transition-new(root){ animation:none; }   /* 겹치기 움직임 없음 */
  .왼쪽칸{ view-transition-name:side; overflow-anchor:none; }
  .위띠{ view-transition-name:top; }
  ::view-transition-old(side),::view-transition-new(side),::view-transition-old(top),::view-transition-new(top){ animation:none; }
</style>
<link rel="expect" href="#paintReady" blocking="render">   <!-- 끝까지 읽고 한 번에 보이기 -->

<!-- 본문 맨 끝 -->
<div id="paintReady" hidden></div>
<script>
  /* ① 기억해 둔 숫자·띠 먼저 채우기 → ④ 아이콘 바꾸기 → ⑤ resize 한 번 → ② 왼쪽 칸 스크롤 되돌리기 */
</script>
```
- 화면마다 `@view-transition` 을 끄는 곳(일정표 등 `navigation:none`)은 그 이유가 있으니 건드리지 않는다.
- `blocking="render"` 는 첫 화면을 조금 늦춘다(가짜 자료 실측 느린 PC 0.9→1.4초) — 대신 깜빡임이 없다. 대표는 깜빡임 없음을 골랐다(11-27).
