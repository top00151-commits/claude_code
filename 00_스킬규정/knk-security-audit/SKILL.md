## 1. 시작하기 전 — 대표께 네 가지를 먼저 묻는다

바로 착수하지 않는다(대표 규정 「지시 이해 먼저」). 물을 것:

1. **어디까지** — 코드만 / 코드+서버 설정 / 거기에 시험 서버 확인까지
2. **어떤 위험을 먼저** — ①남의 대화·파일 ②밖에서 들어오기 ③비밀값 ④첨부 바이러스·서버 멈춤 ⑤자료 사라짐 (여러 개 고를 수 있게)

4. **결과물** — 쉬운 보고서만 / 보고서+상세 기록 / 문서 없이 대화로만

## 2. ⛔ 절대 지킬 것

1. **운영 서버에 접속·수정·재시작하지 않는다.** 운영 설정이 필요하면 그 시스템 담당 세션에 **읽기만** 부탁한다.
2. **실제 공격을 운영에 하지 않는다.** 시험은 격리된 시험 서버에서 가짜 자료로만.
3. **비밀값은 값을 보지도 적지도 않는다.** `.env` 를 통째로 열지 않는다 — **이름으로 콕 집어** 보고(`grep -E '^KNK_MSG_ENV='`), 「어디에 드러나는가」까지만 적는다. 결과 파일·답장에 값 조각도 쓰지 않는다.
4. **직원 대화 내용·`data/`·`backups/` 를 열지 않는다.**
5. **김정락(대표)–안지연(67) 1:1 방은 어떤 경우에도 대상이 아니다**(전역 최우선 1규칙).
6. **고치지 않는다.** 감사팀은 점검·보고까지. 코드 수정·배포는 그 시스템 담당 세션이 한다.

### 비침습으로 밖에서 확인되는 것 (운영에 들어가지 않고)
회사 사이트의 로그인 화면을 **한 번 열어 응답 머리말만** 읽으면 아래가 바로 답이 난다. 직원이 브라우저로 여는 것과 같은 행위다. **로그인 시도는 하지 않는다.**
- 운영 모드가 켜져 있나 → 보안 헤더(CSP·X-Frame-Options·HSTS·Referrer-Policy)가 실려 나오는지
- HTTPS 강제하나 → `http://` 로 열어 301 인지
- 앱 포트가 밖에 열려 있나 → 그 포트로 한 번 연결해 보고 막히는지
- 오류 화면으로 서버 속이 새나 → 화면 글에 경로·오류 자취가 있는지

## 3. 영역을 여덟으로 나눈다

하나씩 서브에이전트에 맡긴다. **공통 지침 파일을 먼저 쓰고** 과제문은 짧게 한다.

| 번호 | 영역 | 핵심 질문 |
|---|---|---|
| S0 | 서버·배포 설정 | 감사팀이 직접 — Dockerfile·기동 스크립트·실행 옵션·앞단 프록시 |
| S1 | 남의 대화·파일 | 권한 검사를 빠뜨린 입구, 번호만 바꿔 남의 것 보기 |
| S2 | 밖에서 들어오기 | 로그인·세션·토큰·무차별 대입 막기 |
| S3 | 비밀값 | 코드·기록·화면·깃 이력에 열쇠가 드러나나 |
| S4 | 첨부파일 | 바이러스 검사·확장자·저장 경로·내줄 때 머리글 |
| S5 | 한도(안정성) | 빠진 한도, 한 요청이 전체를 붙잡는 구조 |
| S6 | 자료 사라짐 | 삭제 경로·백업·복구·되돌림 |
| S7 | 끼워 넣기 | 데이터베이스 조작·화면 코드 주입·경로·명령 실행 |

**출발점을 미리 찾아 과제문에 넣는다** — 라우트 수, 로그인 검사 없는 라우트 목록, 핵심 함수 줄 번호. 그래야 서브에이전트가 헤매지 않는다.

### ⚠ S5(한도)는 표현을 조심한다
「디도스로 서버 멈추게 하는 법」처럼 쓰면 **안전장치에 걸려 작업이 중단된다.** 같은 내용을 **「한도가 제대로 걸려 있는지 점검 — 빠진 한도를 찾아 목록으로」** 라는 방어 관점으로 쓴다. 찾아내는 결과는 같다.

## 4. 🔴 이 회사 코드에서 반복해 틀리는 함정 일곱 (가장 중요)

**2026-11-23 점검에서 실제로 빠진 함정들이다. 이것 때문에 대표께 두 번 잘못 보고했다.**

### ① 저장소 주석·Dockerfile 은 운영과 다르다
이음 실측(세션 10 확인)에서 **설정 파일의 보관 방식 · 실행 사용자 · 포트 · 시간 제한 · 시작 파일**이 저장소 설명(주석·Dockerfile)과 모두 달랐다.
(실제 값은 운영 약점이라 **저장소에 적지 않는다** — `01_보안점검\` 진행 기록(깃 제외)에 있다.)
→ **운영 설정은 저장소가 아니라 운영에서 확인한다.**

### ② `@login_required` 가 없다고 인증이 없는 게 아니다
이음 라우트 426개 중 73개에 그 표시가 없지만, 전수 확인하면 **함수 안에서 더 엄하게 막는다**(로그인→손님 차단→방 참여 확인). socketio `connect` 도 표시는 없지만 검사가 있다.
→ **표시 유무로 판단하지 말고 함수 안을 연다.** 「로그인 검사 없는 라우트 목록」은 **조사 출발점이지 문제 목록이 아니다.**

### ③ 변수 대입만 보고 「응답에 나간다」고 단정하지 않는다
`pw_hint = "..."` 가 있다고 응답에 실리는 것이 아니다. **응답 조립부(`jsonify`·`results.append`)까지 따라가** 그 칸이 실제로 들어가는지 본다.
(※ 이음의 `api_lookup_employee` 는 실제로 들어 있었다 — 하지만 **확인 없이 단정한 것이 문제**였다.)

### ④ 함수 설명(docstring)은 코드가 아니다
이 저장소에는 코드와 어긋난 옛 설명이 있다. 설명을 근거로 쓰지 않는다.

### ⑤ 🔴 시험 사본은 `git archive HEAD` 로 뜬다 — 공용 작업 폴더를 복사하지 않는다
**다른 세션이 같은 폴더를 동시에 고치고 있다.** 2026-11-23 에 내가 넘긴 수정을 세션 10 이 반영한 **그 파일을 복사해 시험**하고 「원래부터 문제없었다」고 잘못 정정했다.
```bash
git archive HEAD | tar -x -C <시험폴더>     # 고정된 판
```
→ **시험 결과가 코드 읽기와 다르면, 코드가 틀린 게 아니라 「내가 다른 판을 봤을 가능성」을 먼저 의심한다.** 사본과 HEAD 의 해시·출현 수를 대조한다.

### ⑥ 「아주 위험」은 감사팀이 코드로 다시 확인한 뒤 보고한다
서브에이전트 결과에는 과한 표현이 섞인다. 실제 사례:
- 「백업이 꺼져 있다 = 아주 위험」 → **일부러 끈 것**이었다(「NAS 스냅샷이 담당」이라고 코드에 적혀 있었다). 진짜 문제는 「그 뒤 복구를 증명한 적이 없다」는 것.
- 「화면에 늘 '바이러스 검출 차단'이라 적혀 있다」 → **그 문구는 실제 감염 때만 나간다.**
→ 등급이 높을수록 **원문을 직접 열어 확인**한다. 틀린 것을 고치게 만드는 게 더 나쁘다.

### ⑦ 정정을 보내기 전에 git 으로 한 번 더 확정한다
2026-11-23 에 정정을 먼저 보내 담당 세션 작업을 헛돌게 했다. **철회할 때도 근거를 붙인다.**

## 5. 시험 서버 만드는 법

1. `git archive HEAD | tar -x -C <시험폴더>` — **고정된 판**(함정 ⑤)
2. 환경변수: `KNK_MSG_ENV=development` · `KNK_MSG_ASYNC=threading` · `KNK_MSG_TRANSLATE_MOCK=1`
3. 데이터 경로는 보통 **코드 파일이 있는 폴더 기준**이라, 폴더를 따로 떼면 운영 자료와 자동으로 분리된다. 분리됐는지 **직접 확인**한다(새 열쇠 파일이 시험 폴더에 생기는지 등).
4. 가짜 직원 몇 명을 직접 넣는다. `users` 표에 `created_at` 같은 **NOT NULL 칸**이 있으니 빠뜨리지 않는다.
5. 포트를 열지 않고 **`app.test_client()`** 로 부르는 쪽이 빠르고 안전하다. 진짜 포트가 필요하면 **운영·다른 세션이 쓰는 포트는 피한다**(목록은 공유 메모리).
6. ⚠ 시험 사본은 개발 모드라 `TRUSTED_PROXIES=0` 이다 → **`X-Forwarded-For` 가 적용되지 않는다.** 접속 주소 관련 시험은 운영과 같은 프록시 설정에서 다시 재야 한다.

## 8. 점검 때 꼭 보는 것 (이음에서 실제로 나온 것들)

- 비밀번호를 받는 입구가 **하나가 아니다.** 로그인 화면 말고 토큰 발급·비밀번호 확인 입구가 더 있으면 **같은 잠금을 쓰는지** 본다(이음은 안 썼다).
- **「화면에서만 막는 것」을 찾는다.** `must_change_password`·동의서처럼 서버가 안 막고 화면만 띄우는 구조가 이 저장소에 여럿 있었다. 판정 함수가 **조회용 입구에서만 불리면** 강제가 아니다.
- **꺼져 있는 보호 장치**를 찾는다. 기본값이 꺼짐인데 운영에서 켠 적 없는 것(이음에서 실제로 있었다 — 세부는 깃 제외 기록에).
- **설치·배포 스크립트가 써 넣는 값**을 본다. 개발 모드·전체 허용을 적어 두면 나중에 그걸 돌리는 순간 보호가 풀린다.
- **잠금을 쥔 채 바깥을 기다리는 코드** — 이 회사 시스템은 일꾼이 하나라 치명적이다. 이음에서 같은 유형이 **네 번** 재발했다.
- **지운 기록이 남는가.** 「누가 몇 건을 지웠나」를 밝힐 수 없으면 그것 자체가 문제다.
- **사람이 고르지 않은 자료가 저절로 바뀌는 길** — 저장이 다른 줄·다른 표까지 퍼뜨리거나, 화면을 열기만 해도(GET) 값을 고쳐 저장하거나, 이름으로 자동 연결하는 코드. 자료를 믿을 수 없게 만들므로 **자료 사라짐과 같은 무게**로 본다.

## 9. 함께 쓰는 운영 스킬 (원본 = `00_스킬규정\`)

점검할 때 「이게 규정 위반인가」를 판단하는 기준은 이 스킬들에 있다. 지적을 쓰기 전에 해당 스킬의 점검표를 본다.

| 스킬 | 점검에서 쓰는 곳 |
|---|---|
| `knk-no-silent-change` | **자료 사라짐·자료 못 믿음 영역** — 고른 줄만 저장하나 · 퍼뜨릴 때 확인받나 · 화면 열기가 쓰지 않나 · 자동 변경에 이력·되돌림이 있나 (웍스 점검표 22곳: `01_HAIST_WORKS\작업기록\2026-11-25_1201_z1191z152_점검_…`) |
| `knk-screen-exit` | 화면 영역 — 새로 열린 화면·팝업·파일 보기에서 **나갈 길이 있나**(갇히는 화면은 사람이 강제로 창을 닫게 되어 작업이 날아간다) |
| `knk-done-status` | **보고서·결과 문구** — 등급별 지적마다 「고쳐야 끝인가 · 누가 할 일인가」를 ✅/⏳/👉 로 밝힌다 |
| `knk-four-view-verify` | **감사팀 자신의 결과 검증** — 지적을 보고하기 전에 사용자·실무자·관리자·대표 입장으로 다시 본다. 특히 **허상**: 코드·운영에서 실측하지 않은 값(「코드가 N 이니 운영도 N」·저장소 주석·Dockerfile)을 사실로 쓰지 않았나. 이음 점검에서 실제로 **세 번** 틀렸다(4절 함정 · 공용 폴더 사본으로 오판 · 과한 표현). 고친 판을 확인할 때는 **정상 사용자가 막히지 않는지**를 먼저 잰다 |
