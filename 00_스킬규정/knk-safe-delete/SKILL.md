## 1. 규칙 — 한 줄로

**숨기기는 「안 보이게만」, 삭제는 「목록에서 빼기」다. 다른 곳이 쓰고 있는 파일·줄은 지우지 않는다. 사람은 몰라도 운영자는 되살릴 수 있게 남긴다.**

## 2. 세 가지를 나눈다

| 이름 | 하는 일 | 되돌리기 | 화면 |
|---|---|---|---|
| **숨기기** | 쓰는 사람 고르기·목록에서만 빠짐 · 관리 목록에는 남음 | 「다시 보이기」 단추로 사용자가 직접 | 회색 「숨김」 표시 |
| **삭제** | 관리 목록에서도 빠짐(표시 칸 `deleted=1` + 숨김) · DB 줄·파일은 남김 | 화면에서는 안 됨 · 운영자가 DB 사본·칸으로 되살림 | 붉은 글자 「🗑 삭제」 + 한 번 더 묻기 |
| **완전 삭제**(파일·줄을 없앰) | 정말 없어짐 | 안 됨 | **대표가 따로 지시할 때만** · 쓰는 곳이 0인 것을 센 뒤에만 |

- 이름을 정확히 쓴다. 「숨기기」를 눌렀는데 지워지거나, 「삭제」를 눌렀는데 숨기기만 되면 안 된다.
- 삭제를 넣어도 숨기기는 그대로 둔다(잠깐 빼 두는 길).

## 3. 지우기 전에 「누가 이것을 쓰나」부터 센다

| 쓰는 곳 | 예 | 지우면 |
|---|---|---|
| 이미 보낸 메시지·메일 | 스티커 파일 이름 · 첨부 주소 | 옛 대화 그림이 깨짐 |
| 다른 표의 번호 연결 | 수주 → 고객사 번호 · 일정 → 사람 번호 | 화면 오류 · 이름 빈칸 |
| 엑셀·인쇄·보고서 | 옛 견적서 · 월 보고 | 지난 자료가 달라짐 |
| 같은 이름을 다시 만들기 | 지운 모음 이름으로 새 모음 | 이름 겹침 검사에 걸려 못 만듦 |

- 쓰는 곳이 하나라도 있으면 **파일·줄을 남기고 표시만** 한다(2절 「삭제」).
- 이름 겹침 검사는 **지운 것을 빼고** 센다. 지운 이름으로 다시 만들 수 있어야 한다.
- 지운 것이 화면에서 빠지는 자리를 **모두** 고친다: 관리 목록 · 쓰는 사람 고르기 · 추천 · 검색 · 내려받기 · 다른 화면의 같은 목록(공용 계산 한 곳에서 거르면 가장 안전).

## 4. 화면

- 단추 자리: 목록 줄과 상세(안쪽) 화면 **두 곳**. 붉은 글자로, 다른 단추와 높이는 같게(`knk-even-layout`).
- 누르면 한 번 더 묻는다. 묻는 글에 넣을 것:
  - 무엇을 지우는지(이름 · 개수)
  - 지금 쓰는 사람에게 보이는 중이면 「직원 화면에서도 바로 빠집니다」
  - 「화면에서는 되살릴 수 없습니다」
  - 「이미 보낸 메시지(옛 자료)는 그대로 보입니다」
- 끝나면 결과 첫 줄은 `knk-done-status`(✅ 완료 — 「○○」을 삭제했습니다).
- 다른 사람 화면에도 바로 반영한다(이음 = 바뀜 알림 한 번).

## 5. 서버

- 관리자만 · 아니면 403. 없는 것·이미 지운 것은 404.
- `DELETE` 입구는 **표시를 바꾸는 것 하나만** 둔다. 파일을 지우는 코드(`os.remove`·`unlink`)는 넣지 않는다.
- 바꾸기 전 이력(누가 · 언제 · 무엇)을 남긴다. 운영 DB를 손으로 고치면 변경자 = 시스템(`knk-no-silent-change` 4번).

## 6. 시험·검사기

- 격리 서버에서: 지우기 → 목록·고르기에서 빠짐 → **옛 그림·옛 첨부 주소 200** → 직원 403 → 다시 지우면 404 → 같은 이름 다시 만들기 → DB 줄 남음.
- 검사기에 나쁜 예를 넣는다: 「파일을 지우는 판」「관리자 검사를 뺀 판」「목록에서 안 거르는 판」이 실제로 걸리는지.
- 운영 확인은 읽기 전용으로 숫자만: 지운 것 `deleted=1` · 남은 것 그대로 · 파일 수 그대로 · 옛 그림 주소 200.

## 7. 지켜야 할 것

- 사용자 대신 지우지 않는다. 지우기는 대표·담당자가 화면에서 직접 한다(빅터는 확인만).
- 잘못 지웠다고 하면 DB 사본·표시 칸으로 되살린다(그래서 지우지 않고 남긴다).
- ⛔ 김정락–안지연 1:1 방·관련 자료는 시험·조회 대상에서 처음부터 뺀다(철칙 1규칙).
