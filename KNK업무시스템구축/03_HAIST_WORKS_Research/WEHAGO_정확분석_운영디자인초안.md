## 0. Executive Summary

### 0.1 WEHAGO 물류관리 = 5 대분류 + 기준정보 (공식 매뉴얼 검증)

|---|---|---|
| 1 | **영업관리** | 견적서·수주서·**출고지시서**·**출고처리**·전자세금계산서·전자계산서 |
| 2 | **구매관리** | **발주서**·**입고처리** |

| 5 | **외주관리** | 외주자재출고등록·외주제품입고처리·외주매입마감및회계처리·외주출고현황·외주입고현황·생산지시대비외주출고/입고현황·외주매입마감현황 |

### 0.2 핵심 흐름 (one-line)

```
[영업] 견적서 → 수주서 → 출고지시서 → 출고처리 → 전자세금계산서
[구매] 발주서 → 입고처리 → (회계전표 자동)
[생산] 생산(작업)지시서 → [BOM전개] 자재출고처리 → 생산입고처리 → 생산입고현황
[외주] 외주자재출고등록 → 외주제품입고처리 → 외주매입마감및회계처리
[재고] 기간별입출고현황 (전 모듈 합산)
```

### 0.3 KNK 매핑 한 줄

KNK는 SO/PO/Project 다대다(v5H132~136) + 호기 코드(003M2501·WP-LOA·HM-001·M2504) + baby V2 매출주문/재고가 **분리** 운영 중. WEHAGO 패턴을 흡수해 **HAIST_WORKS 단일 자재모듈로 통합**할 경우, 5 대분류 중 **구매·생산·재고**부터 단계 도입 가능 (영업은 baby V2와 중복, 외주는 KNK 외주율에 따라 후순위).

### A.2 핵심 5 화면 Deep Dive

#### A.2.1 품목등록 (자재등록 = 모든 자재의 시작점)

**기능 목적** (WEHAGO 고객센터 인용):
> "분류등록 정보는 '기능모음 > 분류등록' 으로 등록한 분류 정보를 사용하며, 단위등록 정보는 '기능모음 > 등록 > 단위등록' 으로 등록한 단위 정보를 사용"

**입력 항목** (영상 자막 메타데이터 + 커뮤니티 가이드 종합):
- **분류** (대분류·중분류·소분류 — 분류등록 메뉴 사전 등록 필수)
- **품목코드** (사용자 직접입력)
- **품목명**
- **규격**
- **단위** (구매·매출·자재투입·재고 단위 각각 — 단위등록 사전 등록)
- **투입생산단위**
- **적정재고량**
- **표준원가** (제조품 재고평가·재고단가 산정 기준)
- **입출고창고** (기본 창고 — 창고등록 사전 등록)
- **세금계산서명**
- **거래명세서명**
- (+ 제조품 여부·외주처리 여부 등 분기 플래그)

**검증 한계**: 03 시점 공식 화면 캡처 미수집(403). 위 필드는 검색 결과 단편 + Smart A 매뉴얼 PDF 메타에서 종합한 근사. 세부 위치·필수/선택은 KNK 계정 직접 접속 시 확인 필요.

#### A.2.2 발주서 (구매관리 진입점)

**기능 목적** (WEHAGO 솔루션 페이지 인용):
> "생산 진행 상황을 고려한 구매 예정량을 미리 파악할 수 있으며, 발주서 기반으로 입고와 전표처리를 쉽게할 수 있습니다."

**전형적 입력 항목** (한국 ERP 표준 + WEHAGO 메뉴 일관성):
- 발주번호 (자동 채번 가능)
- 발주일자
- 거래처 (거래처등록 참조)
- 거래처별 배송지 (거래처별배송지등록 참조)
- 납기일자
- 담당자
- 품목 라인 (다행)
  - 품목코드/품목명·규격
  - 수량 (구매단위)
  - 단가
  - 공급가액·부가세·합계
  - 입고예정일
  - 비고
- 첨부 (사양서·도면 등)

**연계**:
- → **입고처리**에서 "구매관리 > 발주서" 적용 가능 (검색 결과 인용)

#### A.2.3 입고처리 (구매 → 자재 실재고 진입)

**기능 목적** (WEHAGO 고객센터 인용):
> "입고처리는 구매관리 > 발주서 메뉴에서 작성한 발주서를 적용하여 입고 정보를 입력하는 메뉴"

**전형적 입력**:
- 입고번호 (자동 채번)
- 입고일자
- 거래처
- 발주서 적용 (발주번호 선택 → 라인 자동 채움)
- 입고창고 (창고등록 참조 — 품목별 기본창고 자동)
- 품목 라인:
  - 품목·규격·발주수량
  - **입고수량** (분할 입고 가능)
  - 단가·금액
  - LOT/Serial 번호 (옵션)
- 회계전표 자동 생성 (회계 모듈 연동)

**효과**: 입고 즉시 **재고 +**, **회계 매입 전표 자동**, **거래처 채무 +**.

#### A.2.4 자재출고처리 (BOM전개 — KNK가 가장 흡수할 가치 큰 화면)

**핵심 기능** (WEHAGO 고객센터 2024-09-12 업데이트 인용):
> "자재출고처리 BOM전개 기능 개선"

**작동 패턴** (검색 결과 + 일반 ERP 표준):
1. 사용자가 **생산(작업)지시서** 선택
2. 시스템이 해당 지시서의 제품 BOM(Engineering·공정경로·프로젝트 중 1종)을 조회
3. **BOM전개** 버튼 → 필요 자재 목록 자동 산출 (수량 = 지시 수량 × BOM 단위소요량)
4. 출고창고·LOT·실제 출고수량 확인/조정
5. 저장 → **재고 −**, 생산지시 자재투입 기록

**전형적 입력**:
- 출고번호·출고일자
- 출고창고
- 작업지시번호 (생산(작업)지시서 적용)
- 자재 라인:
  - 품목·규격
  - **소요량** (BOM 산출)
  - **출고수량** (실제, 분할 가능)
  - LOT·시리얼
  - 비고

**연계**:
- ← **생산(작업)지시서** (자재 라인은 BOM에서 자동)
- → **생산입고처리** (제품 입고 시 자재 실투입 마감)
- → **공정관리** (불량·검사·자재투입 추적)

#### A.2.5 생산(작업)지시서 + 생산입고처리

**생산(작업)지시서** (WEHAGO 고객센터 인용):
> "생산(작업)지시서 메뉴는 생산할 품목에 대한 지시 내용을 입력하는 메뉴로 상단부에 제품 품목, 하단부에 자재 품목 정보를 입력"

**구조**:
- 상단(헤더): 지시번호·지시일자·납기·**제품 품목**(생산할 것)·지시수량·작업장
- 하단(라인): **자재 품목**(투입할 것 = BOM 전개 결과)
  - 자동: BOM에서 가져옴
  - 수동: 직접 추가 가능

**생산입고처리** (생산 완료 시):
- 작업지시번호 적용
- 생산입고일자
- 입고창고
- **입고수량** (실제 양품)
- 불량수량
- 자재 실투입 마감
- → 회계 전표 자동 (제품 재고 +, 자재 재고 -, 제조원가 분개)

**조회 메뉴 분리** (WEHAGO 고객센터 인용):
- **생산지시현황**: "지시번호별·일자별·품목별" 3 탭으로 지시 내역 조회
- **생산입고현황**: "입고번호별·일자별·품목별" 3 탭으로 입고 내역 조회

```sql
CREATE TABLE items (
    id BIGSERIAL PRIMARY KEY,
    code TEXT UNIQUE NOT NULL,
    name TEXT NOT NULL,
    type TEXT NOT NULL CHECK (type IN ('material','semi','product')),
    classification_id BIGINT REFERENCES classifications(id),
    spec TEXT,
    unit_purchase TEXT,
    unit_sales TEXT,
    unit_input TEXT,
    unit_stock TEXT,
    standard_cost NUMERIC(15,2),
    optimal_stock NUMERIC(12,2),
    safety_stock NUMERIC(12,2),
    default_warehouse_id BIGINT REFERENCES warehouses(id),
    primary_vendor_id BIGINT REFERENCES vendors(id),
    tax_invoice_name TEXT,
    statement_name TEXT,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

-- 2. 거래처 / 창고 / 분류 / 단위
CREATE TABLE vendors (...);
CREATE TABLE warehouses (...);
CREATE TABLE classifications (id, parent_id, level, name);
CREATE TABLE units (code TEXT PRIMARY KEY, name TEXT);

-- 3. BOM
CREATE TABLE boms (
    id BIGSERIAL PRIMARY KEY,
    parent_item_id BIGINT REFERENCES items(id),  -- 제품
    bom_type TEXT CHECK (bom_type IN ('engineering','process','project')),
    project_id BIGINT REFERENCES projects(id),    -- KNK v5H 다대다
    version TEXT,
    is_active BOOLEAN
);
CREATE TABLE bom_lines (
    bom_id BIGINT REFERENCES boms(id),
    child_item_id BIGINT REFERENCES items(id),
    qty_per NUMERIC(12,4),
    unit TEXT,
    sequence INT,
    PRIMARY KEY (bom_id, sequence)
);

-- 4. 발주
CREATE TABLE purchase_orders (
    id BIGSERIAL PRIMARY KEY,
    po_number TEXT UNIQUE,
    order_date DATE,
    vendor_id BIGINT,
    delivery_address_id BIGINT,
    due_date DATE,
    owner_id BIGINT,        -- 담당자
    project_id BIGINT,      -- 호기 연결 (KNK)
    status TEXT,            -- draft/submitted/approved/closed
    total_amount NUMERIC,
    created_at TIMESTAMPTZ
);
CREATE TABLE po_lines (...);

-- 5. 입고
CREATE TABLE receipts (
    id BIGSERIAL PRIMARY KEY,
    receipt_number TEXT UNIQUE,
    po_id BIGINT REFERENCES purchase_orders(id),
    receipt_date DATE,
    warehouse_id BIGINT,
    created_at TIMESTAMPTZ
);
CREATE TABLE receipt_lines (...);

-- 6. 생산지시
CREATE TABLE work_orders (
    id BIGSERIAL PRIMARY KEY,
    wo_number TEXT UNIQUE,
    project_id BIGINT,      -- 호기 003M2501 등
    product_item_id BIGINT,
    qty_ordered NUMERIC,
    issue_date DATE,
    due_date DATE,
    workstation TEXT,
    status TEXT,
    created_at TIMESTAMPTZ
);
CREATE TABLE wo_material_lines (
    wo_id BIGINT,
    item_id BIGINT,
    qty_required NUMERIC,
    qty_issued NUMERIC,
    qty_actual NUMERIC,
    lot_number TEXT,
    PRIMARY KEY (wo_id, item_id)
);

-- 7. 자재출고 / 생산입고
CREATE TABLE material_issues (...);   -- 자재출고처리
CREATE TABLE production_receipts (...); -- 생산입고처리

-- 8. 재고 트랜잭션 (모든 모듈 공통 기록)
CREATE TABLE stock_movements (
    id BIGSERIAL PRIMARY KEY,
    item_id BIGINT,
    warehouse_id BIGINT,
    qty_delta NUMERIC,    -- + 입고 / - 출고
    source_type TEXT,     -- receipt/issue/production_in/sales/adjust
    source_id BIGINT,
    lot_number TEXT,
    moved_at TIMESTAMPTZ,
    created_by BIGINT
);
CREATE INDEX idx_stock_item_warehouse ON stock_movements(item_id, warehouse_id, moved_at);
```
