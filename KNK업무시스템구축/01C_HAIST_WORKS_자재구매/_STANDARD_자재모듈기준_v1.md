## 2. 자재모듈 5단계 라이프사이클 (KNK 표준)

### 2.1 흐름도
```
[견적 요청] → [주문 확정] → [발주] → [입고] → [출고]
   │             │           │        │        │
   └─ 영업/SO    └─ PO 전 단계   │        │        └─ 생산투입·판매·외주
                                │        │
                                │        └─ 검수 → 재고 가용
                                └─ 공급사 통보·납기관리
```

### 2.2 단계별 책임 시스템
| # | 단계 | 핵심 데이터 | KNK 시스템 위치 | 비고 |
|---|---|---|---|---|
| 1 | 견적 | RFQ·견적서 | KNK 운영 그룹웨어 (별도 결재) | 본 모듈 범위 외 |
| 2 | 주문(SO) | 매출주문 | HAIST WORKS `/sales/orders` (실무팀2) | 사업자 영역 |
| 3 | **발주(PO)** | 발주서 헤더+라인 | HAIST WORKS `/po` (본 모듈) | ⭐ |
| 4 | **입고(MR)** | 입고처리 (구매·생산·외주제품 3종) | HAIST WORKS `/po/{id}/receive`·`/stock/receipts` | ⭐ |
| 5 | **출고(MO)** | 자재출고 (판매·생산·외주자재 3종) | HAIST WORKS `/stock/issue`·`/stock/issues` | ⭐ |

### 2.3 가용재고 정의 (참고 ERP 일반 패턴)
```
가용재고 = 기초재고 + 입고합계 + 입고예정 - 출고합계 - 출고예정
       = 실재고 + 발주잔량 - 출고예정
```
**KNK 적용:** 발주 라인의 `(수량 - 입고완료수량)`을 입고예정으로 가산. 출고예정은 작업지시(WO)의 미출고 라인.

#### 3.1.1 핵심 필드 (1차 자료 기반)
| # | 필드 | 데이터 타입 | 예시 | 필수 | 비고 |
|---|---|---|---|---|---|
| 1 | 품목코드 (PK) | string(20) | `KNKK000000713` | ✅ | KNK 자체 채번 |
| 2 | 품명 | string(120) | `FITTING` | ✅ | |
| 3 | 규격 | string(80) | `KQ2S04-M5A` | | 검색 핵심 |
| 4 | 조달구분 | enum | `구매품` / `자체생산` / `외주` | ✅ | 코드값 (1·2·3) |
| 5 | 품목계정 | enum | `원재료` / `반제품` / `완제품` / `상품` / `소모품` | ✅ | |
| 6 | 재고단위(UOM) | string(8) | `EA` / `m` / `kg` / `식` / `장` | ✅ | |

| 13 | 품목비고 | text | | | |
| 14 | 이미지 (썸네일) | URL/blob | | | 시안1 부품 카드 |
| 15 | HS코드 | string(10) | | | 수출입용 (실무팀1B 연계) |

#### 3.1.2 코드 체계 (KNK 현행 분석 → 표준화)
1차 자료에서 식별된 패턴:
- `KNKD000000xxx` — D 시리즈 원재료 (시트류)
- `KNKK000000xxx` — K 시리즈 원재료 (가장 많음, 일반 부품)
- `KNKJ000000xxx` — J 시리즈 원재료 (특수)
- `KNK-P-xxxx` — PCB 류
- `001M2411-AQ00-001` — 프로젝트 매핑 코드 (BOM 연계)
- 외부 코드 그대로 사용 가능 (예: `SB684ZZ`, `0604B-20`, `66601-1`)

**KNK 표준 신규 채번 (v2 권장):**
```
KNK-{대분류2자}-{시리즈1자}-{6자리연번}
예: KNK-PT-K-000713 (Parts·K시리즈·713번)
```
*기존 코드와 병행 운영 + 마이그레이션 라인 별도 (DB 스키마 작업, 결재 필요).*

### 3.3 창고·위치 마스터 (Warehouses)
1차 자료 식별값:
- `KNK-001` `KNK1층자재창고`
- `KNK-002` `KNK2층자재창고`
- `KNK-003` `구매사무실`

**확장 권장:** `위치(랙·셀)` 필드 추가 (모바일 바코드 스캔 대비).

### 3.4 단가 마스터 (Pricing) — 2종 구조

#### 3.4.1 품목별 단가 (Item-level)
- 1품목 × **매입 7단가** + **매출 7단가**:
  - `상한가 / 정상가 / 하한가 / 설정가1 / 설정가2 / 설정가3 / 설정가4`
- 일괄 엑셀 업로드 양식 지원

#### 3.4.2 거래처별 단가 (Vendor-Item-level)
- 거래처 × 품목 조합으로 매입·매출 단가 별도 관리
- 예: 광원전기 KNKJ000006451 = 16,500원 / 우리산전 동일품 = 18,000원
- 예외 등록 (Override) 패턴

#### 3.4.3 우선순위 적용 규칙
```
PO 작성 시 단가 자동 호출:
  1) 거래처별 단가가 있으면 → 그것 사용
  2) 없으면 → 품목별 정상가
  3) 없으면 → 설정가1 → 설정가2 → 설정가3 → 설정가4 (fallback chain)
  4) 모두 없으면 → 수동 입력
```

| 입고완료수량 | (집계) | 잔량 = 수량 - 입고완료 |
| 프로젝트 | `001T2602` | 라인별 프로젝트 매핑 가능 |
| 품목비고 | | |

#### 4.1.2 채번 규칙
- prefix: `PO-KNK-`
- 본문: `YYYYMMDD` + 5자리 일련 (그날 31번째 발주 = `00031`)
- 자동 채번 (External 입력 금지)
- 예: `PO-KNK-2026020600031`

#### 4.1.3 PO 상태 라이프사이클 (KNK 표준)
```
DRAFT(작성중)
   │ 작성·검토
   ▼
APPROVED(승인) ─ 결재 필요시 ─┐
   │                        │
   │ 공급사 통보              │
   ▼                        │
ISSUED(발주완료) ◀─────────────┘
   │ 입고 시작
   ▼
PARTIAL(부분입고) ─ 잔량 있음
   │ 모든 라인 입고 완료
   ▼
RECEIVED(입고완료)
   │ 회계 마감
   ▼
CLOSED(종결)

[취소경로] CANCELLED ← DRAFT/APPROVED/ISSUED 어디서나 가능 (RECEIVED 이후 X)
[지연경로] OVERDUE   ← ISSUED/PARTIAL에서 납기 초과 시 자동 라벨
```

**현재 KNK DB enum과의 매핑:**
| KNK 표준 v1 | 현재 DB (database.py:4659) | 갭 |
|---|---|---|
| DRAFT | 작성중 | ✅ 일치 |
| APPROVED | (없음) | ⚠️ 신설 필요 |
| ISSUED | 발주완료 | ✅ 일치 |
| PARTIAL | 부분입고 | ✅ 일치 |
| RECEIVED | 입고완료 | ✅ 일치 |
| CLOSED | (없음) | ⚠️ 신설 필요 (회계 마감) |
| CANCELLED | 취소 | ✅ 일치 |
| OVERDUE | (없음, 라벨만) | ⚠️ 동적 계산 권장 |

→ enum 확장은 별도 결재 필요 (라우트·DB 스키마 변경 권한 외).

### 4.2 입고 (Material Receipt, MR)

#### 4.2.1 입고 3종 분류 (1차 자료 기반)
| 종류 | 용도 | 발생원 |
|---|---|---|
| 구매입고 | 외부 발주서 입고 | PO |
| 생산입고 | 자체 생산 완제품·반제품 | WO 종결 |
| 외주제품입고 | 외주가공 완료품 | 외주 PO |

#### 4.2.2 입고 워크플로 (KNK 표준)
```
[PO ISSUED 상태] → /po/{id}/receive 화면
   │
   ├─ 입고 수량 입력 (라인별, 부분입고 허용)
   ├─ QC 결과 (합격 / 불합격 / 보류)
   ├─ 창고·위치 지정
   ├─ 입고증빙 (사진·문서 업로드)
   └─ 회계 전표 트리거 (별도 모듈 위임)
   │
   ▼
[입고완료수량 갱신]
   │
   ├─ 모든 라인 완료 → PO 상태 RECEIVED
   └─ 일부 잔량 → PO 상태 PARTIAL
```

#### 4.2.3 채번 규칙
- prefix: `MR-KNK-`
- 본문: `YYYYMMDD` + 5자리
- 예: `MR-KNK-2026020600007`

### 4.3 출고 (Material Out, MO)

#### 4.3.1 출고 3종 분류 (1차 자료 기반)
| 종류 | 용도 | 사용처 |
|---|---|---|
| 판매출고 | 완제품·상품 매출 | SO 연계 |
| 생산출고 | 자재투입 (생산용) | WO + BOM 전개 |
| 외주자재출고 | 외주가공처 자재 지급 | 외주 PO + BOM |

#### 4.3.2 출고 헤더-라인 분리 (참고 ERP 일반 패턴, KNK 적용)
**헤더 (`material_outs`):**
- 자재출고번호 (PK): `MO-KNK-YYYYMMDD-NNNNN`
- 출고일·생산품(완제품) FK·생산수량·거래처(외주 시)·부서·사원·관리항목·비고

**라인 (`material_out_items`):**
- 품목·수량·**로스율**·출고창고·**프로젝트**·**생산작업지시서번호**·품목비고

**핵심 결정 포인트:** 출고 라인은 반드시 **프로젝트 코드 매핑** 필수 (실원가 계산 키).

#### 4.3.3 BOM 전개 트리거 (시안1 사양 보존)
1. WO 생성 시 BOM 자동 호출
2. 작업지시 수량 × BOM EA당 수량 = 필요 자재 수량 산출
3. 가용재고 검증 → 부족분 발주 권고
4. 일괄 출고 처리 → 자재출고 헤더+라인 자동 생성

### 4.4 재고 (Inventory)

#### 4.4.1 핵심 공식 (1차 자료 컬럼 그대로)
```
기말재고 = 기초재고
        + 입고합계(구매입고 + 생산입고 + 외주제품입고)
        - 출고합계(판매출고 + 생산출고 + 외주자재출고)
```

#### 4.4.2 재고 보고서 5종 (KNK 표준)
1. **재고 현황** — 품목별 기초·입고·출고·기말 (1차 자료 그대로)
2. **재고 이동** — 시계열 입출고 트랜잭션
3. **ABC 분석** — A(상위 70%)·B(20%)·C(10%) 분류
4. **회전율** — 출고합계 / 평균재고
5. **안전재고 알림** — 적정재고량 대비 미달 품목

#### 4.4.3 FIFO 출고 권고
**원칙:** 입고일자 빠른 lot부터 출고 (선입선출). 단가 기준 실원가 산정.
