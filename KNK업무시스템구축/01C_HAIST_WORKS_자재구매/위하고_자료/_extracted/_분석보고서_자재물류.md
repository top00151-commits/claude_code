## 1. Chapter 1 — 기초정보관리 (자재 마스터)

### 1.1 품목등록 — 핵심 필드

| 영역 | 항목 | KNK 매핑 (parts 테이블) |
|---|---|---|
| 식별 | 품목코드 / 품명 / 규격 / 단위 | `part_no` / `part_name` / `spec` / `unit` ✅ |
| 분류 | **품목계정** (7종) | `item_account` ⚠️ z56 SQL에 추가 (미적용) |
| 분류 | **조달구분** (구매품/생산품) | `procurement_kind` ⚠️ z56 SQL에 추가 (미적용) |
| 단가 | 매입단가 / 매출단가 | `last_price` / `std_price` (단가 이력 별도 — z56 `item_prices`) |
| 재고 | **환산재고수량** | (HAIST WORKS 미도입) |
| 재고 | **적정재고량** | `safety_stock`과 별도 개념 — 검토 필요 |
| 분류 | 대분류 / 중분류 / 소분류 | `category` / `category_main` / `category_series` ✅ |
| 창고 | 입고창고 / 출고창고 (기본값) | `default_warehouse` ⚠️ z56 SQL에 추가 |

**품목계정 7종 (참조 SaaS ERP A):**
1. 상품
2. 원재료
3. 부재료
4. 제품
5. 반제품
6. 부산품
7. 저장품

**KNK 적용 의견:**
- 현재 KNK `biz_div` (T/M/E/C 사업부)와는 **다른 축** — 사업부 X 품목계정 = 2축 분류
- "원재료/부재료/제품"은 회계처리 + 재고평가의 분기 기준 (자재출고 시 대체출고 결정)
- KNK는 EMS 사출 제조업 — **원재료(수지·첨가제) / 부재료(포장재·기타) / 제품(완성품) / 반제품(가공품) / 저장품(소모품)** 5종 채택 권장 (상품·부산품은 KNK 비대상)

### 1.2 창고등록

- 창고코드 (8자) + 창고명 (30자) + **창고분류코드** (창고분류등록 사전)
- 담당부서 / 담당사원 / 관리항목
- KNK 미도입 — 추가 검토 필요 (현재는 단일 창고 가정)

### 1.3 BOM등록 — 핵심 설계

| 영역 | 항목 | 의의 |
|---|---|---|
| 모품목 | 제품 / 반제품만 가능 | BOM 헤더 |
| 자품목 | 원재료 / 부재료 / 제품 / 반제품 / 부산품 | BOM 라인 |
| 수량 | **정미수량** | 실 투입량 |
| 수량 | **로스율 (%)** | 유실 비율 |
| 수량 | **필요수량** | 정미수량 × (정미수량 ÷ 로스율) 자동계산 |

**KNK 적용 의견:**
- z56 SQL의 `bom_items` 테이블 + `loss_rate` 컬럼 — **이 매뉴얼과 정확히 일치하는 설계** ✅
- 적용 위임 상태 (빅터/대표 라인) — 실무팀3에서 검증된 표준대로 진행 가능

### 1.4 품목별단가 vs 거래처별단가 (단가 우선순위 4단계)

`물류환경설정 > 물류 > 단가설정`에서 1개 모드 선택:
1. **품목별단가** — 모든 거래처 동일 단가
2. **거래처별단가** — 거래처×품목 단가
3. **직전단가 4종**:
   - 품목별직전단가 (출/입고 메뉴 내)
   - 품목별 거래처직전단가 (출/입고 메뉴 내)
   - 품목별직전단가 (메뉴 무관 전역)
   - 품목별 거래처직전단가 (메뉴 무관 전역)

**KNK 적용 의견:**
- 실무팀3 결재 통과한 **7단가 구조** (매입 7 + 매출 7)는 이 매뉴얼의 단순 매입/매출 2단가보다 풍부
- z56 SQL `item_prices` + `vendor_item_prices`로 양쪽 수용 가능 ✅
- 자동 적용 우선순위는 **거래처별 → 품목별 → 직전** 로직 채택 권장 (KNK는 거래처별이 더 자주 변경됨)

### 1.5 일괄매매군 — 패키지 발주

- 정기적으로 구매하는 자재 묶음을 한 번에 입력
- 발주서 · 입고처리에서 "일괄군 품목적용" 클릭 시 수량 곱셈으로 일괄 입력
- 매입군 ↔ 매출군 변환 (원가율 / 이익율 입력)

**KNK 적용 의견:**
- 자재구매센터에서는 패키지 발주가 빈번 (예: 사출 소모품 SET)
- 우선순위 ⚪ 낮음 — 추후 차수에서 도입 검토

## 2. Chapter 3 — 구매관리 (발주 풀체인)

### 2.1 프로세스

```
발주서 → 입고처리 → 매입마감 및 회계처리 → 지급등록 → (회계관리 전표)
```

각 단계는 **참조 적용** (이전 단계 데이터를 LIST 또는 건별로 불러옴).

### 2.2 발주서 (`po_form.html` 대응)

| 영역 | 항목 | KNK 매핑 (purchase_orders + po_items) |
|---|---|---|
| 식별 | 발주번호 (구분코드 + YYMMDD + 채번자리) | `po_number` (PO-YYMMDD-NNN) ✅ |
| 기본 | 거래처코드 / 거래처명 | `supplier_id` ✅ |
| 기본 | 부서 / 사원 / 관리항목 | (HAIST WORKS 미도입) |
| 기본 | VAT 여부 (3종) | (HAIST WORKS 미도입) ⚠️ |
| 상태 | **완료여부** (미진행/진행중/완료) | 자동 갱신 — `status` 5종(작성중/발주완료/부분입고/입고완료/취소)과 매핑 차이 |
| 상태 | **마감여부** (부/여) | (HAIST WORKS는 status로 통합) |
| 라인 | 품목계정 / 품목코드 / 품명 / 규격 / 단위 | `part_id` + `part_name_snapshot` 등 ✅ |
| 라인 | 납기일 (라인별) | (po_items.delivery_date 미도입 — z56 SQL에 없음) ⚠️ |
| 라인 | 수량 / 단가 / 공급가액 / 부가세 | `qty` / `unit_price` (vat 별도 필드 없음) ⚠️ |
| 라인 | 프로젝트 | `project_id` (헤더 레벨) — **라인별 프로젝트는 z56 `po_item_links` 다대다로 처리** ✅ |
| 라인 | 품목비고 | (HAIST WORKS 미도입) |
| 라인 | 다규격 (1~5) | (HAIST WORKS 미도입) |
| 보조 | 일괄군 품목적용 | (미도입) |
| 보조 | 현재고 (선택일/총재고) | (미도입 — 입력 화면에서 재고 확인) |
| 보조 | 이메일 전송 | (HAIST WORKS 미도입) |
| 보조 | 인쇄설정 / 비고등록 / VAT설정 | (미도입) |

**VAT 여부 3종 — 핵심 차이:**
- VAT 미포함: 수량×단가 = 공급가액, 부가세 = 공급가액×10%
- VAT 포함: 입력금액 ÷ 1.1 = 공급가액
- VAT 없음: 부가세 0

**KNK 적용 의견:**
- 현재 HAIST WORKS는 `total_amount` 단일 — VAT 모드 도입 시 `vat_mode` + `supply_amount` / `vat_amount` 분리 필요
- z56 SQL에 VAT 관련 컬럼 없음 → **z57 차후 마이그레이션 검토 항목**

### 2.3 입고처리 (`po_receive.html` 대응)

| 영역 | 항목 | KNK 매핑 |
|---|---|---|
| 식별 | 입고번호 | (HAIST WORKS는 `goods_receipts` 별도 — z56 SQL에서 강화 필요) |
| 보조 | **발주적용** (건별 / LIST) | KNK는 단순 발주 ID 참조 ✅ |
| 라인 | **창고 / 프로젝트** (라인별) | (HAIST WORKS는 단일 창고 가정) |

**KNK 적용 의견:**
- z57 `po_receive.html` 의 **LOT/유효기한/비고** 라인은 매뉴얼 표준에 부합 ✅

## 3. Chapter 8 — 재고관리 (22개 메뉴)

### 3.1 핵심 입출고 메뉴 (4종)

| 메뉴 | 용도 | KNK 매핑 |
|---|---|---|
| **2. 입출고조정** | 차용·대여·파손·소모로 인한 재고 증감 | `stock_movements.kind=ADJUST` ✅ |
| **3. 재고이동** | 창고↔창고 또는 프로젝트↔프로젝트 이동 | `stock_movements.kind=TRANSFER` ✅ |
| **4. 재고평가** | 출고원가 / 재고금액 자동 산출 | (KNK 미도입 — FIFO 단순 평가) |
| **5. 재고평가현황** | 평가 결과 조회 | (KNK 미도입) |

### 3.2 재고평가 3가지 방법

| 방법 | 원리 |
|---|---|
| 1. 총평균법 | 일정기간 매입합계 ÷ 매입수량 = 단가 |
| 2. 선입선출법 (FIFO) | 먼저 입고된 것부터 출고 |
| 3. 이동평균법 | 매입 시마다 잔액+매입금액 ÷ 잔량+매입수량 |

**KNK 적용 의견:**
- KNK는 현재 FIFO만 (stock_movements.remaining_qty 기반) ✅
- 총평균법은 회계 단순화 — 사출 제조 특성상 FIFO 유지 권장
- 이동평균법은 단가 안정성이 중요한 경우 — 우선순위 ⚪ 낮음

### 3.3 재고평가 옵션

- **음수재고 통제**: 출고로 인해 음수 재고가 발생할 때 통제 (여/부)
- **입고단가 통제**: 입고 단가가 0인 경우 평가 진행 여부 (수량만 / 수량+단가)
- **수불통제일자**: 재고평가 종료월의 마지막 일자가 자동 통제일자 — 이전 일자의 입출고는 입력·삭제 불가

**KNK 적용 의견:**
- **수불통제일자** 개념은 강력한 데이터 무결성 도구 — KNK 도입 권장
- `schema_migrations` (z56 SQL)는 단순 버전 — 별도 `inventory_lock_dates` 테이블 검토

### 3.4 재고 수불 매핑 (참조 SaaS ERP A 표 1)

| 항목 | 1.입출고기준 | 2.마감기준 |
|---|---|---|
| **직전재고** | 품목초기이월 + 조회기간 이전 재고 | 동일 |
| **입고합계** | 구매입고 + 생산입고 + 외주입고 + 입고조정 | 매입마감 + 생산입고 + 외주매입마감 + 입고조정 |
| **출고합계** | 판매출고 + 생산출고 + 외주출고(무상) + 출고조정 | 매출마감 + 생산출고 + 외주출고(무상) + 출고조정 |
| **기말재고** | 직전재고 + 입고 - 출고 | 동일 |

**KNK 적용 의견:**
- HAIST WORKS는 **입출고기준**만 사용 (마감 단계 미분리)
- 매뉴얼 표 1은 메뉴 매트릭스로 stock_movements.kind 매핑 표준 제공 — 자재모듈 표준 v2에 반영

### 3.5 품목계정별 대체출고 매트릭스 (표 2)

|메뉴 \ 품목계정| 상품 | 원재료 | 부재료 | 제품 | 반제품 | 저장품 | 부산품 |
|---|---|---|---|---|---|---|---|
| 매출마감 | **정상** | 대체 | 대체 | **정상** | 대체 | 대체 | 대체 |
| 자재출고 | 대체 | **정상** | **정상** | 대체 | **정상** | **정상** | 대체 |
| 외주출고(유상) | **정상** | 대체 | 대체 | **정상** | 대체 | 대체 | 대체 |
| 외주출고(무상) | 대체 | **정상** | **정상** | 대체 | **정상** | **정상** | **정상** |
| 입출고조정(출고) | 대체 | 대체 | 대체 | 대체 | 대체 | 대체 | 대체 |

**해석:**
- "정상출고" = 일반 매출/판매 영역의 출고
- "대체출고" = 자산 → 자산 전환 (예: 원재료 → 제품 전환 시 원재료는 대체출고)
- 자재출고 시 원재료/부재료/반제품/저장품은 **정상출고** (실제로 소비됨)
- 제품/부산품은 **대체출고** (다른 자산으로 전환)

**KNK 적용 의견:**
- 사출 EMS 제조업 관점: 원재료(수지) → 자재출고(정상) → 생산입고(제품으로 정상입고)
- 이 매트릭스는 **회계 분개 자동화의 핵심** — KNK는 회계 분개를 시스템에서 처리하지 않으므로 **참고만**

### 3.6 적정재고량 vs 안전재고

매뉴얼은 `적정재고량` 1개 개념만 사용:
- 모든 재고 현황 화면에서 **소급과다(소)량 = 재고수량 - 적정재고량** 표시
- 양수 = 과다 / 음수 = 부족

**KNK는 안전재고(safety_stock) 1개 사용 중**:
- 재주문점 (ROP) / 발주량 (ROQ)는 별도
- 실무팀3 결재 통과한 7단가는 단가 영역 — 적정재고량은 별도

**KNK 적용 의견:**
- KNK는 `safety_stock` 1개로 통일 — 매뉴얼의 "적정재고량"과 동일 개념
- 재고현황 모든 페이지에 "소급과다(소)량" 컬럼 추가 검토 (현재는 KPI strip만)

### 3.7 재고회전율 (참조 SaaS ERP A 22번 메뉴)

```
회전율 = 일정기간 출고량(or 금액) / 평균재고량(or 금액)
평균재고 = (기초 + 기말) / 2
```

장기부동재고명세는 **회전율이 기준값보다 낮은 품목** 만 조회.

**KNK 적용 의견:**
- z57 `stock_turnover.html` 의 FAST/NORMAL/SLOW 3밴드는 동일 개념 ✅
- 다만 **금액 기준 회전율**은 미도입 (현재는 수량만) — 단가 이력 마이그레이션 후 추가 가능
