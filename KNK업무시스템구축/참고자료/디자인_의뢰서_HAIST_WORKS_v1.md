## 1. 회사 / 시스템 소개

### 1-1. 회사
- **상호:** 주식회사 케이엔케이 (KNK)
- **브랜드:** HAIST Innovation
- **슬로건:** *Human & AI create the Best*
- **사업분야:**
  - **T 검사기:** 휴대폰 부품(센서/PCB/디스플레이) 기능검사 자동화 장비
  - **M 자동화:** 디스플레이/배터리 압착, 부품 부착 자동화 라인
  - **E 기타 / C 소모품:** 부품·소모품 공급
- **주요 고객사:** 삼성전기, 삼성전자, 드림텍, 시노펙스, 한국성전, 두성테크, 파트론, 엠씨넥스, 파인텍, 욱광, 세경하이테크, 글로베스트안산, KNK VINA(베트남 법인) 등
- **거래 규모:** 단가 KRW 30만~24억 / 호기 단위 1~12대 / 통화 KRW·USD·VND 혼용

### 1-2. 시스템 (HAIST WORKS)
- **목적:** 영업견적·수주·생산·납품·수금·통관·품질을 하나의 플랫폼에서 통합 운영
- **사용자 규모:** 사내 86명 (대표/팀장/PM/영업/생산/구매/품질/통관)
- **현재 상태:** 약 130개 템플릿, 142개 라우트, 88개 DB 테이블, 운영 중인 실서비스
- **최우선 가치:** **"어려워 보이지 않게"** (메모리 룰: 디자인팀 핵심 지침)
- **외부 라이브러리 정책:** **타사 브랜드/상표/UI 자산 직접 차용 금지** (KNK 자체 디자인만)

## 3. 기술 스택 및 제약

### 3-1. 백엔드
- **FastAPI** (Python 3.10+) + **Uvicorn**
- **SQLite** (운영 DB, 단일 파일)
- **Jinja2** 템플릿 (서버 사이드 렌더링)
- **포트:** localhost:8081

### 3-2. 프론트엔드
- **No-build:** 빌드 도구 없음 (Webpack/Vite 사용 안 함)
- **No SPA:** React/Vue/Svelte 사용 안 함
- **CSS:** 순수 CSS (Tailwind 안 씀, 변수만 사용)
- **JS:** Vanilla JS (jQuery·Alpine·Stimulus 없음)
- **Icons:** 이모지 + 일부 SVG inline
- **차트:** Chart.js 가능 (현재 일부 페이지 사용)

### 3-3. 디자인 결과물 적용 방식
- **HTML 마크업 + CSS** 형태로 받아서 Jinja 템플릿에 직접 합성
- 모든 페이지는 `_v5_partials/chrome.html` (top-bar + sidebar) 를 include 해야 함
- CSS는 `_v5_partials/styles.html` 의 디자인 토큰을 활용하거나 토큰 자체를 갱신

### 3-4. 모바일 지원
- 현재 데스크톱 우선 + 미디어 쿼리 일부 (`@media (max-width:1100px)`)
- **모바일 풀 반응형 필수 아님** — 단, 1100px 이하에서 사이드바 햄버거 토글 동작은 유지 필요

## 6. 페이지별 상세 사양

> 아래는 **핵심 페이지 25개**의 상세 사양입니다. 나머지 페이지는 동일 패턴으로 응용 가능합니다.

### 🏢 6-A. 인증·홈

#### 6-A-1. `login.html` — 로그인
- **입력:** 사번/비밀번호
- **표현:** 좌측 KNK 로고 + 슬로건 / 우측 입력 폼
- **왜 이렇게:** 입사 첫 진입점 — *"Human & AI create the Best"* 인상 각인
- **요청:** 차분하면서 신뢰감 — 공장/제조 이미지 절제

#### 6-A-2. `home.html` — 통합 홈
- **입력:** 없음 (대시보드)
- **표현:** 매출영업·자재구매 2개 큰 카드 + 오늘 KPI 요약 + 최근 알림
- **왜 이렇게:** 입사자가 한눈에 자신의 업무 분야로 진입
- **현행 문제:** 카드가 너무 크고 단조로움

#### 6-A-3. `guide.html` — 사용 가이드
- **입력:** 없음 (정보 페이지)
- **표현:** 메뉴별 사용법 + FAQ
- **요청:** 매뉴얼 같지 않게, 카드형 인덱스 + 검색

---

### 💼 6-B. 매출영업센터

#### 6-B-1. `sales_home.html` — 매출 홈
- **입력:** 없음 (대시보드)
- **표현:** 6개 KPI 카드 (이번주 납기 / 이번달 납기 / 납품대기 / 송장대기 / 수금대기 / 미수금) + 진행 프로젝트 목록 + 최근 수주
- **왜 이렇게:** 영업담당이 매일 아침 9시에 보는 화면 — "오늘 뭐 해야 하나" 즉시 파악
- **현행 문제:** 정보 밀도 낮음, 차트 부족

#### 6-B-2. `projects.html` — 프로젝트 등록 (목록)
- **입력:** 검색·필터 (사업부 / 상태 / 고객사)
- **표현:** 카드 그리드 (관리번호 / 프로젝트명 / 고객사 / 진행률 / 액션 버튼)
- **왜 이렇게:** *"관리번호 우선"* — 관리번호가 가장 크고 명확하게 보여야 함 (사용자 메모리 룰)
- **요청:** 호박색 진한 배지로 관리번호 강조 (이미 적용 중)

#### 6-B-3. `project_detail.html` — 프로젝트 상세 ⭐ 가장 복잡
- **입력:** 인라인 편집 (호기별 단가/납기/상태/통관정보 19개 필드)
- **표현:**
  ```
  ┌─ 헤더 (관리번호 + 프로젝트명 + 상태 + 액션) ────┐
  │ [추가 검사기 발주] [소모품] [수리·정비] [수정] │
  ├─ KPI 4개 (전체업무/완료/누적공수/수주액) ──────┤
  ├─ 세부 정보 (접기/펴기) ──────────────────────┤
  │  ① 기본 정보  ② 일정  ③ 금액  ④ 메모          │
  ├─ 수주(SO) 카드 ────────────────────────────┤
  │  SO 1: 호기별 라인 (라벨/단가/상태/납기/메모) │
  │  SO 2: ...                                   │
  │   ├─ ASSEMBLY: 단순 호기 표 (5~10 컬럼)       │
  │   └─ PARTS: 정식 PACKING LIST 28컬럼 표 ⭐   │
  │       └─ 컬럼 그룹 토글 chip 바              │
  │       └─ 가로 스크롤 (sticky 프록시)         │
  │       └─ 풀스크린 팝업 모드                  │
  └─ 진행 업무 / 일일업무 / 변경 이력 ──────────┘
  ```
- **왜 이렇게:** 한 프로젝트에서 *제안→견적→수주→호기별 진행→납품→통관→수금* 전체 라이프사이클을 끝까지 추적해야 함
- **PARTS 28컬럼 사연:** 베트남 KNK VINA 부품 수출용 정식 PACKING LIST가 통관·세관에 그대로 사용됨. 컬럼: 관리코드/품번/제조사/원산지/박스/스펙/상태/공급사/수량/단위/HS코드/관세율/VAT율/단가KRW/금액KRW/단가USD/금액USD/관세KRW/관세USD/최종USD/상세/팔레트/중량
- **현행 문제:** 너무 길어서 스크롤 지옥 → **최우선 개선 대상** (디버그 모드로 영역 분석 권장)

#### 6-B-4. `project_form.html` — 프로젝트 등록 폼
- **입력:** 프로젝트명/사업부/고객사/모델/수량/단가/통화/일정/상태 + (T/M의 경우 출고형태 ASSEMBLY/PARTS)
- **표현:** ① 기본 ② 일정 ③ 금액 4단 섹션
- **왜 이렇게:** 입력 항목이 많아 단계별 그룹핑

## 7. UX 원칙 / 사용자 페르소나

### 7-1. 페르소나
| 페르소나 | 역할 | 핵심 니즈 |
|---|---|---|
| **김대표** | CEO | 전사 KPI 한 화면 + 의사결정 자료 |
| **장부장** | 영업팀장 | 수주 현황 / 미수금 / 고객사 |
| **이매니저** | 영업담당 | 견적·수주·납기 일별 추적 |
| **박PM** | 프로젝트 매니저 | 호기별 진행 / 일정 / 이슈 |
| **정대리** | 구매담당 | 발주 / 입고 / 재고 / 안전재고 |
| **최주임** | 통관담당 | 수출 PL / CI / FTA / B/L |
| **이반장** | 생산반장 | 작업 지시 / QC 결과 |
| **김사원** | 일반 직원 | 일일 업무 / 알림 / 결재 |

### 7-2. 핵심 UX 원칙

1. **관리번호 우선** — 모든 표/카드/리스트에서 *관리번호가 가장 먼저, 가장 명확하게*
2. **한 화면에 다 보이게** — 스크롤 최소화 (대표님 직접 지시)
3. **컴팩트** — 한국 제조업 — 정보 밀도 높지만 깔끔
4. **헤더는 sticky** — 표 스크롤 시 컬럼명 절대 안 움직임
5. **상태별 컬러** — 진행중/완료/취소/보류 한눈에
6. **숫자는 monospace** — 금액·번호 정렬감
7. **이모지 적극 활용** — 어렵게 보이지 않게
8. **호박색 액센트** — KNK 정체성 (빨강 + 호박)
9. **실수 방지** — 삭제/취소는 한 번 더 확인, 위험 작업은 빨강
10. **검색·필터 어디서나** — 데이터 많은 페이지는 상단 필터 필수

## 8. 현재 알고 있는 통점 (Pain Points)

> **빅터(개발자)가 인지한 디자인 통점 — Claude Design 우선 검토 부탁**

### 8-1. 페이지 헤더 일관성 부족
- 페이지마다 `page-head` 높이/폰트가 들쭉날쭉 (18px ~ 26px)
- crumb / title 간격도 페이지마다 다름
- → **공통 페이지 헤더 컴포넌트 정의 필요**

### 8-2. 정보 밀도 vs 가독성 균형
- 컴팩트 추구하다 글자가 너무 작아짐 (10px대)
- 크게 하면 한 화면에 안 들어감
- → **명확한 타이포 스케일 정의 필요**

### 8-3. PARTS 28컬럼 표 (project_detail) ⭐ 최난제
- 가로 스크롤 + 세로 스크롤 + 풀스크린 + 컬럼 그룹 토글 — 복잡도 폭발
- 사용자가 매번 헤매고 데이터 유실 사고 발생
- → **표 자체를 다른 패러다임으로 재설계 필요** (예: 카드 모드 + 표 모드 토글, 섹션별 분리, 스텝 위저드 등)

### 8-4. KPI 카드 통일성
- 페이지마다 KPI 카드 디자인이 다름 (큰 카드 / 슬림 바 / 표 형식)
- → **KPI 컴포넌트 시스템화 필요** (3~4개 변형 정의)

### 8-5. 표 (Table) 디자인 천차만별
- 어떤 표는 행 간격 넓고 어떤 표는 좁고
- 헤더 sticky 어떤 데는 되고 어떤 데는 안 됨
- 행 hover / 클릭 / 인라인 편집 일관성 없음
- → **표 컴포넌트 표준화 필수**

### 8-6. 모달/팝업 부재 또는 비일관
- 인쇄 양식만 별도 페이지 → 신규 탭으로 띄움
- 풀스크린 토글 (project_detail SO 카드)만 있고 일반 모달은 없음
- → **모달 시스템 정의 필요**

### 8-7. 폼 입력 UX
- 입력 필드 크기/라벨/검증 메시지 천차만별
- 날짜 입력은 어떤 데는 input[type=date], 어떤 데는 텍스트
- → **폼 컴포넌트 표준화 필요**

### 8-8. 사이드바 고정 너비 (220px)
- 메뉴 아이템 너무 많음 (15+) → 스크롤 발생
- 모바일에서는 햄버거로 가려짐
- → **사이드바 그룹핑 / 접기 / 검색 추가 검토**

### 8-9. 인쇄 양식 (CI / PL / 견적서 등)
- 화면용 페이지에 `@media print` 일부만 적용
- A4 깔끔한 인쇄 안 되는 페이지 다수
- → **인쇄 전용 레이아웃 별도 정의 필요**

### 8-10. 다크 모드 / 접근성
- 현재 라이트 모드만
- 색맹 / 저시력 대응 안 됨
- → **WCAG AA 수준 검토 + 다크 모드 옵션 (선택)**

## 10. Claude Design 결과물 형식 요청

### 10-1. 우선순위 (1~3 우선)
1. **공통 컴포넌트 시스템** (chrome / page-head / KPI 카드 / 표 / 폼 / 모달 / 칩 / 배지 / 버튼)
2. **수주 관리** (`sales_orders.html`) — 가장 자주 보는 페이지
3. **프로젝트 상세** (`project_detail.html`) — 가장 복잡, 통점 집중
4. 매출 홈 / 프로젝트 목록 / 고객사 / 견적서
5. 자재구매 홈 / 발주 / 부품
6. 일일업무 / 주간 / 알림함
7. 수출입 / 통관 / FTA
8. 재고 / 품질 / 환율
9. 관리자 / 권한
10. 인쇄 양식 (CI / PL / 견적서 / B/L)

### 10-2. 결과물 형태 (택일 또는 조합)
- **(A) HTML/CSS 파일** — 그대로 Jinja 템플릿에 합성 가능
  - `{{ ... }}` Jinja 변수는 placeholder 로 표시 (예: `{{ project.name }}`)
  - 권장 형식
- **(B) 마크업 + 디자인 토큰** — CSS 변수 갱신 + HTML 구조 변경 제안
- **(C) Figma / 이미지** — 빅터가 코드로 구현 (시간 추가 소요)

### 10-3. 필수 포함 사항
1. **반응형:** 1100px 이하에서 최소한 깨지지 않도록
2. **접근성:** WCAG AA (대비 4.5:1, 키보드 포커스 가시화)
3. **인쇄 친화:** A4 용지에 깨끗히 출력되도록
4. **다국어 대비:** 한글/영문 혼용 (베트남어 가능성 고려)
5. **성능:** CSS 200KB 이하, 외부 폰트 1개 이내

### 10-4. 제외 사항 (절대 변경 금지)
- ❌ 라우트 (URL 구조)
- ❌ 권한 분기 (`{% if user.is_admin %}` 등)
- ❌ DB 스키마
- ❌ 비즈니스 로직 (호기 라인 계산 / 환율 / 관세 등)
- ❌ Jinja 변수명
- ❌ 메뉴 코드 (`M-01-XX`) — 디버그용

### 10-5. 디버그 영역 라벨 활용
- 빅터가 만든 `?debug=1` 모드 활용 권장
- 페이지 어디서든 `?debug=1` 추가 → 모든 영역에 이름 + 크기 표시
- Claude Design은 영역명 그대로 사용해서 의사소통 (예: `kpi-bar 높이 36px`, `split-left 너비 460px`)

### 10-6. 단계별 협업 제안
1. **Step 1 (1주차):** 디자인 시스템 정의 (토큰 / 컴포넌트 / 타이포 스케일)
2. **Step 2 (1주차):** 핵심 5개 페이지 시안 (수주관리 / 프로젝트 상세 / 매출홈 / 캘린더 / 일일업무)
3. **Step 3 (2주차):** 시안 검토 + 빅터 적용
4. **Step 4 (2주차):** 나머지 페이지 가이드라인 적용
5. **Step 5 (3주차):** 인쇄 양식 / 모달 / 폼 컴포넌트 마무리
