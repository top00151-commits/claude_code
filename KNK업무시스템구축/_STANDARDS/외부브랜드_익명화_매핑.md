## 4. 유지 항목 (기능 식별자 — 변경 시 시스템 영향)

> 표시 텍스트가 아니라 코드·연동에 필요한 식별자이므로 보존. 단계적 처리 대상.

| 종류 | 예시 | 보존 사유 |
|---|---|---|
| 라우트 URL | `/hr/hiworks`, `/admin/hiworks-settings` | 변경 시 backend 라우팅·북마크 영향 |
| 변수·상수명 | `hiworks_approval_url`, `HIWORKS_LINK_KEYS`, `HIWORKS_API_BASE` | DB 키·코드 식별자 |
| DB 설정 키 | `hiworks_messenger_token`, `hiworks_domain` 등 | app_settings 저장 키 (마이그레이션 필요) |
| API URL 기본값 | `https://office.hiworks.com/`, `https://api.hiworks.com` | 실제 외부 연동 동작에 필요 |

## 6. 후속 권장 (단계적 처리 — 빅터/대표 판단)

1. `hiworks_*` 변수명·DB 키 → 중립 식별자(`groupware_*`)로 리네이밍 (DB 마이그레이션 동반)
2. 라우트 `/hr/hiworks` → `/hr/groupware` 등 (URL 변경 + 내부 링크 일괄 수정)
3. 파일명 `hiworks_client.py`, `hr_hiworks.html` → 중립 명칭 (import·렌더 경로 동반 수정)
4. API URL 기본값 → admin 설정 입력 강제(하드코딩 제거)

> 위 1~4는 코드 로직·DB 영향이 크므로 별도 변경관리(롤백 계획 포함) 후 진행 권장.
