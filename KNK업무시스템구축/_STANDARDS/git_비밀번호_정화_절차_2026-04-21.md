## 1. 1순위 — 노출 비밀번호 무효화 (파일 정리보다 먼저)

**이미 GitHub에 올라간 비밀번호는 회수 불가로 간주.** 히스토리를 지워도 클론·포크·캐시 가능성 존재. 따라서:

- [ ] **전 직원 비밀번호 강제 재설정** (`knk2026!`·`knk1234` 등 공통 비번 전부 무효화)
- [ ] 가능하면 첫 로그인 시 강제 변경 플래그 (`users.force_pw_change`) 적용
- [ ] 재설정 결과는 평문 파일로 저장하지 말 것 (1회용 전달·즉시 폐기)

## 3. 3순위 — git 히스토리에서 영구 제거 (filter-repo)

> 🚨 **히스토리 재작성 = force push 필요 = 모든 워크트리/세션에 영향.** 반드시 백업 후, 대표 승인하에 실행.

### (a) 백업 먼저 (절대 생략 금지)
```bash
# 전체 저장소 미러 백업
cd "C:/Users/top00/JR"
git clone --mirror "Claude 코드/.git" "claude_code_BACKUP_20260421.git"
```

### (b) filter-repo 설치
```bash
pip install git-filter-repo
git filter-repo --version   # 설치 확인
```

### (c) 히스토리에서 제거
```bash
cd "C:/Users/top00/JR/Claude 코드"

git filter-repo --invert-paths \
  --path "KNK업무시스템구축/01_HAIST_WORKS/data/_credentials_2026-04-28.csv" \
  --path-glob "KNK업무시스템구축/01_HAIST_WORKS/data/knk.db.*" \
  --force
```

### (d) 커밋 메시지의 비밀번호 문자열도 제거 (aaa67f1 메시지에 knk2026! 있음)
```bash
git filter-repo --replace-message ../replace.txt --force
# replace.txt 내용 예:
#   knk2026!==>[REDACTED]
#   knk1234==>[REDACTED]
```

### (e) origin 재연결 + 강제 push
```bash
# filter-repo 가 origin 을 제거하므로 재추가
git remote add origin git@github.com:top00151-commits/claude_code.git
git push origin --force --all
git push origin --force --tags
```

### (f) filter-repo 설치 불가 시 대안
- **BFG Repo-Cleaner** (Java 필요): `bfg --delete-files _credentials_2026-04-28.csv` + `bfg --delete-files "knk.db.*"`
- 또는 git 내장 `git filter-branch` (느림, 비권장)

## 4. 다른 워크트리·세션 영향 (force push 후속)

force push 후 **다른 세션(01A/01B/01C/10 등)이 같은 origin을 공유하면 히스토리 불일치 발생.** 각 세션은:
```bash
git fetch origin
git reset --hard origin/main   # ⚠️ 로컬 미push 작업 있으면 먼저 백업·rebase
```
→ 이 부분은 **대표 조율 필요**. 감사팀은 force push 전 전 세션 동기화 상태 점검 권고.
