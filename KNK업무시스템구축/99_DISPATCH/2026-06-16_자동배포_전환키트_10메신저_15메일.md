# 자동배포 전환 키트 — 10 메신저 · 15 메일 (전산담당자용)

작성 2026-06-16. 목적: **01 WORKS처럼** "claude_code(모노레포)에 push → 라이브 자동 반영" 을
메신저·메일에도 적용. (01은 이미 완료. 아래는 10·15를 같은 방식으로 전환하는 1회 작업.)

## 0. 현재 상태 / 왜 1회 작업이 필요한가
| 앱 | 현재 라이브 배포 | 자동? |
|---|---|---|
| 01 WORKS | NAS 1분 cron `git pull`(auto_deploy.sh) ← `knk-haist-works` | ✅ 완료 |
| 10 메신저 | 윈도우 `deploy/sync_to_synology.ps1` 수동 업로드. GitHub=백업 | ❌ |
| 15 메일 | 윈도우 `deploy/sync_to_nas.ps1` tar 수동 전송 | ❌ |

→ 10·15는 NAS에 "자동으로 받는 장치(cron)"가 없다. 그걸 1회 설치하면 01처럼 자동이 된다.

## 1. 준비된 것 (이 저장소에 이미 포함)
- `10_KNK_Messenger/deploy/auto_deploy.sh` · `setup_auto_deploy.sh`
- `15_KNK_Mail/deploy/auto_deploy.sh` · `setup_auto_deploy.sh`
- (01 참고 원본: `01_HAIST_WORKS/deploy/auto_deploy.sh`)

각 `auto_deploy.sh` 상단 **CONFIG**(APP_DIR·SERVICE)와 주석 **P1~P3**(선행조건)을 실제 NAS와 대조할 것.

## 2. 전환 절차 (앱마다 동일, NAS에서 1회)

### (a) GitHub 미러 켜기 — 모노레포 → 배포저장소  *(claude_code 쪽, 1회)*
01의 `.github/workflows/mirror-works-to-deploy.yml` 을 복사해 **경로·저장소만** 바꾼 워크플로를 추가:
- 메신저: paths `10_KNK_Messenger/**`, 대상 repo `knk-messenger`
- 메일:   paths `15_KNK_Mail/**`,   대상 repo `knk-mail`(없으면 먼저 생성)
- **토큰 권한 확장**: 현재 `DEPLOY_REPO_TOKEN` 은 `knk-haist-works` 전용일 수 있음.
  Fine-grained 토큰을 편집해 `knk-messenger`·`knk-mail` 에도 **Contents: Read and write** 추가.
- 두 저장소가 라이브보다 뒤처져 있을 수 있으니, 01처럼 **먼저 import(라이브→모노레포 정합) 후** 미러 켤 것.
  (01의 `import-live-into-monorepo.yml` · `reconcile-report.yml` 을 동일 패턴으로 사용)

### (b) NAS 디렉터리를 git clone 으로 (선행조건 P1·P2)
현재 /opt/knk_messenger, /opt/knk_mail 은 파일업로드 방식이라 git clone 이 아닐 수 있음.
**데이터·.env·logs 백업 후**, 해당 경로를 배포저장소의 git clone 으로 정비:
```
# 예(메신저). 실제 경로/repo 확인 후:
cd /opt && mv knk_messenger knk_messenger.bak && \
  git clone git@github.com:top00151-commits/knk-messenger.git knk_messenger && \
  cp -a knk_messenger.bak/{.env,data,logs,.venv} knk_messenger/ 2>/dev/null
```
메일도 동일(repo·경로는 실제 값으로).

### (c) cron 자동배포 설치 (1회)
```
cd /opt/knk_messenger && bash deploy/setup_auto_deploy.sh   # 메신저
cd /opt/knk_mail       && bash deploy/setup_auto_deploy.sh   # 메일
```
→ 이후 모노레포에 push → 미러 → 배포저장소 → NAS 1분 cron pull → 자동 재시작.

## 3. 검증
- (a) 미러 워크플로 1회 report 실행 → 코드 차이 확인(라이브 되돌림 없는지). 이상 없으면 live.
- (b)(c) 후, 모노레포에서 사소한 변경 push → 1~2분 뒤 라이브 반영 확인.

## 4. 주의 (중요)
- **메신저는 컨테이너(Docker)+gunicorn+supervisord** 구조라, git-pull 전환 시 컨테이너 내부에서
  cron·supervisorctl 이 도는지(PID1=bash 이슈) 반드시 확인. 안 되면 기존 PS1 배포 유지가 안전.
- 전환 완료 후에는 **윈도우 수동 스크립트(sync_to_synology/sync_to_nas)와 병행 금지** — 둘 다 쓰면 또 갈라진다.
- 전환 후 규칙: **모든 작업은 claude_code(모노레포)에서만.** 라이브 저장소 직접 수정 금지.
