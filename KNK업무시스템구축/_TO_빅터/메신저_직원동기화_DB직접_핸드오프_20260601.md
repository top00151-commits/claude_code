## 0. 무엇이 바뀌었나 (대표 결정)
- 발주는 "directory API(서버-서버, env 키)" 였지만, 대표님이 **"로그인은 메신저 SSO로만 하니, 그냥 등록된 직원을 WORKS에 동일하게 1회 넣자"** 로 단순화 지시.
- 따라서 **env 공유키·API 호출 방식은 보류**합니다. 대신 **메신저 DB → WORKS DB 직접 1회 동기화**.
- (참고) 제가 만든 `GET /msg/api/sso/directory` 는 **env 미설정이라 503으로 닫혀** 있습니다. 이 방식엔 불필요하니 **그대로 닫아두거나** 나중에 제거해도 됩니다. (무해)
- 제가 NAS에서 직접 실행하려 했으나, 안전장치가 **"운영 HR DB에 외부 세션이 직접 SSH-root 접근"** 을 막았습니다(합리적). → **DB 주인인 01이 실행**하는 게 거버넌스상 맞습니다.

## 1. 준비된 스크립트 (이미 deploy 폴더에 있음)
```
01_HAIST_WORKS/deploy/sync_employees_messenger_to_works.py
```
- 읽기: 메신저 `/opt/knk_messenger/data/messenger.db` (users, **게스트 제외** 전 직원)
- 쓰기: WORKS `/opt/knk_haist/data/main.db` (users)
- **업서트 로직은 기존 `import_employees_from_excel.py` 의 `apply_employee` 와 동일** (이름+이메일/전화 매칭→갱신, 동명이인 아닌 단일 이름 매칭→갱신, 미매칭→신규 INSERT). raw SQL 난사 아님.
- 비대화형(프롬프트 없음). `--dry-run`(읽기전용) / `--apply`(반영).

## 2. 실행 순서 (01 deploy/SSH 경로로)
```bash
# 0) 스크립트를 컨테이너에 배포 (WORKS deploy 로 deploy/ 폴더 올라가면 자동 포함)
#    경로: /opt/knk_haist/deploy/sync_employees_messenger_to_works.py

# 1) 미리보기 (읽기 전용 — DB 변경 0)
python3 /opt/knk_haist/deploy/sync_employees_messenger_to_works.py --dry-run
#    출력: 갱신 N · 신규 N · WORKS에만 있음(메신저 미등재) N · 예시 목록
#    → 대표/01 이 숫자·예시 확인

# 2) WORKS DB 백업 (필수)
cp /opt/knk_haist/data/main.db /opt/knk_haist/data/main.db.bak_empsync_$(date +%Y%m%d_%H%M%S)

# 3) 실제 반영
python3 /opt/knk_haist/deploy/sync_employees_messenger_to_works.py --apply
```
- DB 경로가 다르면 `--msg-db` / `--works-db` 로 지정 가능(기본값은 위 운영 경로).

## 3. 필드 매핑 (메신저 → WORKS users)
| WORKS 컬럼 | 메신저 출처 |
|---|---|
| name | display_name |
| name_en / name_vi | display_name_en / display_name_vn |
| email / phone | email / phone |
| employee_no, login_id | employee_no(사번; 없으면 username) |
| entity | entity (KOR\|VN, 미지정이면 베트남어 이름 유무로 추정) |
| rank | title (직급) |
| dept_code | **department(부서 '이름')** ← ⚠️ 아래 주의 |
| role / is_active / must_change_pw | member / 1 / 1 (신규 INSERT 시) |

## 4. ⚠️ 짚을 점
1. **부서**: 메신저는 부서 **이름**(예: "경영"), WORKS는 `dept_code`(코드/팀)로 매핑. 일단 부서 **이름을 dept_code 자리에 그대로** 넣었습니다 → **팀 매핑은 01이 보정** 필요(이름→team_id). 이름·연락처·사번은 정확.
2. **초기 비밀번호**(신규 INSERT 한정): 본사=휴대폰 숫자, VN=9999, must_change_pw=1. 단 로그인은 메신저 SSO라 실제론 거의 안 쓰임(WORKS users NOT NULL 충족용).
3. **매칭 충돌**: 메신저·WORKS에 같은 사람이 **다른 이메일/전화**면 신규로 INSERT 될 수 있음 → **dry-run 출력에서 '신규 N' 이 예상보다 크면** 매칭키 점검(동명이인/이메일 불일치).
4. **WORKS에만 있고 메신저엔 없는 사람**: 스크립트가 목록만 출력(자동 비활성 안 함). 퇴사/유지 판단은 수동(대표).

## 5. 회신 부탁 (→ `_TO_메신저세션/`)
- dry-run 결과(갱신/신규/WORKS-only 숫자)
- apply 완료 여부 + 부서→팀 매핑 보정 계획
- directory API(503) 유지/제거 선택
