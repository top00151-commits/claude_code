# [메신저 → 빅터(01)] WORKS 프로젝트 이력 수신 API — 발주

> **작성일**: 2026-06-01
> **발신**: 메신저 세션 (10_KNK_Messenger)
> **수신**: 빅터(01, HAIST WORKS 담당)
> **상태**: 메신저 쪽 **전송 모듈 선구현·배포 완료(기본 OFF 게이팅)**. WORKS(01) 쪽 **수신 엔드포인트** 작업 요청.
> **관련**: SSO 발주(`메신저_WORKS연결_발주_20260531.md`) 와 동일 인증키(RS256) 재사용.

## 0. 한 줄 요약
메신저 **프로젝트방**의 대화를 AI가 요약한 **"프로젝트 이력 스냅샷"**(증분 누적 + 첨부목록 + 프로젝트 메타)을, 생성될 때마다 **WORKS의 해당 수주(프로젝트) 이력란으로 자동 전송**합니다. WORKS는 **수신 엔드포인트 1개**만 만들어 주시면 됩니다.

## 1. 배경 / 현재 메신저 상태
- 메신저엔 이미 `project_history` 테이블이 있고, **하루 1회 자동 + 수동 '지금 갱신'** 으로 스냅샷이 쌓입니다.
- 이번에 **WORKS 자동전송 모듈을 선구현**했습니다:
  - 게이팅: 환경변수 `KNK_WORKS_HISTORY_URL`(수신 주소) + 관리자 토글(`works_history_sync`) **둘 다 ON** 일 때만 전송.
  - **현재는 URL 미설정이라 전 구간 no-op** — 01이 엔드포인트를 확정하면 메신저는 env 만 채우면 즉시 동작.
  - 전송 성공 시 `synced_to_hw=1` 마킹, 실패분은 **하루 1회 재시도 sweep**.

## 2. WORKS(01) 가 만들 것 — 수신 엔드포인트 1개
```
POST  <당신이 정한 경로>      (예: https://works.knknara.co.kr/api/ingest/project-history)
```
- **인증**: `Authorization: Bearer <RS256 JWT>`
  - 메신저 SSO 개인키로 서명. 검증은 기존 SSO 공개키(`GET /msg/api/sso/public-key`) 그대로.
  - claim: `iss=knk-messenger`, `aud=haist-works`, `purpose=project_history_sync`, `iat/exp`(만료 120초).
  - `aud == "haist-works"` 이고 서명·만료 정상일 때만 수락. (사용자 토큰 아님 — **서비스 토큰**)
- **요청 body (JSON, UTF-8)** — 메신저가 보내는 실제 형식:
```json
{
  "source": "knk-messenger",
  "history_id": 123,                      // 메신저 내부 이력 PK (중복수신 멱등키로 사용 권장)
  "room_id": 45,                          // 메신저 방 id
  "project": {                            // 프로젝트 방의 메타 (items 테이블)
    "code": "001M999",                    // 관리번호 ← WORKS 수주 매칭 키 후보
    "name": "테스트용장비",
    "customer": "케이엔테크",
    "status": "active"                    // active|hold|done|cancelled
  },
  "period": { "start": "2026-05-31T10:00:00+00:00", "end": "2026-05-31T19:00:00+00:00" },
  "message_count": 12,
  "attachment_count": 2,
  "summary_text": "…AI 요약(한국어, 보고서 톤)…",
  "attachments": [
    { "name": "도면.pdf", "size": 482113, "mime": "application/pdf",
      "url": "https://haist.knknara.co.kr/msg/uploads/…", "sender": "홍길동", "sent_at": "2026-05-31T14:00:00+00:00" }
  ],
  "model": "gpt-5.4-mini",
  "created_mode": "auto",                 // auto(자동) | manual(수동)
  "created_at": "2026-05-31T19:05:00+00:00"
}
```
- **응답**: 성공 `2xx`(JSON 자유). 메신저는 2xx 면 전송완료로 마킹, 그 외/타임아웃이면 다음 sweep 에 재시도.
- **멱등성(중요)**: 같은 `history_id` 가 재시도로 두 번 올 수 있습니다. **history_id(또는 source+history_id) 로 upsert** 처리해 중복 누적을 막아주세요.

## 3. 협의가 필요한 결정 (회신 주세요 → `_TO_메신저세션/`)
1. **수신 경로(URL)** — 확정해 주시면 메신저 env `KNK_WORKS_HISTORY_URL` 에 넣습니다.
2. **수주 매칭 키** — 메신저 `project.code`(관리번호)로 WORKS 수주를 찾으면 되는지? 다른 키가 필요하면 알려주세요(그 값을 payload 에 추가).
3. **첨부 처리** — 첨부는 메신저 URL(다운로드 링크)만 보냅니다. WORKS 가 파일 자체를 당겨갈지(미러링), 링크만 보관할지.
4. **권한/표시** — WORKS 에서 이 이력을 누가(수주 담당자?) 어디(수주 상세의 '진행 이력' 탭?)서 보는지.

## 4. 메신저 쪽 완료 내역 (참고)
- `_works_history_sync_enabled()` / `_works_service_token()`(RS256 서비스토큰) / `_send_history_to_works()`(POST+멱등 마킹) / `_works_retry_unsynced()`(재시도 sweep)
- 스냅샷 생성(자동·수동) 직후 best-effort 전송 (실패해도 요약 기능 영향 없음)
- 관리자 화면(권한 탭)에 "📤 프로젝트 이력 → WORKS 자동전송" 토글 + 상태표시(주소 미설정 시 경고)
- 배포 완료(healthz 200). **URL 미설정이라 현재는 아무 것도 전송하지 않음.**

## 5. 붙이는 순서 (제안)
1. 01 이 수신 엔드포인트 + 멱등 upsert 구현 → 경로 회신
2. 메신저가 `KNK_WORKS_HISTORY_URL` 설정 + 관리자 토글 ON
3. 프로젝트방에서 '지금 갱신' 1회 → WORKS 수신 확인 → 카드에 "📤 WORKS 전송됨" 표시되면 성공
