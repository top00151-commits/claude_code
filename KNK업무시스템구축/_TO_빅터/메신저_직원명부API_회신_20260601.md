## 0. 한 줄 결론
요청하신 `GET /msg/api/sso/directory` 를 **그대로 구현·배포**했습니다. 게스트(고객사) 제외 **전 직원**을 요청 JSON 형식으로 반환합니다. 공유키만 양쪽에 넣으면 바로 동기화 가능합니다.

## 1. 엔드포인트 (확정)
```
GET  http://localhost:5050/msg/api/sso/directory      (서버-서버, 내부 호출)
헤더: X-SSO-Service-Key: <공유키>
```
- **인증**: 헤더 값 == 메신저 env `KNK_SSO_SERVICE_KEY` (상수시간 비교, 타이밍공격 차단).
  - env 미설정 → **503** `service_unconfigured` (절대 안 열림)
  - 키 누락/불일치 → **403** `forbidden`
- **HTTPS 강제 안 함** (내부 localhost http 호출 위해). 브라우저용 CORS 미적용(서버 전용).

## 2. 응답 (HTTP 200, JSON)
```json
{
  "users": [
    {
      "employee_no": "5",
      "name_kr": "김정락",
      "name_en": "Kim Jeongrak",
      "name_vi": null,
      "dept": "경영",
      "position": "대표이사",
      "entity": "KOR",
      "email": "kjr@knk.co.kr",
      "phone": "010-1234-5678",
      "is_admin": true,
      "works_access": true,
      "active": true
    }
  ],
  "count": 132,
  "generated_at": "2026-06-01T09:55:00+00:00",
  "source": "knk-messenger"
}
```

**필드 매핑 / 주의**
- `employee_no` = 메신저 `employee_no`(사번). **없으면 username 으로 대체**(사번=로그인ID 정책이라 대부분 존재). 대표=`"5"`.
- `name_kr/name_en/name_vi` = `display_name`/`display_name_en`/`display_name_vn`. 베트남 직원은 `name_vi` 채움, 본사는 보통 `null`.
- `dept`=`department`, `position`=`title`(직급).
- `entity` = `KOR`|`VN` (일부 미마이그레이션 계정은 `null` 일 수 있음 → 그쪽에서 사번/부서로 보정 권장).
- `email`/`phone` = 그대로.
- `is_admin` = 메신저 role==ceo.
- `works_access` = WORKS 진입 허용 플래그(bool).
- `active` = 재직 여부(bool).

## 3. 발주서 5개 질문 답변
1. **엔드포인트 가능?** → 네, `GET /msg/api/sso/directory` 구현·배포 완료.
2. **env명 `KNK_SSO_SERVICE_KEY` 동의?** → 네. **양쪽(메신저 컨테이너 env + WORKS env)에 같은 비밀값** 필요.
3. **내부 주소 `http://localhost:5050/msg` 맞나?** → 네. 메신저 gunicorn 이 컨테이너 내부 5050 포트, BASE_PATH `/msg`. WORKS·메신저가 같은 컨테이너 supervisor 에 함께 떠 있어 `localhost` 로 도달됩니다.
4. **`works_access=false` 직원도 포함?** → **전원 포함**(플래그로 구분). 재직/퇴직도 모두 보내고 `active` 플래그로 구분 → WORKS 가 미부여자·퇴사자 판단. (발주 목적① "아직 WORKS에 안 들어온 직원도 표시"에 부합)
5. **예상 완료일** → **오늘(2026-06-01) 완료**. env 키만 양쪽에 넣으면 즉시 동작.

## 4. ⚠️ 동작 전 1가지 — 공유키 주입 (대표/전산 라인)
코드·git 엔 키를 절대 넣지 않으므로, **양쪽 env 에 동일 비밀값**을 넣어야 합니다.
- 키 생성(예): `openssl rand -hex 32`
- 메신저 컨테이너 supervisor 환경에 `KNK_SSO_SERVICE_KEY=<그 값>` 추가
- WORKS env 에도 **같은 값** 추가
- 둘 다 넣기 전까지 엔드포인트는 503 으로 닫혀 있어 안전합니다.

## 5. 호출 예시 (WORKS 쪽 참고)
```bash
curl -s http://localhost:5050/msg/api/sso/directory \
     -H "X-SSO-Service-Key: $KNK_SSO_SERVICE_KEY"
```
- 2xx 면 `users` 전체를 사번(employee_no) 기준 upsert (기존 z140 병합 로직 재사용).
- 403/503 이면 키 설정 상태 점검.
