## 2. 기존 코드 분석 — 재사용 가능 자산

### mail_send.py (v5H228, 2026-05-31)
- 현재 구조: 직원 본인의 **외부 그룹웨어 SMTP 계정**으로 발송 (smtps:465, SSL)
- 비밀번호는 Fernet 암호화 보관 (`KNK_MAIL_KEY` 환경변수, 미설정 시 자동 비활성)
- **재사용 가능**: 메일 작성(EmailMessage)·첨부 처리·주소 검증·자격증명 암호화 패턴
- **Phase 0에서 교체할 부분**: SMTP 접속처만 AWS SES SMTP 엔드포인트로 바꾸면 발송 전환 가능
  (AWS SES도 SMTP 인터페이스 제공 → 코드 구조 거의 그대로)

### ai_client.py (274줄)
- `ai_chat()` / `ai_translate()` / `ai_summarize()` / `ai_vision()` 전부 가동 중
- 메일 AI 4종(분류·번역·요약·답장초안)은 **이 모듈 그대로 호출**하면 됨 — 신규 개발 불필요
- Claude/OpenAI 자동 선택 + 안전 폴백(키 없으면 비활성) 구조 이미 완성

## 4. ⚠ Day 1 핵심 발견 — 정의서 보완 필요 사항

### 발견 1. Cloudflare 받기는 "네임서버 이전"이 전제 조건
- 정의서 1순위 수신안인 Cloudflare Email Routing은 **knknara.co.kr 도메인 전체의
  네임서버를 Cloudflare로 옮겨야** 사용 가능 (무료 플랜은 서브도메인만 등록 불가)
- 이는 Phase 4(MX 전환) 시점의 큰 DNS 변경과 묶이는 사안 → 전산담당자·등록기관 확인 필수
- **POC(Phase 0)에서는 본 도메인을 건드리지 않는 방법으로 검증해야 함** (제약 2·3 준수)

### 발견 2. POC용 수신 경로 — 본 도메인 무접촉 2가지 방안
| 방안 | 방법 | 비용 | 본 도메인 영향 |
|---|---|---|---|
| **A. 테스트 도메인 신규 구매** | 예: knk-mail-test.com → Cloudflare 등록 (목표 구조 그대로 검증) | 연 1~2만원 | **0 (완전 분리)** ⭐ 권고 |
| B. 서브도메인 + AWS SES 수신 | mail-test.knknara.co.kr 에 MX 1줄 추가 (현 DNS에서) | $0.10/1000통 | MX 1줄 추가만 (낮음) |

- A안이 목표 구조(Cloudflare 받기)를 그대로 검증할 수 있어 권고. B안은 DNS 접근만 되면 더 빠름.

### 발견 3. 발송 전환은 저위험
- AWS SES는 SMTP 인터페이스 제공 → 기존 mail_send.py 구조 유지한 채 접속처만 교체
- SES 도메인 인증(DKIM)은 DNS에 TXT 레코드 추가 — MX와 무관, 수신에 영향 0
  (단, 이것도 DNS 접근 권한 필요 → 전산담당자)
