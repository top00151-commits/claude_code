## 2. 발견한 실제 버그 2건 + 수정

### 버그 A — 받은 메일 본문 한글·베트남어 깨짐 (영향 큼)
- **원인**: `mail_store.parse_raw_email()`이 `email.message_from_string()`(문자열 파싱) 사용.
  인코딩되지 않은 **8bit UTF-8 본문**(한글·베트남어)을 `get_payload(decode=True)`가 `raw-unicode-escape`로 처리 → 글자 깨짐.
- **실증**(동일 원문 비교):
  - `from_string`: `'안녕…  b�o gi�'` ← 깨짐(현 운영)
  - `from_bytes` : `'안녕하세요 카탈로그 요청드립니다. báo giá'` ← 정상
  - base64/quoted-printable(지메일류)은 **둘 다 정상** → Gmail 발 메일은 멀쩡했던 이유.
- **수정**: `message_from_string` → **`message_from_bytes`**(str 입력은 `encode('utf-8','surrogateescape')` 후 파싱).
  추가로 비표준 raw 8bit **헤더/파일명**도 `_recover8()`로 surrogateescape→UTF-8 복구(절대 예외 X). 정상 RFC2047 헤더는 무영향.
- **운영 영향**: Gmail 등 인코딩 메일은 이전에도 정상이었으나, 8bit로 보내는 일부 메일서버·클라이언트에서 본문이 깨질 수 있던 **잠복 정확성 버그**를 사전 차단.

### 버그 B — `default_owner` 가 존재하지 않는 컬럼 조회
- **원인**: `default_owner()` 1순위 SQL `WHERE username='kjr'` — `users` 테이블에 `username` 컬럼 **없음**(실제 `login_id`). `try/except`로 가려져 항상 2순위(`name='김정락'`)로 폴백 → 동명 계정 다수면 낮은 id로 감(**z383 '엉뚱한 계정으로 감' 원인 일부**).
- **수정**: `username='kjr'` → **`login_id='kjr'`**. (실 라우팅은 이미 `mail_default_user_id` 바인딩이 우선하므로 현 운영 영향은 없지만, 폴백 로직이 의도대로 동작하도록 정정.)
