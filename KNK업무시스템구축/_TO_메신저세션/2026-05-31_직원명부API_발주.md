## 0. 목적

메신저에 **전 직원의 완전한 정보**(사번·이름(한/영/베)·부서·직급·메일·연락처·법인)가 등록돼 있음.
WORKS 가 이걸 **통째로 가져와 동기화**하게, 메신저에 **직원 명부 API 1개**를 열어 주세요.

→ 효과: ① 아직 WORKS에 안 들어온 직원도 명부에 표시 ② 사번·연락처·다국어 이름 정확히 채움
③ 토큰 sub 가 username 으로 나가는 문제(대표 계정)도 명부 기준으로 정정됨.

## 1. 요청 API

### `GET /msg/api/sso/directory`  (서버 전용)

- **호출**: WORKS(NAS) → 메신저 **내부 주소**(`http://localhost:5050/msg/...`) 서버-서버
- **인증**: 헤더 `X-SSO-Service-Key: <공유키>` (양쪽 OS 환경변수 `KNK_SSO_SERVICE_KEY`, 코드·git 금지). 키 없으면 **403**
- **응답 (HTTP 200, JSON)**:
```json
{
  "users": [
    {
      "employee_no": "5",          // 사번 (필수, 문자열)
      "name_kr": "김정락",          // 한글 이름 (베트남 직원은 '한국 발음')
      "name_en": "Kim Jeongrak",   // 영문 이름
      "name_vi": null,             // 베트남어 이름 (베트남 직원만)
      "dept": "경영",               // 부서명 (WORKS 팀명과 매칭됨)
      "position": "대표이사",        // 직급
      "entity": "KOR",             // KOR | VN
      "email": "kjr@knk.co.kr",
      "phone": "010-1234-5678",    // 연락처
      "is_admin": true,            // 메신저 ceo/관리자 여부
      "works_access": true,        // WORKS 사용 권한 부여 여부
      "active": true               // 재직 여부
    }
    // ... 전 직원
  ]
}
```

**필드 메모**
- `employee_no` = 사번. **username(kjr 등)이 아니라 실제 사번 숫자/코드**여야 함 (대표=5 등).
- 베트남 직원: `name_vi`(베트남어) + `name_kr`(한국 발음) + `name_en`(영문) 모두 채워주세요.
- `dept` 는 WORKS 팀명/코드와 매칭(예: "기술영업팀"). 가능한 한 WORKS 팀명과 동일하게.
- `works_access=false` 인 직원도 명부엔 포함(표시는 되되 진입은 WORKS 가 막음) — 또는 true 만 보내도 됨(택1, 알려주세요).

## 2. WORKS 쪽 동작 (우리가 함 — 참고용)

- WORKS 관리자 화면의 **"메신저 직원 동기화"** 버튼 → 위 API 호출 → 전 직원 upsert
  - 사번(employee_no) 기준 매칭 + 이름 병합(중복 방지) — 기존 z140 로직 재사용
  - 부서→팀 매핑(team_id), 다국어 이름·메일·연락처 채움
- 즉 메신저는 **명부 API 만** 제공하면 됨. 나머지는 WORKS 가 처리.

## 3. 보안

- 서버 전용(브라우저 노출 금지). `X-SSO-Service-Key` 필수.
- 개인정보(메일·연락처) 포함이므로 **내부망 + 키** 로만 접근.
