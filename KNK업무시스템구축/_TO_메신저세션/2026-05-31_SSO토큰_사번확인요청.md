# [메신저 세션 확인 요청] SSO 토큰 sub(사번)이 대표 계정에서 username 으로 나감

## 0. 증상

HAIST WORKS 사용자 목록에서 **김정락(대표)·김동후(대표)의 "사번"이 `kjr` / `kdh`** 로 표시됨.
안지연(사번 67)은 정상 표시. → 즉 **WORKS 는 메신저 SSO 토큰의 `sub` 값을 그대로** 사번으로 씀.

## 1. 원인 (WORKS 쪽에서 확인됨)

- WORKS `/sso/land` 는 JWT의 **`sub` 클레임을 사번(employee_no)** 으로 사용.
- 안지연 → 토큰 `sub = "67"` (정상, 숫자 사번).
- 김정락 → 토큰 **`sub = "kjr"`** 로 들어옴 (사번이 아니라 **옛 username/로그인ID**).
- 김동후 → 토큰 `sub = "kdh"`.

→ **메신저가 발급하는 SSO 토큰의 `sub` 가 대표 계정에서 사번이 아니라 username 으로 나가고 있음.**
(메신저 SSO 명세: `sub = 사번(employee_no), 없으면 username` — 즉 **대표들 employee_no 가 비어 username 으로 폴백**된 것으로 추정)

## 2. 확인/수정 요청 (메신저 측)

1. **김정락·김동후 계정의 사번(employee_no) 이 실제로 설정돼 있는지** 확인
   - 대표님 말씀: 김정락 사번 = **5** (메신저에도 등록돼 있다고 함)
   - 그런데 토큰 `sub` 가 `kjr` 로 나가므로, employee_no 가 비었거나 토큰 생성이 username 을 쓰는 중
2. **SSO 토큰의 `sub` 가 항상 사번(employee_no)으로** 나가도록 보장
   - employee_no 가 설정된 계정은 반드시 그 값을 `sub` 로
   - (대표 계정 employee_no: 김정락=5, 김동후=? 확인 후 설정)
3. 수정 후, 김정락이 "WORKS 열기" 재진입하면 WORKS 사번이 **5** 로 자동 정정됨
   (WORKS 는 사번 매칭 + 이름 기반 병합으로 기존 계정에 5를 자동 반영 — z140)

## 3. 참고 — WORKS 동작(정상)

- WORKS 는 토큰 `sub` 를 사번으로 저장하고, 같은 이름의 기존 계정과 병합함.
- 따라서 메신저가 `sub=5` 로 보내주면 → 기존 김정락 계정 사번이 5로 정정됨(중복 없음).
- 즉 **WORKS 수정 불필요. 메신저 토큰 sub 만 사번으로 나가면 끝.**

## 4. 빠른 확인 방법(메신저 측)

김정락 로그인 상태에서 발급되는 JWT payload 의 `sub` 값을 찍어보면 즉시 확인됩니다.
`sub` 가 `"5"` 면 정상, `"kjr"` 면 employee_no 미설정/폴백.
