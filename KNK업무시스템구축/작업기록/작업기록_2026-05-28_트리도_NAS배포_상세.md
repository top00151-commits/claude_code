### 🅓 오후 2 — `/works/` subpath 기술 결정

#### 문제
HAIST WORKS 템플릿에 **`<a href="/login">` 같은 절대경로 875+ 개**.
subpath 로 배포 시 브라우저가 `/login` 으로 가서 404.

#### 검토 옵션 3가지
- 옵션 A: 875곳 일괄 치환 (6~10시간, 위험)
- 옵션 B: nginx `sub_filter` 자동 재작성 (코드 0 변경)
- 옵션 C: 루트 `/` 로 가기 (코드 0 변경)

#### 결정: **B (sub_filter)**
대표 명시: `/works/` 사용. 코드 손 안 대고 nginx 가 응답 HTML·JS·CSS의 절대경로를 자동 변환.

```nginx
sub_filter 'href="/'   'href="/works/';
sub_filter 'src="/'    'src="/works/';
sub_filter 'action="/' 'action="/works/';
sub_filter 'fetch("/'  'fetch("/works/';
sub_filter 'url("/'    'url("/works/';
proxy_redirect / /works/;
```

장점: 즉시 배포 / 단점: gzip 비활성화 + 일부 JS 동적 URL 못 잡을 수 있음 (운영하며 개선).

## 6. 오늘 발견·교훈

### 🔴 발견
1. **git add . 위험성**: `.gitignore` 없으면 비밀번호 파일·DB·업로드 등 무차별 포함

3. **SSH 키 권한**: 새로 생성한 ed25519 키가 umask 영향으로 0777 → SSH 가 거부 (`bad permissions`)
4. **GitHub PAT 인증**: 사용자가 PAT 발급·복사·붙여넣기 과정에서 오류 잦음 → SSH 키 방식이 더 안정적
5. **`/works/` subpath**: 875곳 hardcoded URL 일괄 수정보다 nginx sub_filter 가 훨씬 빠르고 안전

### 🟢 잘된 점
