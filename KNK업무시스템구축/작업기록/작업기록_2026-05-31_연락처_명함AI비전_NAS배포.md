## 2. 제작 내역 (코드)

### 2-1. 데이터베이스 — `app/database.py`
- 신규 테이블 **`shared_contacts`** (거래처 종속 `customer_contacts`와 별개)
  - 컬럼: `name, position, company, department, mobile, phone, fax, email, address, note, card_image, source(manual/card/signature), customer_id, created_by, created_at, updated_by, updated_at`
  - 인덱스: name / company / email / mobile
  - `init_db()`의 `SCHEMA`에 `CREATE TABLE IF NOT EXISTS`로 추가 → 서버 시작 시 자동 생성(기존 데이터 무영향)

### 2-2. 로직 모듈 — `app/contacts.py` (신규)
- **명함 텍스트 파서** `parse_card_text()` — 이름/직책/회사/부서/전화/휴대폰/팩스/이메일/주소 정규식 추출
  - 라벨 위치 기반 전화 분류(`_extract_phones`) — 한 줄에 `Tel/Fax` 혼재 시 뒤바뀜 방지
  - 이름 추출 `_extract_name` — "홍길동 부장"처럼 직책 붙은 줄·단독 이름줄 대응
- **메일 서명 파서** `parse_signature()`
- **AI 항목분리(텍스트)** `ai_parse_card()` — OCR 텍스트만 AI 전송
- **AI 비전(이미지 직접)** `ai_vision_card()` — 명함 이미지를 JPEG 정규화(≤1600px) 후 멀티모달 AI에 전송 → 항목 추출
- **다중 OCR 결과 채택** `parse_card_best()` — 여러 PSM 결과 중 항목 최다 채택 + AI 병합
- **중복 감지** `find_duplicates()` (휴대폰/이메일/전화)
- **CRUD** `list_contacts/get_contact/create_contact/update_contact/delete_contact` + `can_edit()`(권한)
- **내보내기** `export_csv_bytes`(전사 CSV) · `to_vcard`/`vcards_all`(vCard) · `vcard_qr_png`(QR) · `export_outlook_csv_bytes`(Outlook CSV)

### 2-3. OCR 엔진 강화 — `app/biz_doc.py`
- **명함 전용 다중-PSM OCR** `extract_card_texts()` — PSM 3·11·4·6 시도(명함은 블록이 흩어져 단일 PSM6 부적합). 사업자등록증용 PSM6 기본은 보존
- **명함 전처리 보강** `_preprocess_image(for_card=True)` — 어두운 배경(검정/남색 명함) 자동 감지 → 역상(invert)
- **한글 데이터 최고품질** `download_korean_traineddata(force_best=True)` — `tessdata_best` 강제 업그레이드

### 2-4. AI 클라이언트 — `app/ai_client.py`
- **`ai_vision()`** 신규 — 멀티모달(비전) 단발 호출(Claude/OpenAI 공용). 이미지(base64)+지시문 → 응답
- 기본 모델: OpenAI `gpt-4o-mini`(비전 지원). `KNK_AI_MODEL`로 변경 가능

### 2-5. 라우트 — `app/main.py` (총 15개)
- 페이지: `/contacts`(목록·검색) · `/contacts/new`(직접입력) · `/contacts/scan`(명함) · `/contacts/from-signature`(서명) · `/contacts/{id}`(상세) · `/contacts/{id}/edit`
- 처리: `POST /contacts`(등록) · `POST /contacts/{id}`(수정) · `POST /contacts/{id}/delete`
- AI/OCR: `POST /contacts/parse-card`(비전 우선→Tesseract 폴백) · `POST /contacts/parse-signature` · `POST /contacts/check-dup` · `POST /contacts/upgrade-korean-ocr`
- 내보내기: `/contacts/export.csv` · `/contacts/outlook.csv` · `/contacts/vcards.vcf` · `/contacts/{id}/vcard` · `/contacts/{id}/qr`

### 2-6. 화면(템플릿)

## 3. 명함 인식 동작 우선순위

```
명함 사진 업로드
   │
   ├─ ① AI 비전(OpenAI GPT) 이미지 직접 판독   ← 키 등록 시 (정확도 최상, 다국어)
```

## 5. NAS 운영 적용 (works.knknara.co.kr) — 트러블슈팅 상세

### 5-1. 구조 확인
- `works.knknara.co.kr` = 공인 IP `106.243.113.236` = **회사 NAS(별도 서버)**, cloudflared 터널 아님
- SSH: `ssh -p 31201 root@o.knknara.co.kr` → Ubuntu 20.04 컨테이너(`root@KNKHAIST`)
- 앱: supervisord `[program:knk-works]` (uvicorn, 127.0.0.1:8081), 경로 `/opt/knk_haist`, venv `/opt/knk_haist/.venv`(openai 2.38 설치됨)
- 메신저 `knk-messenger`는 같은 supervisord에 공존 → **건드리지 않음**

### 5-2. 증상
- 키 등록 후에도 명함 화면이 "기본 인식(Tesseract)" + "Tesseract 미설치" → AI 비전 미작동

### 5-3. 원인 추적
1. NAS 코드에 AI 비전 함수 존재 확인(`ai_vision`/`ai_vision_card`/`ai_vision_ready` = 각 1) → **코드는 있음**
2. supervisor conf `environment=`에 키를 넣고 재시작 → 그래도 앱 프로세스의 `OPENAI_API_KEY` **길이 0** (빈 값)
3. 실행 래퍼 `/opt/knk_haist/.venv/bin/run_knk_works.sh` 확인 →
   ```bash
   set -a
   source /opt/knk_haist/.env      # ← supervisor 환경변수를 .env가 덮어씀
   set +a
   exec .venv/bin/uvicorn app.main:app ...
   ```
   → **`.env`가 `OPENAI_API_KEY=`/`KNK_AI_PROVIDER=`를 빈 값으로 덮어쓰고 있었음 = 근본 원인**

### 5-4. 해결 (정답: 키를 `.env`에 등록)
- `/opt/knk_haist/.env` 백업 후, supervisor conf에 넣어둔 키를 그대로 `.env`로 이전(`OPENAI_API_KEY=…`, `KNK_AI_PROVIDER=openai`)
- `supervisorctl restart knk-works` → 앱 프로세스 `OPENAI_API_KEY 길이=164`, `KNK_AI_PROVIDER=[openai]` 확인
- `works.knknara.co.kr` → 연락처 → 명함으로: **"✅ AI 비전 인식 켜짐"** + 명함 인식 성공

### 5-5. 적용 명령 요약 (키 노출 없는 방식)
```bash
# 키 입력(화면 미표시) — 반드시 read 먼저 실행 후 붙여넣기
read -rsp "OpenAI 키: " OPENAI_KEY; echo
# .env 백업 + 키 반영(파이썬, 이스케이프 안전)
cp /opt/knk_haist/.env /opt/knk_haist/.env.bak.ai_$(date +%Y%m%d_%H%M%S)
# (.env 의 OPENAI_API_KEY / KNK_AI_PROVIDER 라인을 실제 값으로 치환 — 본 기록 §2 스크립트 참조)
supervisorctl restart knk-works
```

> **핵심 교훈:** 이 NAS는 앱 환경변수를 **`/opt/knk_haist/.env`** 에서 읽는다(supervisor `environment=`는 .env에 덮임). **앞으로 NAS 환경변수(키 등)는 반드시 `.env`에 설정**할 것.

## 6. 보안 사고 기록 ⚠️

- 작업 중 OpenAI 키를 입력 프롬프트가 아닌 **명령창에 직접 붙여넣어** 키가 화면·shell history·대화에 평문 노출됨
- 조치: **노출된 키 폐기(Revoke) + 새 키 재발급** → 새 키로 `.env` 등록 완료. shell history의 `sk-proj-` 라인 삭제
- **재발 방지:** 키 입력은 항상 `read -rsp` 먼저 실행 → 프롬프트 뜬 뒤 붙여넣기(무표시). 키는 `.env`/환경변수에만, **깃·코드·문서엔 평문 금지**

## 8. 남은 일 / 주의사항

1. **NAS 코드 최신화 점검** — 오늘 추가한 `vcards.vcf` 등 일부가 NAS에 미반영일 수 있음(`/contacts/vcards.vcf` 404 확인됨). 전체 기능(vCard/Outlook 내보내기)까지 쓰려면 **최신 코드 NAS 재배포** 필요
2. **키 중복 정리(선택)** — 현재 키가 `supervisor conf`와 `.env` 양쪽에 있음(.env가 실제 사용). 정리하려면 supervisor conf의 추가분 제거 가능(필수 아님)
3. **비용 모니터링** — 명함 1장당 GPT 비전 호출 1회(gpt-4o-mini 저렴). 대량 등록 시 호출량 비례
4. **`KNK_시작.bat` LAST UPDATE 되돌림 현상** — 작업 중 bat의 LAST UPDATE 라인이 옛 값(z119)으로 되돌아간 경우 발견. bat 덮어쓰는 외부 동작 점검 필요(코드 자체는 정상)
5. **로컬 키** — 이 PC(개발)에도 키 등록됨. NAS와 별개
