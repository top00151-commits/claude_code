**main.py 라우트 변경**:
- `GET /login` → `/sso/login` 자동 redirect (admin 백도어는 `?admin=1`)
- `POST /login` → admin/ceo 만 허용 (Q2=B)
- `GET /sso/login` → 메신저 `/msg/sso/login?redirect_uri=...` redirect
- `GET /sso/callback` → JWT 검증 + upsert + 세션 생성
- `GET /logout` → 로컬 세션 + pwv 캐시 정리

**get_user() 미들웨어 보강**:
- SSO 사용자 5분마다 userinfo 호출 (pwv 검증)

**login.html**:

**requirements.txt**:

## 3. 운영 시나리오 (4가지)

### A. 메신저 로그인 상태에서 HAIST WORKS 접속 (일상)
```
works.knknara.co.kr → /sso/login → 메신저 즉시 JWT 발급 → /home
(비밀번호 입력 0회)
```

### B. 메신저 미로그인 상태에서 HAIST WORKS 접속
```
works.knknara.co.kr → 메신저 SSO 화면 표시
→ 사용자가 사번/비번 입력 (메신저 화면)
→ 메신저 로그인 완료 → JWT 발급 → works.knknara.co.kr/home 복귀
(한 번만 로그인, 이후 시나리오 A로 전환)
```

### C. 메신저 장애 발생 (드문 케이스)
```
works.knknara.co.kr/login?admin=1 → admin/ceo 전용 백도어 폼
→ admin·ceo 만 자체 로그인 가능 (운영 유지)
일반 사용자는 메신저 복구 대기
```

### D. 메신저에서 직원이 비번 변경
```
직원이 메신저에서 비번 변경 → password_version +1
→ HAIST WORKS get_user() 호출 시 5분 내 fetch_userinfo() → 401 _invalid
→ 세션 파기 → 다음 요청 시 자동 /sso/login 재유도
→ 새 비번으로 메신저 로그인 → HAIST WORKS 자동 진입
```

## 7. 학습 정리 — 5가지 교훈

### 7.1 두 저장소 분리 인식 (commit 위치 주의)
- 메인: `claude_code.git` (작업 폴더 루트)
- NAS 운영: `knk-haist-works.git` (`01_HAIST_WORKS/` 안)
- → **NAS 운영 코드 변경은 `01_HAIST_WORKS/` 안에서 commit+push**

### 7.2 NAT loopback 컨테이너 안에서 외부 도메인 불가
- 같은 도메인이라도 컨테이너 안 → 외부 → DSM → 컨테이너 안 라우팅 timeout
- 해결: 같은 컨테이너 안 서비스는 **localhost 또는 컨테이너 내부 IP** 호출
- 브라우저용 URL과 서버용 URL **명확히 분리**

### 7.3 환경변수 단일 vs 분리
- 단순화한답시고 단일 변수로 묶으면 사용처 다를 때 문제 (브라우저 vs 서버)
- 처음부터 **PUBLIC / INTERNAL 분리**가 깔끔

### 7.4 bash case 패턴 매칭 함정
- `${1:-default}` 는 "default" 문자열을 반환
- case 패턴 `""` 와 매칭 안 됨 (빈 인자가 아니라 "default" 문자열이라)
- 빅터 권장: `ARG=${1:-}` 빈 인자로 명시 후 case 에서 `""` 매칭

### 7.5 DB 파일명 가정 금지
- `main.db` 는 빅터 가정. 실제는 `knk.db`
- → 환경변수 `KNK_DB_PATH` override + 자동 감지 패턴 처음부터
