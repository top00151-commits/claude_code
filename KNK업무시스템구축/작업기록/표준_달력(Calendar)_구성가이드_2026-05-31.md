# 표준 달력(Calendar) 컴포넌트 구성 가이드

> **작성**: 빅터(01) · 2026-05-31
> **기준 화면**: `매출·영업 → 수주목록`(`sales_orders.html`)의 좌측 1개월 달력
> **목적**: HAIST WORKS 내 **모든 달력을 이 방식으로 통일** 적용
> **원본 코드**: `app/main.py`(빌더) + `app/templates/sales_orders.html`(CSS·템플릿)

---

## 0. 한눈에 — 달력은 3덩어리로 구성된다

```
① 데이터 빌더(Python)  →  ② 데이터 모델(dict)  →  ③ 템플릿(Jinja+CSS) 렌더
   _build_month()           {year, month, weeks}     .cal-grid / .cal-day
```

- **①**: 파이썬 표준 `calendar` 모듈로 "일요일 시작" 주(week) 배열 생성 + 날짜별 상태(공휴일·카운트·D-day) 계산
- **②**: `{year, month, weeks[][day_dict]}` 형태의 순수 데이터 (템플릿은 로직 없이 그리기만)
- **③**: 7열 그리드. 날짜칸마다 숫자·공휴일 배지(K/V)·건수·주말/오늘/선택 색

> 핵심 원칙: **빌더가 모든 판단을 끝내고, 템플릿은 색만 입힌다.** (다른 페이지는 빌더의 "일별 데이터 소스"만 바꾸면 됨)

## 2. 데이터 모델 (②) — 템플릿이 받는 구조

```python
m = {
  "year": 2026,
  "month": 5,
  "weeks": [            # 주 배열 (각 주 = 7일)
    [ day, day, day, day, day, day, day ],   # 일~토
    ...
  ]
}
```

**날짜칸(day) 한 칸의 필드** — 이게 표준 계약(contract):

| 필드 | 타입 | 의미 |
|---|---|---|
| `date` | `"2026-05-31"` | ISO 날짜(키·링크용) |
| `day` | `31` | 일(숫자) |
| `in_month` | `bool` | 이번 달 날짜인가(아니면 흐리게) |
| `count` | `int` | 그날 항목 수(0이면 미표시) |
| `amount` | `float` | 그날 금액 합(옵션, 툴팁용) |
| `cls` | `"empty/overdue/past/d3/d7/future"` | 칸 배경 상태 |
| `is_today` | `bool` | 오늘인가 |
| `is_selected` | `bool` | 선택된 날인가 |
| `hol_kr` | `str/None` | 한국 공휴일명(있으면 K 배지) |
| `hol_vn` | `str/None` | 베트남 공휴일명(있으면 V 배지) |
| `is_sun` | `bool` | 일요일(주말색) |
| `is_sat` | `bool` | 토요일(주말색) |

> **다른 달력에 적용 시**: 이 12개 필드만 채워주면 템플릿·CSS를 그대로 재사용한다.

## 3. 백엔드 빌더 (①) — `_build_month()` 표준 구현

```python
def _build_month(year, month, *, today, today_iso, selected_iso,
                 day_data, HOLIDAYS_KR, HOLIDAYS_VN):
    """달력 1개월 데이터 생성 (일요일 시작).
    day_data: { "YYYY-MM-DD": {"count": int, "amount": float, "overdue": int} }
              ← 페이지마다 다른 '일별 데이터 소스'. 이것만 갈아끼우면 됨.
    """
    import calendar as _cal
    cal = _cal.Calendar(firstweekday=6)          # 6 = 일요일 시작
    weeks = []
    for week in cal.monthdatescalendar(year, month):   # 그 달이 걸친 모든 주(앞뒤 달 포함)
        row = []
        for dt in week:
            iso = dt.isoformat()
            in_month = (dt.month == month)
            b = day_data.get(iso) or {"count": 0, "amount": 0.0, "overdue": 0}
            d_left = (dt - today).days
            # 칸 배경 상태(cls) — 건수 0이면 empty, 아니면 D-day로 분류
            if b["count"] == 0:        cls = "empty"
            elif b["overdue"] > 0:     cls = "overdue"     # 지남+미처리
            elif d_left < 0:           cls = "past"        # 지난 날(처리됨)
            elif d_left <= 3:          cls = "d3"          # 임박(3일)
            elif d_left <= 7:          cls = "d7"          # 주간(7일)
            else:                      cls = "future"      # 여유
            row.append({
                "date": iso, "day": dt.day, "in_month": in_month,
                "count": b["count"], "amount": b["amount"], "cls": cls,
                "is_today": (iso == today_iso),
                "is_selected": (iso == selected_iso),
                "hol_kr": HOLIDAYS_KR.get(iso),
                "hol_vn": HOLIDAYS_VN.get(iso),
                "is_sun": (dt.weekday() == 6),
                "is_sat": (dt.weekday() == 5),
            })
        weeks.append(row)
    return {"year": year, "month": month, "weeks": weeks}
```

**포인트**
- `calendar.Calendar(firstweekday=6)` → **일요일 시작**. (월요일 시작이면 `0`)
- `monthdatescalendar()` → 그 달이 걸친 주 전체(앞뒤 달 날짜 포함) → `in_month`로 흐림 처리
- `weekday()`: 월=0 … 토=5, 일=6
- `cls`는 "건수+D-day" 규칙. 페이지 성격에 맞게 분기만 바꿔도 됨(색은 §4 클래스 그대로)

## 4. 일별 데이터 소스(버킷) — 페이지마다 이것만 교체

날짜별 `{count, amount, overdue}` 를 만드는 부분. **달력 종류가 달라지면 여기만 바꾼다.**

```python
day_data = {}
for it in items:                       # items = 그 페이지의 대상(수주/일정/발주 등)
    dd = (it.get("due_date") or "")[:10]   # ← 날짜 기준 필드 (페이지마다 다름)
    if not dd:
        continue
    b = day_data.setdefault(dd, {"count": 0, "amount": 0.0, "overdue": 0})
    b["count"]  += 1
    b["amount"] += _amt(it)                # 금액 합(없으면 0)
    st = (it.get("status") or "").upper()
    if dd < today_iso and st in ("CONFIRMED", "DRAFT"):   # '지남+미처리' 정의(페이지별)
        b["overdue"] += 1
```

> 예) 일정 달력이면 `due_date` 대신 `event_date`, `overdue` 규칙은 "미완료" 등으로.

## 5. 공휴일 (한국/베트남) — 전사 공용 상수

- **모듈 최상단 공용 dict**: `HOLIDAYS_KR`, `HOLIDAYS_VN` = `{ "YYYY-MM-DD": "공휴일명" }`
- 생성기: `_build_holidays_auto()` — `holidays` 라이브러리로 **KR·VN 자동 계산**(7년 슬라이딩: 작년~5년후). 음력·대체공휴일·nghỉ bù 자동 처리. 매년 수동 갱신 불필요.
- **대체공휴일 구분**:
  - 한국: 공휴일명에 `'대체'` 포함 → K 배지 **점선**(`.alt`)
  - 베트남: 명에 `'Nghỉ bù'` 포함 → V 배지 **점선**

```python
hol_kr = HOLIDAYS_KR.get(iso)   # 있으면 K 배지 + 날짜 빨강
hol_vn = HOLIDAYS_VN.get(iso)   # 있으면 V 배지
```

> 다른 달력은 **이미 있는 `HOLIDAYS_KR/VN`를 그대로 import**해 쓰면 됨(중복 생성 금지).

## 6. 네비게이션 — `cal_nav` + URL 파라미터

```python
cal_nav = {
  "prev":    "2026-04",     # 이전 달
  "next":    "2026-06",     # 다음 달
  "today":   "2026-05",     # 이번 달
  "current": "2026-05",     # 현재 보는 달(<input type=month> 값)
  "is_today_view": True,    # 이번 달 보는 중인가
}
```

- URL 파라미터 **`?cal_ym=YYYY-MM`** 로 표시 월 변경 (없으면 오늘 월)
- 다른 필터(예: `biz`)는 링크에 함께 보존: `?biz=T&cal_ym=2026-06`
- 표준이라 파라미터명도 **`cal_ym`** 로 통일 권장

## 7. 템플릿 (③) — Jinja 표준 스니펫

```jinja
<div class="cal-card">
  <div class="cal-title">
    <span>📅 {{ m.year }}.{{ '%02d'|format(m.month) }}</span>
    <span class="nav">
      <a href="?cal_ym={{ nav.prev }}">←</a>
      <a class="today-btn" href="?">오늘</a>
      <a href="?cal_ym={{ nav.next }}">→</a>
      <input type="month" value="{{ nav.current }}"
             onchange="if(this.value) location.href='?cal_ym='+this.value;">
    </span>
  </div>
  <div class="cal-grid">
    <div class="cal-dow sun">일</div><div class="cal-dow">월</div><div class="cal-dow">화</div>
    <div class="cal-dow">수</div><div class="cal-dow">목</div><div class="cal-dow">금</div><div class="cal-dow sat">토</div>
    {% for week in m.weeks %}{% for d in week %}
      {% if d.in_month %}
      {% set _hol = d.hol_kr or d.hol_vn %}
      <a class="cal-day cls-{{ d.cls }} {% if d.is_today %}today{% endif %} {% if d.is_selected %}selected{% endif %}"
         href="?due_date={{ d.date }}"
         title="{{ d.date }}{% if d.hol_kr %} · 🇰🇷 {{ d.hol_kr }}{% endif %}{% if d.hol_vn %} · 🇻🇳 {{ d.hol_vn }}{% endif %} · {{ d.count }}건">
        {% if _hol %}
        <span class="hol-badge">
          {% if d.hol_kr %}<span class="b kr {% if '대체' in d.hol_kr %}alt{% endif %}">K</span>{% endif %}
          {% if d.hol_vn %}<span class="b vn {% if 'Nghỉ bù' in d.hol_vn %}alt{% endif %}">V</span>{% endif %}
        </span>
        {% endif %}
        <span class="d {% if d.is_sun or _hol %}sun{% elif d.is_sat %}sat{% endif %}">{{ d.day }}</span>
        {% if d.count %}<span class="cnt">{{ d.count }}</span>{% endif %}
      </a>
      {% else %}<div class="cal-day out"><span class="d">{{ d.day }}</span></div>{% endif %}
    {% endfor %}{% endfor %}
  </div>
</div>
```

> 주말/공휴일 색은 **숫자(`.d`)에만** 적용: `is_sun OR 공휴일 → .sun(빨강)`, `is_sat → .sat(파랑)`.

## 10. 다른 달력에 적용하는 법 (체크리스트)

새 화면에 달력을 넣을 때:

1. **CSS 복사** — §8 `.cal-*` 블록 그대로(이미 공용화하면 import만)
2. **빌더 복사** — §3 `_build_month()` 그대로. `firstweekday=6`(일요일 시작) 유지
3. **공휴일 재사용** — 모듈의 `HOLIDAYS_KR / HOLIDAYS_VN` 그대로 사용(새로 만들지 말 것)
4. **일별 데이터 소스만 교체** — §4 처럼 그 페이지의 `items`·날짜필드(`due_date`/`event_date`…)·overdue 정의로 `day_data` 생성
5. **네비 표준** — URL 파라미터 `cal_ym=YYYY-MM` 통일, 다른 필터는 링크에 보존
6. **템플릿 복사** — §7 스니펫. `href`(날짜 클릭 시 동작)와 `title`만 페이지에 맞게
7. **데이터 모델 계약 준수** — §2의 12개 필드를 반드시 채울 것(빠지면 색/배지 누락)

> **권장(중복 줄이기)**: §8 CSS와 §7 템플릿을 `_v5_partials/calendar.html` 같은 **공용 partial**로 빼고, 빌더는 공용 헬퍼 `build_month(...)`로 추출하면, 새 달력은 "day_data만 넘기고 include" 한 줄로 끝난다. (차기 리팩터 제안)
