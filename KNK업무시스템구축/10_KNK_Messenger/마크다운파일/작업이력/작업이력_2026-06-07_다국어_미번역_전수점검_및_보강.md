- **`ko` 에 있는데 `vi`/`en` 에 없는 키 = 0개.** → **번역표(ko/vi/en) 자체는 이미 완전**.
- 코드에서 쓰는 키 518개 중 `ko` 정의 없는 건 5개(전부 `status.`·`lang.`·`item.` 같은 **동적 prefix** — 런타임 조합 키라 정상).

### 그럼 화면에 왜 한국어가 남나? — 원인 2가지
1. **캐시(옛 i18n.js)**: 오늘 새 번역이 많이 추가됐는데 휴대폰이 옛 i18n.js 를 캐시 → 옛(한국어) 화면. **앱 완전 재시작/하드 새로고침으로 해결**.
   - 예: 작성기 자동번역 배너(`composer.autoHint`)는 **vi 번역이 이미 존재**(`🌐 Dịch tự động BẬT (...) — Gửi kèm bản gốc + bản dịch`). 한국어로 보였다면 캐시 문제.
2. **i18n 키 없이 한국어로 하드코딩된 문자열**: 오늘 추가/변경분 다수가 `data-i18n` / `KNK_t` 연결 없이 한국어 그대로. → **이번 작업의 핵심 = 이걸 찾아 키로 전환·번역.**

## 2. i18n 시스템 사용법 (참고)

- **정적 HTML**: 요소에 `data-i18n="키"`(텍스트) / `data-i18n-ph="키"`(placeholder) / `data-i18n-title="키"`(title) / `data-i18n-html="키"`(HTML).
  - 주의: `data-i18n` 은 요소의 textContent 를 통째로 교체 → **중첩 `<span>` 이 있으면 그 부분만 별도 span 으로 감싸서** 키를 건다.
  - 주의: **동적으로 내용이 바뀌는 컨테이너**(예: AI 요약 본문)에는 `data-i18n` 금지(언어 전환 시 내용이 지워짐).
- **JS 동적 문구**: `window.KNK_t("키", "한국어폴백")` — 현재 언어 문구 반환, 키 없으면 폴백.
  - 치환: `KNK_t("키","폴백 {n}").replace("{n}", 값)` (KNK_t 는 치환 미지원).
- **키 추가**: `static/js/i18n.js` 의 `I18N = { ko:{...}, vi:{...}, en:{...}, zh:{...} }` **각 언어 블록에 같은 키**로 추가.
  - **일반 UI = ko/vi/en** 3개. **zh 는 '고객초대(게스트)' 관련 문자열만** (대표 지시).
- 로드 순서: `i18n.js` → `app.js`. (런타임에 `window.KNK_t` 항상 존재)
