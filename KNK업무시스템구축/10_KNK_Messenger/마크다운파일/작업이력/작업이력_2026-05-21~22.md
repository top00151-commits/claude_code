## 1. 요청(요청목록) 워크플로 전면 개편

### 1-1. "내 요청" 종합 관리 화면
- 기존: 나에게 **배정된** 요청만 표시 → 내가 **보낸(위임한)** 요청은 추적 불가.
- 변경: `/api/my/requests` 를 `assigned_to=나 OR requested_by=나` 로 확장.
  - **📥 받은 요청** (담당자=나) / **📤 보낸 요청** (요청자=나) 2개 섹션으로 분리 표시.
  - 각 항목에서 **방에 안 들어가도 바로 상태 변경** (인라인 버튼).
  - 행 클릭 시 해당 방으로 이동은 유지.
  - 요청 변경 시 패널이 열려 있으면 실시간 갱신(`requests_updated` 소켓).

### 1-2. 역할별 권한 분리
| 역할 | 가능한 동작 |
|------|------------|
| **받은 사람(담당자)** | 시작 · 완료 |
| **요청한 사람(요청자)** | 취소 · 보류 · 보류해제 · 다시열기 |
| **방장 · PM** | 전체 (override) |

- 담당자 미지정이면 요청자가 시작·완료까지 가능.
- 서버(`_request_perms`)가 권한 플래그(`can_start`·`can_complete`·`can_cancel`·`can_hold`·`can_unhold`·`can_reopen`)를 계산해 목록 API로 내려주고, 프론트는 그 플래그대로 버튼만 노출.

### 1-3. "보류(on_hold)" 상태 신설
- 상태 흐름: 열림 → 진행중 → 완료 / + **보류** · 취소.
- 요청목록 다이얼로그에 "보류" 탭 추가, 보라색 상태 배지.

### 1-4. 완료 시 메시지 필수
- 완료 클릭 → 메시지 입력(필수). 예: "도면 메일로 보냈습니다".
- 그 메시지가 방에 일반 메시지로 게시되어 **요청자에게 전달 + 푸시**, 요청은 완료 처리.

### 1-5. 진행 중 요청 있으면 방 나가기 차단
- 본인에게 배정된 열림/진행중/보류 요청이 그 방에 있으면 **나가기 거부** + 안내.
- 완료/취소/보류해제 후 나갈 수 있음.

### 1-6. 요청 등록 다이얼로그 개선
- 담당자 후보 = **현재 방 멤버만** (전체 사용자 X).
- 담당자 **검색형 피커**(이름·직급·부서 검색해 선택, 비우면 미지정).
- 폼 가로 스크롤 제거(`min-width:0` + `width:100%`).

## 2. 권한 체계 — 부방장 → PM

- 표기 전부 **부방장 → PM** 으로 변경.
- **PM = 방장 권한 동일**: 내보내기·역할변경·초대정책 모두 방장·PM 동일 허용.
- 단, **방장(host)은 보호** — 내보내기·강등 불가. 방장 위임(transfer)은 방장만 가능.

---

## 3. 태블릿 / 키보드 / 모바일 UX

- **세로 키보드**: 입력창이 화면 중간에 뜨던 문제 — `translateY` 보정을 폰 레이아웃에만 적용(태블릿은 `chat-app` 높이만 조정).
- **가로 키보드**: 입력창이 사라지던 문제 — 터치 기기 공통으로 `body` 스크롤 잠금(`position:fixed`) 적용.
- **입력창 버튼줄 가림**: 뷰포트 메타 `interactive-widget=resizes-content` 와 충돌하던 `virtualKeyboard.overlaysContent=true` → `false` 로 변경(키보드가 화면을 밀어올림).
- **스레드 답글 입력창**: `.thread-panel` 높이를 `var(--vvh)` 로 → 키보드 위로 정상 배치.
- **키보드 높이 보정**: visualViewport·VirtualKeyboard API 중 큰 값 채택(삼성 키보드 툴바 대응).
- (참고) 상단 상태바 표시 ON 일 때 약간의 오프셋 잔존 — 현재 사용엔 지장 없음.

## 5. 1:1 대화방

- 상대가 나가도 **기존 방 재사용**(`direct_key` 컬럼) → 다시 대화 시작 시 새 방이 안 생기고 **이전 대화 내용 유지**.
- 빠진 멤버 자동 재입장 + 접속 중이면 소켓룸 즉시 합류(실시간 수신).

## 6. 알림 / 푸시

- **보고 있는 방인데 알림이 오던 문제**: `document.hasFocus()` 가 태블릿 키보드 때문에 부정확 → 터치 기기는 "방 열림 + 화면 보임"이면 보는 중으로 간주해 억제.
- **OS 푸시 팝업**: 서버 푸시 억제를 PC 접속만 보던 것(`_user_has_active_pc`) → **기기 무관 활성 세션**(`_user_has_active_session`)으로 변경. 어느 기기로든 앱을 보고 있으면 푸시 안 보냄. 클라 presence·heartbeat 도 전 기기 적용.
