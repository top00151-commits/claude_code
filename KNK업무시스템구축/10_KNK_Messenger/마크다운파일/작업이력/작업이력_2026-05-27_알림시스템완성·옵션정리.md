## 1. 알림 옵션 5개 → 2개 단순화 ⭐⭐

### 배경
5개 옵션 중 3개가 실효성 없거나 중복.

### 삭제된 옵션
| 옵션 | 삭제 사유 |
|---|---|
| 사이드바 방 항목 깜빡임 | 색상 #FEF2F2 vs #FEE2E2 거의 동일 → 시각 효과 거의 없음 + 안 읽음 뱃지와 중복 |
| 탭/제목 깜빡임 | 모바일 PWA 에는 탭 없어 무의미. PC 도 실효성 낮음 |
| 화면 안 토스트 (우하단 카드) | 시스템 알림과 중복. 5초 화면 가림. 실효성 낮음 |

### 최종 옵션 (2개)
- ☑ **새 메시지 알림 받기** (보낸사람+대화방+내용 표시 - 휴대폰 잠금화면·컴퓨터 팝업)
- ☑ **🔒 팝업 알림 내용 숨기기** (보낸사람+대화방+내용 없이 "KNK message" 만 표시)

### 부가 정리
- 라벨 "OS 알림 토스트" → 사람친화 한글 ("휴대폰 잠금화면·컴퓨터 팝업")
- 토스트 위치 라벨 "우상단" → "우하단" (CSS `right:16px; bottom:16px` 반영)
- 3언어 (ko/vi/en) i18n 모두 정리

## 2. PC 더블 알림 버그 수정 ⭐

### 증상
PC 에서 메시지 한 번 받으면 알림이 2회 발생 (인앱 알림 + SW 푸시 알림 둘 다)

### 원인
`_PC_ACTIVE_STALE_SEC = 30` 으로 줄였던 값이 JS 하트비트 간격(30초) 과 동일.
→ 타이밍 어긋나는 순간 (heartbeat 직전) 서버가 PC 비활성 판정 → 푸시 발사 → 더블 알림

### 수정
`_PC_ACTIVE_STALE_SEC: 30 → 60` (JS 코드 주석에 명시된 원래 의도값으로 복원)

커밋: `18f9dd1`

## 3. 알림 "왔다 안왔다" 버그 수정 ⭐

### 증상
방에 들어갔다 나와도 그 방의 알림이 자주 안 옴. 한참 뒤 다시 오기도 함.

→ 서버 측 `active_room=10` 이 그대로 유지됨 + JS 하트비트로 ts 도 fresh.
→ 서버: "사용자가 방 10 보고 있음" → 그 방 푸시 차단 계속.

### 수정
`leaveRoomView()` 안에 `_notifySWActiveRoom(null)` 추가.

## 4. FCM Topic 헤더 제거 — 배지 합산 작동 ⭐⭐

### 증상
서버 SQL = 6 (안 읽은 메시지 6개) 인데 휴대폰 아이콘 배지 = 1 멈춤.

### 진단 흐름
1. `/api/admin/badge_diag` endpoint 추가 → SQL 결과 확인 → 6 정상 계산됨
2. 그래도 아이콘 = 1 → 클라이언트 측 문제 의심
3. `/api/admin/push_log` endpoint 추가 → 푸시 발사 시 badge 값 확인
4. **빅터 직접 관찰 후 결정적 단서**: "다른 방 메시지 보냈더니 배지가 2 됐어"
   → 배지 = **활성 알림 카드 수** (setAppBadge 값 무시)

### 원인 1 — FCM Topic 헤더로 collapse
`webpush(..., headers={"Topic": tag})` → 같은 Topic 푸시들 FCM 에서 1개로 합쳐짐 (W3C Push 표준).
6개 메시지 발사 → 1개만 휴대폰 도달 → badge=1.

### 원인 2 — Chrome PWA 의 배지 정책 (구조적 한계)
Chrome Android PWA 는 `navigator.setAppBadge(N)` 호출을 OS 에 그대로 전달하지 않고, **OS 의 활성 알림 카드 수** 를 배지로 사용.
- 네이티브 앱: setAppBadge → OS 직접 → 정확한 N 표시
- PWA: setAppBadge 무시 → 알림 카드 수 자동 표시
- Google 의도적 정책 (PWA 가 OS 알림 시스템 우회 차단)

### 수정·결론
- Topic 헤더 제거 → 모든 푸시 도착 보장
- 배지 = "안 읽음 있는 방 개수" 로 받아들이기 (한 방 N 개 메시지 = 1 카드 = 1 배지)
- 진짜 메시지 수 합산 원하면 → **네이티브 앱 (Capacitor)** 필요

커밋: `6b8243d`

## 5. 알림 지연 보완 — 구독 병렬 전송 ⭐

### 분석
"팝업이 안 왔다가 다른 방 메시지가 깨우면 그제서야 옴" 패턴 → **Android Doze 모드 / Samsung 배터리 최적화** 가 주요 원인 (OS 차원, 코드 우회 불가).

서버 측에서 우리가 할 수 있는 마이크로 최적화:
- 같은 사용자의 여러 구독 (PC + 휴대폰 + 태블릿) 을 순차 → 병렬 HTTP 전송으로 변경.
- 3 기기 = 150~600ms (sequential) → 50~200ms (parallel) — 약 3배 단축.

### 구현
`send_push_to_user` 에 `concurrent.futures.ThreadPoolExecutor` 도입. 사용자당 최대 8 워커.

### OS 차원 권장 설정 (직원 공지 필요)
**Samsung Galaxy 시리즈**:
- 설정 → 배터리 → KNK 메신저(또는 Chrome) → 배터리 사용량 → **"제한 없음"**
- 설정 → 배터리 → "배터리 보호 모드" → **해제**

**일반 Android**:
- 설정 → 앱 → KNK 메신저 → 배터리 → **"제한 없음" 또는 "최적화 안 함"**

이 1회 설정만으로 알림 도착률 크게 개선됨.

## 8. 동작 매트릭스 (최종)

| 상태 | OS 알림 | 사운드 | 배지 |
|---|---|---|---|
| 같은 방 보는 중 | 안 뜸 ✅ | 안 남 | 그 방 = 0 |
| 다른 방 보는 중 | 뜸 | 매번 (renotify) | 그 방의 카드 1장 = +1 |
| 메신저 백그라운드 | 뜸 | 매번 | 카드 수만큼 |
| 잠금화면 | 뜸 | 매번 | 카드 수만큼 |
| PC 활성 세션 있음 | 안 뜸 | — | 인앱 알림으로 처리 |

같은 방 메시지가 N개 와도 OS 알림 1장 (collapse). 배지 1 증가.
방이 M 개에서 안 읽음 있으면 배지 = M.

## 9. 잔존 한계 (구조적, 우회 불가)

1. **PWA 배지 = 활성 알림 카드 수** — Chrome 정책. 진짜 메시지 수 표시는 네이티브 앱만 가능.
2. **Android Doze 모드 지연** — 배터리 최적화 설정으로 일부 완화 가능 (사용자 설정).
3. **FCM 전송 지연 1~5초** — 정상. 즉시 도달 보장 불가.
4. **iOS PWA 한계** — iOS 16.4+ 기본 푸시 지원하지만 배지·백그라운드 안드로이드보다 더 제약.

→ 위 4가지 완전 해결 원하면 **Capacitor 하이브리드 앱** (Android + iOS, 10~12 영업일).
