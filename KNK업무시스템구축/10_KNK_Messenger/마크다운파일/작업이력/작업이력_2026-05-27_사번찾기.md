# 2026-05-27 (저녁) — 로그인 화면 "내 사번 찾기" 기능 추가

## 배경

- 메신저 테스트 배포 단계 — 직원들에게 사번/로그인 ID 안내 필요
- 직원들이 자기 사번을 모르는 경우 다수 → 관리팀에 일일이 문의하기 어려움
- 대표 지시: 로그인 화면에서 이름 입력 → 사번·부서 자체 확인 기능

## 결정 사항

| 항목 | 결정 |
|---|---|
| **검증 방식** | 이름만 입력 → 사번 + 부서 + 직급 표시 (본인이 직접 확인) |
| **본사/베트남** | 한 화면에서 통합 검색 (이름으로 자동 매칭) |
| **동명이인** | 최대 5명 카드로 표시 |
| **비번 안내** | 결과 카드에 같이 표시 (본사 = 휴대폰 / 베트남 = 9999) |
| **안전장치** | 시도 횟수 제한 (같은 IP 5분 내 20회 또는 실패 5회 시 차단) |
| **베트남 공통 비번 9999** | 첫 로그인 강제 비번 변경(must_change_password=1)으로 커버 OK |

## 1) 백엔드 — `POST /api/lookup_employee`

위치: `app.py` 의 `login` 함수 직후 (~ line 2118)

```python
@app.route("/api/lookup_employee", methods=["POST"])
def api_lookup_employee():
    # body: {"name": "홍길동"}
    # 응답: {"results": [...], "total": N}
    # 차단: 429 / 너무 짧음: 400
```

### 입력 검증
- `name` 길이 2~40
- LIKE 와일드카드(`%`, `_`, `\`) 이스케이프 처리

### 차단 정책
- `_lookup_attempts` (in-memory `{ip: [(ts, success), ...]}`)
- `_LOOKUP_WINDOW_SEC = 300` (5분)
- `_LOOKUP_MAX_PER_WINDOW = 20` (5분 내 총 시도 20회 시 차단)
- `_LOOKUP_MAX_FAIL_PER_WINDOW = 5` (5분 내 실패 5회 시 차단)
- nginx 뒤 X-Forwarded-For 추출

### 정렬·페이지
- 완전일치 우선 → 글자 수 짧은 순 → id 순
- 최대 5건

### 응답 필드 (각 result)
```json
{
  "username": "5",
  "employee_no": "5",
  "display_name": "홍길동",
  "department": "관리팀",
  "title": "사원",
  "mode": "kor",      // kor / vn / unknown
  "pw_hint": "본인 휴대폰 번호 (숫자만 11자리)"
}
```

### 본사/베트남 분류 — `_classify_user_mode(username)`

| username 패턴 | 분류 | 예시 |
|---|---|---|
| 순수 숫자 | **kor** | "5", "10" |
| `@knknara.co.kr` 이메일 | **kor** | "user@knknara.co.kr" |
| `vn` + 숫자 | **vn** | "vn1", "vn23" |
| `@knkvn` 도메인 | **vn** | "user@knkvn.local" |
| **영문 슬러그** (애매) | **unknown** | "kjr", "nguyenvana" |

→ **unknown 케이스**: 양쪽 비번 안내 모두 표시 (`본사: 본인 휴대폰 번호 / 베트남: 9999`)

테스트 결과 9/9 통과:
```
[OK] '5'                  -> kor
[OK] '10'                 -> kor
[OK] 'vn1'                -> vn
[OK] 'vn23'               -> vn
[OK] 'kjr'                -> unknown
[OK] 'nguyenvana'         -> unknown
[OK] 'user@knknara.co.kr' -> kor
[OK] 'user@knkvn.local'   -> vn
[OK] ''                   -> unknown
```

## 2) 프론트엔드 — `templates/login.html`

### 링크 추가
"신규 직원 등록은 관리자에게..." 위에 빨간색 링크:
```html
🔍 내 사번(아이디) 찾기
```

### 모달 (about-overlay 패턴 재사용)
- 이름 입력란 + "찾기" 버튼
- 결과 카드 (이름 + 모드 뱃지 + 직급 + 소속 + 로그인 아이디 + 초기 비밀번호)
- "이 아이디로 로그인하기" 버튼 → 로그인 폼에 자동 채움 + 모달 닫기 + 비번칸 포커스

### 모드 뱃지
- 🇰🇷 본사 → 파란색
- 🇻🇳 베트남 → 노란색
- unknown → 뱃지 표시 안 함

### XSS 방어
- 모든 동적 텍스트는 `escapeHtml()` 통과

### 에러 처리
- 429: "잠시 후 다시 시도해 주세요"
- 400 (이름 짧음): "이름을 2자 이상 입력해 주세요"
- 200 + results 빈 배열: "해당 이름의 직원을 찾을 수 없습니다"
- 네트워크 오류: "네트워크 오류"

## 5) 보안 고려

| 위험 | 완화책 |
|---|---|
| **사번 노출 위험** | 베트남 9999 공통 비번 + 사번 노출 시, 첫 로그인 시 강제 비번 변경 (`must_change_password=1`) 으로 본인이 먼저 잡으면 안전. 대표 판단으로 수용. |
| **남용 (브루트포스로 직원 명단 수집)** | 같은 IP 5분 내 20회 시도 또는 실패 5회 시 자동 차단. nginx 뒤 X-Forwarded-For 추출. |
| **PII 누설** | 휴대폰·이메일은 절대 표시 안 함. 사번·이름·부서·직급만 표시 (회사 내 공지 수준). |
| **SQL Injection** | parameterized query + LIKE 와일드카드 이스케이프. |
| **XSS** | 모든 동적 HTML 은 `escapeHtml()` 통과. |
| **로그인 안 한 상태에서 호출 가능** | 의도된 동작 (직원이 로그인 못해서 사번 찾는 화면이므로). 차단 정책으로 보완. |
