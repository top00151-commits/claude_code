## 2. 알림 시스템 — 모바일 OS 한계 우회 ⭐⭐⭐

### 문제
- 모바일(휴대폰·태블릿)에서 메시지 받고 채팅창에서 확인해도 OS 알림 팝업이 사라지지 않음
- PC 는 정상 동작

### 5번 실패한 접근 (학습 내용)

| 버전 | 전략 | 결과 |
|---|---|---|
| v15 (이전) | 페이지에서 `notification.close()` | Samsung Internet 무시 |
| v16 | SW message 채널로 `.close()` 위임 | 일부만 동작 |
| v17 | push 핸들러 강제 close + 60/250ms 재시도 | 그래도 잔존 |
| (서버) | 본인에게 clear 푸시 + 500ms 지연 | 무력 |
| v18 | 활성 방 + 페이지 포커스 시 알림 안 띄움 | clients.matchAll() 빈 결과 → 무력 |
| v19 | explicit close 제거 + 알림 body 진단 prefix | 진단으로 원인 확인 |
| v20 | URL 기반 활성 방 검출 + 2초 하트비트 | clients.matchAll() 자체가 Chrome PWA 에서 빈 배열 |

### 원인 분석 (v19 진단 정보로 확정)

진단 prefix: `[v20 ar=- hb=-/7s url= tag=room_10]`
- `ar=-` : Chrome 이 SW 를 수시로 종료 → `_activeRoomId` 메모리 변수 소실
- `vis=0 foc=0` : 푸시 컨텍스트 진입 시 visibilityState 가 hidden 으로 인식
- `url=` 비어 있음 : Chrome Android PWA 에서 `clients.matchAll()` 자체가 빈 배열 반환 (알려진 한계)

→ **SW 안의 모든 페이지 추적 방법이 모바일에서 안 됨.**

### 최종 해결책 — 서버측 active_room 추적 (v21)

**원리**: SW 가 페이지를 못 본다면, **서버가 본다**. 푸시 자체를 안 보냄.

**app.py 변경**
```python
# _user_connections[uid][sid] 에 active_room 필드 추가
_user_connections[uid][sid] = {
    "device": ..., "active": ..., "ts": ...,
    "active_room": None,   # ← 신규
}

def _presence_set_active_room(uid, sid, room_id):
    conn["active_room"] = int(room_id) if room_id else None
    conn["ts"] = time.time()

def _user_is_viewing_room(uid, room_id):
    """uid 의 어떤 소켓이든 room_id 를 active_room 으로 가지고 있고
    최근(_PC_ACTIVE_STALE_SEC) 이내면 True → 푸시 스킵."""
    for info in _user_connections.get(uid, {}).values():
        if info.get("active_room") != room_id: continue
        if time.time() - info.get("ts", 0) > 30: continue
        return True
    return False

# push_message_to_room_members 안에서
target_room_id = int(tag.replace("room_", ""))
for m in members:
    uid = m["user_id"]
    if _user_has_active_session(uid): continue       # PC 활성
    if _user_is_viewing_room(uid, target_room_id): continue  # ← 추가: 그 방을 보고 있음
    send_push_to_user(uid, ...)
```

**Socket 이벤트 신규**
```python
@socketio.on("set_active_room")
def on_set_active_room(data):
    uid = session.get("user_id")
    rid = data.get("room_id")
    _presence_set_active_room(uid, request.sid, rid)
```

**클라이언트 (app.js)**
```javascript
function _notifySWActiveRoom(roomId) {
    // (A) SW 에 알림 (PC 용, fallback)
    reg.active.postMessage({type: "set_active_room", roomId});
    // (B) 서버에 알림 (모바일 핵심)
    socket.emit("set_active_room", { room_id: roomId });
}
// openRoom 끝에서 호출
// socket reconnect 시 재발사
```

### 효과 확정 (진단 결과)

테스트 시나리오: 휴대폰·태블릿이 방 10 진입 → 10초 대기 → PC 가 방 10 에 메시지

```json

  {"uid": 36, "action": "skip", "reason": "viewing_room"},  ← 태블릿 ✅
  {"uid": 39, "action": "skip", "reason": "viewing_room"}   ← 휴대폰 ✅

```

→ **두 기기 모두 푸시가 발사되지 않음** → OS 알림 안 뜸 → 사용자 의도와 일치.

### SW v21 → v22 정리
- v18~v20 의 SW 측 차단(activeRoomId / 하트비트 / URL) 은 그대로 유지 (이중 안전망)
- 알림 body 진단 prefix 는 v21 에서 제거
- v22 는 진단 endpoint·로깅 모두 제거한 안정 버전
