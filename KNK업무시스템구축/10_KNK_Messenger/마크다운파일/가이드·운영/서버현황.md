## ⚙️ 서비스 구성 (Supervisor)

| 서비스명 | 역할 | 포트 |
|---|---|---|
| `knk-messenger` | Python Flask + Gunicorn (WSGI) | 5050 (내부) |
| `knk-nginx` | 리버스 프록시 + HTTPS 종단 | 80 / 443 |
| `cron` | 정기 작업 (백업·푸시 정리 등) | — |

### 서비스 관리 명령 (NAS SSH 내부)
```bash
# 상태 보기
supervisorctl status

# 메신저 재시작 (코드 배포 시)
supervisorctl restart knk-messenger

# 로그 보기
tail -f /opt/knk_messenger/logs/gunicorn.log
tail -f /opt/knk_messenger/logs/gunicorn.err.log
```

### 자동화된 배포 (로컬 → NAS)
```powershell
# 로컬 (Windows) 에서 코드 수정 후 1줄 실행:
.\deploy\sync_to_synology.ps1
```
→ 파일 자동 동기화 + supervisorctl restart + /healthz 확인까지 자동.

## 🚨 장애 대응

### 응답 없음 / 헬스 체크 실패
```bash
# 1) 서비스 상태 확인
supervisorctl status

# 2) 메신저만 재시작
supervisorctl restart knk-messenger

# 3) nginx 까지 재시작 (HTTPS 끊김 시)
supervisorctl restart knk-nginx

# 4) supervisord 자체가 죽었을 때 (드물지만)
/etc/init.d/supervisor restart
```

### 헬스 체크 URL
```
https://haist.knknara.co.kr/msg/healthz   (외부)
http://127.0.0.1:5050/healthz             (내부, NAS 안에서)
```
정상 응답: HTTP 200 + JSON `{"ok": true, ...}`

### 로컬 진단 (서버 변경 없이 상태만 확인)
```powershell
.\deploy\sync_to_synology.ps1 -Diag
```
