# 사내 메신저 이용·보안 동의서 — 진행 가이드

> **이 문서 용도**: 동의서(이용·보안준수 확인서)를 **나중에 전 직원에게 정식 적용**할 때, 이 문서 하나로 그대로 진행한다.
> **현재 상태(2026-06-03 기준): 일시 중지 (아무에게도 안 뜸). 기능·문서·로직은 전부 완성되어 보존됨.**
> 대표 지시: *"이제 이 동의 문서 그만 띄워. 결정나면 내가 다시 지시할게."*

---

## 1. 지금 상태 한눈에

| 항목 | 상태 |
|---|---|
| 동의서 본문 | ✅ 완성 (v4, 14개 항목 / 한국어 + 베트남어) |
| 팝업·동의 처리 기능 | ✅ 완성·배포됨 (NAS 라이브) |
| 동의 기록(감사추적) | ✅ DB 테이블·기록 로직 완성 |
| **현재 노출 여부** | ⏸ **꺼짐** — 테스트 대상이 비어 있어 **아무에게도 안 뜸** |
| 정식 전 직원 배포 | ⛔ **아직 안 함** (법률검토 후 대표 결정 대기) |

**왜 지금은 안 뜨나?**
지금은 "테스트 모드"이고, 테스트 대상 명단(`CONSENT_TEST_USERNAMES`)을 **비워뒀습니다(`[]`)**.
원래 테스트 대상은 대표님(사번 5) 한 분뿐이었으므로, 비우면 **완전히 멈춥니다.**

---

## 2. 동의서가 어떻게 작동하나 (쉬운 설명)

- **언제 뜨나**: 직원이 로그인했을 때, 동의가 필요하면 **전체 화면을 막는 팝업**으로 동의서를 보여줌.
- **끝까지 읽어야 함**: 스크롤을 끝까지 내려야 **[동의합니다]** 버튼이 켜짐.
- **동의 안 하면**: **[동의하지 않음] = 로그아웃**. (동의해야 메신저 사용 가능)
- **언어**: 사용자 화면 언어가 베트남어면 베트남어, 그 외는 한국어로 표시.
- **고객사(외부 게스트)는 제외** — 동의서 안 뜸.
- **다시 묻는 주기**: 정식 모드에서는 **첫 로그인 + 약 100일마다** 재동의.
- **내용을 바꾸면**: 버전 번호(`CONSENT_VERSION`)를 올리면 **전 직원이 다시 동의**하게 됨.
- **기록**: 누가·언제·어떤 버전에·어느 IP/기기에서 동의했는지 DB에 남음(감사추적용).

### 두 가지 모드
| 모드 | 누구에게 | 빈도 | 용도 |
|---|---|---|---|
| **테스트 모드** (`CONSENT_TEST_MODE = True`) | 명단(`CONSENT_TEST_USERNAMES`)에 든 사번만 | **매번** (동의 기록 무시) | 화면·문구 반복 점검 |
| **정식 모드** (`CONSENT_TEST_MODE = False`) | **전 직원** (게스트 제외) | 첫 로그인 + 100일 주기 | 실제 운영 |

> 지금은 **테스트 모드 + 명단 비움** → 그래서 아무에게도 안 뜸.

## 3. 다시 켜는 법 (정확히 이 한 줄)

> ⚠️ 아래는 **법률검토(4장)를 끝낸 뒤** 진행 권장. 변경 후에는 배포(`deploy\sync_to_synology.ps1`) 필요.

**파일: `consent_doc.py`**

### (A) 나/일부 인원에게만 다시 테스트로 띄우기
```python
CONSENT_TEST_MODE = True
CONSENT_TEST_USERNAMES = ["5"]     # 띄울 사번(로그인 ID) 추가. 예: ["5", "1023"]
```

### (B) 전 직원에게 정식으로 띄우기
```python
CONSENT_TEST_MODE = False           # 이 한 줄이면 전 직원 + 100일 주기 정식 적용
# CONSENT_TEST_USERNAMES 는 정식 모드에서 무시되므로 그대로 둬도 됨
```

변경 → `deploy\sync_to_synology.ps1` 실행(빅터가 자동 처리) → 직원들이 새로고침/재로그인하면 적용.

## 4. 전 직원 정식 배포 전 — 반드시 챙길 것 (법률·노무 체크리스트)

> 동의서 본문(`consent_doc.py`)에도 *"전 직원 배포 전 노무사·변호사 검토 권장"* 메모가 있습니다.
> **강제동의(동의 안 하면 사용 제한) 구조라 검토가 특히 중요합니다.**

- [ ] **노무사 검토** — 강제동의 구조의 적법성, **취업규칙**과의 연계(편입·불이익 변경 절차), 근로자 동의 방식.
- [ ] **변호사(개인정보·노동) 검토** — 아래 법령 적합성:
  - [ ] **개인정보보호법** — 수집·이용 동의 형식, 위탁·**국외이전** 고지(외부 AI·서버 호스팅), 보유기간(3년/5년) 근거.
  - [ ] **통신비밀보호법** — 1:1 대화방 열람 예외 조항, 업무자료 확인 범위의 적법성.
  - [ ] **근로기준법 / 취업규칙** — 모니터링·기록 관리의 고지·동의 요건.
- [ ] **베트남 법인(KNKVINA) 적용 검토** — 베트남 **개인정보보호법(Nghị định 13/2023/NĐ-CP)** 적합성, 베트남어 번역의 법률 용어 정확성, 현지 노동법상 동의 방식.
- [ ] **문의처·권리행사 창구 확정** — (주)케이엔케이 관리팀 / KNKVINA 관리팀 (현재 문서 기재값 검증).
- [ ] **거부 시 실제 운영 정책 확정** — 동의 거부자에 대한 업무상 제한 범위(법적 리스크 검토).
- [ ] 검토 결과로 **문구 수정 시 → `CONSENT_VERSION` 올림**(5장).

## 5. 정식 배포 절차 (단계별)

1. **4장 법률검토 완료** + 수정 의견 반영.
2. 문구 수정했으면 `consent_doc.py`의 `CONSENT_VERSION` 을 올림(예: 4 → 5). → 기존 동의자도 새 버전 재동의.
3. **테스트로 먼저 확인** (3장 A) — 대표/소수 사번에 띄워 화면·번역·스크롤·동의 흐름 점검.
4. 이상 없으면 **정식 전환** (3장 B): `CONSENT_TEST_MODE = False`.
5. 빅터가 배포(`sync_to_synology.ps1`) + GitHub 백업.
6. **사전 공지** — 동의서가 뜬다는 안내(본사·베트남), 거부 시 영향, 문의처.
7. 배포 후 **동의 현황 모니터링** (DB `consent_agreements` — 6장).

## 6. 구성 요소 — 코드 어디에 뭐가 있나 (개발용 메모)

| 파일 | 역할 |
|---|---|
| `consent_doc.py` | **동의서 본문(ko/vi)** · `CONSENT_VERSION` · `CONSENT_TEST_MODE` · `CONSENT_TEST_USERNAMES` |
| `app.py` | 게이트 로직 + API + 테이블. (아래 상세) |
| `static/js/app.js` | 로그인 후 `/api/me/consent` 조회 → 필요 시 팝업 표시 · 스크롤 끝 감지 · [동의/거부] 처리 |
| `templates/chat.html` | 동의 팝업 HTML (`.consent-gate` > `.consent-card`, 제목 `#consentTitle`) |
| `static/css/style.css` | `.consent-*` 스타일 (제목 `.consent-head h2` — 2026-06-03 `word-break:keep-all` 적용해 한국어 단어 단위 줄바꿈) |

**`app.py` 상세**
- `CONSENT_INTERVAL_DAYS = 100` — 재동의 주기(일).
- `consent_agreements` 테이블 — `user_id, version, agreed_at, ip, user_agent` (감사추적).
- `_consent_needed(db, user_id)` — 현재 버전 동의 없거나 100일 경과 시 True.
- `GET /api/me/consent` — 동의 필요 여부 + 본문(사용자 언어). 테스트 모드면 명단 기준, 정식이면 `_consent_needed`. 게스트는 항상 False.
- `POST /api/me/consent` — 동의 기록(시각·IP·UA). 게스트 차단.

**배포 포함 여부**: `deploy\sync_to_synology.ps1` 의 `$Items` 에 `consent_doc.py` 포함됨 ✅ (백엔드 변경도 배포됨).
