## 0. 한 줄 요약
지금 메신저(웹/PWA)는 그대로 두고, **PC용 "전용 창 껍데기(.exe)"** 를 씌우는 안.
내용·기능·서버·업데이트는 **지금과 동일**(서버 배포 = 자동 반영), **창과 PC 동작만** 외부 메신저 PC앱처럼 만듦.
**앱스토어·Mac 불필요.**

## 1. 이 문서 vs 휴대폰 앱 — 혼동 방지 (제일 중요)

| 구분 | 휴대폰 앱 (기존 검토) | **PC 데스크탑 앱 (본 건)** |
|---|---|---|
| 대상 | 아이폰 · 안드로이드 | **윈도우 PC** |
| 기술 | Capacitor | **Electron** |
| 목적 | 푸시 알림 신뢰성 + 앱 설치 | **슬림 창 + 트레이 상주 + PC 백그라운드 알림** |
| 앱스토어 | Play/App Store 등록 필요 | **불필요 (직접 설치)** |
| Mac | iOS 빌드용 필요 | **불필요** |
| 문서 | `앱_제작_준비.md` | 본 문서 |

> 둘은 **같은 NAS 서버를 쓰는 별개의 껍데기**. 하나만 해도, 둘 다 해도 됨.
> 대표님이 걱정하신 "플레이스토어·아이폰"은 **휴대폰 앱** 쪽 얘기 — **PC 앱은 그 부담 전혀 없음.**

## 2. 기본 장점 (왜 PC 앱인가)

- ⭐ **트레이 상주 + 백그라운드 알림** — 창 닫아도(트레이로) 알림 계속 옴 (지금 PWA는 닫으면 약함)
- ⭐ **부팅 시 자동 실행** — PC 켜면 알아서 대기
- ⭐ **작업표시줄 안 읽은 수 배지 · 깜빡임**
- **창 자유** — 슬림하게 / "항상 위에" 고정 / 위치·크기 기억  ← 이번 요청의 출발점
- **"진짜 프로그램" 느낌** — 브라우저 탭 아닌 독립 앱 → 직원 신뢰·채택률 ↑
- **보안 통제** — 주소창 없음 · 우리 도메인 밖 이동 차단 · 개발자도구 차단

> 메신저 정의서 1순위 = "외부 메신저 대신 이걸로(채택률)". 위 항목이 그 격차를 메움.

## 3. 확장 가능 기능 (알림·자동시작 외) — 업무 허브 관점 가치순

**⭐ 업무에 바로 도움**
1. **화면 영역 캡처 → 바로 전송** — 화면 일부를 드래그로 잘라 주석 달고 방에 즉시 전송 (브라우저론 어려움)
2. **자리비움 자동 감지** — 키보드·마우스 멈춤/PC 잠금 시 → 상태 자동 "자리비움" (업무 추적과 직결)
3. **알림에서 바로 답장** — 알림창에서 앱 안 열고 바로 답장
4. **딥링크(knkmsg://)** — WORKS·메일 링크 클릭 → 데스크탑 앱이 **그 방/메시지를 바로 엶** (관문 연결 강화)
5. **WORKS 알림 통합** — 결재·할 일 알림도 **같은 트레이로** (※ WORKS 쪽 연동 작업 필요)

**편의**
6. 글로벌 단축키 + 빠른 입력창 (어디서나 빠른 메시지)
7. 항상 위 고정 / 화면 가장자리 도킹
8. 드래그앤드롭 + 우클릭 "메신저로 보내기"
9. 여러 방 동시 창

**관리·보안**
10. 도메인 잠금 · 기기 등록형 자동 로그인 · 원격 설정/강제 업데이트(전 PC 일괄)

**참고 (가능하나 신중)**
- 복사·캡처 제한(DLP): 가능하나 복잡 — 보통 과함
- PC 켜짐 = 출근 연동: 프라이버시 민감 — 권장 안 함

> 한 번에 다 안 함. **기본 껍데기(알림·트레이·창) 먼저 → 수요 따라 하나씩** 추가.

## 4. 접속 방식 — 다 같이 씀 (한 서버, 여러 문)

| 사용자 | 권장 | 이유 |
|---|---|---|
| **우리 직원 (PC)** | .exe 데스크탑 앱 *(또는 브라우저)* | 트레이·슬림창·백그라운드 알림 |
| **우리 직원 (폰)** | 휴대폰 앱 *(또는 브라우저)* | 진짜 푸시 |
| **고객 / 외부 게스트** | **브라우저 링크 (설치 X)** ✅ | **가볍게** — 기존 게스트 초대 그대로 |

- 브라우저·PWA·.exe·폰앱 **전부 같은 NAS 서버** → 같은 계정·데이터·실시간 동기화. **섞어 써도 됨.**
- **.exe는 "추가 옵션"**. 지금 브라우저/PWA는 **그대로** 작동 (아무것도 안 없어짐).
- **고객·외부는 브라우저** — 설치 요구 안 함. 정의서 **"고객사는 가볍게"** 원칙과 일치. (2026-06-03 대표 방침)

## 5. 필요한 것

**A. 기술**
- Electron 프로젝트 1개 (얇은 껍데기 — 메신저 URL 로드)
- 창 설정: 최소폭·트레이·자동시작·배지·항상위 + 도메인 고정
- 빌드: electron-builder (설치본/무설치 .exe)
- (선택) 앱 자체 자동 업데이트: electron-updater + NAS/GitHub Releases

**B. 서명 (배포 신뢰)**
- 코드 서명 인증서(OV) — 연 단위. 안 하면 "확인되지 않은 게시자" 경고 + 백신 오탐 가능 → **서명 권장**

**C. 배포·운영**
- 설치 파일 받을 곳(NAS 다운로드 / 사내 공유) + 설치 안내 1장
- 내용 업데이트: **기존 그대로** (서버 배포 = 자동)
- 폴더 분리: `10_KNK_Messenger_PCApp/` 새 폴더 (기존 메신저 코드 안 건드림)

## 8. 위험요소 / 주의

- 서명 없으면 SmartScreen 경고·백신 오탐 → **서명으로 해결**
- 인증서 발급 절차·시간 (최근 하드웨어 토큰 요구로 다소 까다로워짐)
- 신규 앱 초기, 백신 평판 전 드문 오탐 → 서명 + 시간이 해결
- **최초 1회** 직원 PC 설치 필요 (이후 내용 업데이트는 자동)
- Mac을 **PC로 쓰는** 직원이 있으면 macOS용 별도 빌드·서명(애플 개발자 $99/년) — 윈도우만이면 무관

## 9. 유의사항 (대표 참고 — 결정 시 고려)

1. **순서** — 휴대폰 앱(알림 신뢰성)·HTTPS·메신저 안정화가 더 본질·토대. **그 위에 PC앱**. → 권장 순서: ① 안정화·HTTPS → ② 휴대폰 앱(푸시) → ③ PC앱.
2. **진짜 수요 검증** — PC 슬림창은 대표 1인 요청에서 출발. **시제품 먼저 → 몇 명 써보게 → 반응 보고 확대.**
3. **1인(빅터) 운영 부담** — 껍데기 늘수록(웹·PWA·PC·폰) 관리 면 증가 → **단계적**.
4. **인증서 갱신** — 코드서명·SSL 매년 갱신 필요(만료 시 경고·접속 문제). **담당·갱신 알림** 지정. ⚠️ *2026-06-03 화면에 "…증 만료…갱신…" 빨간 알림 포착 — SSL 인증서 만료면 PC앱보다 시급, 우선 확인 요망.*
5. **되돌리기 쉬움** — .exe 안 맞으면 **배포만 멈추면 전원 브라우저 복귀**, 데이터 손실·잠김 0. **낮은 위험.**
6. **판단 기준 = 채택률** — 정의서 1순위. PC앱이 채택률을 올리는지로 판단. 더 큰 지렛대(쉬움·모바일 푸시·온보딩) 가리지 않게.

## 10. 결론 / 권고

- "좁게" 하나만이면 → 지금 PWA로 충분, 굳이 안 가도 됨.
- **트레이 상주·백그라운드 알림·자동시작·업무 허브 확장기능**까지 보면 → **채택률 관점 가치 큼.**
- 비용은 사실상 **서명 인증서 연 10~50만원 + 초기 ~1주** (서버·스토어·Mac 추가 없음).
- 진행 권고: **① 안정화·HTTPS 마무리 → ② 시제품(서명 없이 사내 테스트)으로 체감·수요 확인 → ③ 좋으면 서명·정식배포.**
