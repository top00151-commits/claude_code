# KNK 메신저 — 프로젝트 히스토리 & 맥락

> 새 클로드/새 담당자가 "왜 이렇게 만들었는지"를 빠르게 파악하기 위한 요약본입니다.
> 운영·배포·복구의 실무 절차는 루트의 `CLAUDE.md` 를 먼저 보세요. 이 문서는 배경·결정 이유 중심입니다.

## 1. 무엇을, 왜

㈜케이엔케이(KNK)의 **사내 전용 업무 메신저**. 외부 상용 메신저/그룹웨어 대신, 회사가 데이터를
**자체 NAS 서버에 보관**하고 업무 흐름(프로젝트방·업무요청)에 맞춘 도구를 직접 갖기 위해 자체 개발.
베트남 법인 합류를 대비해 화면 전체 **다국어(한·베·영)** 지원.

## 2. 핵심 기능

- 실시간 채팅(Socket.IO), 1:1·그룹·프로젝트방
- **업무 요청(지시) 관리** — 담당자/요청자/방장·PM 역할별 권한, 상태(진행중·보류·완료), 완료 시 메시지 필수
- 귓속말(특정인에게만 보이는 메시지), 멘션, 파일·사진 공유, 갤러리
- **프로젝트 대시보드** — 고객사·코드·납기·열린 요청 한눈에
- 출근/퇴근·회의중·외근 등 상태 표시 (회사망 접속 자동 감지 → 자동 출근 전환)
- AI 자동번역(한·영·베), 푸시 알림, PWA(설치형 웹앱)
- 사용자 관리(엑셀 일괄 등록, 한글+영문 이름·직급·부서), 최고관리자/관리자 권한 체계

## 3. 권한 체계 (중요)

- **최고관리자(소유자)** = `top0015@knknara.co.kr` (`app.py` `OWNER_USERNAME`). 부팅 시 자동 `ceo`·활성 보장,
  강등·비활성·삭제 차단(보호), 모든 채널 자동 소속, **다른 관리자 임명·해임은 이 계정만** 가능.
- **관리자(role=`ceo`)** — 사용자 관리·설정 등 가능하나 관리자 임명/해임은 불가.
- 채널 생성 권한: 관리자 또는 직급이 대표/임원/팀장/법인장.

## 4. 운영 아키텍처 & 과거 장애 (반드시 인지)

- 프로덕션: 사내 **Synology NAS** 도커 컨테이너. 안에서 **supervisord** 가 nginx + cron + gunicorn(eventlet, single worker, 5050) 관리.
- ⚠️ **컨테이너 PID 1 = bash** (supervisord 아님). → supervisord 데몬이 죽으면 아무도 안 살려서 **영구 502 다운**.
  - 실제로 한 번 발생함(배포 중). 메모리·디스크·OOM 문제 아니었고 순수 구조적 결함.
  - 조치 완료: ① 배포 스크립트가 supervisorctl 무응답 시 supervisord 자체를 재기동하는 분기 추가 ② nginx autostart=true.
  - 남은 근본 대비: 외부 워치독 `deploy/nas_watchdog.sh` 를 DSM 작업 스케줄러에 등록 (전산 담당자 작업, `deploy/전산담당자_메신저_안정화_작업서.pdf` 참고).
- 소스코드는 **GitHub + NAS(`/opt/knk_messenger`) 양쪽**에 존재 → 한쪽이 사라져도 복구 가능.

## 5. 다국어(i18n) 구조

- `static/js/i18n.js` 에 `I18N = {ko, vi, en}` 딕셔너리. 세 언어 **키 개수 항상 동일**해야 함(배포 전 패리티 검증).
- HTML 속성: `data-i18n` / `data-i18n-html` / `data-i18n-ph` / `data-i18n-title`.
- 서버가 사용자/법인에 따라 기본 언어 결정(`_user_ui_lang`), DB `users.ui_lang`.
- 이름·직급·부서는 DB에 영문 컬럼(`display_name_en`/`title_en`/`department_en`) 별도 — 베/영 화면에선 영문 표시(없으면 한글 폴백).
- **브라우저 자동번역 차단 필수**: `<html translate="no">` + `notranslate` meta. (안 하면 "Tiếng Việt"→"베트남사람" 오역 + 한국어로 자동복귀 버그)
- 진행 상태: 1~4단계 대부분 완료. 남은 tail = 일부 오류/관리자 경로 alert·confirm + **서버측 오류 메시지 다국어**(서버 언어 인지 구조 필요).

## 6. 개발 관례 (지켜온 규칙)

- **지시 받으면 즉시 착수 금지** → 이해한 내용 먼저 정리·보고 → 확인 후 진행 (절대준수).
- 사람 친화 한글 용어. 외부 상용 제품명 직접 거론 금지(중립 명칭).
- 배포 = 커밋 → `deploy\sync_to_synology.ps1` → `git push`. 매 변경은 독립적으로 안전하게(검증→커밋→배포→healthz 확인→push).
- 비밀값 출력 금지. 프로덕션 SSH 직접 조작은 승인 후. `reset_beta_data.py` 명시 지시 전 실행 금지.

## 7. 재해 복구 빠른 경로

1. 새 PC에 Claude Code + Git 설치 → `git clone git@github.com:top00151-commits/knk-messenger.git`
2. 폴더에서 클로드 실행 → 클로드가 `CLAUDE.md` 자동 인식
3. `& "deploy\recover_setup.ps1"` 실행 → 빠진 것 점검·안내
4. 비밀키(NAS 접속·배포키) 3~4개를 **사람이 직접** OS 환경변수로 설정 (보관함에서)
5. `& "deploy\recover_setup.ps1" -RunDiag` 로 서버 연결 확인 → 정상 배포 가능
