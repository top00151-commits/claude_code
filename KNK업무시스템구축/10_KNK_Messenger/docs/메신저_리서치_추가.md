## 0. 리서치 범위
이미 결정된 4종(스레드·PC 푸시 억제·고급 검색 필터·자동 삭제 타이머/나에게 보내기) 외, **KNK Messenger 차기 적용 후보 기능**을 발굴. KNK는 자체호스팅 메신저를 직접 구현하므로, **오픈소스(Mattermost/Rocket.Chat/Zulip) 사례를 1순위 참고**로 본다.

## 1. 후보 기능 카탈로그

### A. 읽음·존재감 UX

**A-1. 채널 단위 "Seen by" 카운터** (Mattermost·Teams형)
- 1:1은 카톡 "1" 식 읽음 표시, 채널은 "읽음 N명" 호버 시 명단. Slack은 일부러 안 함(부담), 카톡은 N명 카운트만 — KNK는 **하이브리드(1:1=즉시표시, 공개채널=요청 시 펼침)** 권장.
- 가치: 중간 | 난이도: 중
- 시나리오: 대표가 공지 채널에 "내일 9시 비상회의" 게시 → 임원 7명 중 5명만 읽음 표시 → 미확인 2명에게 메신저 자동 리마인드.

**A-2. 상태 표시(자리비움·회의 중·방해 금지) + 자동 동기화** (Slack·Teams·Mattermost)
- 캘린더 일정 연동으로 회의 중 자동 전환 + 사용자 정의 상태("HAIST WORKS 운영 중", 이모지 포함).
- 가치: **높음** | 난이도: **소**
- 시나리오: 자재구매 담당이 거래처 미팅 외출 — 상태 자동 "외근 중 14:00 복귀" → 발주 문의자가 채팅 대신 메일로 우회.

---

### B. 메시지 핸들링

**B-1. 핀(고정) 메시지 + 채널 사이드바** (Mattermost·Telegram·Slack 공통)
- 채널당 N개 고정. KNK는 **"오늘의 공지" 1개 + 영구 핀 무제한** 분리 권장.
- 가치: **높음** | 난이도: **소**
- 시나리오: 운영팀 채널 상단에 "안전점검 체크리스트 PDF"와 "당직 휴대전화 번호" 영구 핀 → 신규 입사자가 별도 안내 없이 자가 학습.

**B-2. 메시지 편집·삭제 정책 + 편집 흔적 표시** (Zulip·Mattermost·Telegram)
- Zulip은 편집 이력 전체 보존 가능, Slack은 "(edited)" 표시만. KNK는 **공개 채널=24시간 내 편집 허용+이력 보존, 1:1=무제한 편집+이력 미보존** 권장.
- 가치: 중간 | 난이도: 중
- 시나리오: 발주서 가격을 채널에 잘못 게시 → 30분 후 수정 → 감사팀이 "원본 → 수정" 이력 확인 가능 → 분쟁 차단.

**B-3. 인용 답장(Quote Reply) + 전달(Forward) with 출처 보존** (Telegram 표준)
- 단순 복붙이 아니라 **원본 메시지 ID·작성자·작성시각 메타데이터를 보존**한 채 다른 채널·DM으로 전달. Telegram의 결정적 강점.
- 가치: **높음** | 난이도: 중
- 시나리오: 현장 작업자가 "장비 X 누유 발견" 사진 보고 → 정비팀장이 임원 채널로 forward → 출처·시각·작성자 자동 보존되어 별도 캡션 불필요.

**B-4. 저장된 메시지(Saved Messages) "나에게 보내기" 확장** (Telegram형)
- 이미 결정된 "1인방"을 **태그·"채팅별 보기" 모드·핀**으로 확장. Telegram Saved Messages 2.0 사양 차용.
- 가치: **높음** | 난이도: **소**
- 시나리오: 대표가 외근 중 영수증 사진을 1인방에 #경비 태그로 저장 → 복귀 후 회계팀에 일괄 forward.

### C. 협업 가속기

**C-1. 이모지 리액션 + 워크플로 트리거** (Slack 결정판)
- 단순 감정 표현 넘어, **특정 이모지 → 자동화 트리거**. 예: 메시지에 ✅ 리액션 → 자동으로 "완료" 채널로 이동 + 작성자에게 DM.
- 가치: **매우 높음** | 난이도: 중
- 시나리오: 발주 요청에 부장이 👍 리액션 → 자동으로 ERP 발주 승인 API 호출 + 요청자에게 "승인 완료" 알림.

**C-2. 멘션함(Mentions Inbox) + 미읽 점프** (Zulip·Slack)
- @멘션·@channel·키워드 알림을 **별도 인박스**로 집계. 다중 채널에서 누락 방지.
- 가치: **높음** | 난이도: **소**
- 시나리오: 출근 후 멘션함 1곳만 열면 밤사이 받은 호출 12건 일괄 확인 → 채널 일일이 안 들러도 됨.

**C-3. 화상회의 허들(Huddle) — 약식 음성통화** (Slack 모델)
- 일정 잡지 않고 채널·DM에서 즉시 음성 통화. Discord Stage처럼 채널 상시 입장 가능.
- 가치: 중간 | 난이도: **대** (Jitsi/LiveKit 임베드 권장)
- 시나리오: 자재팀 채널에 "30초만요" 허들 시작 → 부장 3명 즉시 합류 → 결정 후 종료.

---

### D. AI·자동화

**D-1. AI 메시지 요약·작성 도움** (Slack AI·Teams Copilot)
- 채널 일간 요약, 긴 스레드 요약, 작성 톤 조정. Slack AI는 한국어 미지원(2025년 기준 영/스/일만) — **KNK는 한국어 우선 LLM 직접 연동(GPT-4/Claude/HyperCLOVA)으로 즉시 우위**.
- 가치: **매우 높음** | 난이도: 중
- 시나리오: 대표가 "어제 자재팀 채널 요약" 요청 → 3초 만에 결정사항·미결사항·담당자 정리 카드 출력.

**D-2. 음성 → 텍스트 자동 변환(STT) + 회의 자동 요약** (Teams Copilot 표준)
- 음성 메모·허들 녹음을 한국어 STT(Whisper/Clova) → 텍스트 + 요약.
- 가치: **높음** | 난이도: 중
- 시나리오: 현장 작업자가 음성으로 "3호기 베어링 마모, 교체 필요" 메모 → 텍스트 변환 + #정비요청 자동 태그.

**D-3. 봇·웹훅·HAIST WORKS 양방향 연동** (Mattermost·Rocket.Chat 강점)
- Incoming/Outgoing Webhook + Slash Command + Bot Account. KNK는 HAIST WORKS PO·SO·프로젝트 이벤트를 채널로 푸시 + 채널에서 슬래시 커맨드로 ERP 조작.
- 가치: **매우 높음** | 난이도: 중
- 시나리오: `/po 2026-0042` 입력 → 봇이 발주 상세 카드 출력 + 변경 시 채널 자동 알림.

### E. 외부 협업·보안

**E-1. 게스트 사용자 / 임시 초대 링크** (Discord·Mattermost·Zulip)
- 외부 거래처를 **특정 채널만, 기간 한정**으로 초대.
- 가치: **높음** | 난이도: 중
- 시나리오: 신규 시공업체에 7일 한정 "현장 사진 공유" 채널 게스트 초대 → 프로젝트 종료 시 자동 만료.

**E-2. 다국어 자동 번역** (Teams 표준·Line OpenChat·Rocket.Chat)
- 메시지 입력 즉시 수신자 언어로 자동 번역.
- 가치: 중간 | 난이도: **소** (DeepL/Google Translate API)
- 시나리오: 베트남 협력사가 베트남어로 발주 확인 → 한국 자재팀은 한국어로 자동 변환된 메시지 수신.

**E-3. Screen Security / View Once / 스크린샷 차단** (Signal)
- 견적·계약·인사 채널에서 OS 레벨 스크린샷 차단 + iOS 알림 미리보기 차단.
- 가치: 중간 | 난이도: 중 (OS API 의존, 완벽 차단 불가)

---

### F. 모바일·접근성

**F-1. 모바일 잠금화면 Quick Reply** (WhatsApp/Telegram 표준)
- 잠금화면 알림에서 직접 답장. 안드로이드 RemoteInput / iOS UNNotificationAction.
- 가치: **높음** | 난이도: **소**

**F-2. 운영 알림 위젯 / 홈 화면 미니뷰** (Telegram·WhatsApp)
- 홈 화면에 채널 최신 N개 메시지 위젯.
- 가치: 중간 | 난이도: 중

## 2. KNK 차기 우선 적용 Top 5 (이번 4종 외)

| 순위 | 기능 | 근거 |
|---|---|---|
| **1위** | **D-3. 봇·웹훅·HAIST WORKS 연동** | KNK 메신저의 존재 이유. 이게 없으면 카톡 대비 차별점 0. 이미 Flask 기반이라 구현 친화적. **선결 인프라**. |
| **2위** | **C-1. 이모지 리액션 + 워크플로 트리거** | 1위의 사용자 진입점. ✅ 하나로 ERP 승인까지 가는 UX는 카톡·텔레그램 어디도 못 함. 대표 결재 동선 단축 직접 효과. |
| **3위** | **D-1. AI 한국어 요약·작성 도움** | Slack AI 한국어 미지원이라 즉시 차별화 가능. 대표 정보 과부하 해소 = 사용량의 1차 동인. 외부 LLM API만 붙이면 됨. |
| **4위** | **A-2. 상태 표시 + 캘린더 자동 동기화** | "지금 답할 수 있는 사람" 식별은 KNK 현장-사무 혼재 환경의 본질 문제. 난이도 소·체감 효과 큼. |
| **5위** | **B-3. 인용 답장 + 출처 보존 Forward** | 현장 보고 → 임원 보고 사슬에서 출처 유실이 분쟁 원인. Telegram이 가장 잘 한 기능이며 감사 추적성에도 직결. |

**차순위(6~10위):** B-1 핀(소난이도·고가치), C-2 멘션함(과채널 환경 필수), E-1 게스트 사용자(외부 거래처 필수), F-1 Quick Reply(모바일 즉답), D-2 STT 한국어(현장 음성보고).

**제외 사유:**
- C-3 허들·화상회의 → KNK 규모상 Teams/Zoom 병용이 합리적, 자체 SFU 부담 큼
- E-3 Screen Security → 사진 촬영 우회 가능, ROI 낮음
- E-2 자동 번역 → 거래처 다국어 비중 확인 후 후속 결정

## 3. 결론
**Top 5는 모두 KNK가 자체 구현 가능한 범위**이며, HAIST WORKS 양방향 연동(1위) + 한국어 AI(3위) 두 축이 **카톡/텔레그램으로 못 하는 영역**을 직격한다. 1·2위는 1~2주 안에 PoC 가능, 3·4·5위는 각 3~5일 작업량. 1차 결정 4종과 함께 단계 1로 묶으면 KNK 메신저 v1.0의 차별화 골격이 완성된다.
