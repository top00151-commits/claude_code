# KNK Messenger — 비전과 로드맵

대표 직접 하달 (2026-05-08): **기존 메신저으로 흩어진 회사 자산을 회수하고, 기존 메신저이 못한 부분을 모두 보완한다. 그리고 HAIST WORKS 와 연결한다.**

---

## 왜 만드는가 — 기존 메신저의 4대 한계 (대표 진단)

| # | 페인포인트 | KNK 손실 |
|---|---|---|
| **1** | **대화 = 휘발** — 업무 모든 대화가 히스토리로 남지 못함 | 회사 이력·노하우·자산이 소실 |
| **2** | **전달 확인 불가** — 봤는지 안 봤는지, 이해했는지 모름 | 누락·중복·뒤늦은 사고 반복 |
| **3** | **대용량 파일 한계** — DWG 도면·동영상이 기존 메신저 한도 초과 | 이메일·웹하드 우회 → 또 흩어짐 |
| **4** | **첨부 히스토리 정리 불가** — 어느 파일이 어느 건의 어느 버전인지 모름 | "그 도면 어디 갔지?" 매일 발생 |

**기존 메신저의 강점 (반드시 유지·초월해야 함)**
- 베트남어 번역 (불완전하지만 작동) → **AI 번역으로 더 정확하게**
- 사진·동영상·문서·도면 전달 편의 → **드래그·페이스트·25MB→500MB 확장**
- 모바일 푸시 → **이미 PWA + Web Push 완비**

## 솔루션 매핑 — 페인 → 메신저 기능 → 코드

### 페인 #3. 대용량 파일 (DWG·동영상) ⭐ 즉시 해결

| 기존 메신저 한계 | KNK 메신저 |
|---|---|
| 100MB 한도, .dwg 차단 | **500MB 기본**, `KNK_MSG_MAX_UPLOAD_MB` 환경변수로 1GB+ 가능 |
| 진행률 표시 빈약 | **XHR 진행률 바**, 큰 파일 안심하고 업로드 |
| 파일 보존 보장 없음 | NAS 볼륨 + HyperBackup 영구 보관 |
| .dwg/.dxf/.step/.stp/.stl 등 차단 | 도면 형식 화이트리스트에 이미 포함 |

**구현**: `MAX_UPLOAD_MB` 환경변수화 + 프론트 진행률 + 가이드 갱신 (Phase 1 완료)

---

### 페인 #2. 전달 확인 + 미확인 추적 ⭐ 즉시 해결

| 기존 메신저 한계 | KNK 메신저 |
|---|---|
| "1" 사라지면 끝, 누가 안 봤는지 모름 | **읽음 배지 + 미확인자 이름 툴팁** (이미 구현) |
| 봤다고 액션 한 거 X | **✓ 전달확인 버튼** — "확인했습니다" 명시 |
| 중요한 메시지 묻힘 | **미확인 N시간 → 자동 푸시 재전송** + 상위자 통보 |
| 책임 불명확 | 메시지→요청 승격 시 **담당자 + 마감일 명시** (이미 구현) |

**구현**:
- `message_acks` 테이블 — 전달확인 명시 기록
- 메시지에 ✓ 버튼 + 미확인자 카운트
- (Phase 2) cron 워커로 미확인 N시간 후 푸시 재전송

---

### 페인 #4. 첨부 히스토리 ⭐ 즉시 해결

| 기존 메신저 한계 | KNK 메신저 |
|---|---|
| 같은 도면 v1·v2·v3 가 흩어져서 어느 게 최신인지 모름 | **파일 버전 체인** — 동일 파일 업로드 시 v2, v3 자동 연결 |
| 누가 다운받았는지 모름 | (Phase 2) 다운로드 로그 |
| 어느 건과 관련있는지 모름 | **아이템(고객사×모델)별 갤러리** 이미 구현 |
| 검색 안 됨 | FTS5 + 파일명 검색 이미 구현 |

**구현**:
- `attachment_versions` 테이블 — 같은 이름 파일을 부모-자식 체인으로 묶음
- 업로드 시 동일 방·동일 파일명 감지 → "v2 로 업로드?" 물어봄
- 갤러리에서 v 배지 표시 + 버전 전체 보기

### 페인 #1. 이력 자산화 ⭐ 단계적 (코어 + AI)

| 기존 메신저 한계 | KNK 메신저 |
|---|---|
| 시간 흐르면 그냥 쌓임 | **아이템 타임라인** 이미 구현 — 날짜별 이벤트 그룹 |
| 결정·합의가 안 보임 | **메시지 결정 마킹** (`kind=decision`) — 향후 추가 |
| 인수인계 시 처음부터 다시 | **AI 자동 요약** — Claude Haiku, 월 ~₩2,000 |
| 이력 검색 어려움 | FTS5 + 메타·요청·파일 통합 검색 (이미 구현) |
| 외부에 공유 어려움 | **아이템별 Excel 내보내기** (5시트, 이미 구현) |

**구현**:
- (Phase 1) 메시지 별표(★)로 중요 결정 마킹 + 별도 보기
- (Phase 2) Claude API 통합 — 아이템별 일/주 단위 자동 요약
- (Phase 3) 인수인계 보고서 자동 생성

### 베트남어 번역 (Claude Haiku) — Phase 2

| 항목 | 기존 메신저 | KNK 메신저 |
|---|---|---|

| 비용 | "무료" (사용자에게) | **월 ₩2,000~5,000** (회사 부담) |
| 단축키 | 메뉴 깊음 | 메시지 우측 🌐 1클릭 |
| 원문 / 번역 토글 | 한쪽만 표시 | **둘 다 표시 + 토글** |

## HAIST WORKS 연결 — Phase 3 (메신저 베타 정착 후)

### 통합 시나리오
1. **SSO** — WORKS 로그인 세션 → 메신저 자동 인증
2. **사용자 동기화** — WORKS 88명 마스터 → 메신저 자동 등록 (이미 시드 스크립트 작성됨)
3. **결재 알림 봇** — WORKS 결재 요청·승인·반려 이벤트 → 메신저 시스템 메시지로 푸시
4. **ERP 이벤트 봇** — 발주서 생성·납기 변경·검수 완료 이벤트 → 해당 아이템 방에 자동 시스템 메시지
5. **양방향**: 메신저에서 "결재 올리기" 버튼 → WORKS 결재함으로 직접 점프

### 통합 시 새로 가능한 시나리오
- 베트남 직원: 메신저로 "이 도면 결재 가능한가요?" → 봇이 자동으로 WORKS 결재 상태 응답
- 김 이사: 메신저에서 결재 알림 받음 → 1탭으로 WORKS 진입 → 승인 → 메신저에 자동 통보
- 신규 입사자: 아이템 방 들어가기만 하면 그동안 모든 결재·메시지·도면이 한 화면에 정리

### 빅터 권한 범위
- 메신저 (10팀) 측 코드 — 빅터 직접 수정
- WORKS (01팀) 본체 — 빅터 수정 금지, **API 호출만**. 본체 작업은 01 팀에 발주

## 운영 환경 (확정 — 2026-05-08)

```
인터넷 (베트남·한국 직원)
   ↓ HTTPS 443 (msg.knknara.co.kr)
회사 라우터 → Synology NAS DSM nginx (Reverse Proxy + Let's Encrypt SSL)
   ↓ HTTP 5050 (WebSocket)
Container Manager → Docker (ubuntu:20.04)
   ↓ gunicorn eventlet
Flask + Socket.IO + SQLite + FTS5
   ↓ 볼륨 마운트
NAS /docker/knk-messenger/data (HyperBackup 정기 보관)
```

- ✅ **사내 자산** — 회사 NAS 운영, 외부 의존 없음
- ✅ **베트남 접속** — HTTPS 도메인으로 어디서나 ~80ms
- ✅ **24/7** — NAS 자체 UPS + 컨테이너 auto-restart + HyperBackup
- ✅ **확장 가능** — 사용자 100명 무리 없음, 1000명 시 NAS 사양 업그레이드 또는 Lightsail 이전
