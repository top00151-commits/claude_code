## 3. install 스크립트 재실행 — nginx duplicate server 에러

```
nginx: [emerg] a duplicate default server for 0.0.0.0:8080
  in /etc/nginx/sites-enabled/knk-messenger.bak.20260528_182352:10
```

**원인 (치명적)**: 스크립트가 nginx 백업 파일을 `sites-enabled/` 안에 만들었는데, nginx 는 이 디렉터리의 **모든 파일** 을 설정으로 읽음. 백업이 두 번째 설정으로 인식되어 default_server 충돌.

**조치 1**: 백업을 `/root/nginx-backups/` 로 분리.
**조치 2**: `sub_filter_types` 에서 `text/html` 제거 (nginx 기본값이라 중복 경고).

```
commit e1a6f83 — fix(deploy): nginx 백업을 sites-enabled 밖으로 이동 + text/html 중복 제거
```

NAS 측 수동 수습:
```bash
mkdir -p /root/nginx-backups
mv /etc/nginx/sites-enabled/knk-messenger.bak.* /root/nginx-backups/
```

## 10. 전산담당자(최보현 상무) 협업 — 진짜 구조 발견

### 10.1 상무님 확인: DSM Reverse Proxy 현황

| 설명 | 소스 | 대상 |
|---|---|---|
| `HAIST.HTTP` | `http://haist.knknara.co.kr:80` | `http://localhost:5050` |
| `HAIST.HTTPS` | `https://haist.knknara.co.kr:443` | `http://localhost:5050` |

→ **`/msg/` 는 DSM에 별도 등록 없음**. 도메인 전체가 `localhost:5050` (메신저 gunicorn) 으로 직행. `/msg/` prefix 는 **메신저 Flask 앱 내부 라우트가 직접 처리** 중.

### 10.2 DSM Reverse Proxy 한계

- 소스에 `path` 입력 불가 (`haist.knknara.co.kr/works` 입력 시 에러)
- **호스트명 + 포트** 단위만 지원

### 10.3 상무님 의견

> "지금 DSM 에 web Server 를 쓰는게 아니라, HAIST 컨테이너의 Web Server 를 쓰는건데 자꾸 DSM 세팅을 바꾸라고 하는 것 같음"

→ **빅터가 메신저 구조를 오해**한 것. 컨테이너 안 nginx에 `/works/` location 추가했지만, **외부 traffic이 nginx 안 거치고 gunicorn 직행**이라 무용지물.
