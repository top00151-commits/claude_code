## 2. 원인 — 이음 `static/js/app.js` 두 곳

### ① 윗줄 「🔴 회의 중」 — `_mtgHeadState` (3164~3172행 부근)

```js
if (st === "started" && !(endMs && now >= endMs + _MTG_STUCK_MS)) return "live";   // 3169행
```

- 주석의 뜻(대표 결정): **「녹음이 켜져 있으면」** 끝 시각이 지나도 「회의 중」 · 12시간 지나면 잊힌 녹음으로 보고 종료.
- 그런데 코드는 **`stage === "started"`** 로 판정한다.
- WORKS 의 `stage = "started"` 는 **두 경우**를 다 포함한다(`_meeting_msg_stage`):
  1. 녹음 중(`rec_state == 'recording'`) ← 원래 의도
  2. **「▶ 회의 시작」만 누르고 녹음은 없는 회의**(녹음·정리가 아무것도 없으면 기본값 `started`) ← 이번 경우
- 그래서 **녹음이 없는데도 끝 시각 + 12시간 동안 「🔴 회의 중」**. 이 회의는 12:00 끝 → **자정까지** 「회의 중」으로 보인다.

### ② 아래 줄 「🔴 회의 진행 중 · … · 녹음 안 됨」 — (3247~3260행 부근)

```js
} else if (st === "started") {        // 3247행
  ...
  txt = ... "🔴 회의 진행 중 · {name} · 녹음 안 됨" ...   // 3258행
```

- **시간을 전혀 안 본다** → 녹음 없이 시작만 된 회의는 **며칠이 지나도 아래 줄이 「회의 진행 중」**.
  (9/17·9/18 회의 카드도 지금 윗줄은 12시간이 지나 「✅ 회의 종료」로 바뀌었겠지만, **아래 줄은 여전히 「진행 중」**일 것)

## 3. 수정안 (이음 화면만 · 서버·WORKS 변경 없음)

WORKS 는 이미 `recording`(z1114)을 준다. 그 칸을 쓰면 된다.

**① 윗줄** — 「녹음 중일 때만」 끝 시각을 넘겨 「회의 중」:

```js
if (st === "started" && c.it.recording !== false && !(endMs && now >= endMs + _MTG_STUCK_MS)) return "live";
```

- `recording === false`(녹음 없음) → 이 줄을 건너뛰어 **끝 시각이 지나면 「✅ 회의 종료」**.
- `recording` 칸이 없는 옛 WORKS 응답은 `!== false` 라 **예전 동작 그대로**.

**② 아래 줄** — 끝 시각이 지났고 녹음이 없으면 「진행 중」이라 하지 않기. 예:

- 끝 전: `🔴 회의 진행 중 · {name} · 녹음 안 됨` (지금 그대로)
- **끝 뒤: `⏹ 회의 끝남 · {name} · 녹음 없음`** (새 글 · 4개 언어)
- 버튼 「📋 회의록 열기」는 그대로 둬도 된다(나중에 음성 파일을 올릴 수 있으니).
- 끝 시각은 카드가 이미 가진 `data-mtg-end`(`end_ms`)를 쓰면 된다.

**점검 권장**: 방을 연 채로 끝 시각을 넘길 때 `_mtgHeadRefresh` 가 윗줄뿐 아니라 **아래 줄도** 다시 그리는지.

## 4. WORKS 쪽 — 바꿀 것 없음 (확인 사항)

- `msg/status` 의 `recording`·`rec_secs` 는 운영에서 정상(회의 40 → `recording: false`).
- **z1118(안드로이드 녹음기 기본)과 무관**: 이번 회의는 `?autorec=1` 착지 자체가 없었다(z1118 이 바꾼 곳은 그 착지 화면).
- 「녹음 안 됨」 자체의 이유: 「▶ 회의 시작」 뒤 **누른 분의 WORKS 창이 WORKS 까지 오지 않았다**(접속 기록에 autorec 착지 없음). 창이 막혔는지(팝업·앱 고르기 창 등)는 WORKS 기록으로는 알 수 없다 — 기기 정보가 없음.
