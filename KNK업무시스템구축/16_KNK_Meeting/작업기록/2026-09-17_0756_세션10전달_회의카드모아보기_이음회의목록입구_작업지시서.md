## 1. 무엇에 쓰나 (대표 결정 포함)

- WORKS 「회의록」 화면 위 탭 2개: 「📝 회의록」(기존 목록) | **「🗓 회의 카드 모아보기」**(신규).
- 카드 1장 = 이음 🗓 목록 카드와 같은 정보: 상태(예정·회의 중·회의 종료) · 일시(시작~끝, 한국/베트남) · 진행 시간 · 장소 · 등록 담당 · 참석자 · 외부 참석자 · (등록 담당이면) 응답 현황 · (참석자면) 내 응답 · 회의록 단계와 버튼.
- 묶음: 지금 회의 중 → 진행할 회의 → 진행한 회의(최근 60일, 「지난 회의 더 보기」로 60일씩).
- **대표 결정 ① 보기 전용** — 참석 응답·수정·삭제·「▶ 회의 시작」은 지금처럼 이음 회의 카드에서.
- **대표 결정 ② 보이는 회의 = 이음 🗓 회의와 똑같이** — 판단은 **이음 한 곳**(`api_meetings_list` 규칙).
  WORKS 는 공개범위 규칙을 흉내내지 않는다. (남이 만든 비공개 회의는 대표 계정에도 안 보임 — 이음과 같음)
- 회의록 단계·「📋 회의록 보기」 버튼은 **WORKS 가 붙인다**(기존 `msg/status` 와 같은 판단·같은 착지) → 이음은 회의록을 몰라도 된다.

## 2. 입구 계약 — WORKS 쪽 코드가 이 모양으로 이미 만들어져 가짜 입구로 시험 중

### 2-1. 요청

```
POST /api/works/meetings
X-SSO-Service-Key: <공유키>          ← 기존 _sso_service_key_ok() 그대로 (키 없음·불일치 → 403)
Content-Type: application/json

{"employee_no": "KNK0001", "from": "2026-07-19", "to": "2027-09-18"}
```

- `from`·`to` = 회의 **시작 날짜** 범위(양 끝 포함). 비교 대상은 `substr(start_at,1,10)` — 저장된 그 회의 현지 날짜 그대로.
- 형식은 `YYYY-MM-DD`. 형식이 틀리거나, `to < from`, 또는 기간이 **450일 초과** → `400 {"ok": false, "error": "range_invalid"}`
  (WORKS 는 보내기 전에 같은 검사를 하므로 평소엔 안 생김)
- WORKS 가 보내는 기간: 처음 = 오늘-60일 ~ 오늘+366일 / 「더 보기」 = 그 앞 60일씩.

### 2-2. 보는 사람 찾기

- 사번 = `users.employee_no` 또는 로그인ID `users.username` — **둘 다 대소문자 무시** (`/api/works/notify` 와 같은 기준 + VN 사번 대문자 규칙).
- 아래를 모두 만족하는 사람이 **정확히 1명**일 때만 보는 사람으로 인정:
  `active=1` · 게스트 아님(`_is_guest`) · 봇 아님(`username` 이 `zz_` 로 시작하지 않음)
- 아니면 → `404 {"ok": false, "error": "viewer_not_found"}`
  🔴 **`viewer_not_found` 글자 그대로** — WORKS 는 이 값으로 "입구가 아직 없음(그냥 404)"과 "직원을 못 찾음"을 구별해 안내한다.

### 2-3. 보이는 회의 = `api_meetings_list` 와 같은 조건 + 기간

```sql
SELECT DISTINCT m.* FROM meetings m
LEFT JOIN meeting_attendees ma ON ma.meeting_id = m.id
WHERE (m.created_by = :me OR ma.user_id = :me OR m.visibility = 'all' OR m.visibility = :my_scope)
  AND substr(m.start_at, 1, 10) BETWEEN :from AND :to
ORDER BY m.start_at DESC
LIMIT 301                      -- 301번째가 있으면 truncated=true, 돌려주는 것은 300건까지
```

- `:my_scope` = `"vn" if _mtg_is_vn_user(viewer) else "hq"` (목록과 같은 함수 — viewer 행에 `entity`·`department` 가 있어야 함)
- 지운 회의는 행이 없으니 안 나온다(🗓 목록과 같음).
- 🔴 **🗓 목록 규칙을 나중에 바꾸면 이 입구도 함께** — 두 곳이 어긋나면 WORKS 탭과 이음 🗓 이 다른 회의를 보여준다.
  가능하면 WHERE 조건을 **한 함수로 묶어 두 곳이 같이 쓰기**를 권합니다(검사기로 대조해도 됨).

### 2-4. 응답 200

```json
{
  "ok": true,
  "truncated": false,
  "items": [
    {
      "id": 123,
      "title": "삼성전기_FPGA 관련 설비 TEST 결과 관련 미팅",
      "start_at": "2026-09-16T15:00",
      "tz_offset": 9,
      "tz_label": "한국",
      "duration_min": 60,
      "location": "2층 회의실2",
      "visibility": "all",
      "organizer": {"name": "배승진 프로"},
      "attendees": [
        {"name": "김동후", "response": null, "is_organizer": false},
        {"name": "배승진", "response": "attending", "is_organizer": true}
      ],
      "externals": ["고객사 담당"],
      "me": {"is_organizer": false, "is_attendee": true, "response": "attending"}
    }
  ]
}
```

| 칸 | 값 (🔴 `_meeting_to_dict` 와 **같은 값**) |
|---|---|
| `id` | `meetings.id` — WORKS 는 이 번호로 `meetings.msg_meeting_id`(= `msg/start` 가 넣는 그 번호)를 찾아 회의록을 붙인다 |
| `title` · `start_at` · `tz_offset` · `tz_label` · `location` · `visibility` | 저장값 그대로 (`visibility` = all/hq/vn/private) |
| `duration_min` | `_mtg_dur(row)` |
| `organizer.name` | `created_by_name` (이름 직책) · 없으면 `""` |
| `attendees[]` | `_meeting_to_dict` 의 참석자 **순서·값 그대로** — `name` = display_name · `response` = attending/declined/change/null (**등록 담당은 비어 있으면 attending** — v793 표시 규칙) · `is_organizer` |
| `externals` | `_mtg_externals(row)` |
| `me.is_organizer` | `created_by == viewer` |
| `me.is_attendee` | viewer 가 `attendee_ids` 에 있음 (`i_am_attendee`) |
| `me.response` | `my_response` |

🔴 **보내지 않는 것**: `note`(회의 내용) · `zoom_link` · `tags` · 참석자 id·사번 · `alert_min` — 이번 카드에 안 씀(필요한 것만).

### 2-5. 오류

| 경우 | 응답 |
|---|---|
| 공유키 없음·틀림 | `403 {"error": "forbidden"}` (기존 모양) |
| 보는 사람 못 찾음 | `404 {"ok": false, "error": "viewer_not_found"}` |
| 기간·형식 오류 | `400 {"ok": false, "error": "range_invalid"}` |
| 서버 안 예외 | `500 {"ok": false, "error": "internal"}` + 로그(메시지는 로그에만) |

WORKS 쪽 안내(참고): 403 → "이음이 요청을 거부했습니다(연결 키 확인 필요)" / 404+viewer_not_found → "이음에서 내 계정(사번)을 찾지 못했습니다" / 그 밖의 404 → "이음에 회의 목록 입구가 아직 없습니다(이음 업데이트 전)" / 그 밖 → "이음 응답 오류(코드)" / 연결 실패 → "이음에 연결하지 못했습니다".

## 3. 구현 메모 (권장)

- **부하**: `_meeting_to_dict` 를 그대로 쓰면 회의 1건당 조회 2번(참석자·등록 담당) → 300건이면 600번. eventlet 단일 워커라 오래 붙잡지 않게 **참석자·등록 담당을 한 번에(IN) 조회**하는 쪽을 권합니다. 값은 위 표와 같아야 합니다.
- **WORKS 쪽 호출량**: 사람+기간별 30초 캐시 · 8초 제한 · 연결 실패 뒤 15초 쉼 · 탭을 열었을 때와 열어 둔 동안 2분마다만. → 탭을 연 사람 수 정도.
- **게이트 스위치**: 이음 화면이 바뀌지 않고(보기 전용 · WORKS 탭) 이음 🗓 에서 이미 보이는 회의만 돌려주므로 대표 먼저 게이트는 없어도 됩니다. 필요하다고 보시면 대표님께 확인해 주세요.
- **게스트 차단은 보는 사람 찾기 단계에서** — 게스트 사번으로 물어도 회의가 새지 않게(404).

## 4. 시험 권장 (세션 10 방식대로)

1. 공유키 없음 / 틀림 → 403
2. 사번 없음 · 게스트 · 봇 · 비활성 · 같은 사번 2명 → 404 `viewer_not_found`
3. **같은 사람·같은 기간이면 🗓 목록(`GET /api/meetings`)과 회의 집합이 같다** (가장 중요)
4. 남이 만든 비공개 회의는 안 나옴 · 내가 참석자면 비공개도 나옴 · hq/vn 범위 · 본사·법인 직원 각각
5. 기간 경계: `from` 당일·`to` 당일 포함 · 450일 초과 400 · 형식 오류 400
6. 301건 → `truncated: true` · 300건 반환
7. 등록 담당의 빈 응답 → `attending` · 외부 참석자 · 진행 시간(직접 지정 · 7일)
8. 응답에 `note`·`zoom_link`·`tags` 가 **없음**
9. 사번 대소문자(VN) · 로그인ID 로 찾기
