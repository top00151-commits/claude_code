### 🔴 구조를 바꿔야 했던 까닭

지금까지 **줄 전체가 링크 하나**였다(`<a class="mtg-card" href="/meetings/{id}">`).
**링크 안에 또 링크를 넣을 수 없다** — 넣으면 브라우저가 이상하게 동작한다.
→ 바깥을 `<div class="mtg-card">` 로 바꾸고 안쪽을 **「본문 링크 + 바로가기 둘」** 로 나눴다.
겉모습(테두리·여백·마우스 올릴 때 뜨는 느낌)은 **그 칸이 그대로 갖는다.**

```
<div class="mtg-card">                     ← 겉모습·flex
  <a class="mtg-main" href="/meetings/{id}">  ← 줄 전체 누르기(지금까지와 같다)
     제목 + 배지 + 날짜·작성자·팀·장소
  </a>
  <div class="mtg-acts">
     ✏ 수정   ← 고칠 수 있으면 링크 / 못 고치면 흐린 글자
     📄 양식   ← /meetings/{id}/doc
  </div>
</div>
```

- 휴대폰(≤560px)에서는 **글자를 숨기고 그림만** 보인다(줄이 좁아지지 않게).
- ⛔ **줄 전체를 누르면 지금처럼 수정 화면**으로 간다 — 쓰시던 습관을 바꾸지 않았다.

### 🔴 권한은 **한 곳**에서만 판정한다

`_can_edit_meeting(u, m, c)` — 작성자 · 알림 등록 담당 · admin/ceo · **그 회의 참석자**.
목록 라우트에서 **그 함수를 그대로 부른다.** 규칙을 화면이나 목록에 **다시 적지 않았다**
(다시 적으면 나중에 한쪽만 고쳐 어긋난다).

🔵 **느려지나 — 재 봤다**: 목록 한도는 300줄이다.
**300줄 권한 계산 = 1.3~1.7 ms**(줄당 0.005 ms · 3회 측정). 지금 운영 31줄이면 **약 0.1 ms**.
→ 묶어 읽는 최적화는 **하지 않았다**(필요 없다).

## 4. 🔴 시험에서 걸린 거짓경보 — 고친 것은 **검사기**

### ① 「링크 안에 링크가 4개」 → 전부 **주석에 적힌 글자**

운영 그대로에도 **3개**가 있었다(바깥 틀 JS 주석의 `<a href>` 설명글).
내 쪽 1개는 **내가 쓴 CSS 주석**이 범인이었다 — 주석에 꺾쇠 태그를 적었기 때문.

→ ⓐ **주석에서 꺾쇠 태그를 뺐다**(「링크 하나」로 고쳐 씀) ·
   ⓑ 검사를 **「0개」가 아니라 「운영과 견줘 늘지 않았나」** + **「줄 토막 안쪽은 0개」** 로 바꿨다.
🔵 **교훈: 구조를 글자로 보는 검사가 있는 곳에서는 주석에 태그를 쓰지 말 것.**

### ② 닫는 태그·CSS 이어진 줄이 「설명 안 됨」

줄을 한 겹 감싸서 들여쓰기가 바뀐 `</a>` 와, 내 CSS 의 이어진 줄들.
→ 허용 목록에 더했다. ⚠ 이때 `}` 같은 **흔한 토막은 넣지 않는다** — 넣으면 아무 줄이나 통과해 검사가 죽는다
(z1165 에서 한 번 그럴 뻔했다). 대신 **글자가 없는 구조 줄**만 봐준다.

### 🔴 ③ 또 밟은 셸 함정 (오늘 세 번째)

한글이 든 앵커를 **셸 heredoc 으로 파이썬에 넘겨** cp949 로 깨졌다 → 「앵커 0개」.
**내 규칙(「긴 글·한글은 셸 대신 편집 도구로」)에 이미 있는데 또 밟았다.**

## 4-B. 🔴🔴 처음 만든 것이 **다른 시험 4곳을 깨뜨렸다** — 설계를 바꿨다

### 무엇이 깨졌나

처음에는 줄 바깥을 **`<div class="mtg-card">`** 로 바꾸고 본문 링크에 새 이름(`mtg-main`)을 줬다.

```

```
**네 곳이 그 이름에 기대고 있었다.**

### 🔵 그래서 설계를 바꿨다 — 고친 것은 **시험이 아니라 내 코드**

네 시험을 고치는 길도 있었지만, **그러면 남의 준비물 폴더 네 곳을 건드려야** 하고
같은 이름에 기대는 다른 것이 또 있을 수 있다. 그래서 **내 쪽을 바꿨다**:

| | 처음 안 | 고친 안 |
| --- | --- | --- |
| 바깥 칸 | `div.mtg-card`(이름을 뺏음) | **`div.mtg-row`**(새 이름) |
| 본문 링크 | `a.mtg-main`(새 이름) | **`a.mtg-card`** — **이름·href 그대로** |
| 겉모습 | 바깥이 가짐 | 바깥이 가짐 (같음) |
| 깨지는 시험 | **4곳** | **0곳** |

→ 보이는 모습은 똑같고, 아이콘도 카드 **안**에 놓인다. **네 시험이 하나도 안 깨진다.**

🔵 **검사에 못박았다**(②-B): 「`a.mtg-card[href^="/meetings/"]` 모양이 살아 있나」 ·
「`verify_cards` 의 정규식이 줄을 세나」 · 「카드 탭엔 그 줄이 없나」 — **다음 사람이 또 바꾸면 걸린다.**

### 🔴 교훈 — 내 기억에 이미 있던 규칙을 안 지켰다

> 「**화면 글·라벨·단추·꾸러미 이름을 바꿀 때는 그 줄을 글자로 보는 검사·시험을 먼저 찾을 것**」

나는 **클래스 이름**도 거기 든다는 걸 놓쳤다. 글자만이 아니라 **구조·이름**도 남이 글자로 본다.
→ ⏭ 앞으로 화면 구조를 바꾸기 전에 **그 클래스 이름으로 저장소 전체를 먼저 훑는다.**
   (이번에는 회귀가 잡았지만, 운영 코드에 그런 선택자가 있었다면 **화면이 죽었을 것**이다.
    실제로 제품 코드는 `mtg-card` 를 **CSS 로만** 써서 살았다 — 운이 좋았다.)
