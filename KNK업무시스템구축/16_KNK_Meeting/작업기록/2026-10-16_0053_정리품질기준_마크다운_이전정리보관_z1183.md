### 고친 정리 지키기 (검증 7 — 대표 확인 「확인 + 이전 정리 보관」)
- 전: 「✏ 고치기」로 고친 정리도 **다른 화면·다시 연 화면·녹음 추가 자동 정리**에서는 확인 없이 덮어썼다(같은 화면을 띄운 채일 때만 화면이 물었다) → 검증 7 = **아니오**.
- 이제: 고치면 DB 에 「고친 표시」(`summary_edited_at`) → 「🔄 다시 정리」·녹음 올린 뒤 자동 정리가 **서버에서 먼저 묻는다**(200 + `need_confirm` · 409 로 하면 브라우저 콘솔에 빨간 오류) → 「아니오」 = 그대로(AI 안 부름 · 「고친 정리를 그대로 두었습니다」 · 실패 아님) · 「예」 = 새 정리 + 고친 정리는 **「이전 정리」로 보관**.
- 다시 정리할 때마다 바로 앞 정리를 보관(정리 글 + **그때의 AI 결정·할 일** — 사람이 넣은 것·일일카드로 보낸 것은 빼고 그대로 둔다).
- **「↩ 이전 정리」** 단추(고칠 수 있는 사람 · 이전 정리가 있을 때만) = 지금 ↔ 이전 **맞바꾸기**(한 번 더 누르면 돌아온다) · 남이 먼저 바꿨으면 맞바꾸지 않는다(충돌 409) · 보기만 하는 사람·남의 메모는 못 한다.
- DB 칸 7개(idempotent `ALTER ADD COLUMN` · 빈 글 기본 · 업무 데이터 안 건드림): meetings `summary_prev`·`summary_prev_items`·`summary_prev_at`·`summary_edited_at` / voice_notes `summary_prev`·`summary_prev_at`·`summary_edited_at`.
