## 1. 무엇이었나 — **사슬의 다음 고리**

| 고리 | 한도 | 언제 걸렸나 |
| --- | --- | --- |
| ① AI 답 길이 | `max_tokens` 1500 고정 | **z1168 에서 고침**(원문 길이에 맞춤) |
| ② 앞단(리버스프록시) 기다림 | **60초** | **z1169·z1170 에서 고침**(정리를 뒤에서 돌림) |
| ③ **AI 통신 기다림** | **`TIMEOUT_SEC = 30`** | **← 이번에 걸린 것** |

```
app/ai_client.py:44    TIMEOUT_SEC = 30
```

30초는 **짧은 답**(번역·한 줄 요약)에 맞춘 값이다. z1168 로 정리 답이 수천 자가 되자 30초를 넘기기
시작했다. OpenAI SDK 는 **재시도를 2번** 하므로 **90초쯤 버티다** 「Request timed out」을 낸다.

🔵 **받아쓰기용 클라이언트는 전부터 300초**를 쓰고 있었다(`ai_client.py:796`
`openai.OpenAI(api_key=key, timeout=300)`). **정리만 30초**에 묶여 있었다.

🔵 **이번엔 까닭이 정확히 보였다** — z1169 전이었다면 앞단이 먼저 끊어 「정리하지 못했습니다」로만
   끝났을 것이다. 뒤에서 돌리게 바꾼 덕분에 **AI 가 준 진짜 오류 글**이 화면까지 왔다.

### 🔴 왜 메모 3(27,950자)은 됐고 메모 2(19,684자)는 안 됐나

**길이 문제가 아니라 그때그때 걸리는 시간 문제**다. 13:10 의 메모 3 은 30초 안에 들어왔고,
오늘 다시 누른 메모 2 는 못 들어왔다. **30초는 아슬아슬한 선**이었고 운에 맡기고 있었다.

## 2. 고친 것 — **정리 호출에만** 300초

```python
TIMEOUT_SEC = 30                 # 공용 — 그대로 둔다
EXTRACT_TIMEOUT_SEC = 300        # z1172 — 정리 전용

def ai_chat(..., timeout_sec: float = 0):
    ...
    if timeout_sec and timeout_sec > 0:
        try:
            client = client.with_options(timeout=timeout_sec)   # 공용 클라이언트는 그대로
        except Exception:
            pass                                                # 못 바꾸면 지금까지대로
```

- `ai_extract_note`(음성 메모 · 본호출 + 끊겼을 때 재호출) · `ai_extract_meeting`(회의록) 세 곳에서
  `timeout_sec=EXTRACT_TIMEOUT_SEC` 를 준다.
- ⛔ **공용 `TIMEOUT_SEC` 은 안 건드렸다** — 올리면 **남의 기능까지 전부** 바뀐다.
- 🔵 `with_options()` 는 **새 사본을 돌려주고 원래 클라이언트는 안 건드린다**(SDK 로 실측 확인:
  openai 2.38.0 · anthropic 0.109.1 둘 다).
- 🔵 바꾼 파일은 **`ai_client.py` 하나**, **전부 보태기**(기존 호출은 한 줄도 안 바뀜).

## 5. 🔴 이번에 배운 것

### ⓐ 🔴🔴 **「한도는 사슬」을 알고도 세 번 연속 다음 고리에 걸렸다**

z1168(길이) → z1169·z1170(앞단 60초) → z1172(AI 30초). **세 번 다 같은 사슬**이었다.
메모리에 「한도는 하나가 아니라 사슬이다」가 이미 있었고, 어제 「**시간도 세라**」까지 적었는데
**고리를 끝까지 세지 않고** 한 칸씩 끌려다녔다.

⏭ **「더 길게/더 크게」 바꿀 때는 그 값이 지나가는 고리를 *한 번에 전부* 적어 놓고 시작할 것.**
   이번 건의 고리 = ①답 길이 ②AI 통신 기다림(`TIMEOUT_SEC`·재시도) ③앞단 기다림 ④DB 칸 크기(20,000자).
   🔵 ④는 아직 여유가 있다(지금 최대 4,032자).

### ⓑ **같은 파일 안에 이미 답이 있었다 (두 번째)**

받아쓰기용 클라이언트는 `timeout=300` 이었다 — **바로 아래 줄에**. z1170 때도
`main.py:5316` 의 교훈이 같은 파일에 있었다.
⏭ **고치기 전에 「이 파일에서 비슷한 일을 하는 다른 자리」를 먼저 볼 것.**

### ⓒ **공용 설정을 바꾸지 않고 내 호출만 바꾸는 길이 있다**

`TIMEOUT_SEC` 을 올리면 간단했겠지만 **남의 기능이 전부 따라 바뀐다.**
`with_options()` 는 사본을 주므로 **내 호출에만** 적용된다 — 그리고 그 사실을
**「정리 뒤에 부른 남의 호출이 다시 30초인가」**로 못박았다.
⏭ 공용 자리를 만질 때는 **기본값을 그대로 두는 보태기**로 하고, **남이 안 바뀌었음을 검사로** 남길 것.

### ⓓ **아슬아슬하게 통과하던 것은 「되는 것」이 아니다**

메모 3 은 됐고 메모 2 는 안 됐다 — 길이 차이가 아니라 **그날 걸린 시간 차이**였다.
⏭ 「한 번 됐다」로 넘기지 말 것. **한도 가까이 있으면 언젠가 넘는다.**
