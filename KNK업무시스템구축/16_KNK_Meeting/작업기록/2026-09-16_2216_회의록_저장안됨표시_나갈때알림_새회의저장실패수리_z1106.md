### ⑥ 새 회의 「저장 실패」의 원인 (2026-06-14 부터)
```
window.__MTG = {
  base_ts: {{ ... if not is_new else '""' }},     ← 새 회의일 때 '""' 가 자동 이스케이프로
  summary: {{ ... if not is_new else '""' }},        &#34;&#34; 가 되어 → JS 문법 오류(Unexpected token '&')
```
- 이 스크립트 전체가 실행되지 않아 화면은 `M = {}` — 새 회의인지(`is_new`)·고칠 수 있는지 모름.
- 그래서 「⌨️ 글로 쓰기 → 💾 저장하고 AI 정리」가 **`PUT /api/meeting/undefined`**(없는 주소)로 가서 「저장 실패」.
  서버의 새로 만들기(POST)는 **아예 불리지 않았다** → 06-14 에 서버 쪽에 넣은 원인 표면화 장치에도 안 잡혔던 이유.
- 녹음 경로는 `ensureMeetingSaved()` 가 `M.id` 만 보고 POST 하므로 그동안 동작했다.
- **재현**: 실제 앱+진짜 크롬에서 고치기 전 화면으로 누르면 `PUT /api/meeting/undefined` · 「저장 실패」 그대로 재현.
- **수리**: `{{ ((...) if not is_new else '')|tojson }}` — 빈 값도 tojson 으로. 새/기존 회의 모두 올바른 JS 로 렌더됨을 node 로 확인
  (정리 글에 `"`·`</script>` 가 있어도 안전).
- 이 파일은 06-14 23:24(`9438e4cd`)에 저장소에 처음 들어올 때부터 이 줄이 있었다.

### ③ 뒤로 가기 — 방식 선택 이유 (실측)
- WORKS 는 링크를 누르면 본문만 갈아끼운다(`_v5_partials/spa_nav.html`). 링크는 문서 **캡처 단계**에서 먼저 확인해 막을 수 있었다.
- 뒤로 가기(`popstate`)는 창(window)에 먼저 등록된 spa_nav 가 **먼저** 받는다 — Chrome 152 에서 캡처로 등록해도 등록 순서대로 불림(실측).
  처음 방식(popstate 캡처 + 주소 되돌리기)은 **주소=회의 · 화면=목록**으로 어긋나는 결함 → 폐기.
- **Navigation API `navigate`(traverse)** 로 뒤로 가기 자체를 취소 → popstate 가 안 생겨 spa_nav 도 안 움직임.
  브라우저 뒤로 버튼(휴대폰 뒤로와 같은 경로)·`history.back()` 둘 다 취소됨을 확인. 다른 문서로의 뒤로 가기는 `beforeunload`(브라우저 기본 확인창)가 맡는다.
- Navigation API 가 없는 브라우저는 **뒤로 가기만** 알림 없이 이동(링크·새로고침·창 닫기 알림은 그대로).

### ⚠ 앞으로 이 파일을 고칠 때
- `$()` 는 이 화면(`.mf-wrap`)이 사라졌으면 `null` — 화면 전환 뒤 뒤에서 끝나는 작업이 **새 화면 칸을 건드리지 않게** 하는 장치. 되돌리지 말 것.
- 서버가 칸 값을 바꾸면(원문·제목) `rebase([...])` 로 기준값도 옮길 것 — 안 옮기면 「저장 안 됨」이 계속 뜬다.
- 이 화면이 스스로 이동할 때(저장·삭제 직후)는 `_leaveOk = true` 뒤 이동.
- 전역 이벤트(beforeunload·click 캡처·navigate)는 `window.__knkLeaveGuardOn` 으로 **한 번만** 등록 — 판단은 지금 보이는 화면의 `window.__knkLeaveCheck`.
