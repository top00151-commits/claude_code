## 2. 바꾼 것 (파일 4개)

### main.py (서버)
- **녹음 조각 저장 입구 5개**: `rec-start` · `rec-chunk` · `rec-finish` · `rec-cancel` · `rec-status` (`/api/meeting/{id}/…`)
  - 조각은 본문 = 소리 바이트 그대로, 순서 = `seq`(1부터). 서버 파일 `meeting_audio/meeting_{id}/rec_*.webm.part` 에 **순서대로 이어 붙임**
  - 순서가 어긋나면 받지 않고 「서버가 기다리는 번호」를 알려 줌(화면이 맞춰 다시 보냄) · 옛(다른) 녹음 조각은 `stale` 로 거절
  - 한도 = `_MEETING_AUDIO_MAX_MB`(300MB · z1111 과 같은 한 곳) · 조각 하나 최대 8MB
  - `rec-finish` 는 **목록·다른 기기(PC)에서도** 부를 수 있다 — 열린 조각을 정식 파일로 닫고 「녹음 중」을 지움
  - 상태 요약(`_rec_view`)에는 **서버 파일 경로를 넣지 않는다**
- **이어서 녹음**: `rec-start` 가 앞서 끊긴 조각을 먼저 정식 파일로 닫아 보존(잃지 않게)
- **음성→글자 워커**: 조각이 여러 개면(끊겼다 이어진 녹음·올린 파일) **순서대로 하나씩** 바꿔 본문에 덧붙임. 하나 끝날 때마다 저장 → 뒤에서 실패해도 앞부분은 남고, 실패한 조각만 남아 다시 시도 가능. 25MB 넘는 조각은 z1111 대로 20분씩 나눠 변환(`_stt_one`)
- 본문 덧붙이기는 잠금(`_STT_APPEND_LOCK`) 안에서 — 두 조각이 같이 끝나도 한쪽이 지워지지 않게
- 음성 파일 올리기(📁)도 같은 줄(pending)에 서서 차례로 변환
- 목록·상세 화면에 녹음 상태 전달

### meeting_form.html (녹음 화면)
- 「녹음 시작」 = **회의록을 먼저 만들고**(목록에 남게) 서버 저장을 연다 → **10초마다 조각을 서버로**
- 다른 앱으로 넘어가는 순간(`visibilitychange → hidden`) **그 자리에서 조각을 내보냄**
- 빨간 띠에 「🔴 본 회의 녹음 중 · 12:30 저장됨」
- 「녹음 종료」 = 서버에 이미 있으니 **마무리만**(큰 파일을 끝에 통째로 올리지 않음) → 음성→글자·AI 정리 자동
- 인터넷이 끊기면: 못 보낸 조각은 순서를 지켜 다시 보냄 → 끝까지 못 보내면 **예전 방식(녹음 전체를 한 번에 올리기)**으로 안전하게 넘어감 · 서버 저장을 아예 못 열면 그렇게 알리고 예전 방식으로 녹음
- **상세 화면 복귀 상자** 「🔴 녹음 중이던 회의입니다 — 지금까지 N분 저장됨」 + 「⏹ 녹음 끝내고 정리」·「🎙 이어서 녹음」
- 소리가 하나도 안 들어왔고 방금 만든 빈 회의록(제목·내용 없음)이면 지움(목록을 더럽히지 않게)
- 안내문을 실제 동작에 맞게: 「다른 앱을 봐도 녹음은 계속됩니다」(약속 못 하는 말) → 「10초마다 서버에 저장돼 창이 닫혀도 남고, 목록에서 「녹음 끝내고 정리」로 마칠 수 있다. 다만 휴대폰이 앱을 재우면 소리가 안 들어올 수 있으니 화면을 켜 두세요」

### meetings.html (회의록 목록)
- 맨 위 **「🔴 녹음 중인 회의 N건」 띠** + 회의마다 「⏹ 녹음 끝내고 정리」 → 끝낸 뒤 그 회의로 옮겨 자동 정리(`?auto=1`)
