## 1. 기능 개요 (사용자 화면 기준)

WORKS 통합 플랫폼 사이드바 **[회의록]** 메뉴 (`/meetings`):
- **목록**: 상단 통계 3종(전체 회의 · 결정사항 · 할 일 건수) + 회의 카드(제목·날짜·작성자·장소·상태 `작성중`·배지 `✓결정 N` `📌할일 N` `팀 공개`) + **[+ 새 회의록]**
- **작성/상세**(같은 폼): 제목·날짜·장소·태그·참석자(자유 텍스트)·회의 원문(body) 입력 → **[AI로 정리]** 버튼 → 결정사항·할 일·요약 자동 추출(수정 가능) → 할 일은 1클릭으로 **일일업무 카드(tasks) 등록**
- **음성**: 녹음 업로드 → **Whisper 음성→글자**(OpenAI 키 필요) → 원문에 추가 → AI 정리
- **연결**: 회의 ↔ 프로젝트(관리코드) · 영업기회 연결, 회의에서 **새 영업기회 생성**(양방향 참조)
- **정식 문서 출력**: `/meetings/{id}/doc` — 공개범위 따라 보안등급 표기(대외비 등)
- **핵심 가치 루프**: 원문 입력 → AI 결정·할일·요약 → 검토 → 일일업무 연동

- **일일업무(tasks)**: action→to-daily가 tasks에 INSERT + linked_task_id 기록. tasks 스키마는 01 세션 영역 — 변경 금지.
- **Eum 메신저**: 메신저 🗓회의(등록·참석자·5/10/15/30분전 푸시)는 **별도 시스템**(10_KNK_Messenger repo). 메신저 회의카드의 "📋회의록" 버튼이 WORKS `/meetings/new?title=...&meeting_date=...` **직접링크 프리필**으로 들어옴 — ⛔이 링크를 SSO로 이중감쌈 금지(이력: 깨진 적 있음). 프리필 쿼리 파라미터 이름 바꾸면 메신저 쪽도 같이 바꿔야 함(=대표 통해 조율).
- **영업기회(sales_opportunities)**: to-opportunity·link — 01 세션 영역과 공유.
- **프로젝트(projects)**: meetings.project_id로 연결.

## 7. 알려진 함정·관련 규정 (회의록 작업에 해당하는 것만)
- **낙관적 잠금**: meetings는 잠금 대상 — 편집화면 열 때 base_ts → 저장 시 전송 → 바뀌면 409. 새 편집 UI도 이 패턴.
- **연결성 안전(절대준수)**: 이름→사람 자동연결은 **명확한 단일후보만**(현행 `_meeting_match_user_id`가 그 원칙). 애매하면 미매칭. `except: pass` 금지.
- **사람 참조는 ID**: 표시는 이름, 저장·연동은 users.id.
- **입력 폼 규정**: 새 입력 폼엔 `_v5_partials/knk_inputs.html`(콤마)+`knk_datepicker.html`(공휴일 달력) include. 날짜는 `input[type=date]`면 자동으로 KNK 달력 적용.
- **시트 여백**: 입력 시트는 모니터 풀폭(max-width 금지 · 예외=인쇄 A4).
- **숨김 요소**: `hidden`이 display CSS에 덮이는 함정 — `#id[hidden]{display:none!important}`.
- **사람친화 용어(절대준수)**: 화면 문구는 쉬운 이름·약어 풀어쓰기. 어려운 용어는 대표가 반려한 이력 있음("계수%" 사례).
- **timezone**: 날짜 경계는 입력자 소속(본사 UTC+9). `datetime('now','localtime')` 패턴 사용 중.
- **테스트 데이터**: 검증용 데이터는 A 접두 관리번호 규칙( /admin/test-data ) — 회의록엔 관리번호가 없으니 제목에 [테스트] 표기 후 삭제 권장.
