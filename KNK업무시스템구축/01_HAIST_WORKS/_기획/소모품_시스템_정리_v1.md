> **버전:** v5H226 z261 ~ z304 · **정리일:** 2026-06-07 · **작성:** 빅터(01)
> **대상:** ㈜케이엔케이(HAIST) — 고객사 소모품 발주를 엑셀 양식으로 받아 시스템에 등록·추적하는 전 과정
> **연관 코드:** `app/consumables.py` · `app/main.py`(소모품 라우트) · `app/database.py`(스키마) · `app/templates/consumable_form_upload.html`·`consumable_detail.html`·`schedule_board.html` · `app/static/templates/소모품수주_양식.xlsx`

## 1. 한눈에 — 전체 흐름

```
[양식 다운로드]  소모품 화면 → "양식 다운로드" (KNK 소모품 등록 양식.xlsx)
      │
      ▼
[고객사 작성]    엑셀에 정보란(고객사·발주일 등) + 품목 라인 + 사진 작성 후 회신
      │
      ▼
[업로드+미리보기] 소모품 → 업로드 → 자동 파싱 → 미리보기에서 매칭·단가 확인·수정
      │
      ▼
[등록 확정]      관리번호·수주번호 자동 부여 + 정보란 전체 + 라인 + 사진 등록
      │
      ├─▶ [상세 화면]    정보란 수정·자재/관리번호 연결·변경 이력 탭·관련부서 통보
      └─▶ [작업일정표]   소모품 한 줄로 표시(수량1·단가=금액=총액), 관리번호 클릭→상세
```

**핵심 철학(연결성 안전 원칙):** 자동 연결은 **명확한 단일 후보일 때만**. 애매하면 미연결로 두고 사용자가 직접 확인·연결한다. (틀린 연결 < 미연결)

## 2. 엑셀 양식 (KNK 소모품 등록 양식.xlsx)

- **다운로드 경로:** 소모품 화면 → `양식 다운로드` 버튼 → 라우트 `GET /consumables/import-template`
- **다운로드 파일명:** `KNK 소모품 등록 양식.xlsx`
- **실제 파일:** `app/static/templates/소모품수주_양식.xlsx`
- **시트 구성:** `[소모품]`(데이터) + `[작성안내]`(안내)

### 2-1. [소모품] 시트 구조 (최종 — z285/z288)

| 행 | 내용 |
|---|---|
| 1 | 제목: `㈜케이엔케이 소모품 발주 요청서` |
| 2~9 | **정보란** (좌측 B/C, 우측 L/M) |
| 10 | 안내 문구 (한 줄에 한 항목…) |
| **11** | **데이터 머리글(헤더)** — 13개 컬럼 |
| 12~ | 품목 데이터 (한 줄에 한 품목) |

**정보란(2~9행):**

| 좌측(B 라벨 / C 값) | 우측(L 라벨 / M 값) |
|---|---|
| 1차 고객사 | 관리번호 *(시스템 자동)* |
| 2차 고객사 | 수주번호 *(시스템 자동)* |
| 납품위치 | 프로젝트명 = `소모품` |
| 발주일 | 모델명 = `해당 월/주차` |
| 납품일 | 장비명 = `소모품 XX종` |
| 고객사 담당자 | KNK 담당자 |
| 고객사 담당자 연락처 | **통화 (M8)** = KRW/USD… |
| | **거래구분 (M9)** = 내수/수출 |

**데이터 머리글(11행) — 13개 컬럼:**

`NO · 연결 관리번호 · 모델명 · 장비명 · 소모품 품명 · 소모품 규격(SPEC) · 사진(PICTURE LOCATION) · 사진(PICTURE) · 수량 · 단위 · 단가 · 금액 · 비고`

- **단가/금액 머리글은 수식**: `="단가 ("&$M$8&")"` → 화면엔 `단가 (KRW)` 로 **통화 자동 표기**
- **금액 셀 수식**: `=IF(단가="","",단가×수량)`

### 2-2. 항목별 의미 (작성안내 시트에 정리됨)

| 항목 | 의미 |
|---|---|
| **연결 관리번호** | 이 소모품이 들어가는 **기존 제작 검사기/장비의 관리번호**. 향후 추적용(알면 기재) |
| **모델명** | **고객사 아이템(제품) 모델명** |
| **장비명** | **당사(KNK)가 제작한 장비의 명칭** |
| 품명 / 규격 | 소모품 품명 / 규격(SPEC) |
| **사진(PICTURE LOCATION)** | 소모품이 **포함된 블럭/부품**의 사진(위치) |
| **사진(PICTURE)** | 해당 **소모품 자체**의 사진 |
| 단가·금액·통화·거래구분 | ㈜케이엔케이에서 정리 |
| 관리번호·수주번호 | **시스템 자동 부여** |

### 2-3. 양식 진화 이력
z261 드림텍 형식 복제 → z281 KNK 표준(헤더 4행) → z283 헤더 10행·정보란 확장 → z285 통화·거래구분 추가(헤더 11행) → z293 작성안내 전면 갱신.

## 3. 업로드 & 파싱 (`consumables.py`)

- **라우트:** `POST /consumables/upload-xlsx` → 파싱 → 미리보기 / `POST /consumables/{co}/import-confirmed` → 등록
- **파서:** `parse_consumable_xlsx(file, image_out_dir)`

### 3-1. 헤더 자동 인식 — `detect_header`
- 1~**16행** 스캔, **가장 키 많은 행**을 헤더로 선택(상단 정보란 라벨에 오탐 안 함)
- `HEADER_KEYS`(키워드 매핑): 요청일/품명/모델/장비명/수량/단위/연결관리번호/NO/규격/단가/금액/비고
- 한 셀 → 한 키만 매핑(충돌 방지). 검출 조건 = 품명 + (수량 or 모델)

### 3-2. 정보란 읽기 — `read_order_meta` (라벨 기반)
- 헤더 위 좌·우 정보란을 **라벨로 찾아** 읽음(셀 위치 무관)
- `_right_value`: 라벨 **바로 옆 4칸 이내** + 다른 라벨이면 무시 → 빈칸일 때 옆 블록 라벨 오인 방지
- 읽는 값: 통화·거래구분·1차 고객사·2차 고객사·납품위치·발주일·납품일·고객 담당자·연락처·모델명·장비명·KNK담당자(영업)
- **통화 추출:** `통화` 라벨 값 → 코드 / 보조로 단가·금액 머리글 `(KRW)` 괄호. 화이트리스트(KRW/USD/VND/JPY/CNY/EUR) 정규화

### 3-3. 사진(이미지) 매칭 — 행 위치 기반(견고)
- **문제였던 것:** 앵커 행 +2 로 모든 사진이 2줄씩 밀림 → 수정
- **해결(z284):** **행 높이를 누적(EMU)** 해서 이미지의 **세로 중심**이 속한 데이터 행에 매칭 → 셀 크기·병합·붙인 위치가 달라도 정확
- **두 사진 칸 구분(z286):** 헤더로 `사진(PICTURE)`=품목사진 / `사진(PICTURE LOCATION)`=위치 구분(`_find_photo_cols`), 미리보기·상세·저장 모두 2칸
- **이미지 균일·고화질(z293/z295):** 썸네일 **320×160(2:1, 가운데 잘라 동일)** JPEG q92 / 원본 긴 변 1920px 비율 유지 q92

### 3-4. 단가·금액
- 단가·금액 컬럼 인식·추출. 금액 비어있으면 `단가×수량` 보강

## 4. 고객사 매칭 — 등록 고객사로만 (z294/z299)

- **함수:** `match_customer_by_name(name)`
- (주)·㈜·주식회사·유한회사·괄호·공백 **무시하고 '상호'로 비교** (`_norm_company`)
- 원문 정확일치 우선 → 정규화 상호가 **정확히 1건** 일치할 때만 연결(정식 명칭 + customer_id)
- 0건/2건+(애매) → 미연결 (엑셀명 그대로, 작업일정표에서 **적색** 표시)
- **상세 1차 고객사는 등록 고객사 드롭다운**으로만 선택(자유 입력 불가)

> 예) `드림텍` · `(주)성수기전` · `주식회사 성수기전` → 모두 등록된 `(주) 성수기전` 으로 연결

## 7. 상세 화면 (`consumable_detail.html`)

### 7-1. 상단 정보란 — 업로드 후 수정 가능(z298/z299)

### 7-4. 자재코드 연결 (z300)
- 업로드 시 품명 정확일치 1건 **자동 연결**
- 상세에서 **🔗 추천(정확일치)** / **🔍 실시간 검색**(`/api/parts/search`) / **해제**

### 7-5. 관리번호 연결 (z301/z302)
- **자동:** 업로드 시 모델 매칭
- **추천(예상 관리번호):** ① 같은 1차 고객사 ② 모델명 90%↑ ③ 장비명 90%↑ **모두 충족** 시 (`suggest_mgmt_for_line`, difflib 유사도 ≥0.9)
- **직접 입력 + 검증:** 입력한 관리번호의 모델/장비가 라인과 **다르면 알람** → "그래도 연결?" 확인 시 **강제 연결**(force) / 없는 번호 안내 / 해제

### 7-6. 관련부서 통보 (z292)
- `📤 관련부서 통보` → **부서 선택 모달**(14개 부서 체크박스·인원수, 기본 **구매팀**)
- 선택 부서 활성 구성원에게 **사내 🔔 알림** 발송(발신자 제외) → "N개 부서 M명 통보 완료"

## 13. 핵심 원칙 (유지 사항)

1. **연결성 안전:** 자동 연결은 명확한 단일 후보일 때만. 애매하면 미연결(수동 유도).
2. **1차 고객사는 등록 고객사로만** 표현(드롭다운). 미연결은 적색.
3. **양방향 동기화:** 상세·작업일정표가 같은 원본(consumable_orders)을 수정 → 자동 일치.
4. **변경은 모두 이력화**(누가·언제·이전→변경).
5. **사진은 균일·고화질**(2:1 320×160 q92), 위치/사진 2칸.
6. **관리번호·수주번호만 자동 부여**, 나머지는 엑셀/사용자 입력.
