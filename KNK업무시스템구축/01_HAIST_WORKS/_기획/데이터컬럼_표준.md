# KNK 데이터컬럼 표준 v1.0

> 확정: 2026-06-06 (대표 결정) · 목적: 다운로드·업로드·작업일정 등 화면 간 **컬럼 통일성** 부여
> 원칙: 100% 동일은 불가(목적이 다름) → **공통 코어는 같은 이름·순서**, 화면별 필요한 것만 뒤에 추가

---

## 1. 용어 통일 (전 화면 공통)
| 통일 전 (혼용) | **통일 후** |
|---|---|
| 관리코드 / 관리번호 | **관리번호** |
| 납기일 / 납품일 | **납품일** (하나로) |
| 1차고객사 / 고객사 | **고객사** (2차는 별도 컬럼) |
| 수주액 / 금액 | **금액** (표시명은 '수주액' 허용) |

---

## 2. 공통 코어 (11) — 모든 화면 **같은 이름·같은 순서**
```
① 관리번호  ② 수주번호  ③ 고객사  ④ 프로젝트명  ⑤ 장비명  ⑥ 모델명
⑦ 출고형태  ⑧ 수량  ⑨ 상태  ⑩ 발주일  ⑪ 납품일
```

---

## 3. 화면별 컬럼 (코어 + 추가)

### 📥 업로드 양식 (등록 입력용)
`코어 11` + **PO유형 · 단가 · 금액 · 통화 · 거래구분 · 2차고객사 · 납품처 · 영업담당자 · 비고**
- 사업부는 관리번호(4번째 글자)로 자동 → 컬럼 불필요(또는 맨 앞 참고용)

### 📊 다운로드 (프로젝트 목록 조회용)
`코어 11` + **금액(수주액)**
- 업로드와 **호환**(왕복): 다운로드 → 수정 → 재업로드 가능해야 함

### 📅 작업일정 (운영 보드)
`코어 11` + **부서(고객사 담당자 부서) · 담당자(고객사 담당자) · 납품위치 · 비고** + **[날짜 그리드]**
- 주의: 여기 '담당자'='고객사 담당자', 업로드의 '영업담당자'=KNK 영업 → **이름 구분**

---

## 4. 구현 순서 (제안)
| 단계 | 내용 |
|---|---|
| **1** | 표준 문서 확정 (본 문서) ✅ |
| **2** | **업로드 양식 재제작**(코어 표준) + **다운로드 동일 컬럼** + **파서 왕복 인식** → 다운로드 파일 그대로 재업로드 가능 |
| **3** | 작업일정 컬럼을 코어 순서로 정렬 |
| **4** | 용어 일괄 변경(관리코드→관리번호, 납기일→납품일) 전 화면 (큰 작업, 점진) |

---

## 5. 매핑 (시스템 필드)
| 표준 컬럼 | DB/필드 |
|---|---|
| 관리번호 | projects.mgmt_code |
| 수주번호 | orders.order_no (소모품=co_no) |
| 고객사 | customer_name |
| 프로젝트명 | name |
| 장비명 | equip_name |
| 모델명 | model_name |
| 출고형태 | shipment_form (ASS'Y/부품/기타/소모품) |
| 수량 | unit_qty |
| 상태 | status |
| 발주일 | order_date |
| 납품일 | due_date (← 기존 납기일 필드 재명명) |
| PO유형 | po_type |
| 단가/금액/통화 | unit_price / order_amount / currency |
| 거래구분 | is_export(내수/수출) |
| 2차고객사 | secondary_customer |
| 납품처/납품위치 | order_items.ship_to |
| 영업담당자 | sales_name |
| 부서/담당자(고객사) | cc_dept / cc_name |
| 비고 | logi_note |
