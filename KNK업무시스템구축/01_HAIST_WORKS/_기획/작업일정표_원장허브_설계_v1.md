## 0. 북극성 (왜 만드는가)

> 사람들이 시스템을 포기하는 진짜 이유 = **"이 단계에서 뭘, 어디에 넣어야 정보가 모이는지 몰라서."**

- 이 시스템의 임무 = **손을 잡고 단계별로 안내**해서, 어렵더라도 **"그래도 할 수 있구나"** 를 느끼게 한다.
- 모든 화면을 이 한 질문으로 검사한다:
  **"영업관리 담당자가 자리를 비워도, 이 사람이 안내만 따라가면 할 수 있는가?"**
- 특히 **출하·수출** 단계에서 사람들이 가장 막힌다 → 거기서 가장 친절해야 한다.

---

## 1. 설계 원칙 3 (앞으로 계속 지킬 기준)

1. **빈칸 금지** — 단계마다 "무엇을" 콕 집어 안내(체크리스트/안내 입력창). 빈 칸을 던지지 않는다.
2. **역할별로 보이는 것만** — 단가·금액·세금계산서 발행여부는 **권한 통과한 사람에게만 서버에서 내려보냄**(화면에서 가리는 척 ❌, 데이터 자체를 안 보냄).
3. **틀 먼저, 디테일은 점진** — 특히 수출 서브단계는 빈 칸+안내만 먼저 깔고 하나씩 붙인다.

---

## 2. 업무 흐름 — 단계 파이프라인

**① 영업 구간** (매출 숫자가 정해짐)
```
입력(등록) → 견적·제안 전달 → 수주
```
**② 생산 구간** (여러 부서가 같이 채움) — 관리 주체가 생산↔기술영업으로 오감
```
제작요청 메일(전부서)
  → 진행[설계·회로·프로그램·전장·조립·테스트]  (생산)
  → 검증[사업부별]                              (생산)
  → 라벨/명판                                   (기술영업)
  → 포장                                        (생산)
  → 출하[국내·수출]                             (기술영업)
```
**③ 매출 마감** (2단계 인식)
```
출하 = 1차 매출(속보)  →  세금계산서 발행 = 최종 매출(확정)
```

- **검증은 사업부별로 다름**: 자동화 = 드라이런 / 검사기 = 반복성검사·성적서 작성
- **관리 주체(담당)**: 입력~제작요청·**라벨/명판·출하 = 기술영업** / 진행·검증·**포장 = 생산** / 세금계산서 = 영업·회계
  (※ "누구나 클릭"이라 담당은 강제가 아니라 **안내 표시**용 — 누가 눌렀는지는 기록됨)
- **출하-미발행**(출하했으나 세금계산서 미발행) = 자동으로 "매출 대기" 목록

## 3. 단계별 "무엇을 · 누가 · 어디에" — (포기 방지의 핵심 표)

| 단계 | 누가(담당) | 칸 클릭 시 묻는 것(안내) | 남는 데이터 |
|---|---|---|---|
| 입력(등록) | 영업 | 고객사·모델·장비·수량·거래구분(내수/수출) | 관리번호 자동발급 |
| 견적·제안 전달 | 영업 | 전달일·견적금액 | 상태=견적/제안 |
| 수주 | 영업 | 수주일·수주금액·납기 | 수주번호·매출 예정 |
| 제작요청(전부서) | 영업/관리 | **[발송] 클릭 → 메일 자동 작성·발행** | 생산 시작·전부서 알림 |
| 진행-설계 | 설계 담당 | 시작/완료일·비고 | 단계기록(누가·언제) |
| 진행-회로/프로그램/전장/조립/테스트 | 각 담당 | 시작/완료일·비고 | 단계기록 |
| 검증(자동화) | 검증 담당 | 드라이런 결과·일자 | 단계기록 |
| 검증(검사기) | 생산 | 반복성검사 결과·**성적서 첨부** | 성적서 파일 |
| 라벨/명판 | **기술영업** | 종류(라벨/명판/둘다)·완료일 | 단계기록 |
| 포장 | **생산** | 포장 완료일·비고 | 단계기록 |
| 출하 | **기술영업** | 출하일·수량·**국내/수출** → 수출이면 서브 펼침 | **1차 매출** |
| (수출) 서브 | 수출 담당 | 원산지증명서·인보이스·패킹리스트·물류예약·관세 체크 | 각 서류 |
| 세금계산서 | 영업/회계 | 발행여부·발행일·금액 | **최종 매출 확정** |

> 이 표가 곧 "안내 입력창"의 내용물이 된다. 담당자는 외울 필요 없이 묻는 대로 답하면 정보가 제자리에 모인다.

## 4. 화면 설계

### 4-1. 보드 한 줄 (지금 일정표 모양 유지 + 단계 진행 띠)
```
관리번호 │ 프로젝트 │ 고객사 │ … │ [진행 단계 ●━━━━○ … ] │ 6 7 8 9 … (날짜)
                                  설계✓ 회로✓ 프로 ◐ 전장○ …  ← 어디까지 왔는지 한눈에
```
- 기존 날짜 막대(진행기간)는 유지. 그 위/옆에 **단계 진행 표시** 추가.
- 막대/단계 칸을 **클릭 → 안내 입력창**.

### 4-2. 칸 클릭 → "안내 입력창" (빈칸 금지의 실체)
**출하 칸 클릭 (수출일 때):**
```
┌ 출하 등록 ───────────────────────────┐
│ 출하일  [2026-06-10]                  │
│ 수량    [10]                          │
│ 구분    ( ) 국내   (●) 수출           │
│  └ 수출 선택 → 아래 펼쳐짐:           │
│     ☐ 원산지증명서   ☐ 인보이스       │
│     ☐ 패킹리스트     ☐ 물류 예약      │
│     ☐ 관세 정리                       │
│     (각 항목 클릭 → 무엇을 넣는지 또 안내)│
│                      [취소]  [저장]   │
└───────────────────────────────────────┘
```
→ 수출이 처음이라도 **체크리스트만 따라가면** 된다. 영업관리가 없어도 진행.

### 4-3. 역할별 보드 두 모습 (마스터/배포본을 자동 분리)
| 보는 사람 | 보이는 것 |
|---|---|
| **영업·관리** | 전체 — 단가·금액·세금계산서 발행여부 + 모든 단계 (= 지금 마스터 엑셀) |
| **부서 담당자** | 기본정보 + 자기 단계만 — **단가·금액·세금계산서 없음** (= 지금 배포본) |

> 효과: **마스터·배포본 두 파일 관리 끝.** 한 번 입력 → 사람마다 맞게 보임. 옛 배포본 어긋남·금액 유출 위험 0.
> 구현: 금액류는 **권한 없으면 서버에서 아예 미전송**(렌더 단계 차단). CSS 숨김 아님.

## 5. 매출 보고서 자동화 (파생 자료 = 보고의 끝)

- **출하 기준**(이번 달 나간 것 — 속보) / **세금계산서 기준**(이번 달 확정 매출) / **출하-미발행**(발행 대기)
- 보고서: **매출현황 · 고객사별 현황 · 월간 · 연간** — 클릭 한 번에 추출(엑셀/화면)
- 데이터 출처: **수주(이미 시스템에 있음) + 출하일 + 세금계산서 발행여부/일** — 세 가지만 채워지면 전부 자동.

---

## 6. 데이터 모델 (새로 필요한 것)

- **단계 진행 기록**: 프로젝트별 단계 상태 — (단계명, 완료여부, 날짜, **기록한 사람**, 비고). 부서가 클릭할 때마다 "누가·언제" 자동 적재(추적).
- **출하**: 출하일·수량·국내/수출.
- **세금계산서**: 발행여부·발행일·금액.
- **수출 서브**: 원산지증명서·인보이스·패킹리스트·물류예약·관세 (틀만 먼저, 점진). → **기존 FTA 원산지증명서 모듈에 연결**.
- **역할별 금액 차단**: 보드/보고서 렌더 시 권한 검사(서버).
- **연결성 원칙 준수**(z262~): 자동연결은 단일후보만 · 실패 표면화 · 식별자 UNIQUE.

## 7. 기존 시스템과의 연결 (크게 안 벗어남)

이미 가진 것 위에 얹는다 — 새로 짓는 게 아니다:
- **작업 일정표 보드**(1·2단계 완료) — 모양 그대로, 단계·안내입력만 추가
- **수주/프로젝트/상태**(orders·projects·status) — 단계 = 기존 status를 현실 흐름으로 확장
- **고객사·권한**(can_view_sales 등) — 역할별 금액 숨김에 그대로 사용
- **FTA 원산지증명서 모듈** — 수출 서브단계에 연결
- **메일 발송** — 제작요청 메일 자동 발행에 사용

## 8. 구현 순서 (점진 — 한 번에 다 안 함)

| 단계 | 내용 | 가치 |
|---|---|---|
| **1** | 단계 파이프라인 + 칸 클릭 "안내 입력창" + **역할별 금액 숨김** | 원장 뼈대 — 부서들이 직접 채우기 시작 |
| **2** | 출하 + 세금계산서 두 시점 기록 | 매출의 두 못 |

| **4** | 제작요청 메일을 보드에서 한 번에 발행 | 수주→생산 전환 |
| **5** | 수출 서브단계 디테일(원산지증명서·인보이스·패킹·물류·관세) 점진 부착 | 수출 끝까지 안내 |

## 9. 결정사항 (2026-06-07 대표 확정)

1. **단계 담당** — ✅ **누구나 클릭 가능** + "누가 눌렀는지" 기록(추적). (나중에 부서 제한 부착)
2. **진행 6단계(설계·회로·프로그램·전장·조립·테스트)** — ✅ **동시 진행 가능** → 순서형 아님, **각각 독립 체크**.
3. **라벨/명판** — ✅ **한 단계** (둘 다 할 때도, 하나만 할 때도) → 클릭 시 라벨/명판/둘다 표시.
4. **제작요청 메일** — ✅ **현재 = 전체 발송**. **향후 = 사업부별 라우팅**(검사기→검사기 관련부서 / 자동화→자동화 관련부서). → 발송 틀 먼저, 라우팅은 나중 부착.
5. **국내/수출 구분** — ✅ **대부분 등록 때 구분됨**(거래구분) → 출하 안내창에 **거래구분 자동 채움 + 변경 가능**.

## 10. 1단계 상세 설계 (단계 파이프라인 + 안내 입력 + 역할별 금액 숨김)

### 10-1. 보드에 "단계" 칸 추가
- 정보 칸 끝(날짜 그리드 앞)에 **단계 칸 1개** 추가.
- 표시: **현재 단계 배지** (예: 〔수주〕→〔진행〕→〔검증〕→〔출하〕) + **진행 6 미니닷**(설계·회로·프로그램·전장·조립·테스트).
- 색: 회색=전 / 파랑=진행 / 초록=완료.
- 클릭 → 그 프로젝트의 **단계 패널** 열림.
- 기존 날짜 막대·막대 메모는 그대로 유지.

### 10-2. 단계 패널 ("이 건, 지금 어디까지?")
```
[001T2601] 드림텍 검사기 1호기                          [✕]
 ✅ 입력             06/01 (홍길동)            [기술영업]
 ✅ 견적·제안 전달    06/02 (홍길동)            [기술영업]
 ✅ 수주             06/03 (홍길동)            [기술영업]
 ✅ 제작요청  [📧 발송됨 06/03] [다시 발송]     [기술영업→전부서]
 진행(동시): ✅설계 ✅회로 ◐프로그램 ☐전장 ☐조립 ☐테스트  [생산]
 ☐ 검증  (검사기→반복성·성적서 / 자동화→드라이런)         [생산]
 ☐ 라벨/명판  (라벨 / 명판 / 둘다)                       [기술영업]
 ☐ 포장                                                 [생산]
 ☐ 출하  (국내/수출 — 거래구분 자동)                      [기술영업]
 ──────────────────────────  (아래는 영업·관리에게만 보임)
 ☐ 세금계산서 발행                                       [영업·회계]
```
- 각 단계 줄 끝에 **담당(안내 표시)** — 강제 아님, **누구나 클릭** 가능, 누른 사람은 기록.
- 각 항목 클릭/체크 → **안내 입력창**(그 단계가 묻는 것) → 저장 시 **날짜·누른 사람 자동 기록**.
- 진행 6칸은 **독립 토글**(동시 진행). 라벨/명판은 한 줄(라벨/명판/둘다 선택). 포장은 그 다음.

### 10-3. 안내 입력창 (단계별 — 3장 표의 "묻는 것")
- **출하** → 출하일·수량·국내/수출(거래구분 자동·변경가능). 수출이면 서브체크(원산지증명서·인보이스·패킹·물류·관세 — 틀만, 점진).
- **검증** → 사업부별 안내 분기(검사기: 반복성·성적서 첨부 / 자동화: 드라이런 결과).
- **세금계산서** → 발행여부·발행일·금액 (영업·관리만).
- **제작요청** → [발송] → 메일 자동 작성(현재 전체, 향후 사업부별).

### 10-4. 역할별 금액 숨김 (마스터/배포본 자동 분리)
- 보드 금액류 칸(단가·금액·세금계산서) + 패널 '매출' 구역 + (향후)보고서: **권한 없으면 서버에서 미전송**.
- 판정: `can_view_sales` 등 기존 권한 사용.

### 10-5. 데이터 모델 (1단계)
- **단계 기록표** `project_stage_log`:
  `(ref_kind, ref_id, stage_key, sub_key, done, on_date, by_user, memo, extra(JSON), updated_at)` · UNIQUE(ref_kind, ref_id, stage_key, sub_key)
  - stage_key: `input · quote · order · prod_request · progress · verify · label · pack · ship · tax_invoice`
    (담당 안내: label·ship = 기술영업 / progress·verify·pack = 생산 / tax_invoice = 영업·회계)
  - progress sub_key: `design · circuit · program · wiring · assembly · test` (동시 진행 → 각 행)
  - 출하 extra: 수량·국내/수출 / 세금계산서 extra: 발행여부·금액
- **연결성 원칙 준수**: upsert UNIQUE · 실패 표면화 · 임의필드 차단(stage_key 화이트리스트).
- **추적**: by_user·updated_at 항상 기록.

### 10-6. 1단계 산출물 / 비포함
- **포함**: 단계 칸·단계 패널·안내 입력창(전 단계)·역할별 금액 숨김·단계 기록표.
- **비포함(다음 단계)**: 매출 보고서 자동화(3단계)·제작요청 메일 사업부별 라우팅(4단계)·수출 서브서류 실제 연결(5단계, 지금은 체크 틀만).
