## 사본 만들기 (운영 서버에서 · 읽기 전용)

```bash
timeout 300 python3 -c "
import sqlite3,time,os
S='/opt/knk_haist/data/knk.db'; D='/tmp/wp02_rehearsal.db'
M=('mail_messages','mail_attachments','mail_aliases','mail_signatures','user_mail_creds','mail_large_files','mail_rules','mail_blocklist','mail_fetch_accounts','mail_fetch_seen')
t0=time.time(); src=sqlite3.connect('file:'+S+'?mode=ro',uri=True); dst=sqlite3.connect(D); src.backup(dst); src.close()
print('BACKUP_SEC',round(time.time()-t0,1),'FULL_BYTES',os.path.getsize(D))
n=0
for t in M:
    try: n+=dst.execute('DELETE FROM ['+t+']').rowcount
    except Exception: pass
dst.commit(); dst.execute('VACUUM'); dst.close()
print('MAIL_ROWS_REMOVED',n,'FINAL_BYTES',os.path.getsize(D)); print('SRC_BYTES_NOW',os.path.getsize(S))
"
```

- 원본은 `mode=ro` — **쓰기가 물리적으로 불가능**합니다(시도 시 `attempt to write a readonly database`).
- 삭제·압축은 **새로 만든 사본에서만** 일어납니다.
- 메일 10개 표를 비우는 이유: 메일이 용량의 99.4%이고 ERP 전환 범위 밖이기 때문입니다.

가져올 때는 `scp`·`sftp` 가 서버 로그인 메시지 때문에 실패하므로, 압축+텍스트 변환으로 받고 지문을 대조합니다:

```bash
ssh -p <SSH_PORT> <SSH_USER>@<OPERATIONS_HOST> "sha256sum /tmp/wp02_rehearsal.db; echo BEGIN64; gzip -c /tmp/wp02_rehearsal.db | base64 -w0; echo; echo END64" | Out-File -Encoding ascii "받을경로.b64"
```

> 접속 정보(`<SSH_USER>`·`<OPERATIONS_HOST>`·`<SSH_PORT>`)는 **저장소에 적지 않습니다.** 승인된 운영 비밀·환경 관리 문서에서만 확인하세요.

## 타입 매핑의 근거 — 기존 KNK 규정 그대로

새로 만든 규칙은 없습니다. 전부 **이미 확정된 규정**을 따릅니다.

| 대상 | PostgreSQL 타입 | 근거 |
|---|---|---|
| **수량** | `bigint` | **z1048**(2026-07-24 대표 지시) 수량=정수 · 실측: 수량 컬럼 10개 **소수 0건** |
| **금액** | `numeric` (정밀도 제한 없음) | **z1026**(2026-07-21 대표 확정) 원화=정수·외화 2자리 / **z1024** 왕복 반올림 금지 |
| 환율·마진·중량 | `numeric` | z1048 예외(소수가 정당한 칸) |
| **날짜·시각** | `text` (글자 그대로) | **WP-02 대표 결정**(2026-07-24) 1차는 원형 보존 · **KNK 시간대 표준 v1** 은 애플리케이션에서 판정 |
| 그 외 정수 | `bigint` | — |
| 단일 정수 기본키 | `bigint GENERATED BY DEFAULT AS IDENTITY` | SQLite AUTOINCREMENT 대응 |
| 복합 기본키 | `PRIMARY KEY (a, b)` | 실측 6개 표 |

### 금액에 정밀도를 지정하지 않는 이유 (실측 근거)

처음에 `numeric(20,2)`로 시도했다가 **두 가지 실제 문제**를 만났습니다.

1. **소수부가 최대 16자리인 값이 실재**합니다(부동소수점 계산 찌꺼기). `numeric(20,2)`로 받으면 반올림되어 합계가 달라집니다 — `order_items.unit_price` 에서 **0.0145 차이** 실측.
2. **정수부 20자리 이상값**이 있어 `numeric(20,2)`는 `numeric field overflow` 로 **이관 자체가 실패**했습니다.

1차 이관의 최우선 원칙은 **원본 보존**이므로(날짜를 글자 그대로 두기로 한 대표 결정과 같은 철학), 값을 그대로 담고 **z1026 규정은 애플리케이션에서 강제**합니다 — 현행과 동일합니다. 자릿수 정리와 이상값 판정은 별도 정제 단계에서 근거를 남기고 수행합니다.

> 참고: `double precision`(부동소수점)으로 옮기면 큰 금액에서 **19,460원 오차**가 발생합니다(실측). 금액에는 절대 쓰지 않습니다.

## 아직 이전하지 않은 것 (2차 범위 · `object_matrix.csv` 에 `미이전(2차)` 로 표시)

- 외래키 제약 **228개** (ON DELETE CASCADE 52 · SET NULL 4)
