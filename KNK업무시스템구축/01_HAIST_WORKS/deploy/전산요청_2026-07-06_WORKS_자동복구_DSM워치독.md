# [전산 요청] KNK WORKS 자동복구 — 외부 DSM 워치독 등록 (2026-07-06)

## 배경 (왜 필요한가)
KNK WORKS(업무시스템)는 **다운되면 안 되는 핵심 시스템**입니다. 신 컨테이너 구조에서 앱(uvicorn `knk-works`·5051)이 죽거나 멈추면(hang) 컨테이너 안에서 자동으로 되살릴 안전망이 필요합니다. (2026-06-22 WORKS 단독 502 등 실제 사고)

2중으로 자동화합니다:
- **1단계(이미 적용·LIVE, 2026-06-22)**: 컨테이너 **내부** 워치독 `works_watchdog.sh` — 루트(`/`) 생존확인을 감시해 앱이 죽거나 멈추면 `supervisorctl restart knk-works` 로 **사람 개입 없이 자동 재기동**. 부팅훅(`/root/.bash_profile` `KNK-WORKS-WATCHDOG-START`)에 등록되어 재부팅 후에도 자동.
- **2단계(이 요청)**: 컨테이너 **밖** DSM 워치독 — 1단계가 못 살리는 경우(**컨테이너 통째 멈춤 / NAS 재부팅 후 컨테이너 자체가 안 뜸 / 내부 워치독까지 죽음 / supervisord 사망**)를 위한 최종 안전망.

## 요청 사항 (전산, 1회 등록 — 약 5분)

### 1) 컨테이너 이름 확인 ★중요
NAS 에 SSH 접속 후:
```
docker ps --format '{{.Names}}'
```
→ **WORKS 컨테이너 이름 확인**(예상: `KNKHAIST.WORK`). 다르면 아래 스크립트의 `CONTAINER=` 값을 그 이름으로 **반드시 수정**. (컨테이너 안 hostname 은 `KNKHAIST` 이지만 docker 이름은 다를 수 있음)
+ 프로그램명 확인: `docker exec <컨테이너명> supervisorctl status` → `knk-works` 맞는지(다르면 `PROG=` 수정).

### 2) 워치독 스크립트 복사
첨부 파일 **`nas_watchdog_works.sh`** 를 NAS 호스트의
```
/volume1/docker/knk_haist/nas_watchdog_works.sh
```
로 복사하고 실행권한 부여:
```
chmod +x /volume1/docker/knk_haist/nas_watchdog_works.sh
```
(경로의 `knk_haist` 폴더명이 다르면 실제 경로로. 스크립트 내용은 경로와 무관.)

### 3) DSM 작업 스케줄러에 등록 (1분 간격)
**DSM > 제어판 > 작업 스케줄러 > 생성 > 예약된 작업 > 사용자 정의 스크립트**
- 사용자: **root**
- 일정: 매일 / 반복: **1분 간격**
- 실행 명령:
  ```
  sh /volume1/docker/knk_haist/nas_watchdog_works.sh
  ```
- 저장 후 **[실행]** 으로 1회 수동 테스트 → 로그 확인:
  ```
  cat /var/log/knk_watchdog_works.log
  ```

### 4) (강력 권장) 컨테이너 자동 재시작 켜기
**DSM > Container Manager > 컨테이너 > (WORKS 컨테이너) > 설정** 에서
**자동 재시작(restart=always)** 활성화 → **NAS 재부팅 시 컨테이너가 자동으로 다시 뜸**(재부팅 후 미기동 문제의 근본 해결).

## 동작 요약 (등록 후)
- 1분마다 컨테이너 루트(`/`) 생존확인 → 정상(어떤 HTTP 코드든 응답)이면 아무것도 안 함.
- 컨테이너가 멈춰 있으면 → `docker start`.
- 연속 2회(약 2분) 무응답(`000`) → ① 컨테이너 안 `supervisorctl restart knk-works` → 그래도 안 되면 ② `docker restart`.
- 복구/실패 시 **DSM 관리자 알림**(synodsmnotify) 발송.

## 검증 기준
- 등록 후 [실행] → `/var/log/knk_watchdog_works.log` 에 점검 기록이 남으면 정상.
- (선택) 업무 외 시간에 `docker stop <WORKS 컨테이너>` → 2~3분 내 워치독이 자동으로 다시 띄우는지 로그로 확인.
- **메신저·Mail 컨테이너 무영향**(WORKS 만 대상).

## 비고
- 1단계 내부 워치독(`works_watchdog.sh`)은 이미 적용되어 있어, **이 2단계 등록 전에도** 앱 단위 장애는 자동복구됩니다. 2단계는 '컨테이너 통째 장애·재부팅·supervisord 사망'까지 막는 최종 안전망입니다.
- 비밀값(.env)·WORKS 코드는 건드리지 않습니다. 이 작업은 **DSM 호스트 측 스케줄러 등록 + 컨테이너 자동재시작 설정**뿐입니다.
