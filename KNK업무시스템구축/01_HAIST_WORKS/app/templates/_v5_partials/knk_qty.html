{# v5H226z1048 (대표 지시): 수량 입력칸 = **정수 전용** 공용 규정. ──────────────────────────────────────────────────────────────────────── 왜 만들었나 — 안지연 프로 신고(2026-07-24) *"수량 +1 단위로 올라갔으면 좋겠는데 또 0.01 단위로 변하네요 ^^ 왜 안바꿔주시죠?"* *"이전에도 다른 페이지에서 수정을 한것 같은데... 또 이러네"* → 대표: **"수량 규정으로 입력해서 모두 적용해줘"** 전수 조사 결과 `step="0.01"` 이 **26곳**. 한 곳씩 고치면 새 화면에서 계속 재발한다 (실제로 복사되어 퍼졌다) → **공용 규정으로 건다**(현황판 §4 3겹 원칙 ②공용 코드로 강제). 무엇을 하나 · 수량 성격의 `input[type=number]` 를 찾아 **step=1** 로 바꾸고 소수 입력을 막는다. · 🔴**min 도 같이 정수로 올린다** — HTML 숫자칸의 유효값은 **min 을 기준으로 step 씩** 증가한다. `min=0.01 · step=1` 이면 허용값이 0.01 → 1.01 → 2.01 이 되어 **고치나 마나**가 된다(실제 함정). · 이미 소수가 들어 있는 값은 **건드리지 않는다** — 사람이 보고 고치게 둔다(말없이 바꾸지 않는다 · cf §4 규칙 32). 대상 판별(이름으로) name / id / class / data-k 에 qty · quantity · 수량 이 들어간 것. ⛔예외 `data-knk-decimal` 을 붙이면 건너뛴다(소수가 정당한 칸 — 중량·환율 등). 단가·금액·환율·비율은 애초에 대상이 아니다(price/amount/rate/pct 이름). ⚠새 화면은 아무 것도 안 해도 된다 — styles.html 이 이 파일을 include 하므로 자동 적용된다. ⚠배포 전 `deploy/check_standards.py` 가 새로 들어온 소수 수량칸을 잡는다. #}
