문서 본문에 `HEAD` 해시를 적으면 **그 문서를 고치는 커밋 자신을 셀 수 없어 반드시 틀려진다.**
V1 초판에서 실제로 "11 앞"이라 적었으나 실제는 12였다(자기참조 오류).

### 3.2 어떻게 고쳤나

- 본문에서 **HEAD 해시를 전부 제거**했다
- 판정 기준을 **코드 최종 커밋 `6ddda6cf`** 로 고정했다 — 그 뒤 커밋은 문서뿐이므로 판정에 영향이 없다
- `origin/main..HEAD` **커밋 목록을 판정 근거로 쓰지 않는다** — 문서 커밋이 섞여 숫자가 흔들리기 때문

### 3.3 기계 확인

```
git diff --stat 6ddda6cf..<문서 커밋들>   →  .md 파일만
git diff --name-only 6ddda6cf..<위와 같음> | grep -E "^(app|tests|deploy)/"  →  없음
```

**판정하실 코드는 `6ddda6cf` 하나입니다.**

## 4. ④ 화면 증거 경로 연결 — ⚠ 조건부 (한계를 명시함)

### 4.1 이미지 파일은 없습니다 — 정직히

V1 §8.4 에 이미 적었듯, **로컬 화면 확인의 캡처 이미지 파일은 저장소에 0개**다. 이유는 두 가지다.

1. 실물 BOM 화면에는 **고객 단가**가 들어 있어 저장소에 커밋할 수 없다
2. 캡처를 자동으로 남기는 장치를 A단계 범위에서 만들지 않았다

**"캡처 7종을 찍었다"는 문장은 이미지 파일이 있다는 뜻이 아니다.** 화면을 띄워 눈으로 확인했다는 뜻이다.

### 4.2 대신 무엇으로 증명하는가 — 기계 실측

이미지 대신 **HTML 을 직접 받아 파싱하거나 브라우저에서 값을 재는 방식**으로 남겼다.
사람이 "봤다"고 말하는 것보다 재현 가능하고, 숫자로 검증된다.

| 확인 항목 | 증명 방식 | 결과 |

| 원본↔읽은값 대조 | 임시 DB 라우트 실행 + 응답 파싱 | 13줄·160줄·319줄 전부 일치 |

| 불일치 전체 목록 | 결과화면 HTML 파싱 | 전 건 렌더 확인 |
