## 1. 대표 확정 지시 대응 (2026-07-25)
### 1) 호기 분할·통합 — "구조만, 실행 없음"
| 지시 | 구현 |
|---|---|
| 단일 필드(`split_from`) 금지 · 1:N·N:1 관계 구조 | `project_unit_relations` **행 단위 관계** — 원본·결과·유형(SPLIT/MERGE)·사유·change_id·적용시점·처리자·**승인자**·기록시각 |
| 실행 버튼·API·승인 없음 | 라우트·모듈에 **생성 경로 없음**(읽기 `get_unit_relations`만) — 테스트로 실증 |
| 일반 사용자 생성 차단 | 앱에 쓰기 경로 자체가 없음 · `/units/{id}/split` = **404** 실증 |
| 기존 Unit 물리삭제 금지 | 취소=CANCELLED · 분할 원본 보존 실증 |

### 2) BOM·발주·생산 영향 경고 — "거짓 통과 금지"
| 지시 | 구현 |
|---|---|
| 작동 안 하는 경고를 정상처럼 보이면 안 됨 | `impact_status()`가 표 미존재를 **`wired=False`(미연동)** 로 반환 — **'영향 없음'이라 말하지 않음** |
| 안내 문구 | 화면 상단 상시 노출: **"BOM·발주·생산 영향 분석은 아직 연동되지 않았습니다. 영향 확인이 필요한 호기 변경은 승인 처리할 수 없습니다."** |
| 영향 확인 필요한 변경은 실행 불가 | **확정(CONFIRMED) 호기**의 번호 변경·취소 = 미연동 상태에서 **차단**. 개발·미확정은 정리 가능(문서 §4: "BOM Release·발주·생산투입 **이후** 변경은 Change 승인 필요") |
| 이력 있으면 승인 없이 변경 불가 | 연동되면 `has_impact` 검사로 자동 전환(코드에 이미 구현) |
| WP-04 연동 대상·완료 조건 명시 | 아래 §5 |

## 2. 데이터 구조 (표 4개)
```
프로젝트(관리번호)
  └─ 호기 project_units [영구 id]  ← BOM·자재·생산·출하가 붙는 유일한 축
       ├─ 개발호기명(working_name) · 현재 호기번호(NULL 가능) · 상태 3종
       ├─ 호기번호 변경이력  project_unit_identifier_history
       ├─ 수주 다중 연결      project_unit_order_links  (ORIGIN/추가/변경/취소)
       └─ 분할·통합 관계      project_unit_relations    (V1=구조만)
```
- **현재 호기번호 유일성** = 같은 프로젝트·**미취소** 건에서만(취소된 호기 번호는 재사용 가능 — 실증)
- 씨앗 출처(`seed_order_no`·`seed_unit_label`) 불변 스냅샷 보존
