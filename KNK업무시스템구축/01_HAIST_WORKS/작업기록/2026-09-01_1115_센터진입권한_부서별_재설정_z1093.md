- **작성**: 2026-09-01 (화) 11:15 KST
- **지시**: 대표 — *"김동후,김정락,기술영업팀,관리팀은 지금 적용된 사항으로 보존하고 나머지 부서들 권한을 수정해줘. … 테스트 기간이라 이렇게 먼저 적용해서 완료되면 다시 부서별, 개인별 권한 재 부여예정임."*
- **화면**: 관리자 → 사용자 수정 → 🔑 센터 진입 권한

## 1. ⭐ 먼저 찾은 것 — 화면에서 꺼도 소용이 없었다

지시를 받고 코드를 보니, 체크박스만 정리해서는 **지시를 이행할 수 없는 구조**였다. 두 가지 이유다.

### ① 앱을 켤 때마다 권한을 되살리는 코드

`database.py` 의 권한 시드에 주석까지 **"idempotent, 매 init 실행"** 이라고 적혀 있었다.

```python
UPDATE users SET can_view_logistics=1 WHERE role='member' AND team_id IN (1,2,3,7,8,9,10)
UPDATE users SET can_view_sales=1     WHERE role='member' AND team_id IN (1,2,3)
```

→ 관리자 화면에서 체크를 꺼도 **다음 기동 때 다시 켜졌다.** 실제로 운영 플래그 현황이 이 두 줄의 결과와 정확히 일치했다(검사기 9명 전원 vSales=1 등).

### ② 팀 번호·직책으로 무조건 여는 코드

| 함수 | 코드가 무조건 열던 대상 |
|---|---|
| `can_view_sales` | 팀 1·2·3 |
| `can_use_sales` | 팀 1·2·3 + **`can_use_logistics` 폴백** |
| `can_view_logistics` | 팀 1·2·3·7·8·9·10 |
| `can_use_logistics` | 팀 7·10 |

특히 `can_use_sales` 끝의 `return can_use_logistics(user)` 때문에
**자재·구매 등록 권한자에게 매출·영업 등록까지 딸려 열렸다** — 구매팀이 정확히 그 경우라
"구매팀 = 매출영업 접근불가" 지시와 정면으로 어긋났다.

## 2. 고친 것 (4겹)

| 층 | 파일 | 내용 |
|---|---|---|
| DB 시드 | `app/database.py` | **매 기동 팀 시드 2줄 제거** — 이게 없으면 무엇을 해도 되살아난다 |
| DB 1회 세팅 | `app/database.py` | 지시대로 부서 권한 세팅 (**`app_settings` 가드로 딱 1회**) |
| 서버 판정 | `app/main.py` | 권한 함수 4개에서 **팀 번호 자동 허용 제거 + 폴백 제거** |
| 화면 안내문 | `admin_user_form.html` | *"팀 1·2·3은 기본 허용"* → *"체크한 대로만 열립니다"* |

**역할(`admin`·`ceo`·`executive`) 자동 허용은 그대로 유지**했다. 대표 결정(*"관리자는 예외 — 그대로 둠"*)이며,
이걸 빼면 본사 관리팀 세 분(체크가 전부 꺼져 있고 관리자 역할로만 열려 있음)까지 막혀 보존 지시를 어기게 된다.

### 1회 가드가 꼭 필요한 이유

대표가 *"완료되면 다시 부서별·개인별 권한 재부여 예정"* 이라고 했다.
1회 가드가 없으면 그 재부여가 **다음 기동 때 이 세팅으로 덮여** 사라진다.
`app_settings.z1093_center_perm_reset` 표시가 남으면 두 번 다시 돌지 않는다.
(다시 적용하려면 그 키를 지우고 재기동)
