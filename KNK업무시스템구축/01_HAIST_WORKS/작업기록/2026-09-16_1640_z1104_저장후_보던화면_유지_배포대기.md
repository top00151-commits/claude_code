## 2. 원인 (코드 실측)

작업일정표에서 관리번호를 누르면 그 수주번호를 **`?so=<수주번호>`** 로 넘긴다
(`schedule_board.html:213` → `main.py:6540` → `project_detail.html:536`, z695).
상세는 그 조건이 있으면 **그 수주를 메인(편집) 카드로** 올리고, 없으면 **가장 오래된 수주(최초 수주)** 를 올린다.

그런데 저장 뒤 새로고침이 이랬다:

```js
window.location.href = window.location.pathname + '?_t=' + Date.now();
```

`pathname` 만 쓰므로 **지금 주소의 조건이 통째로 버려진다** → `?so=` 가 사라짐 → 규칙대로 최초 수주 카드가 뜬다.
**같은 줄이 `project_detail.html` 안에 8곳**이었다(한 곳만 고치면 나머지 7곳에서 그대로 재발).

### 딸려 있던 두 번째 결함 — 화면 위치도 맨 위로

화면 위치 복원(z984b·대표규정)의 열쇠는 `knkpos:` + 경로 + **주소 조건**이다(`chrome.html:1079`).
`_t` 값이 저장할 때마다 달라지니 **같은 화면인데 열쇠가 매번 달라져** 복원할 것을 못 찾았다.
즉 «저장하면 화면이 맨 위로 올라가는» 것도 같은 원인이었다.

- 전 템플릿 293개 스윕: 이 패턴은 **`project_detail.html` 에만** 있었다.
- 서버에서 `_t` 를 읽는 곳 **0곳** — 순수 캐시버스터다(실측).

## 3. 고친 내용

### ① 공용 새로고침 한 벌 — `_v5_partials/chrome.html` (전 화면 공통 · 209개 화면이 포함)

```js
window.knkReloadKeepView = function(){
  try {
    var sp = new URLSearchParams(location.search || '');
    sp.set('_t', String(Date.now()));          /* 캐시버스터는 갱신 */
    var q = sp.toString();
    location.href = location.pathname + (q ? ('?' + q) : '');
  } catch (e) { location.reload(); }
};
```

주소의 조건은 그대로 두고 `_t` 만 갈아끼운다(쌓이지 않음). 옛 브라우저 폴백은 `location.reload()` — 그 역시 주소를 안 버린다.

### ② 위치 복원 열쇠에서 `_t` 제외 — 같은 파일 `normSearch`

```js
if ((eq < 0 ? p : p.slice(0, eq)) === '_t') continue;   /* 값이 매번 달라 열쇠가 어긋났다 */
```

→ **저장 전·후가 같은 열쇠** → 보던 위치 그대로.

### ③ `project_detail.html` 8곳 전부 `knkReloadKeepView();` 로 교체

### ④ 배포 전 검사기 — `deploy/check_standards.py` `check_reload_keep_view`

`location.href/assign/replace` 에 `location.pathname + '?…'` 를 넘기는 자리를 잡는다(줄바꿈·공백 변형 포함).
주석·Jinja 주석은 뺀다. 같은 실수가 다시 들어오면 **배포 전에 막힌다.**
