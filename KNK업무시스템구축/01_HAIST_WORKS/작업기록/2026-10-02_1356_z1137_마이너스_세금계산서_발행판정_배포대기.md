## 2. 원인 — 「금액은 플러스」라는 가정이 판정에 남아 있었다

z1135 는 **입력**에서 이 가정을 고쳤다(`-` 를 지우던 재포맷). 같은 가정이 **판정·집계** 세 곳에 더 있었다.

| 곳 | 예전 식 | 결과 |
|---|---|---|
| 작업일정표 색 판정 `refreshTaxStatus` | `if(anyAmt && total>0)` | 마이너스 수주는 판정을 통째로 건너뜀 → **무색** ← 신고 |
| 작업일정표 1차 금액 미리 채움 | `if(rt>0)` | 마이너스 건만 빈칸 → `-` 를 손으로 쳐야 함 |
| 납품·수금 `sales_shipments_receipts_page` | `nothing_issued = 발행합계 <= 0` · `잔액 > 0` 일 때만 발행 대기 | 마이너스로 다 끊은 건이 「전부 미발행」에 세어짐 · 마이너스 수주를 안 끊으면 **어느 목록에도 안 나옴** |

진짜 함수 원문을 node 로 돌려 재현했다(고치기 전):

| 넣은 값 | 색 |
|---|---|
| 수주 -1,865,000 / 1차 -1,865,000 (운영 실제값) | **무색** |
| 수주 +1,865,000 / 1차 +1,865,000 | 초록 |
| 마이너스 건에 **플러스로 잘못** 넣음 | **무색** — 틀려도 안 걸러졌다 |

### 문제없던 곳 (확인만 함 · 손대지 않음)

## 4. 고친 것

### 작업일정표 (`app/templates/schedule_board.html`)

- 색 판정: `total>0` → **`total!==0`**. 합계=수주금액이면 초록, 다르면 주황(부호가 달라도 주황).
  수주금액 0(미입력)만 판정에서 뺀다 — 견줄 금액이 없다.
- 1차 금액 미리 채움: `rt>0` → **`rt!==0`**. 마이너스 수주도 수주금액 그대로 미리 채운다.
- 범례 풍선말에 「마이너스(네고·할인) 건도 같은 기준」.

### 납품·수금 (`app/main.py`)

- 발행 판정을 순수 함수 **`_sr_bill_state(total, issued_amt, eps)`** 로 뺐다.
  미발행 잔액을 **수주금액의 방향으로** 본다(플러스 수주는 +, 마이너스 수주는 −). 넘겨 끊은 쪽은 예전처럼 0.
  「하나도 안 끊음」= 발행합계의 **크기**가 0.
  **수주금액 0 이상 · 발행합계 0 이상인 건은 예전 식과 한 글자도 다르지 않다**(308조합 전수 대조).
- 위쪽 「마감이월」 숫자 = **줄의 상태가 마감이월인 수**(대표 결정 «목록과 맞춘다»).
- 발행 칩: 마이너스 금액만 적고 발행일이 없어도 「끊은 것」으로 표시(`abs`).
- 「챙길 것」 정렬: 잔액 **크기** 순.

### 납품·수금 화면 (`_v5_partials/_sr_row.html` · `sales_shipments_receipts.html`)

- 미발행 잔액 강조색: `> 0` → `!= 0`(마이너스 잔액도 남은 것).
- 「미발행 잔액 많은 순」 정렬: 크기로.

### 검사기 (`deploy/check_standards.py`) — `check_tax_sign`

① 색 판정이 `total>0` ② 수주금액(`rowamt`)을 `>0` 으로 거름 ③ `_sr_bill_state` 가 없거나 **원문을 뽑아
실제로 돌려 보니** 마이너스를 미발행으로 봄 ④ 화면 함수가 스스로 판정 ⑤ 위쪽 숫자를 줄 상태와 다른 조건으로 셈
⑥ 잔액 강조가 `> 0`. 주석에 옛 조건을 적어 둔 것은 안 잡는다.

- (곁) z1135 때 내가 쓴 설명글의 `\-` 가 파이썬 3.12 에서 `SyntaxWarning` 을 내고 있었다 → 원시 문자열로.
