## 3. ⭐근본 버그 2개 (이번에 드러남)

### 3-1. 공휴일 이름이 **영어**로 나와 제헌절 제외가 무력화 (7/17 이 빨간 공휴일)

- `holidays` 라이브러리는 `language=` 를 **안 주면 OS 로케일**(`LANGUAGE`/`LANG`)을 따른다.
  LIVE 컨테이너가 한국어 로케일이 아니어서 **`"Constitution Day"`** 를 돌려줬다.
- 그런데 제외 규칙이 `if "제헌절" in name: continue` — **한글 이름 검사**라서 **안 걸렸다.**
  → **7/17 이 빨간 공휴일로 표시**(LIVE 실측). 툴팁도 영어.
- **로컬 재현 성공**: `LANG=en_US.UTF-8 LANGUAGE=en_US python -c "holidays.KR(years=[2026])['2026-07-17']"` → `Constitution Day`.
- **근본 수정**: `KR(years=…, language="ko")` · `VN(years=…, language="vi")` **명시**.
  같은 명령을 영어 로케일에서 다시 돌려 `제헌절` 이 나오고 **제외까지 되는 것**을 확인.
  구버전 라이브러리(=`language=` 미지원)면 `TypeError` 를 잡아 인자 없이 재시도 → **날짜는 절대 잃지 않음**.
- 이름 판정은 한글·영문 둘 다 차단: `_KR_HOL_DROP = ("제헌절", "constitution day")`.

### 3-2. 베트남 **대체공휴일 점선**이 처음부터 한 번도 안 그려지고 있었다

- 템플릿들이 `{% if 'Nghỉ bù' in d.hol_vn %}alt{% endif %}` 로 판정 — **대문자 N**.
  라이브러리 실제 값은 **소문자** `Ngày Giỗ Tổ Hùng Vương (nghỉ bù)`. → **영원히 False.**
- → 서버 `_hol_is_alt(name)` / 화면 JS `isAltHol(name)` 공용 함수로 통일
  (`대체` · `nghỉ bù` · `alternative` · `substitute` 4표기를 소문자로 비교).
- 이제 `HOLIDAYS_VN` 값이 한국어라서 `대체휴일` 로 잡히고, 언어가 또 바뀌어도 안 깨진다.

## 6. 못 고친 것 · 남은 것 (정직히)

1. **2026-08 / 09 월은 로컬 DB에 행이 없어 두 일정표 화면으로는 못 봤다.**
   두 화면은 `{% if rows %}` 라 데이터가 없으면 표 자체가 안 그려진다.
   → **엔진·`_calendar_day_marks` 단위 검증으로는 8/15 광복절·8/17 대체·9/1·9/2 국경절이 전부 정상**임을 확인했고,
   화면 렌더는 데이터가 있는 2026-01~07 로 대신 확인했다(같은 코드 경로).
   **LIVE 에서 8월로 넘겨 한 번 더 눈으로 볼 것.**
2. **`so_calendar.html` 은 죽은 부품**(include 0곳)이다. 이번엔 일관성만 맞추고 **삭제하지 않았다** — 삭제는 별도 판단 필요.
3. **베트남 공휴일명 한국어 표기표(`_VN_HOL_KO`)는 12건 수동 표**다. 라이브러리가 새 이름을 내면 **베트남어 원문이 그대로 보인다**(깨지지는 않음). 새 이름이 보이면 표에 추가.
4. **`/calendar` 셀 배경(`.holiday{background:#fef2f2}`)은 한국·베트남 공휴일을 구분하지 않는다** — 규정에 그 색 조항이 없어 **손대지 않았다**(현행 유지).
5. 규정 §1 의 **줄 번호 표기는 예전 값이라 이미 어긋나 있다**. 이번에 공휴일 엔진 항목만 '함수 이름 기준'으로 고쳤고, 나머지 줄 번호는 그대로 뒀다.
