# 세금계산서·단가 금액에 소수점이 입력되지 않던 문제 — z1095

- **작성**: 2026-09-07 (월) 11:55 KST
- **신고**: 이새롬 프로 — *"수정 후 세금계산서 금액 입력 시 소숫점이 입력이 안됩니다."* (023T2508 PBA · KNK VINA · USD)
- **지시**: 대표 — *"달러 입력 기준 조건이 있어… 연결되는 모든 사항에도 반영이 정확하게 될 수있도록 정리하고 실제로 다 반영이 되는지도 확인을해."*

## 1. 원인 — 같은 결함의 **재발**이다

`z986`에서 **대표님이 같은 신고**를 하셨다(*"소수점 이하 직접 입력이 아예 안 됨"* · 005M2510 EUR).
그때 **작업일정표만 고쳤다** — 커밋 제목이 `fix(works/board)` 다. 프로젝트 화면 두 곳이 빠져 그대로 남았다.

금액칸의 콤마 재포맷이 이렇게 돼 있었다:

```js
var raw = pa.value.replace(/[^0-9]/g, '');   // 숫자만 남긴다 → '.' 이 키 입력 즉시 사라진다
pa.value = raw ? Number(raw).toLocaleString() : '';
```

| 화면 | 소수점 | 상태 |
|---|---|---|
| 작업일정표 | ○ | z986에서 고침(`_fmtAmtTyping`·`inputmode=decimal`) |
| **프로젝트 상세 — 세금계산서 팝업** | **✕** | **z986 누락** ← 이번 신고 |
| **프로젝트 등록·수정 — 항목 단가** | **✕** | **z986 누락** |
| 소모품 상세 | ○ | 재포맷기가 없어 원래 입력 가능(`inputmode`만 numeric이었음) |
| 서버 저장·DB·집계 | ○ | `float()` / `REAL` — 손댈 것 없음 |

### ⚠ 못 넣는 것으로 끝나지 않았다 — 고치면 10배가 된다

`1,315.5` 가 든 칸에서 숫자를 한 글자만 눌러도 소수점이 사라져 **`13,155`** 가 된다.
그대로 저장하면 매출이 10배로 잡힌다. 시험에서 옛 코드로 실제 재현했다(§4 §2).

### 달러 입력 기준 조건

`_fmt_money`(z750→**z751 대표 지시 통화 표시 표준**): **KRW 정수 · 외화 소수 2자리**(셋째 자리 ROUND_HALF_UP).
타이핑 중에는 통화가 바뀔 수 있어 **소수 2자리까지 받아 두고**, KRW 정수화·반올림은 서버 저장과 표시가 맡는다.

### 재발 방지 검사

`replace(/[^0-9]/g` 가 **금액 문맥(±3줄)** 에 있으면 배포 전에 잡는다.
⚠ 변수명이 `pa` 처럼 짧아 같은 줄만 봐서는 못 잡는다(실제 사례) → 주변 줄까지 본다.
날짜(YYYYMMDD)·전화번호 정규화는 `[^0-9]` 가 정당하므로 잡지 않는다. 주석도 제외한다.

### 화면 실측 — **실제 팝업 코드를 그대로 떼어 브라우저에서 한 글자씩 타이핑**

```
금액칸 inputmode = decimal
기존값 초기표시 = "1,315.5"
 '1' → "1"   '3' → "13"   '1' → "131"   '5' → "1,315"
 '.' → "1,315."      ← 옛 코드는 여기서 소수점이 사라졌다

저장 클릭 → 서버로 보낸 값  tax_invoice_amt1="1315.5"
셀 data-amt(다음 편집 기준) = "1315.5"
셀 화면 표시 = "1,315.50 USD"
```

**입력 → 전송 → 저장값 → 재표시**까지 소수가 정확히 흐르는 것을 실물로 확인했다.

## 5. 손대지 않은 것

- 작업일정표(`schedule_board.html`) — z986로 이미 정상. 무접촉.
- `_tiFmtAmt` 의 **통화 기호 위치** — 이 함수는 `1,315.50 USD`(코드 뒤), 서버 `money()` 는 `$1,315.50`(기호 앞).
  **금액 값은 양쪽 다 정확**하고 이번 신고와 무관해 범위에 넣지 않았다. 표기 통일은 별건.
- 수량 정수 규정(z1048) — 금액과 별도 편집기라 영향 없음(시험 §5로 확인).
