# 화면 위치 복원 표준 — "돌아오면 보던 자리 그대로" (z984)

- **일자**: 2026-07-16 (최초 응답 '보류'는 대표 오클릭 — 정정 승인 "진행해"로 배포)
- **신고**: 김정락 대표 — "작업화면 이동 시 이전 위치로 갔으면… 목록에서 스크롤 내려 관리번호 찾아 들어갔다가 목록/저장으로 돌아오면 맨 위로 리셋돼 또 찾아야 함. 이 부분만이 아니라 거의 다 이래. 수정하고 **규정으로 등록**해달라." (사례: 소모품 발주 목록 101C2512 → 상세 → ←목록 → 맨 위 리셋)
- **결론 한 줄**: 원인은 SPA 전환기(spa_nav)가 본문 교체 직후 무조건 `scrollTo(0,0)` 리셋 + 위치 기억 장치 부재. 공용 레이아웃(chrome.html) 전역 1곳에 "URL별 위치 기억+복원"을 심어 **전 화면 자동 적용**.

## 1. 원인
- 인앱 이동은 SPA 전환(spa_nav — 본문 .main만 교체)인데, 교체 직후 `newMain.scrollTop=0; window.scrollTo(0,0)` 로 항상 맨 위 리셋. 뒤로가기(popstate)도 같은 경로라 동일.
- 저장 후 새로고침(작업일정표 셀 편집 등 reload 패턴)도 위치 소실.
- 위치를 기억해 뒀다 복원하는 장치가 앱 어디에도 없었음.

## 2. 조치 — chrome.html 전역 IIFE (`__knkScrollRestore984`)
- **저장**: URL(경로+쿼리)별로 창 스크롤 + 본문(.main) 스크롤을 sessionStorage(탭 단위)에 수시 저장 — 스크롤 스로틀(150ms) + **링크 클릭 직전(pointerdown)** + 창 떠날 때(pagehide).
- **복원**: 같은 URL로 다시 오면 그 위치로 — ①SPA 전환(`knk:navigated` 후 setTimeout 0 → spa_nav 리셋 '다음'에 실행) ②전체 로드/새로고침(DOMContentLoaded) ③뒤로가기 모두. 긴 표가 늦게 그려져도 문서 높이가 찰 때까지 **최대 2초 재시도**.
- **생략 규칙**: `#앵커` 또는 `focus_ref/focus_so` 파라미터 진입(명시적 이동·보드 강조)은 복원하지 않음.
- 탭 단위(sessionStorage)라 탭 닫으면 초기화 — "며칠 전 위치로 튀는" 혼란 없음.

## 3. ⭐ 규정 (전 화면 공통 — 메모리 `knk_scroll_restore_standard`)
1. **새 화면은 별도 작업 불필요** — chrome.html 포함(표준 레이아웃)만으로 자동 적용.
2. 페이지 코드에서 **임의 `scrollTo(0,0)` 재설정 금지** (명시적 앵커/강조 이동 제외).
3. 특정 위치로 이동시키는 기능은 `#앵커` 또는 `focus_*` 파라미터를 사용(복원과 충돌 없음).
4. 저장 후 같은 URL로 reload/redirect 하면 위치가 유지된다 — 저장 흐름 설계 시 이를 전제.

## 4. 검증
- Jinja(chrome.html) + esprima(z984 IIFE·spa_nav 회귀) ✅
- 배포 후 LIVE: 소모품 발주 목록 스크롤→상세→[← 목록] 위치 복원 / 작업일정표 셀 저장 reload 후 위치 유지 확인.

## 5. 부수 효과
- 작업일정표 셀 편집(450ms reload)·상품 수량 편집 등 **모든 reload 패턴이 보던 위치를 유지**하게 됨.
- 뒤로가기(popstate)도 위치 복원.
