## 1. 원인 — 동명 종사업장에서 LIMIT 1 이 항상 본사를 선택

- **실측(읽기 전용 DB)**: 드림텍 본사(id 74)·아산(id 75)의 **정식명이 바이트까지 동일** `(주) 드림텍`
  (customers.name UNIQUE 는 도입 전 구데이터라 동명 2건 존재). 구분은 시스템명(alias)뿐
- 전환기 주력 흐름 = **신규 등록 화면에서 기존 관리번호 + 비신규 PO유형(개조 등)** → 추가 발주 전환(z202).
  이 경로의 발주처 매칭이 `WHERE name=? LIMIT 1` → 엑셀 이름 "(주) 드림텍" 입력 시 **id 빠른 본사(74) 고정**
  → SO 발주처=본사 → 작업일정표·상세가 본사로 표기(z705: SO 발주처 우선)
- 프로젝트 자체 고객 연결은 z651/z653 으로 이미 안전(그래서 프로젝트 정보는 아산) — **SO 발주처 경로만 낡은 매칭**이 남아 있던 것

## 2. 수정 — z651 공용 해석(resolve_customer_id)으로 교체

| 입력 | 결과 |
|---|---|
| picker 로 종사업장 선택 | 그 선택(최우선) |
| 이름 타이핑 — 유일 후보 | 자동 연결 |
| 이름 타이핑 — **동명 다수** (드림텍 사례) | 자동연결 금지 → **기존 프로젝트 고객(아산) 상속 저장**(z202 원설계) |

→ **아산 프로젝트에 엑셀 이름을 그대로 쳐도 처음부터 아산으로 저장** — 요청 충족. 본사 발주가 진짜면 시스템명 '드림텍(본사)' 입력 또는 picker 선택.
