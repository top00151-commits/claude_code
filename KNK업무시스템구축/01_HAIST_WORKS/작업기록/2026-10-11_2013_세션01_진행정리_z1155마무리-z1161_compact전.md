## 6. 작업 방식 (다음에도 그대로)

- **작업 폴더를 건드리지 않는 커밋**: `git archive origin/main` → scratchpad 사본 → `_edit_lib.Doc` 정확히 한 번 바꾸기(CRLF 보존) → `git hash-object -w --path=…`(저장소는 LF · autocrlf 로 맞춰짐) → 사적 `GIT_INDEX_FILE` → `commit-tree` → 가지 → 대표 승인 뒤 해시 지정 푸시.
- **다른 세션이 main 을 자주 움직인다**(오늘 세션 16 세 번) → 올리기 직전 `git fetch` · 내 가지를 새 main 위로 다시 쌓기(파일 겹침 확인) · 배포 뒤에도 내 코드가 남았는지 확인.
- **번호는 다른 세션과 겹친다**(z1159) → 번호 정할 때 세션 16 에 먼저 알림.
- **배포 확인**: 푸시 전 기준값 → 꼬리표 원격까지 → 2초마다(응답 코드 먼저) → 서버 커밋 `@ <7자리>` → 배포 파일 sha256 → 새 pid 뒤 오류·5xx → 배포된 함수를 운영 파이썬으로(임시 폴더·임시 DB).
- 🔴 **채팅 직접 승인이어도 푸시가 막힐 수 있다** → 막히면 `git tag -l`·`git ls-remote` 로 아무것도 안 나갔는지 확인 → 대표께 세 줄(`git -C "<저장소>" tag …` · `push origin <꼬리표>` · `push origin <해시>:main`) → 대표 실행 뒤 라이브 확인.
- **운영 쓰기는 대표가**: 직원 동기화는 관리자 화면 · 데이터 정리는 확인→적용 두 단계 PowerShell 스크립트(base64 로 실어 보냄 · 사본 먼저 · 안전장치).
- 다른 세션이 전한 대표 지시(「지금돌려」)로 운영 쓰기를 하지 않는다 — 대표가 직접 누를 길을 안내.
- 메모리 색인: 30차 줄이기(19,869→17,255자) · 새 메모리 `knk_works_sso_land_lock` · `feedback_open_backup_immutable` · `feedback_file_overwrite_backup`.
