## 1. 먼저 — 발송은 성공했다

보내는 주소가 **`top0015@knknara.co.kr`** 로 나가고 **도착까지 했다.**
→ **「받기 계정 자격증명을 SMTP 에 재사용」이 실제로 통한다**는 것이 실증됐다.
하이웍스 「메일 전용 비밀번호」가 POP3·SMTP 공용이라는 추정도 맞았다.

남은 문제는 **배달 위치**(스팸함)였다.

## 2. 진단 — 짐작하지 않고 실측

| 확인 | 결과 | 판정 |
|---|---|---|
| SPF (`knknara.co.kr` TXT) | `v=spf1 include:_spf.hiworks.co.kr ~all` | ✅ 하이웍스 = 정식 발송자 |
| MX | `mailapp.hiworks.co.kr` | ✅ 정상 |
| DMARC (`_dmarc.knknara.co.kr`) | **레코드 없음** | ⚠ 신뢰 신호 하나 빠짐 |
| DKIM 흔한 선택자 10종 | 전부 없음(진짜 선택자는 헤더에만) | — 미확정 |
| **같은 도메인의 다른 메일** | 관리팀·소프트웨어팀 주간보고(11-13)가 **받은편지함**에 정상 도착 | ⭐**도메인 문제 아님** |

→ 도메인·SPF 가 멀쩡한데 우리 메일만 스팸 → **우리가 만든 메시지 자체**를 봐야 한다.

### 결정적 실측

우리 코드가 만드는 헤더를 그대로 재현해 찍어 봤다.

```
--- 구성 직후 헤더 ---
    From / To / Subject / Content-Type / Content-Transfer-Encoding / MIME-Version
send_message 안에 일반 Date 를 넣는 구문 : 없음   (Resent-Date 만 2회)
send_message 안에 Message-ID 추가        : False
```

**→ 우리가 보낸 메일에는 `Date` 도 `Message-ID` 도 없었다.**

- `Date` 는 **RFC 5322 필수** 헤더다. 없으면 규격 미달이다.
- `Message-ID` 도 사실상 모든 정상 메일이 갖는다.
- `EmailMessage` 는 이 둘을 만들지 않고, `smtplib.send_message` 는 **`Resent-Date` 만** 다룬다.
  → 아무도 안 넣어 주는데 우리도 안 넣었다.

하이웍스 **웹메일**로 보낸 동료분들 메일에는 당연히 들어 있었고, 그래서 받은편지함으로 갔다.

## 3. 고침

`app/mail_send.py` 에 `_stamp_required_headers(msg, from_email)` 신설.

```
Date       = 보내는 사람 시간대(한국 +9)
Message-ID = 보내는 도메인으로 (<...@knknara.co.kr>)
이미 있으면 덮어쓰지 않음 (중복 헤더 금지)
```

발송 경로 **두 곳 모두**에서 호출 — `_smtp_send`(현행) · `send_mail`(옛 경로).

## 5. ⏭ 남은 것

1. **대표 재시험** — 다시 한 통 보내 받은편지함으로 가는지.
2. **지메일 스팸함에서 「스팸 아님」 누르기** — 지메일은 이 신호를 강하게 학습한다.
   이미 스팸으로 간 그 메일에 대해 한 번 눌러 주시면 다음부터 크게 달라진다.
3. **그래도 스팸이면** — 그 메일에서 **「메시지 원본 보기」** 를 열어
   맨 위 **SPF / DKIM / DMARC** 세 줄만 알려 주시면 바로 짚는다.
   (본문·비밀번호는 보내지 마실 것)
4. **`_dmarc.knknara.co.kr` 레코드 없음** — 지메일 신뢰 신호가 하나 빠진 상태.
   다만 **같은 도메인 다른 메일은 정상 수신**되므로 이번 스팸의 직접 원인은 아니다.
   도메인 DNS 변경이라 **대표 결정·전산 영역** — 보고만 한다. 넣는다면 `p=none` 부터.

## 6. 교훈

- 🔴 **파이썬으로 메일을 보내면 `Date`·`Message-ID` 는 아무도 안 넣어 준다.**
  `EmailMessage` 도, `smtplib.send_message` 도. 직접 찍어야 한다.
- 🔴 **「도착했다」와 「받은편지함에 도착했다」는 다르다.** 발송 성공을 완료로 보면 안 된다.
- ⭐ **같은 도메인의 정상 메일과 비교**한 것이 진단을 갈랐다 — 도메인·SPF 를 의심하다
  엉뚱한 DNS 를 건드릴 뻔했다. **대조군을 먼저 찾을 것.**
