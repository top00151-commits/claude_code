## 2. 전환 원칙 — po_receive 판단 (셸만 knk, 폼 본문 유지+브리지)

두 폼 모두 **자재 선택 → 실시간 미리보기**가 JS의 생명선이라, z1003 입고(po_receive)와 **동일 판단**:
머리글·제출 바·버튼만 knk로 바꾸고 **:root pq→knk Sage 브리지**로 폼 전체 색을 통일. **JS 0줄 수정.**

| 전환(knk) | 유지(업무 특화·색만 Sage 브리지) |
|---|---|
| 머리글 → knk-page-head + Tabler(이력 `ti-history`·재고현황 `ti-packages`) | 자재 선택 select + **part-info 카드**(JS `innerHTML`에 `.u` span) |
| 하단 액션 → knk-submit-bar(sticky) | **실시간 미리보기**(preview-card·pv*) |
| 버튼 → knk-btn(ghost/primary) | 출고: `.big.mono` 수량 입력 + `.over` 토글 |
| :root → pq→knk Sage 브리지 | 조정: **부호 토글**(sign-toggle ±·setSign)·`qtyHidden`(부호적용 제출값) |
| `.field input:focus` → Sage 포커스 `#3E6F89` | 사이드(요약·가이드·⚠주의) |

## 3. ⭐JS를 건드리지 않은 이유와 증명

- 두 폼의 `onPartChange`·`onQtyChange`(+조정의 `setSign`)가 **innerHTML로 KPI/미리보기를 다시 씀**:
  `piStock.innerHTML = fmt(stock) + '<span class="u">' + unit + '</span>'` — `.u` span·`.big`·`.over/.pos/.neg`·
  `#partSelect`/`#qtyInput`/`#previewCard`/`#pvAfter` 클래스·ID에 의존. JS 문자열 안에 `var(--pq-err/ok/warn)`
  색을 직접 삽입 → **KPI/미리보기를 knk 변형으로 바꾸면 `.u`가 깨짐** → 유지가 정답(입고 KPI와 같은 근거).
- **증명(검증 수치)**: `onPartChange/onQtyChange`·`#partSelect`·`part-info`·`'<span class="u">'` 템플릿·
  (조정)`sign-toggle/setSign/qtyHidden/signPlus/signMinus`·(출고)`priceInput/submitBtn/previewCard/pvAfter`
  전부 보존 확인. `:root` 브리지가 JS 인라인 `--pq-*` 색까지 자동 Sage화.

## 4. 세부

- **제목 이모지 제거**(`📤`/`⚙️`) — 형제 재고 화면(z1004)·po_form과 통일된 **깔끔한 knk-page-title**. 아이콘은 Tabler 버튼이 담당.
- **죽은 CSS 정리**: 머리글/액션바를 knk로 바꾼 뒤 `.si-head`/`.adj-head`/`.si-title`/`.action-bar`/`.btn` 군 삭제
  → `.si-page > .knk-page-head` 배경 보정 + `.knk-submit-bar__note b` 1줄만 남김(가이드 §6 "미사용 선택자" 선제 정리).
- `.field` 입력 래퍼는 **유지**(특수 입력 `.big`/sign-toggle이 JS 토글과 얽혀 있어) — 브리지로 Sage 색만.
