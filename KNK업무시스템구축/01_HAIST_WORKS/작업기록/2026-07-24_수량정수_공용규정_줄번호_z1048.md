## 1. ② 수량 0.01 — 전수 조사부터

| `step` | 개수 |
|---|---|
| **`0.01`** | **26곳** |
| 없음(=정수) | 12곳 |
| `any` | 4곳 |
| `1` | 2곳 |

소모품만의 문제가 아니었다. **복사되어 퍼져 있었다.**
로컬 DB 실측: 수량 컬럼 7개(`order_items.qty` 등) **소수 값 0건** — 규정(수량=정수)대로 쓰는데 **입력칸만 소수를 허용**하고 있었다.

### 🔴 함정 — `step` 만 고치면 안 된다

HTML 숫자칸의 유효값은 **`min` 을 기준으로 `step` 씩** 증가한다.

```html
<input type="number" min="0.01" step="1">   <!-- 허용값 = 0.01, 1.01, 2.01 … -->
```

재고 화면들이 `min="0.01"` 이었다. **`min`·`max` 도 정수로 올려야** 한다.

### 고친 방식 — 3겹 (현황판 §4 3겹 원칙 그대로)

| 겹 | 무엇 |
|---|---|
| ①**공용 처리기** | `_v5_partials/knk_qty.html` — `styles.html` 이 include → **전 화면 자동 적용** |
| ②소스 정리 | 살아있는 화면 **18곳** 의 박힌 값 수정 (남기면 다음 사람이 복사한다) |
| ③배포 전 검사 | `check_standards.py` 에 **수량칸 소수 허용** 검사 추가 → 다시 들어오면 **배포가 막힌다** |

공용 처리기가 하는 일
- 수량 성격 `input[type=number]` → `step=1`·`inputmode=numeric`
- **`min`·`max` 가 소수면 정수로 보정**(위 함정)
- 소수를 붙여넣거나 타이핑하면 **칸을 떠날 때** 정수로 + `input`/`change` 재발화(금액 자동계산이 따라오게)
- **`MutationObserver`** — 나중에 추가되는 줄(`[+ 라인 추가]`)에도 적용. **없으면 "새로 추가한 줄만 0.01"** 이 된다.
- ⛔예외 = `data-knk-decimal` · 단가/금액/환율/중량/비율은 애초에 대상 아님
- 이미 저장된 소수 값은 **건드리지 않는다**(말없이 바꾸지 않는다 · §4 규칙 32)

### 🔴 내가 만든 처리기 자체에 결함이 있었다

판별 정규식을 단어경계로 썼다.

```js
/(^|[^a-z])(qty|quantity)([^a-z]|$)/i     // ❌
```

`i` 플래그 때문에 `[^a-z]` 가 **대문자까지 제외**한다 → `qtyInput` 의 `I` 가 경계로 안 잡혀
**`id="qtyInput"` 인 재고 조정 화면이 그대로 뚫렸다.**

```js
/qty|quantity|수량/i                       // ✅ 들어 있으면 대상, 아닌 건 NOT_QTY 로 걸러냄
```

⭐**§4 규칙 31("규정을 만들면 어긴 코드로 검사기를 시험하라")을 그대로 해서 찾았다.**
일부러 어긴 7줄짜리 시험 파일을 만들어 돌렸다.

| 시험 입력 | 기대 | 결과 |
|---|---|---|
| `name="qty" step="0.01"` | 잡힘 | ✅ |
| `id="qtyInput" step="1" min="0.01"` | 잡힘(camelCase+min 함정) | ✅ |
| `name="counted_qty" step="any"` | 잡힘 | ✅ |
| `name="unit_price" step="0.01"` | 통과(단가) | ✅ |
| `name="net_weight" step="0.01"` | 통과(중량) | ✅ |
| `step="0.5" data-knk-decimal` | 통과(명시 예외) | ✅ |
| `step="1" min="1"` | 통과 | ✅ |

## 2. ① 줄 번호 이빨 빠짐

화면이 **저장된 `line_no` 를 그대로** 찍고 있었다. 중간 줄을 지우면 `1,2,…,10,12,14`.

### ⛔ DB 번호를 다시 매기면 안 된다
`line_no` 가 **사진 파일 이름에 박혀 있다**.
```python
fn = f"line_{matched_line['line_no']:03d}_{idx+1}.jpg"    # line_003_4.jpg
```
다시 매기면 **사진이 엉뚱한 줄에 붙는다.**

→ **보이는 번호만 화면 순번(`loop.index`)** 으로. 정렬이 `ORDER BY line_no` 라 순서는 그대로.
원래 저장 번호는 마우스를 올리면 보인다(`title`).

### 같은 결함이 인쇄물에도 있었다
`{{ it.line_no|default(loop.index) }}` — **line_no 가 있으면 그걸 쓴다** = 같은 이빨 빠짐.

| 화면 | |
|---|---|
| `consumable_detail.html` | 번호 + 사진 뷰어 이름 2곳 |
| `quotation_print.html` | **견적서(고객 발송)** |
| `wo_form.html` · `wo_print.html` | 작업지시서 |
| `fta_print.html` | FTA 원산지증명 |
| `sales_quote_detail.html` | 견적 상세 |

**고객에게 나가는 문서에 번호가 건너뛰면 안 된다.** 전부 수정.

## 4. ⚠ 정직하게

- **이미 저장된 소수 값(사진2의 `0.04`)은 자동으로 안 바뀐다.** 화면에서 사람이 고쳐야 한다.
  값을 말없이 바꾸지 않는 것이 규정(§4 규칙 32)이라 그대로 뒀다.
- **서버 쪽 검증은 안 넣었다.** 화면 입력만 막았다. API 로 직접 소수를 보내면 저장된다.
  대표 지시가 '입력 규정' 이었고, 전 경로에 손대면 위험이 커진다. 필요하면 별건.
- **커밋 메시지 사고**: 백틱이 셸에서 실행되어 커밋 메시지의 예시 문자열 2개가 지워졌다
  (`[^a-z]`, `qtyInput`). **코드·주석은 정상.** force-push 금지 규정에 따라 되쓰지 않고 여기 기록으로 남긴다.
  → 앞으로 커밋 메시지에 백틱을 쓰지 않는다.
