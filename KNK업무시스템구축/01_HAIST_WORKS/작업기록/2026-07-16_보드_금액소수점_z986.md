# 작업일정표 금액 소수점 — 표시 잘림 + 입력 자체 불가 (z986)

- **일자**: 2026-07-16
- **신고**: 김정락 대표 — 005M2510(LMS 프로그램·EUR 수출): ①작업일정표에선 인보이스(세금계산서) 금액 소수점이 안 보여 상세(€65,204.50)와 다르고 발행 합계가 안 맞아 보임 ②(정정) "소수점 표현 의미보다는 **아예 작성이 안 됨** — 직접 입력을 하려 해도"
- **승인**: 대표 "지금 배포 OK"

## 1. 원인 (조사 확정 — 2겹)
### ① 입력 자체 불가 (핵심)
- 보드의 금액 입력칸들은 타이핑할 때마다 천단위 콤마를 다시 씌우는데, 이 재포맷이 `replace(/[^0-9]/g,'')`
  — **숫자 이외를 전부 삭제**해 `.`을 치는 순간 사라짐 → 소수점 이하를 쓸 방법이 없었음.
- 해당 입력기 4곳: 보드 행 세금계산서/인보이스 팝업(z467) · 펼친 호기 줄 팝업(z485) · 펼친 호기 줄
  금액칸(ux-money·단가/세금계산서) · 묶어발행 모달(z559).
- 저장 경로(서버)는 전부 float(소수 보존)여서 **입력기만 통과하면 저장은 정상**이었음 — row-tax(균등분배도
  소수2)·unit-field·schedule_cell_update(수량만 int=규칙대로)·일괄등록 파서 전수 확인.

### ② 표시 잘림 + 색상 판정 오염
- 보드 행이 호기별 세금계산서 금액을 합칠 때(`_agg`) `round()`로 **통화 불문 정수 반올림**
  → €65,204.50 → 65,204 → 화면 €65,204.00. 1+2+3차 합계 163,012 ≠ 수주액 163,012.50 으로
  '일부·불일치(주황)' 색으로 표시(실제로는 전액 발행). 엑셀 다운로드도 같은 집계라 동일하게 잘림.
- 부수: 1차 금액 기본값 프리필도 `Math.round`(163,012.50→163,013을 넣어줌).

## 2. 조치 (z986)
1. **공용 입력 포맷터 `_fmtAmtTyping(v)`**: 정수부만 콤마, 소수점·소수부는 친 그대로(최대 2자리 — 외화
   소수2 규칙). 입력기 4곳 전부 교체 + `inputmode="decimal"`(폰 키패드에 소수점). 수량 칸은 별도
   편집기라 무영향(정수 유지 규칙 불변).
2. **행 집계 소수 보존**: `_agg` `round()` → `round(,2)`+정수로 떨어지면 int(원화 등 기존 표기 유지).
   표시·색상 판정·엑셀 모두 정확해짐.
3. **저장 직후 칸 표시 `_fmtAmtShow(v,ccy)`**: 서버 money()와 동일(KRW 정수·외화 소수 2자리 고정) —
   저장 직후와 새로고침 후 표기 일치. 1차 프리필 정수 반올림 제거. 묶어발행 합계 표시도 소수 반영.
