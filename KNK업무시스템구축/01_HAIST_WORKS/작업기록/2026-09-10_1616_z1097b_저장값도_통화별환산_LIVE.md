## 1. 왜 이 작업이 필요했나

z1097 에서 **화면**의 통화 무시 합산을 고쳤다. 그런데 저장값 `projects.order_amount` 를
채우는 자리가 **서버 코드에 14곳** 남아 있었고, 전부 이랬다.

```sql
SELECT COALESCE(SUM(total_amount),0) FROM orders WHERE project_id=?
```

**통화를 안 본다.** 그대로 두면 수주를 고치거나 프로젝트 상세를 열 때마다
**저장값이 다시 오염된다.**

⭐ **z1093(매 기동 팀 시드)·z1094(기동 cascade 백필)와 똑같은 '되살아남' 함정이다.**
데이터만 고치고 끝냈으면 반드시 되돌아왔다.

## 2. 고친 것

### 공용 함수 2개 신설 (`app/main.py`)

| 함수 | 하는 일 |
|---|---|
| `_recalc_project_amount(c, pid, rates, exclude_cancelled)` | 프로젝트 통화 기준 합계를 **계산**만 한다 |
| `_apply_project_amount(...)` | 그 값을 **저장**한다. 못 정하면 **안 건드린다** |

**규칙**

- 수주 통화가 **하나면 예전과 똑같은 값**(회귀 0)
- 섞이면 각 수주를 **납품월 기준환율**로 원화 환산한 뒤(§4 규칙48) 프로젝트 통화로 되돌림
  (기준월 = 그 프로젝트의 가장 늦은 납품월)
- 환율이 없으면 **`None` 을 돌려주고 아무것도 쓰지 않는다** — 반쪽 숫자로 덮지 않는다

### 바꾼 자리

| 자리 | 수 |
|---|---|
| `order_amount` 저장 지점 | **14곳 전부** → 직접 SUM **0건** |
| 고객사 목록 정렬 | 통화 무시 합산이라 **순서가 뒤집혔다** → 원화 환산 기준 재정렬 |
| 관리자 진단 「고객사 표기 분산」 참고 금액 | 통화별 환산 |

조건부 저장이라 직접 `UPDATE` 가 남는 2곳은 **`ccy-ok` 표식**으로 명시 면제했다
(값의 출처를 주석에 적는다).

### 재발 방지 — 서버 코드 검사 신설
