## 1. 원인

왼쪽 고정이 **CSS 에 박혀 있었다** — 3칸 고정.

```css
.sched .c1{ position:sticky; left:0;         }   /* 관리번호   */
.sched .c2{ position:sticky; left:var(--l2); }   /* 수주번호   */
.sched .c3{ position:sticky; left:var(--l3); }   /* 프로젝트명 */
```

오른쪽 날짜칸에서 출하 처리할 때 **모델명·장비명·고객사가 안 보이는 게 당연**했다.
(칸 숨기기·너비·순서는 이미 계정별로 조절할 수 있었는데 **'고정'만 없었다.**)

## 2. 고친 것

**[⚙ 도구 → 칸 설정]** 목록의 각 칸에 **📌 단추**. 누르면 그 칸이 왼쪽에 붙는다.

| | |
|---|---|
| 기본값 | `관리번호·수주번호·프로젝트명` = **지금까지와 동일**(설정을 안 건드리면 화면 그대로) |
| 관리번호 | **항상 고정**(해제 불가) — 행 펼침의 빈 칸(`.c1`)이 `left:0` 에 기댄다 |
| 최대 | **6칸** (넘으면 안내) — 너무 고정하면 날짜칸이 안 보인다 |
| 순서·간격 | **화면에 놓인 순서(DOM)** 로 계산 → ⠿ 순서 바꾸기·숨기기와 안 어긋난다 |
| 폭 | `colState(k).w` (applyWidths 와 **같은 소스**) → 측정 타이밍에 안 흔들린다 |
| 표시 | 고정 구간 **끝에 빨간 세로선** — 여기까지가 붙어 있는 칸 |
| 저장 | 기존 `COLS` → `/sales/schedule/cols` 그대로 (**서버 무수정**) |

체크박스(**보이기**)와 📌(**붙들기**)는 **별개**다 — 보이면서 안 붙는 칸이 대부분.

## 3. ⚠ 배포 전에 잡은 것 2가지

### ① CSS 를 안 지우면 **해제가 안 된다**
`.c2`·`.c3` 의 `position:sticky` 를 남겨두면 사용자가 풀어도 계속 붙어 있다 → 제거.
**`.c1` 은 유지** — 행 펼침의 빈 칸(`td.c-info.c1`, `data-col` 없음)이 이 규칙에 기댄다.

**⭐HTML 의 `c2`·`c3` 클래스는 남겼다** — 일괄출하가 `tr.querySelector('.c3')` 로 프로젝트명을 읽는다.
클래스까지 지웠으면 **일괄출하가 조용히 망가졌을 것**이다.

### ② 인쇄할 때 고정이 안 풀린다
동적 규칙이 `#schedTable`(id) 을 써서 기존 인쇄 해제 규칙보다 **세다**.

```
내 규칙   #schedTable [data-col="model"]      → (0,1,1,0)
기존 인쇄  .pp-page .sched .c3                 → (0,0,3,0)   ← 진다
해결      .pp-page #schedTable [data-col]      → (0,1,2,0)   ← 이긴다 (!important 없이)
```
`@media print` 쪽도 같이. **인쇄물에 칸이 겹쳐 나올 뻔했다.**

## 5-b. ⚠ z1040b·z1040c — **배포 직후 신고**: "작아졌는데 커지지를 않음"

> 안지연 프로: *"편하게 해주기 위해 괴롭힌다"* / *"열고정을 늘렸다 줄였다 난리치다가 **작아졌는데 커지지를 않음**^^ 돌려줘"*
> 이어서: *"**드래그 하다가** 작아져쏘요… **그렇게 작아질줄 몰랐음** + 그래도 다시 커질줄 알았는데 안됨"*
> ⭐결정적: *"아니 아까 **뭔가 빨간선 하나가 더 있길래 그걸로 고정하는건가?** 하면서 막 난리치다가"*

### 진짜 원인 — **내가 그은 빨간선이 '손잡이'로 읽혔다**

z1040 에서 고정 구간 끝에 **2px 굵은 빨간 세로선**을 그었다.
칸 경계의 굵은 세로선은 누구나 **잡아 끄는 것**으로 읽는다. 게다가 **진짜 손잡이(`col-resizer`)가 바로 그 자리**에 있다.
→ 선을 "잡아보려다" 너비가 확 줄었다. **표시로 그은 선이 조작으로 읽힌 것 — 내가 만든 오해다.**

### 고친 것
| | |
|---|---|
| z1040b | 최소 폭 **28 → 48px**. **읽을 때도 올려 자가치유**(28px 로 저장된 계정은 열자마자 회복). 48=가장 좁은 기본값(수량)과 같아 **남의 화면은 안 바뀜**. ⚠숨김(0폭)은 예외 |
| z1040b | 칸 설정에 **↔ 너비 되돌리기**(칸마다·기본값과 다르면 진하게) — 마우스로 손잡이를 못 잡아도 복구 가능 |
| z1040b | 고정 규칙을 **th/td 로 좁힘**(`[data-col]` 만 쓰면 `<col>` 까지 잡힘) · 인쇄 해제 규칙도 동일 |
| **z1040c** | **빨간선 → 엑셀 '틀 고정'식 그림자**(`box-shadow:4px 0 5px -3px`). 경계는 보이되 **잡는 것처럼 보이지 않는다** |
| **z1040c** | 고정된 머리글에 **설명 툴팁** — 무엇이 고정됐고 어디서 바꾸는지 **화면이 스스로 답한다**(추측하지 않게) |

### ⚠ 내 진단 3연속 오류 — 정정 기록
| 가설 | 실험 결과 |
|---|---|
| `<col>` 에 sticky 가 걸려 너비가 죽었다 | ❌ **틀림** — 300px 지정 정상 적용 |
| 고정된 칸은 손잡이 드래그가 안 된다 | ❌ **틀림** — 고정·비고정 모두 ±60 정상 |
| 좁히면 손잡이를 못 잡는다 | ❌ **틀림** — *머리글이 세로 스크롤 밖*이라 `elementFromPoint` 가 엉뚱한 값을 준 **측정 오류**였다 |

> ⭐**교훈**: `getBoundingClientRect`/`elementFromPoint` 는 **뷰포트 좌표**다.
> 재기 전에 **대상을 화면 안으로 올려놓지 않으면(scrollIntoView) 측정 자체가 거짓말**을 한다.
> 이 오염된 측정으로 하마터면 **엉뚱한 것을 원인이라 보고할 뻔했다.**

### 검증 (LIVE `fb8ba38`)

**빨간 테두리 사라짐**(1px 기본선) + **그림자 적용**(`rgba(0,0,0,.28) 4px 0 5px -3px`) · 고정 머리글 툴팁 ·
시험 중 건드린 대표 계정 설정(폭·고정) **전부 원상복구**.
