# z1014 — 셸 반응형: 좁은 창(노트북)에서 우측 잘림 해결 · 근본원인 min-width:1280px

- **일자**: 2026-07-19
- **발견 경위**: z1013 견적 목록을 크롬(대표 로그인)으로 실측하다 **머리글 우측 액션 버튼(엑셀·새 견적)이 화면에서 안 보임** → DOM엔 존재. 진단 결과 셸 문제로 확인.

## 근본 원인 (크롬 JS 실측으로 확정)
- 대표 창 = **1030px CSS폭**(노트북/HiDPI). 그런데 `.app`이 **1280px**로 벌어져 오른쪽 **250px가 `.app{overflow:hidden}`으로 잘림** → 그 잘린 영역에 머리글 액션 버튼·표 우측 컬럼이 위치.
- 범인 = `static/css/v5_main.css`의 **`.top{min-width:1280px}`(:169)·`.app{min-width:1280px}`(:171)** (v5H40, "탭+아이콘+사용자 안 겹치는 임계값" — **탭 포함** 계산).
- 그런데 **z990에서 워크스페이스 탭을 `.top` 밖(책갈피 줄)으로 이미 옮김** → `.top`은 이제 로고+제목+아이콘만이라 훨씬 좁아도 됨. **옛 최소폭이 stale**로 남아 1024~1279px에서 잘림(≤1023px만 `min-width:auto`로 해제돼 있었음 = 1024~1279 사각지대).
- 실측 검증: `.app{min-width:0}` 주면 앱이 **즉시 1030px로 축소**·액션 버튼(left 797·right 983) **뷰포트 안**·책갈피줄 오버플로우 없음. 스크린샷으로 버튼·아이콘·사용자명·탭 전부 정상 확인.

## 수정 (v5_main.css `@media (max-width:1280px)`에 추가)
```css
.app, .top { min-width: 0; }
.knk-ptabs-list { overflow-x: auto; min-width: 0; }   /* 탭 많을 때 그 줄 안에서 가로 스크롤 */
```
- 특정도: 미디어쿼리(:244+) `.app`이 base `.app{min-width:1280}`(:171)보다 **뒤 = 이김**. ≥1281px엔 무영향(뷰포트가 이미 넓음), ≤1023px엔 모바일 `min-width:auto !important`가 이김 → 1024~1279px 구간만 정확히 해제.
