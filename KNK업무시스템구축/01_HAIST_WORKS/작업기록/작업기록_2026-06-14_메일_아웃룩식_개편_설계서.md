## 0. 대표 지시 3가지 (원문 요지)
1. **폴더 구분**: 받은 메일을 아웃룩처럼 **거래처/고객사별 폴더**로 나눠 보기. (스크린샷 트리: `1고객사 ▸ 탑엔지니어링·세경하이테크·두성테크·드림텍·삼성전기…` / `2.기타 고객사` / `3.외주업체 ▸ 배송 및 포장업체…`)
2. **보기 방식(읽기 창)**: **메일 목록 + 메일 내용을 한 화면에서 같이**. 목록 클릭 시 페이지를 떠나지 않고 옆/아래 창에 내용 표시(아웃룩 3분할).
3. **대화 묶기(스레드)**: 같은 제목으로 `RE: RE: RE:` 계속 오면 **하나의 대화로 묶어 그 아래로 쌓이게**.

**권장 구현 순서: A(읽기 창) → B(대화 묶기) → C(거래처 폴더).** 읽기 창이 기반이고 체감이 가장 큼. 단계별 배포·확인.

## 2. 기능 A — 읽기 창(목록+내용 3분할 보기)  [1순위·기반]

### 2.1 목표
받은편지함을 **2단(또는 3단)** 으로: (좌)폴더트리 — (중)메일 목록 — (우)메일 내용. 목록 클릭 시 **풀페이지 이동 없이** 우측 창에 내용 로드. 안 읽은 메일은 클릭 시 읽음 처리.

### 2.2 설계
- **레이아웃**: `mail_inbox.html` 을 CSS grid 2단(`목록 | 읽기창`)으로. 앱 모드(mail_app)는 본문 전체폭이라 여유. 좁은 화면(모바일)=목록만 → 클릭 시 기존 풀페이지 `/mail/{id}` 로 폴백(반응형 `@media`).
- **내용 로드 방식(택1, 권장 ①)**:
  - ① **HTML 조각 엔드포인트**: `GET /mail/{id}/pane` → mail_view 의 '내용 부분만'(헤더·답장버튼·sandbox iframe·첨부) 렌더해 반환. 목록 JS 가 `fetch` 해서 우측 `#readPane.innerHTML = html` 주입. **장점**: 기존 sanitize+sandbox iframe 그대로 재사용, 보안 동일. **주의**: 주입 후 iframe 높이 보정 스크립트 재실행 필요(스크립트는 주입 HTML 안에 IIFE로 or 목록쪽에서 호출).
  - ② JSON 엔드포인트 + 클라 렌더: 유연하나 safe_html 을 클라가 다시 sandbox iframe srcdoc 으로 만들어야 함(중복). → ① 권장.
  - 구현 팁: `mail_view.html` 을 `{% if pane %}내용만{% else %}풀페이지{% endif %}` 로 분기하거나, 내용 블록을 `_v5_partials/mail_view_body.html` 로 빼서 양쪽 include.
- **목록 클릭**: 행에 `data-mail-id`. 클릭 → `loadPane(id)`: fetch `/mail/{id}/pane` → 주입 → 그 행 .active 표시 + 읽음 처리(`POST /mail/{id}/read` read=1 또는 pane 라우트가 자동 mark_read) + 안읽음 뱃지/카운트 갱신.
- **읽음 처리**: pane 로드시 서버에서 mark_read(현재 /mail/{id} 가 mark_read 함 — pane 도 동일하게).
- **답장/전달/삭제/할일/연락처/번역/인쇄**: 읽기 창 안에서 동작해야. 답장·전달은 `/mail/compose?...` 로 새 창/탭 또는 풀페이지(읽기 창은 보기 전용). 삭제·별표·읽음은 AJAX 후 목록 갱신.
- **빈 상태**: 우측 "메일을 선택하세요" placeholder.

### 2.3 산출물 (A)
- main.py: `GET /mail/{id}/pane`(내용 조각, 본인 메일, mark_read) 라우트 1개.
- mail_inbox.html: 2단 레이아웃 + 우측 읽기창 + 목록 클릭 JS(loadPane) + 반응형 폴백.
- (선택) mail_view 내용 블록을 partial 로 분리해 pane/풀페이지 공용.
- ⚠ SPA/인라인 스크립트 함정([[feedback-spa-inline-script]]): 주입 HTML 의 스크립트는 IIFE·window 노출, iframe 높이보정 재호출.

## 3. 기능 B — 대화 묶기(RE: 스레드)  [2순위]

### 3.1 목표
같은 제목(접두 RE:/FW: 등 제거)으로 오가는 메일을 **하나의 대화**로 묶어 목록에 1줄. 펼치면 그 대화의 메일들이 시간순으로 쌓여 보임. 대화 줄엔 개수 뱃지·최신 날짜.

### 3.2 설계
- **제목 정규화**: 앞부분 반복 접두 제거 — `^(re|회신|답장|fwd?|fw|전달|답신)\s*[:：]\s*` 를 대소문자 무시·반복 제거 + 공백 trim + 소문자화. 빈 제목은 '(제목 없음)'.
  - 정규화 키 = normalized_subject. (동명이인/무관 메일 오묶음 방지 위해 v2 에서 '상대 이메일 도메인' 가미 검토. v1 은 제목만.)
- **그룹핑 위치**: `list_inbox` 결과(이미 필터·정렬됨)를 Python 에서 그룹핑하는 `list_inbox_threads(...)` 신설(mail_store). 각 그룹: {key, latest(대표 메일), count, unread_count, items[]}. 정렬=그룹의 최신 received_at desc.
  - 주의: 검색/필터(q·date·has_att) 적용 후 그룹핑. 카테고리 필터도.
- **UI(읽기 창과 결합)**: 목록에서 대화 줄 = 대표(최신) 메일 행 + `▸N` 펼침. 펼치면 하위 메일 행들(들여쓰기). 하위/대표 클릭 → 읽기 창에 해당 메일(또는 '대화 전체'를 한 화면에 쌓아 보여주기 — 아웃룩 대화뷰처럼). 
  - "그 아래로 쌓이는 형태" = 읽기 창에서 **대화의 모든 메일을 오래된→최신 순으로 카드로 쌓아** 보여주는 게 대표 의도에 가장 부합. → 읽기 창 pane 을 'mail 단건' 외에 'thread 전체'(`/mail/thread/{key}` 또는 `/mail/{id}/pane?thread=1`)도 지원.
- **토글**: 대화 묶기 ON/OFF (아웃룩처럼). 기본 ON. 세션/쿼리 파라미터.

### 3.3 산출물 (B)
- mail_store: `_normalize_subject(s)` + `list_inbox_threads(...)`(기존 list_inbox 래핑).
- main.py: inbox 라우트가 thread 모드 지원(파라미터 `thread=1` 기본) + 대화 전체 pane(`/mail/{id}/pane?thread=1` 또는 별도).
- mail_inbox.html: 대화 줄(개수 뱃지·펼침) 렌더 + 펼치기 JS.
- 정규화 단위 테스트(여러 RE/FW/한글 접두·중첩).

## 4. 기능 C — 거래처별 폴더  [3순위]

### 4.1 목표
좌측에 **거래처(고객사·외주업체) 폴더 트리**. 폴더 클릭 시 그 거래처에서 온 메일만. 보낸사람→연락처→거래처 자동 매핑(데이터연결). 매핑 안 된 건 '미분류'.

### 4.2 설계
- **보낸사람→거래처 해석**: `mail.from_email`(소문자) = `shared_contacts.email`(소문자) → `shared_contacts.customer_id` → `customers`. 
  - 쿼리: `LEFT JOIN shared_contacts sc ON sc.email IS NOT NULL AND lower(sc.email)=lower(m.from_email) LEFT JOIN customers cu ON cu.id=sc.customer_id`.
- **폴더 트리 데이터**: 받은편지함 메일들의 거래처별 카운트 — `customers` 별 GROUP BY. '미분류'(customer 없음) 별도. 
  - 스크린샷의 상위 그룹(1고객사/기타/외주업체) = customers 에 **분류 컬럼**이 필요(현재 tier='일반' 만 있음). v1 은 거래처 평면 나열(+미분류). 상위 그룹화는 customers 에 'group/구분' 개념 추가 검토(C-v2).
- **필터**: inbox 라우트에 `cust=<customer_id>` 파라미터 → list_inbox 에 `customer_id` 필터(위 조인 + `cu.id=?`). '미분류'=`sc.customer_id IS NULL`.
- **UI**: 좌측 폴더 트리(받은편지함 전체 / 거래처별 N / 미분류 N). 읽기 창 레이아웃의 좌측 칼럼. 폴더 클릭 = `?cust=` 로 목록 재조회.
- **데이터 안전**([[feedback-data-connectivity]]): 보낸사람 이메일 **정확 일치**로만 거래처 연결. 애매하면 미분류(추측 금지). A(읽기창)에서 만든 연락처 자동연결과 일관.
- **(후속) 수동 분류**: 메일을 특정 거래처로 수동 이동/지정 — v2(테이블 mail_folder 또는 mail_messages 에 customer_id 캐시 컬럼). v1 은 자동(보낸사람 기준)만.

### 4.3 산출물 (C)
- mail_store: list_inbox/threads 에 `customer_id` 필터 + 거래처별 카운트 함수 `customer_folder_counts(c, user_id)`.
- main.py: inbox 라우트 `cust` 파라미터.
- mail_inbox.html: 좌측 폴더 트리 + 선택 상태.

- **데이터 연결 안전**([[feedback-data-connectivity]], 절대준수): 자동연결은 '명확한 단일 후보'(이메일 정확일치)일 때만. 애매=미분류.
- **저장형 XSS / sanitize**([[works-template-xss-esc]]): 받은 HTML 은 항상 `sanitize_html_for_view` + sandbox iframe. pane 도 동일.
- **SPA 인라인 스크립트 함정**([[feedback-spa-inline-script]]): 읽기 창 주입 HTML 의 스크립트는 IIFE·window 노출·리스너 정리·iframe 높이보정 재호출.
- **앱 모드**: mail_app 시 chrome 대신 slim 헤더. 읽기 창 레이아웃은 전체폭 활용.
- **시간대**([[timezone-standard]]): 날짜 경계는 입력자 소속 기준(본사 KST/베트남 UTC+7). 목록 날짜 표시 유의.
- **검증**: 운영과 동일 코드를 로컬 임시 SQLite(DB.SCHEMA)로 호출 + esprima(JS)·Jinja·ast(py). 제목정규화·스레드그룹핑·거래처조인 단위 테스트.
