## 1. 이미 다 된 것 (회사서 **다시 안 해도 됨**)

- **메일 앱**: NAS의 **KNKHAIST 컨테이너** 안에서 `knk-mail`(uvicorn, 포트 **8201**)로 가동 중. 메신저(`knk-messenger`/5050)·WORKS(`knk-works`/8081)와 **같은 컨테이너·다른 프로그램**(서로 무영향).
- **경로**: `/opt/knk_mail` (코드)·`/opt/knk_mail/.venv`(파이썬)·`/opt/knk_mail/data/`(DB `mail.db`+`.env`+첨부).
- **컨테이너 nginx**: `/etc/nginx/conf.d/knk-mail.conf` 에 `server_name mail.knknara.co.kr → 127.0.0.1:8201` 블록 추가·적용 완료. (안전: 새 파일·새 server_name이라 메신저/WORKS 기본서버 무영향. 검증 워크플로우 3개 리뷰 GO.)
- **검증 완료**: 컨테이너 안에서
  - `curl http://127.0.0.1:8201/healthz` → `{"ok":true,"app":"KNK Eum MAIL",...}` ✅
  - `curl -H 'Host: mail.knknara.co.kr' http://127.0.0.1:8080/healthz` → 같은 메일 JSON ✅ (nginx Host 분기 정상)
  - 프로세스 env 적재(HTTPS_ONLY=1·PUBLIC_BASE=https·강한 세션키)·정적 CSS 200·메신저/WORKS RUNNING 무영향 ✅
- **백업**: 로컬 메일 repo + 모노레포 `claude_code`(GitHub) 푸시 완료.

> 즉 **"문 안쪽(컨테이너)"은 100% 완성**. 남은 건 **"건물 정문(DSM)"에서 새 주소를 안으로 연결**하는 것뿐.

## 2. ★ 회사에서 할 일 — DSM 설정 3개

> DSM = NAS 관리 웹화면. **외부(집)에서는 막혀 있고, 회사 네트워크에서만** 들어가집니다.
> 대표님 계정에 관리자 권한이 없으면 → **전산담당자에게 부탁**(이 §2 그대로 전달, 2분이면 함).

### 2-0. DSM 접속 (회사 네트워크에서)
브라우저 주소창에:
```
http://192.168.123.5:5000
```
(보안주소면 `https://192.168.123.5:5001`. 안 열리면 포트가 바뀐 것 → 전산담당자에게 "DSM 접속 주소" 확인)
→ DSM 로그인 → **관리자 계정**으로 로그인.

### 2-1. DNS — 새 주소를 NAS로
- `mail.knknara.co.kr` 를 **NAS IP로** 등록 (works.·haist.knknara.co.kr 와 **같은 곳·같은 값**).
- 위치: `knknara.co.kr` 도메인의 DNS 관리(가비아/등록기관 또는 DSM의 DNS Server). **works. 가 등록된 그 자리에 mail. 한 줄 추가.**

### 2-2. SSL 인증서 — mail 주소용
- DSM **제어판 → 보안 → 인증서**
- `mail.knknara.co.kr` 인증서 발급(Let's Encrypt) **또는** 기존 `*.knknara.co.kr` 와일드카드 인증서가 있으면 그걸 사용.

### 2-3. 리버스 프록시 — 새 주소를 컨테이너로 (★핵심)
- DSM **제어판 → 로그인 포털 → 고급 → 리버스 프록시 → 생성**
- 입력값 (**haist.knknara.co.kr 설정과 동일 패턴**):
  | 칸 | 값 |
  |---|---|
  | 소스 프로토콜 | **HTTPS** |
  | 소스 호스트이름 | **`mail.knknara.co.kr`** |
  | 소스 포트 | **443** |
  | 대상 프로토콜 | **HTTP** |
  | 대상 호스트이름 | **`localhost`** |
  | 대상 포트 | **`8080`** |
- (사용자 정의 헤더: 메일은 WebSocket 불필요. **Host 헤더 보존**은 DSM 기본값이라 그대로.)
- 저장 후 인증서(§2-2)를 이 프록시에 연결.

> ⚠ **왜 대상이 8080?** 컨테이너 nginx가 8080에서 Host로 분기합니다. `mail.knknara.co.kr` Host로 들어오면 nginx가 메일앱(8201)으로 보냅니다(이미 설정됨). haist.knknara.co.kr 도 같은 8080으로 가서 메신저로 갑니다.

### 2-4. 확인
- 브라우저에서 → `https://mail.knknara.co.kr/healthz`
- **성공** = `{"ok":true,"app":"KNK Eum MAIL","db":"mail.db","tables":13,"missing":[]}`
- (이게 나오면 외부→DSM→컨테이너→메일앱 경로 완성. 단, **로그인은 §3 후**에 됨.)

## 3. 그 다음 — 메신저 로그인 연결 (빅터가 메신저 세션에서)

- 메일 로그인은 **메신저 SSO**를 씁니다. 메신저가 메일을 **새 소비자(audience `knk-mail`)**로 인식해야 토큰 검증이 됩니다.
- 메신저 측에 등록 필요:
  1. **audience `knk-mail`** 토큰 발급 (메일 진입 시)
  2. **redirect_uri 허용목록**에 `https://mail.knknara.co.kr/sso/land` 추가
  3. (선택) 직원명부 API `GET /api/sso/directory` + 공유키 `KNK_SSO_SERVICE_KEY` → 메일 `.env`에 동일값 (일괄 동기화용. 없어도 로그인 시 본인 자동등록은 됨)
- **이건 빅터가 별도 '메신저 세션'에서** 진행(메신저는 다른 repo). §2 끝나면 말씀 주세요.
- 이 등록 전까지: `mail.knknara.co.kr/healthz`는 되지만, 로그인 시도 시 `/sso/land`에서 토큰검증 실패(안내문). **정상/예상된 상태.**

## 5. 문제 생기면 — 롤백·진단 (컨테이너 SSH 안에서)

```bash
# 메일 앱 상태/로그
supervisorctl status knk-mail
tail -50 /opt/knk_mail/logs/uvicorn-error.log

# 메일 앱만 재시작 (메신저/WORKS 무관)
supervisorctl restart knk-mail

# 메일 nginx 분기 롤백 (메일 노출만 취소, 나머지 그대로)
rm /etc/nginx/conf.d/knk-mail.conf && nginx -s reload

# 메일 앱 완전 중단 (필요 시)
supervisorctl stop knk-mail
```
- DSM 리버스프록시/인증서는 DSM 화면에서 만든 항목을 **삭제**하면 롤백.

## 6. 외부 노출 후 — 사용자에게 열기 전 후속 (빅터, 권장)

검증 워크플로우가 짚은 항목 (지금은 비차단, 직원 공개 전 정리 권장):
1. **받기 catch-all 정책**: 미매핑 수신 주소가 전부 대표 메일함으로 감(resolve_recipient→default_owner). 의도 확인 + **대표 계정을 미러에 `role='ceo'`로 시드**(안 그러면 inbound·admin 라우트가 비활성).
2. **pwv 재검증**: 메신저 측 로그아웃/계정 비활성이 메일 세션에 즉시 반영 안 됨(브라우저 세션 동안). 메신저 SSO 등록(§3)과 함께 보강.
3. (이미 적용) inbound 토큰 상수시간 비교·30MB 상한·세션키 fail-closed·PWA scope '/'.
