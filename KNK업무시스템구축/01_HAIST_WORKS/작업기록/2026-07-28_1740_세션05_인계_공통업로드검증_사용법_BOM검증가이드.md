## 1. 재사용할 공통 자산 (동결 — 복제하지 말고 그대로 사용)

### 1-A. 결과 표시 헬퍼 (클라이언트·JS-fetch용)
- 파일: `app/templates/_v5_partials/knk_verify_msg.html` → 전역 함수 `window.knkVerifyMsg1024(v)`.
- 쓰는 법: 검증 결과 `v`를 넣으면 `✅ 전항목 일치` 또는 `⚠ 다른 값 N건(목록)` **문자열**을 돌려줌. `alert(... + knkVerifyMsg1024(v))`.
- 화면에 include: `{% include '_v5_partials/knk_verify_msg.html' %}` (이미 있으면 생략).
- ⚠ **변경 시 사전협의**(업무분장 §7). BOM은 재사용만.

### 1-B. 검증 결과 데이터 형식 (⭐ 이 스키마를 그대로 반환하면 표시가 자동으로 됨)
```json
{
  "checked": 12,                     // 실제 대조한 행 수
  "ok": true,                        // 불일치 없으면 true
  "diff": [                          // 불일치 목록(최대 20)
    {"row": 3, "name": "품명/식별", "field": "수량", "excel": "4", "saved": "1"}
  ],
  "skipped": "대조 보류 5행(…)",      // 대조 못 한 사유(선택)
  "error": "…",                      // 예외(선택)
  "fields": "품명·규격·수량·단가…"    // ✅ 메시지에 나열할 대조 항목(선택)
}
```

## 2. 두 가지 배선 패턴 (BOM은 2-B '폼POST' 사용)

### 2-A. JS-fetch 업로드 (프로젝트·고객사·수주라인) — 참고
- 확정(JSON fetch) 응답에 `verify`를 실어 보내거나(라인=인라인 대조), 같은 파일을 verify 엔드포인트로 재전송 → 성공 후 `alert(msg + knkVerifyMsg1024(vj.verify))`.
- 참고 구현: z1065 `/projects/import-verify`·z1067 `import-consumable-lines/confirm`(인라인).

### 2-B. 폼 POST + 리다이렉트 업로드 (공급사·자재·**BOM**) — ⭐BOM은 이 패턴
- **확정(apply)에서 verify를 계산하고, 리다이렉트 대신 결과 화면(mode='result')에 verify를 실어 서버 렌더**로 `✅/⚠`를 보여준 뒤 '목록으로' 링크.
- 참고 구현(그대로 본떠서 BOM에 적용):
  - `app/main.py` `suppliers_import_apply`/`parts_import_apply` 성공 경로 = `ctx(req, "..._import.html", ..., mode="result", verify=_vfy)` (전엔 `RedirectResponse`였음).
  - 템플릿 `suppliers_import.html`/`parts_import.html` mode='result' 성공 블록에 **서버 렌더 verify 블록**(skipped/ok/diff 3분기 + '목록으로' 링크)을 넣음 — **이 Jinja 블록을 `bom_upload.html` 결과 화면에 복사**하면 됨.

**서버 렌더 verify 블록(복사용 Jinja)** — `verify` 컨텍스트만 넘기면 동작:
```jinja
{% if verify %}
  {% if verify.skipped %}
  <div class="...warn">⚠ 원본 대조를 건너뜀 — {{ verify.skipped }}</div>
  {% elif verify.ok %}
  <div class="...ok">✅ 올린 엑셀 원본과 대조 {{ verify.checked|default(0) }}행 — 적어 넣은 값 전부 일치 ({{ verify.fields }})</div>
  {% else %}
  <div class="...err">⚠ 올린 엑셀과 다른 값 {{ verify.diff|length }}건 (대조 {{ verify.checked|default(0) }}행)
    <ul>{% for x in verify.diff[:8] %}<li>{{ x.row }}행 {{ x.name }} [{{ x.field }}] 엑셀 {{ x.excel }} → 저장 {{ x.saved }}</li>{% endfor %}
    {% if verify.diff|length > 8 %}<li>… 외 {{ verify.diff|length - 8 }}건</li>{% endif %}</ul>
  </div>
  {% endif %}
{% endif %}
```

## 3. '검증층만' 만드는 원칙 (⭐거짓경고 0 · 저장로직 무접촉)

세션 01이 공급사·자재에 쓴 방식 그대로 BOM에 적용:

1. **저장 로직을 안 고친다.** BOM 파서/저장(`bom.py`)은 그대로 두고, **파서를 `dry_run=True`로 호출해 '파싱행'만** 얻는다(공급사=`suppliers_bulk_import_excel(dry_run=True)`·자재=`parts_bulk_import_excel(dry_run=True)`처럼). → 파싱을 재구현하지 않음.
2. **정확 매칭만 대조.** 키(BOM=품번+시트/버전 등)로 저장행을 **유일하게** 찾을 때만 대조. **모호/복수/병합은 '대조 보류'(skipped 카운트)** — 절대 거짓 '불일치'로 만들지 않는다(신뢰 유지).
3. **엑셀에 적은 칸만 비교.** 빈 칸(시스템 산출값)은 제외. 숫자는 반올림 비교, 텍스트는 trim 비교.
4. **환율·마진 등 '산출' 필드는 검증층에서 조심.** 자재는 금액을 뺐다(세션 05 파서검증 영역). BOM도 단가·금액은 **세션 05가 원본↔파서 단계에서** 책임지는 게 안전.
5. **읽기 전용.** verify는 아무것도 저장/변경하지 않는다.

## 4. BOM 검증에 필요한 것 (업무분장 §5.4·§6 요지 — 세션 05 책임)

- **3단계 구분 대조**: `원본 엑셀 → 파서가 읽은 값 → DB 저장 값`.
- **확인 항목**: 원본 행번호·시트명 / 품번·품명·Maker·수량·단위 / 단가·금액·납기 / 변경 화살표·중간 이력 / 서비스성 의심 / 신규·삭제 표시 / 중복 시트 / 외부 Revision 원문 / 저장된 Revision·Release 근거.
- **표시(검증층) vs 차단(업무층) 분리**:
  - **표시** = 위 공통 `verify` 스키마로 `✅/⚠` 보여주기(세션 01 형식 재사용).
  - **차단** = **세션 05 업무층 책임**: 미해결 불일치·중복 시트·파싱 실패 있으면 **Release 차단**, Release 안 된 BOM으로 **구매요청 생성 금지**. (검증층은 막지 않고 보여주기만.)
