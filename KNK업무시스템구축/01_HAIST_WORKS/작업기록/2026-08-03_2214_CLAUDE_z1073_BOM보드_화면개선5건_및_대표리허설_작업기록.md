## 2. 대표 지적 → 조치

### ① 줄이 안 맞는다 (구분마다 열이 어긋남)

구분(유닛)마다 `<table>` 을 따로 만들어, 표마다 제 내용대로 열 너비를 정하고 있었다.
**실측**: 품명 열 시작이 `490 / 568 / 570 px` 로 제각각.

→ **표를 하나로 합쳤다.** 16개 구분 전부 `품명 372 · 제조사 614 · 대당 801 · 단가 911` 로 일치.
덤으로 열 이름줄이 sticky 로 계속 붙어 있게 되었다(표가 하나라 필수).

### ② 전체를 선택할 수 있게

맨 왼쪽 위 ☑ = **화면에 보이는 줄 전부**. 필터·검색으로 숨은 줄은 건드리지 않는다.
일부만 고르면 "반쯤 찬" 표시. 구분 줄 ☑ 는 그 구분만.
**50개 넘게** 고르고 구매처를 바꾸면 되묻는다(되돌리기 버튼이 없고 이력에만 남으므로).

### ③ 🔴 상세창이 안 열리던 결함 — **운영에도 있었음 · 반영 완료**

`data-item` 을 **큰따옴표** 속성에 넣었는데, Jinja `tojson` 은 `"` 를 escape 하지 않는다
(스크립트 태그·홑따옴표 속성용 설계). 그래서 첫 `"` 에서 속성이 끊겨 `{` 한 글자만 담겼고,
**행을 눌러도 상세·이력 창이 열리지 않았다.** 여는 코드가 `try/catch` 라 조용히 실패해 오래 발견되지 않았다.

- JSON 은 키마다 `"` 를 쓰므로 값이 평범해도 **항상** 깨졌다 → 그 화면의 **모든 줄**
- 운영 BOM 이 0건이라 실제 피해는 없었다(B-0 실측 2026-07-31)
- 전 템플릿을 훑어 같은 표기는 **이 한 곳뿐**임을 확인
- 시험: 따옴표·꺾쇠·한글 등 5종 → **옛 표기 0/5 · 새 표기 5/5**
- 상세 = `2026-08-03_1717_CLAUDE_z1073_BOM보드_상세창결함_운영배포_작업기록.md`

### ④ 금액에 단위가 없다 — 규정 z750 위반

**대표 규정 z750(2026-07-02)**: 통화기호를 숫자 **앞**에 · 자릿수 콤마 · 원화 정수/외화 소수 2자리.
공용 필터 `money(값,통화)` 와 `bom_items.currency` 칸이 **이미 있었는데** 보드만 `'{:,.0f}'` 로 직접 찍고 있었다.

고친 층 4개 — 표의 단가·금액 / 바뀐 값 옛값 병기(`oldv` 에 통화 인자 추가) /
상세창 편집칸 앞 기호(규정 z758 — **input 값에는 숫자만** 유지해 저장이 안 깨지게) / 화면쪽 통화기호 표.
화면 표가 서버 `_CCY_SYMBOL` 과 **같은 표**임을 기계로 대조 확인.

## 5. 리허설이 드러낸 것 2건 (고치지 않음 · 기록)

### 🔴 발견 A — 옛 파일을 올리면 최신 설계변경이 **조용히 되돌아간다**

v4 에서 R1 기반 파일을 올리자 v3 의 설계변경 4건이 **전부 원래 값으로 되돌아갔다**.

```
TEST-BASE-001  단가   15,400 → 84,000
TEST-SUP-002   품명   가상 서포트 바 (보강형) → 가상 서포트 바
TEST-LMG-010   단가   88,000 → 47,000
TEST-BSC-011   제조사 가상제조사Z → 가상제조사B
```

**고장이 아니다** — 미리보기가 `변경 4` 라고 정직하게 보여줬고 이력에도 전부 남았다.
그러나 **"이건 되돌리는 겁니다"** 라는 경고는 없다.
설계팀이 예전 파일을 실수로 올리면 최신 사양이 옛날로 가고, 그 사이 구매팀이 옛 단가로 발주하면 손실이다.

→ **대표 지시로 당일 구현 완료 (z1073f)** — 아래 §5.1 참조.

### 5.1 z1073f — 되돌림 감지 (대표 지시로 당일 구현)

**⭐ 파일 이름·날짜로 '오래된 파일인가'를 추측하지 않는다.** 사람이 파일 이름을 아무렇게나 붙이기 때문이다.
대신 **이력만 본다**: 전에 `A→B` 를 했는데 이번이 `B→A` 면 **그건 되돌림이다.** 다른 해석이 없다.

- `bom.py` `mark_reverts(changes)` 신설 — 각 품목·칸의 **가장 최근 이력 1건**과 대조. DB 는 읽기만.
- 미리보기 화면: 요약칸 **🔄 되돌림 N** · 변경 상세 줄마다 **🔄 되돌림 (v4 에서 한 변경)** 배지
- 경고 문구: *"이 중 N건은 전에 했던 변경을 그대로 되돌립니다 (업로드 버전 v4 에서 한 변경).
  예전 파일을 올리신 것은 아닌지 확인해 주세요… 일부러 되돌리시는 것이라면 그대로 진행하시면 됩니다."*
- ⛔ **막지 않는다.** 사실만 알리고 판단은 사람이 한다(일부러 되돌리는 일도 있다).

**검증 — 깨끗한 임시 DB 에서 4회 업로드 (4/4 통과)**

| 회차 | 올린 파일 | 변경 | 되돌림 | 뜻 |
|---|---|---|---|---|
| v1 | R1 | 0 | 0 | 첫 업로드(이력 없음) |
| **v2** | **R2(설계변경)** | **4** | **0** | ⭐**변별력** — 진짜 새 변경엔 안 붙는다 |
| v3 | R1 (예전 파일) | 4 | **4** | v2 를 되돌림 — 버전까지 정확히 지목 |
| v4 | R2 | 4 | **4** | v3 을 되돌림 |

**화면 실측**(시연 서버 · 001M2607 에 R2 미리보기): `🔄 되돌림 4` · 경고 문구에 `v4` 지목 · 배지 4개.
미리보기만 했으므로 데이터 무변경 확인(15종·업로드 4회 그대로).

재현 키트: `_검증/test_revert.py`
