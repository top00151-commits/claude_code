# 메일 독립 — 전환(cutover) 계획 (5단계)

- 작성: 빅터(01) · 2026-06-14
- 실행 시점: **새 주소(mail.knknara.co.kr) 가동 + 검증 완료 + 메신저 SSO 등록 완료 후, 대표 승인 시**
- 원칙: 새 메일이 새 주소에서 **정상 확인된 뒤에만** WORKS 손댐. 문제 시 즉시 롤백.

## 전제 조건 (모두 충족해야 전환)
1. `https://mail.knknara.co.kr/healthz` = `{"ok": true}`
2. 메신저 SSO 로 메일 로그인 성공(audience `knk-mail`)
3. 받기(가져오기/inbound)·보내기·읽기 새 주소에서 실동작 확인

## 전환 절차
1. **메신저 📧 아이콘 목적지 변경** (메신저 세션): `works.knknara.co.kr/mail…` → `https://mail.knknara.co.kr/sso/login`
2. **Cloudflare Worker 받는 구멍 변경**(받기 쓰는 경우): `WORKS_INBOUND_URL` → `https://mail.knknara.co.kr/api/mail/inbound` (+ 토큰 동일/재설정) → **재배포 필수**
3. **WORKS `main.py` 에서 메일 라우트 제거** — ⚠ **메일 것만**. 같은 구역(12635~13884 근처)에 섞인 **WORKS PWA 라우트는 보존**:
   - ❌ 제거(메일): `/mail/settings`·`/contacts/{}/mail`·`/api/mail/inbound`·`/admin/mail-inbound*`·`/mail/inbox`·`/mail/manifest.webmanifest`·`/mail/sw.js`·`/mail/icon*`·`/mail/app`·`/mail/{id}*`·`/mail/rules*`·`/mail/{id}/att`·star/delete/read/restore/purge·draft·drafts·`/api/mail/*`·signature·compose·send·large·`/dl/{token}`·sent·`/admin/mail-send*`·`/admin/mail-fetch*`·`/mail/trash*`·`/admin/mail-purge*`
   - ✅ **보존(WORKS)**: `/manifest.webmanifest`·`/sw.js`·`/icon-{size}.png`·`/icon.svg`·`/app` (KNK Eum WORKS PWA — 메일 아님!)
   - 방법: 마커 기반 영역 삭제 + `ast.parse` 검증 + 동시세션 외부 헌크 미혼입 확인(기존 `stage_*.py` 패턴). main.py 동시편집 중이므로 **내 삭제만** 반영.
4. **WORKS 호환 리다이렉트 추가**(선택, 권장): `GET /mail/{path:path}` → `https://mail.knknara.co.kr/mail/{path}` (옛 북마크/링크 보존). 또는 `/mail*` → 새 주소.
5. **배포**(WORKS 2-repo) → `/api/version` 확인 → 메일 링크가 새 주소로 가는지 확인.

## 롤백
- 3단계 삭제를 `git revert`/패치 복원 → WORKS 내장 메일 즉시 부활.
- 새 주소에 문제 발생 시 메신저 📧 아이콘만 WORKS 로 되돌리면 사용자 영향 0.

## 데이터
- 별도 DB(완전 분리)이므로 **기존 WORKS 메일 데이터는 새 앱으로 자동 이전되지 않음**.
- 필요 시 일회성 마이그레이션(WORKS mail_messages/attachments → mail.db) 스크립트 별도 작성(대표 결정).
  - 현재 운영 메일량이 적으면 '새 주소부터 새로 시작'도 선택지(가져오기로 하이웍스 메일 적재).
