## 1. 한 장 요약

1. **이음웍스는 「보는 순서」로 짜여 있고, 담당자의 「일하는 순서」와 맞지 않습니다.** 가장 먼저 하는 일인 등록(관리번호·수주번호·제작요청)은 메뉴에 없고, 「📋 프로젝트」 위 「🆕 등록」 탭 안에 숨어 있습니다. 반대로 메뉴에 나와 있는 견적서·영업 기회·수주·납품·수금·미수금은 운영 사용이 0건이거나 보기 전용입니다.
2. **사슬이 세 곳에서 끊깁니다.**
   - 견적서 ↔ 프로젝트: 연결 칸도, 수주로 바꾸는 단추도 없습니다.
   - 작업 일정표(출하·계산서) → 납품·수금: 링크가 없습니다.
   - 납품·수금 → 미수금 → 입금 대사: 기준이 서로 다르고, 입금 대사는 미리보기만 합니다.
3. **입금 쪽은 지금 그대로 열면 오히려 혼란을 줍니다.** 이 문제는 숫자로 확인됐습니다.
   - 고객사 87곳 모두 **결제 조건(일수)이 비어** 있어 입금 예정일을 계산할 수 없습니다.
   - 입금 기록이 **0건**입니다.
   - 💰 미수금 화면은 출하된 수주 **968건 · 50개 고객사 · 약 224억 원을 전부 「미수」**로 셉니다(이미 받은 돈 포함).
4. **안지연 프로의 실제 입금 확인 방식을 그대로 옮기면 됩니다.** 순서는 이렇습니다.
   1. 입금 예정일이 된 고객사 목록
   2. [관리팀에 확인 요청]
   3. 관리팀 답(받음·날짜·금액 / 아직)
   4. 입금 기록
   5. 미수 정리

   재료(세금계산서 발행일)는 이미 품목 줄 5,614줄에 들어 있습니다. 비어 있는 것은 「결제 조건 일수」와 「관리팀과 주고받는 길」 둘입니다.
5. **전원에게 열기 전에 꼭 고칠 것은 7가지**입니다(§6). 나머지는 단계별로 고칩니다. 대표님이 정하실 것은 6가지입니다(§8).

## 5. 입금 확인 흐름 (안지연 프로 방식을 그대로 이음웍스로)

### 지금 (대표님 11-21 설명)
1. 안지연 프로가 입금 일자가 된 고객사를 찾는다(어디서 보는지는 자료 없음 · 엑셀·기억으로 짐작).
2. 관리팀에 입금 여부를 물어본다.
3. 받은 답으로 정리하고, 팀장에게 「입금 완료」를 보고한다(이음).

### 바꾼 뒤 (제안)

```
[작업 일정표] 세금계산서 발행일 입력 (지금도 함)
      │  + 고객사 결제 조건(일수)  ← 처음 한 번 채움(B3)
      ▼
[💰 입금 확인]  ← 메뉴 하나 (지금 「미수금」「입금 대사」「납품·수금」 셋을 하나로 모음)
  고객사별 한 줄: 계산서 금액(부가세 포함) · 입금 예정일 · D-day · 담당자
  ┌ 🔴 예정일 지남   ┌ 🟠 오늘·이번 주   ┌ ⚪ 다음
      │  ☑ 고르기 → [🏦 관리팀에 확인 요청]
      ▼
[이음 요청함] 관리팀이 받음: 「○○사 · 11-20 예정 · 33,000,000원 · 들어왔나요?」
      │  관리팀 답: [✅ 입금됨 (날짜·금액)] / [⏳ 아직] / [💬 일부만]
      ▼
[입금 기록 자동] receipts_payment 에 저장 → 그 고객사 줄이 「입금 완료」로 바뀜
      │  요청한 사람(안지연)이 [확인 완료] → 요청 종료 (요청함 원칙)
      ▼
[팀장·담당자] 같은 화면에서 「내 건」·「팀」으로 봄 · 입금 완료는 팀장 📢 알림(지금 이음 보고를 대신함)
```

### 먼저 정리해야 할 것 (안 하면 첫날부터 숫자가 틀립니다)
- **과거 출하분 968건 · 약 224억 원의 「기초 정리」**
  - 이미 받은 돈이 대부분이지만 기록은 0건입니다.
  - 정리 방식 제안: 「기준일(예: 2026-10-31) 이전 계산서분은 입금 완료로 본다」. 관리팀이 실제 미수 목록(엑셀)을 주면 그 건만 미수로 남깁니다.
  - 정리 방식은 대표님 결정(§8-②)입니다.
  - DB 쓰기는 대표님이 실행하는 .ps1로만 합니다. 기록은 「빅터(시스템 · 대표 승인)」으로 남깁니다.
- **미수 계산 기준 하나로 통일**
  - 지금 화면마다 기준이 다릅니다.
    - 「미수금」: 수주 전체가 출하일 때만 셉니다 · 부가세 빼고 셉니다 · 발주일을 씁니다 · 기본 30일로 봅니다.
    - 「납품·수금」: 호기 하나만 출하해도 셉니다 · 부가세를 포함합니다 · 계산서일을 씁니다.
  - 바꿀 기준: **계산서 발행분(차수별) · 부가세 포함 · 계산서일 + 결제 조건**.
  - 「입금 완료」 판정도 부가세 포함 금액으로 바꿉니다. 지금은 공급가만 받아도 완료가 됩니다.
- **🏦 입금 대사(은행 엑셀)**: 관리팀이 쓸 2단계 기능으로 둡니다. 관리팀에 권한을 줄지는 대표님 결정입니다. 1단계는 「관리팀 답 = 입금 기록」으로도 충분합니다.

## 8. 대표님이 정하실 것

1. **이 순서로 진행할지**: P0 7가지 → (전원 열기) → P1. P0 가운데 P0-4(이음 카드 풀기)는 대표님 「풀어」가 필요하고, 일은 세션 10이 합니다.
2. **과거 미수 기초 정리 방식**: 「기준일 이전 계산서분 = 입금 완료로 봄 + 관리팀이 준 실제 미수 목록만 남김」을 추천합니다. 기준일과 관리팀 담당자를 정해 주셔야 합니다.
3. **관리팀이 이음웍스에서 직접 답할지**: (가) 이음 요청함으로 받고 단추로 답함(추천 · 관리팀은 이음만 써도 됨) / (나) 지금처럼 안지연 프로가 물어보고 대신 입력.
4. **제작요청 기본 받는 부서**: 검사기·자동화·라이프밸류별로 누가 받는지(팀장과 정하셔도 됩니다).
5. **선진행(PO 전) 건 등록·발행**: 관리번호를 먼저 매겨 발행하도록 허용할지.
6. **견적·일정표 메일**: 견적을 이음웍스에 둘지, 매일 일정표 엑셀 메일을 계속 둘지(B4 1단계는 메일을 그대로 두고 쓰기만 쉽게 하는 안).

## 9. 한계 (정직하게)

- 「안지연 프로가 입금 예정일 고객을 관리팀에 확인」하는 장면은 **감사팀 문서에 없습니다**. 대표님 11-21 말씀을 근거로 했습니다. 어떤 엑셀·화면을 보고 찾는지는 확인하지 않았습니다 → 안지연 프로에게 한 번 물어보면 정확해집니다.
- 화면 흐름은 코드로 확인했고, 실제 4명 계정으로 들어가 보지는 않았습니다(SSO라 시험 로그인 불가). 「🔴 막힘」은 코드 근거입니다.
- 미수 224억 원은 「미수금 화면이 세는 값」입니다. 실제 미수가 아닙니다(이미 받은 돈 포함 · 기록 0건). 원화·달러·유로를 한 칸에 더하는지는 확인하지 않았습니다(짐작: 원화가 대부분이라 영향 작음).
- 클릭 수(등록 4~5번)는 코드상 대략입니다. 실측이 아닙니다.
- 사용 숫자는 11-21 20시대 운영 DB 기준입니다.
- 감사팀 문서는 대외비라 근거 번호(메일 #·이음 #)만 옮겼습니다. 개인 대화방 내용은 보지 않았습니다.
