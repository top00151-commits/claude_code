## 1. 무엇이 문제였나

메일을 보내면 보내는 사람이 `test@knk-mailtest.com` 으로 나갔다. 대표 회사 주소
`top0015@knknara.co.kr` 로 나가게 하는 것이 목표.

코드를 보니 보내는 길은 이렇게 생겼다.

| 요소 | 지금 값이 오는 곳 |
|---|---|
| 보내는 주소(From) | `app_settings.mail_from_address` — 비어 있으면 `test@knk-mailtest.com` |
| SMTP 호스트·계정·비번 | `app_settings.mail_send_host / _user / _pass_enc` (클라우드플레어 기준) |

**걸림돌 = 비밀번호.** 회사 도메인(`knknara.co.kr`)의 정식 발송자는 하이웍스다
(MX 가 하이웍스를 가리킨다). 다른 중계망으로 보내면 받는 쪽에서 스팸으로 떨어진다.
그런데 하이웍스 SMTP 로 보내려면 비밀번호가 필요하고, **빅터는 비밀번호를 입력할 수 없다**(규정).

## 2. 길을 찾은 지점

코드에서 두 가지를 확인했다.

1. `mail_fetch_accounts` 에 **받기 계정의 비밀번호가 이미 암호화 저장돼 있다**
   (`password_enc`). 메일이 WORKS 로 들어오고 있다는 건 이게 동작한다는 뜻이다.
2. 받기·보내기 비밀번호가 **같은 Fernet 키**(`KNK_MAIL_KEY`)로 저장된다 —
   `mail_fetch.py` 머리글이 그렇게 적고 있다. 즉 `decrypt` 가 그대로 통한다.
3. `_smtp_send(host, port, login_user, login_pass, from_email, ...)` 는
   **「login 계정과 From 이 달라도 됨」** 이라고 이미 적혀 있다.
4. `mail_send.py` 머리글이 하이웍스 보내기 서버를 **`smtps.hiworks.com:465`** 로,
   「앱 비밀번호 사용 권장」을 house 표준으로 적어 두고 있다 (짐작이 아님).

→ **이미 등록된 받기 자격증명을 보내기(SMTP) 로그인에 재사용**하면
   비밀번호를 한 번도 새로 넣지 않고 끝낼 수 있다.

## 3. 만든 것

### `app/mail_send.py`
| 함수 | 하는 일 |
|---|---|
| `smtp_host_from_fetch(h)` | 받기 호스트 → 보내기 호스트. **확인된 하이웍스만** 표에 있고, 모르는 곳은 빈 값(짐작 금지) |
| `via_fetch_mode/uid/allowed` | 스위치 `off` \| `one`(그 사람만) \| `all` |
| `get_fetch_send_config(c, owner_id)` | 받기 자격증명으로 발송 설정 생성 |
| `get_send_config_for(c, owner_id)` | 대상이면 위를 쓰고, 아니면 기존 시스템 발송망 |
| `system_send_ready(c, owner_id=None)` | 본인 기준 준비 여부 (옛 호출도 그대로 동작) |
| `send_system(..., owner_id=None)` | 대상이면 그 계정으로 로그인 + **From 을 그 계정 주소로 고정** |
| `fetch_send_status(c, owner_id)` | 화면용 — 쓸 수 있는지 + 안 되면 **왜**. ⭐비밀번호 값은 안 담음 |

### `app/main.py`
- `_mail_from_address_for(c, u)` — 이 사람의 보내는 주소. 보낸편지함 기록도 같은 값이 된다.
- `/mail/compose` · `/mail/send` · `/admin/mail-send` 가 **본인 기준**으로 판단.
- ⭐ **저장 라우트를 `section`(`smtp` \| `via_fetch`)으로 분리.**
  화면에 폼이 둘인데 주소가 같아서, 한 폼을 저장하면 다른 폼 값이 **빈 값으로 덮일** 뻔했다.

### `app/templates/admin_mail_send.html`
- 「⭐ 내 회사 메일주소로 보내기」 카드 — 스위치(끄기/나만/전 직원) +
  **「지금 바로 쓸 수 있습니다 ✅」 / 「아직 못 씁니다 ⚠ + 이유」** 를 화면에 직접 보여 줌.
- 발송망 카드 머리에 **「📮 지금 보내는 주소 = …」** 표시.

## 4. 안전 장치

- ⭐ **기본값 `off`** → 켜기 전까지 **동작 변화 0**. 회귀 시험으로 증명(§8).
- From 은 받기 계정 주소로 **고정** — 제공사가 남의 주소 발송을 막으므로.
- 켜져 있어도 받기 계정이 깨졌으면 **시스템 발송망으로 안전 복귀**.
- **끄는 길이 화면에 늘 보인다** (조용한 먹통 방지).
- **스키마 변경 없음** — `app_settings` 행만, 저장할 때 생성. (지난 8-31 다운의 원인 유형 회피)

## 7. 🔴 남은 불확실성 (정직히)

**하이웍스가 POP3 비밀번호로 SMTP 인증도 받아 주는지는 해 보기 전엔 모른다.**
- 보통 같은 「외부 접속용(앱) 비밀번호」 하나로 둘 다 되지만, **실측 전엔 단정 못 함**.
- 실패하면 화면에 **「발송망 로그인 실패」** 가 뜬다. 그러면 하이웍스에서
  **앱 비밀번호 발급 + POP3/SMTP 사용 활성화**가 필요하다.
- 하이웍스 공식 문서는 웹에서 확인하지 못했다. (검색에 나오는 네이버웍스
  「외부 앱 비밀번호」는 **다른 제품**이라 적용하면 안 된다.)

## 8. 교훈

- 🔴 **같은 주소로 POST 하는 폼이 둘이면 반드시 구분자를 둔다.** 안 그러면
  한쪽 저장이 다른 쪽을 빈 값으로 지운다. 시험에 **「대조군: 빈 값으로 저장하면
  정말 지워진다」** 를 넣어 위험이 실재함을 먼저 증명했다.
- 🔴 **Jinja 문법 통과 ≠ 화면이 그려진다.** 없는 칸·필터는 렌더할 때만 터진다 →
  4가지 상태를 **실제로 그려 보는** 시험을 따로 만들었다.
- 🔴 `main.py` 는 **줄끝이 섞여 있다**(LF/CRLF). 문자열 치환 패치는 두 변형을
  모두 시도하고, 맞은 쪽 줄끝으로 넣어야 한다.
- 🔴 **「모르는 제공사는 짐작하지 않는다」** — 받기→보내기 호스트 표에 하이웍스만
  넣고, 나머지는 빈 값 + 화면에서 직접 입력받게 했다. (`smtps.` 를 일반 규칙으로
  만들면 지메일 같은 곳에서 틀린 호스트를 만들어 낸다.)
