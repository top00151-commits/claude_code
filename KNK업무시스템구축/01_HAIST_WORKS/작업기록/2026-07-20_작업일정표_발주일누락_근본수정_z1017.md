- **일자**: 2026-07-20
- **신고(대표)**: 관리번호 001M2607 · 수주 M-260707-1 · KNK VINA · AUTO TESTER HANDLER · 상품(PARTS)수출 · 12품목 · 진행중 — **제작요청서목록·수출통관엔 나오는데 작업일정표에서 검색이 안 되고, 원래 있었는데 갑자기 안 보임.**

## 근본 원인 (크롬 실측 + 코드 확정)
1. **작업일정표(`/sales/schedule`, main.py `_mk_row` 23923줄)**: `if not s and not e: return None` — **발주일(order_date)·납기(due_date)가 둘 다 없으면 행 제외**(전 기간 검색 1900~2999에서도 제외). → 검색해도 0건.
   - 크롬 실측: `/sales/schedule?cust=001M2607` → 데이터행 0. 수주상세(order 2545) meta = `📅 →`(발주일·납기 둘 다 빔).
2. **상품/부품 일괄등록 주문생성(main.py:28624)**: `_pwf.add_followup_order(c, ..., order_date=r.get("order_date") or "", due_date=r.get("due_date") or "", ...)` — **엑셀 행의 발주일/납기가 비면 그대로 빈 값으로 주문 생성**. `add_followup_order`(project_workflow.py:204)·`confirm_order`(:109)는 발주일 기본값 `None`(빈 값 안 채움).
3. **수주번호는 날짜를 품지만 별개**: `generate_so_no`(project_workflow.py:62·`[사업부]-YYMMDD-N`)의 YYMMDD = `ref_date or today`. M-260707-1의 "260707"=생성일 2026-07-07. 이 날짜가 **order_date 필드로는 복사 안 됨** → 수주번호엔 날짜, 발주일 칸은 빔.
- ⭐ 디자인 전환·최근 커밋(z1006~z1016) 무관. "상품 주문이 발주일 없이 통과되는 구조" + 엑셀 발주일 누락이 원인.

## 승인된 수정안 (대표 지시 2026-07-20)
- **① 예방(자동채움)**: 주문 생성 시 **발주일이 비면 수주번호 날짜(=생성일)로 자동 채움**. add_followup_order·confirm_order 공통(모든 상품/부품/완제품 경로).
- **② 백필(기존)**: 이미 발주일 빈 주문 → **수주번호 YYMMDD 파싱해 order_date 채움**. ⚠**DB 직접 수정 금지** → 관리자 엔드포인트(미리보기=개수·목록 먼저, 적용=UPDATE)로. 대표 승인 후 적용.
- **③ 필수화**: 작성(상품 일괄등록·주문/프로젝트 폼)에서 **발주일·납기일 필수 조건**.
- **④ 납기일 없는 건**: 자동채움 ⛔ → **목록으로 대표께 보고**(대표가 직접 입력). 백필 미리보기에 '납기 빈 주문' 목록 포함.

## 구현 계획
1. `add_followup_order`/`confirm_order`: `order_date` 비면 `date.today()`(수주번호와 동일 근거)로 기본. (⚠ 과거 일괄등록의 실제 발주일과 다를 수 있으나, '날짜 없음=보드 실종'보다 나음. 대표가 개별 수정 가능.)
2. 관리자 엔드포인트 `/admin/order-dates-audit`(대표/admin): 
   - 미리보기: order_date 빈 주문 수+목록(수주번호→파싱 날짜), due_date 빈 주문 목록(대표 수동입력용).
   - 적용(POST): order_date 빈 주문에 수주번호 날짜 UPDATE. due_date는 손대지 않음.
3. 필수화: 상품 일괄등록 파서 검증 + 폼 required.
4. 검증(py_compile·Jinja·영향 전수) → 배포 → 백필 미리보기(개수 보고) → 대표 승인 후 적용 → 크롬 실측(이 건이 작업일정표에 나오는지) → 납기 빈 목록 대표께 전달.

## ⭐정밀 조사 결과(코드 전수·2026-07-20)
- **주요 주문생성 3경로 모두 order_date를 오늘로 이미 자동 채움**:
  - `confirm_order`(project_workflow.py:~151) `else: order_date=date.today()` + `UPDATE projects SET order_date=COALESCE(order_date,?)`(프로젝트도 채움).
  - `add_followup_order`(:266) `else: order_date=date.today()`. ⚠단 **projects.order_date는 안 건드림**(기존 프로젝트에 SO만 추가)·**order_items INSERT엔 order_date 컬럼 없음**(호기 날짜 미설정).
  - 견적→수주(main.py:33412) `date.today()`.
- **보드가 읽는 날짜**: 비분할 프로젝트 행=`projects.order_date`(main.py:24032/24095). **분할 줄(PARTS_EXPORT 등)=`_ln["order_date"](호기/주문) or projects.order_date`(24063/24090).**
- **그런데 order 2545(M-260707-1)는 orders.order_date도 빔**(SO상세 `📅 →` 실측) → **자동채움 도입 전 옛 데이터이거나 상품/수출 전용 경로**로 생성됨(현행 주 경로였다면 오늘로 찼을 것).
- **결론**: ①(생성 시 자동채움)은 **주 경로엔 이미 있음**. 진짜 필요한 건 **②백필**(기존 빈 order_date/projects.order_date 채움) + (혹시 남은 상품/수출 누수 경로 마감) + ③필수화 + ④납기 목록.
