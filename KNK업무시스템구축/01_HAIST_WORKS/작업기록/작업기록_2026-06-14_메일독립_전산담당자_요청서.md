# [전산담당자 요청서] KNK Eum MAIL 독립 서버 가동

- 작성: 빅터(01) · 2026-06-14 · 지시: 김정락 대표
- 목적: 메일(KNK Eum MAIL)을 **메신저처럼 별도 서버·별도 주소**로 독립 가동
- 현재: 코드·DB·검증 완료(독립 앱). **아래 인프라 작업이 끝나면 즉시 가동** 가능

> ⚠ **메일주소 불변(절대)**: 새로 만드는 건 **웹 접속용 서브도메인 1개**뿐입니다.
> `@knknara.co.kr` **메일주소·MX·기존 메일 라우팅은 절대 건드리지 않습니다.**

## 1. 새 서브도메인 (웹용 A/CNAME — MX 아님)
- `mail.knknara.co.kr` → NAS 공인 IP (WORKS `works.knknara.co.kr` 와 동일 호스트)
- **정확한 이름은 기존 메일 DNS와 충돌 없게 전산담당자가 확정** (필요 시 `eummail.` 등 대체)

## 2. SSL 인증서
- 위 서브도메인용 인증서 발급/적용 (Let's Encrypt 등, WORKS 와 동일 방식)

## 3. 리버스 프록시
- `https://mail.knknara.co.kr/` → 내부 `127.0.0.1:8201` (메일 uvicorn)
- WebSocket 불필요. 업로드 큰 파일 대비 `client_max_body_size`(또는 동등) 충분히(예: 600M)

## 4. 서비스(자동 기동)
- 작업 폴더: `…/15_KNK_Mail/`
- 실행: `uvicorn app.main:app --host 127.0.0.1 --port 8201`
  (또는 `python run.py`) · 의존성: `pip install -r requirements.txt`
- WORKS 와 **독립 프로세스**(별도 systemd 유닛 등). 메일만 따로 재시작 가능

## 5. 자동 배포(git pull) — WORKS 1분 cron 과 동일 패턴
- 메일 전용 repo(아래 6항) 를 1분 cron 으로 pull → 코드 갱신 시 서비스 reload
- repo 미정 시: 우선 모노레포(`claude_code`)의 `KNK업무시스템구축/15_KNK_Mail/` 경로로 운영 가능

## 6. 메일 전용 repo (대표 승인 후 빅터가 생성)
- 메신저처럼 메일도 **자체 repo** 권장(WORKS 와 분리 배포). 생성은 대표 승인 후 진행.

## 7. 환경변수 (`.env`)
| 변수 | 값/설명 |
|---|---|
| `KNK_MAIL_DB` | 메일 DB 경로 (예: `/volume1/…/15_KNK_Mail/data/mail.db`) |
| `KNK_MAIL_DATA` | 데이터/첨부 폴더 |
| `KNK_MAIL_SESSION_SECRET` | **랜덤 긴 문자열**(세션 서명) — 운영 필수 |
| `KNK_MAIL_PUBLIC_BASE` | `https://mail.knknara.co.kr` |
| `KNK_MAIL_HTTPS_ONLY` | `1` (세션쿠키 Secure) |
| `KNK_MAIL_SSO_AUDIENCE` | `knk-mail` |
| `KNK_MESSENGER_SSO_BASE` | `https://haist.knknara.co.kr/msg` (WORKS 와 동일) |
| `KNK_SSO_SERVICE_KEY` | **메신저와 공유**(직원명부 동기화) — 메신저 요청서 참고 |
| `KNK_MAIL_KEY` | 메일 비번 암호화 Fernet 키(미설정 시 자동 키파일) |
| `ANTHROPIC_API_KEY` 또는 `OPENAI_API_KEY` | AI 요약·번역(선택) |

## 8. 점검
- `https://mail.knknara.co.kr/healthz` → `{"ok": true, ...}` 확인
- 로그인은 메신저 SSO(→ 9. 메신저 요청서 완료 후 동작)
