## 2. 원인 — 두 신고는 한 뿌리다 (날짜 칸이 「그냥 글자 칸」)

공용 달력(`_v5_partials/knk_datepicker.html`)은 **`input.knk-cal` 또는 `input[type=date]`** 에만 붙는다.

| | 지금까지 |
|---|---|
| 발행일(세금계산서 팝업) | 팝업을 만들 때 `type="date"` 로 만든다 → **달력 ✅** |
| 발주일·납품일·거래명세서 | 표 칸을 누르면 **그 자리에서 맨 글자칸**을 만든다 → **달력 ❌** (신고 ①) |

그리고 공용 달력은 브라우저 기본 달력을 끄려고 **`type=date` → `type=text` 로 바꾼다**
(`knk_datepicker.html:257`). 그래서 **브라우저 검사가 사라진다.** 그런데

| 층 | 지금까지 |
|---|---|
| 브라우저 | 검사 없음(위 이유) |
| 화면 저장 코드 | 발행일 값을 **그대로** 보냄 |
| 서버 | `날짜` 칸이면 **받은 글자 그대로 저장**(`database.py` `_ftype == "date"` → `val or None`) |

→ **세 겹이 다 뚫려** 금액도 그대로 들어갔다 (신고 ②). 금액 칸은 "숫자만 입력" 검사가 있었는데 날짜 칸만 없었다.

var _DATE_FIELDS = ['order_date','due_date','statement_date',

- 편집칸을 만드는 자리 **2곳**(`startEdit`·`startUnitEdit`)이 `_mkCellInput()` 을 쓴다 → 발주일·납품일·거래명세서에 달력.

- 저장 전 검사: `startEdit` · `startUnitEdit` · `startTaxInvEdit`(행 팝업) · 호기별 팝업 · `_uxSave`(호기별 표) · 묶음 발행일 · 일괄수정 — **7곳**.
