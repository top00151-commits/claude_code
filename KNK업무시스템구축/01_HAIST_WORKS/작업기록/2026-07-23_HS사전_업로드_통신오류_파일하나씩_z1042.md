# HS 사전 업로드 "통신 오류: Unexpected token '<'" (z1042)

| | |
|---|---|
| 일자 | 2026-07-23 |
| 신고 | 대표 — *"엑셀 업로드했더니 이렇게 나오는데?"* |
| 증상 | `❌ 통신 오류: SyntaxError: Unexpected token '<', "<!DOCTYPE "... is not valid JSON` |
| LIVE | `e0bb02d` |

---

## 0. 증상이 말하는 것

`<!DOCTYPE` = 서버가 **JSON 대신 HTML 페이지**를 돌려줬다는 뜻.
화면은 `r.json()` 만 믿고 있어서 **파서 예외 문구가 그대로 노출**됐다 — 사용자는 원인을 알 수 없다.

HTML 이 오는 경우는 보통 셋: ①게이트웨이 오류(502/504) ②로그인 페이지(세션 만료) ③앱 500 오류 페이지.

---

## 1. 실측 — 무엇이 아닌지부터 좁혔다

| 검사 | 결과 |
|---|---|
| 빈 요청 | **400 JSON** (`파일이 없습니다`) — 엔드포인트 정상 |
| 1·4·8·12·16MB 더미 | **전부 200 JSON** — **용량 한계 아님** |
| 실제 19개 파싱 시간(로컬) | **합계 27.8초** (최대 파일 3.8MB) |

→ 용량이 아니라 **시간**이 문제일 수 있다. 19개를 **한 요청에 몰아** 보내면
서버 분석 28초 + 12MB 전송이 한 연결에 얹혀 **게이트웨이 시간 초과**에 걸릴 수 있다.

### ⚠ 정직하게 — **그 오류를 그대로 재현하지는 못했다**
LIVE 에 실제 인보이스 19개를 올려볼 수단이 없었다(브라우저 자동화로 실파일 주입 불가).
그래서 **원인을 단정하지 않고**, 어느 쪽이든(시간 초과·세션 만료·앱 오류) 통하도록 고쳤다.

> cf 규칙 §4-24 — 재현 못 한 원인은 추정해서 보고하지 말 것.

---

## 2. 고친 것 — 화면만 (서버 무수정)

| | 전 | 후 |
|---|---|---|
| 전송 | 19개를 **한 요청**에 | **하나씩 순서대로** (요청당 1~2초) |
| 진행 | "⏳ 업로드·분석 중…" 만 | **`⏳ 3/19 분석 중 — 파일명`** |
| 한 개 실패 | 전체 중단 | **나머지는 계속** |
| JSON 아닐 때 | 파서 예외 문구 노출 | **사람 말로**: 502/504=`서버 응답 시간 초과` · 로그인 페이지=`로그인이 풀렸습니다` · 그 외=`서버 오류 (HTTP n)` |

⚠**서버는 그대로 뒀다** — 여러 개 받는 기능은 유지하고 화면만 나눠 보낸다
(잘 되는 걸 건드리지 않는다 · 다른 호출부 영향 0).

---

## 3. 검증 (LIVE `e0bb02d` · 화면의 진짜 기능 실행)

가짜 xlsx 3개를 실제 `hsdUpload()` 에 넣어 돌림(파싱 실패하므로 **데이터 변경 없음**):

```
⏳ 1/3 분석 중 — 시험A.xlsx
⏳ 2/3 분석 중 — 시험B.xlsx      ← 순차 전송·진행률 ✅
⏳ 3/3 분석 중 — 시험C.xlsx
완료: 추가 0 · 갱신 0 · 실패 3

❌ 시험A.xlsx — 파싱 실패: File is not a zip file
❌ 시험B.xlsx — 파싱 실패: File is not a zip file   ← 하나 실패해도 계속 ✅
❌ 시험C.xlsx — 파싱 실패: File is not a zip file
```
4.0초. 배포된 코드에 시간초과·세션만료 안내 문구 존재 확인. JS 문법·표준검사 통과.
