## 1. 신고된 증상

> ① 입력하다가 다른 곳으로 갔다 올 때 **이전 입력값이 저장된 상태**라 가끔 화면이 이상하게 동작한다.
>   예를 들어 PO유형을 '추가'로 했다가 나갔다 다시 들어오면 계속 '추가'로 되어 있는데
>   **관리번호를 입력할 수가 없게 된다.** 뭔가 **페이지에 갇혀있는 느낌**.
>
> ② 안지연 프로 — **단가 입력이 계속 안 된다. 단가 칸이 클릭은 되는데 숫자 입력이 안 되는 증상.**

## 2. 원인 ① — 단가가 조용히 지워지고 있었다

### 무슨 일이 있었나

`qUnitSum()` 이 **`v.qty >= 2` 만 보고 '추가발주인지'를 안 봤다.**

```js
if(v.qty>=2){                    // ← 추가발주여도 그냥 실행
  amt.value = sum;               // 합계(=0)로 덮음
  var _a=[];                     // #qUnitRows 가 비어 있어 빈 배열
  var _eq = _a.length>0 && ...;  // → 항상 false
  up.value = '';                 // ← 입력한 단가를 지움
  up.placeholder = '(호기별)';    // ← 사진에 보이던 그 문구
}
```

호출 순서가 결정타였다. **추가발주면** `qBuildUnits()` 가:

```js
wrap.style.display='none';
rows.innerHTML='';          // 호기줄을 지우고
qSyncUnitStatic(false);
qLockHeaderPrice(false);    // 잠금은 풀지만
qUnitSum();                 // ← 여기서 위 블록이 실행됨 (수량이 6이라)
```

→ **호기줄을 막 지운 직후에 "호기줄 기준으로" 단가를 계산**하니, 빈 배열을 보고 단가를 지워버린다.

### 사용자에게 어떻게 보였나
- 수량이나 PO유형을 건드릴 때마다 **입력한 단가가 사라짐** → "입력이 안 된다"
- 안내문이 `(호기별)` 로 남아 **"여기는 못 쓰는 칸"** 으로 오해
- 제출 시 나온 `단가를 입력하세요 (0보다 커야 합니다)` 오류도 실은 **입력한 게 지워져서** 난 것

> ⚠️ 진짜로 타이핑이 막힌 게 아니라 **써도 지워지는** 것이었다. 그래서 "클릭은 되는데 숫자입력이 안 된다"로 표현된 것.

### 수정
```js
var _urows = document.querySelectorAll('#qUnitRows .qf-unit-row');
var _isMulti = (v.qty >= 2) && !qIsFollowup() && _urows.length > 0;
if(_isMulti){ ...기존 계산... }
else if(up && up.placeholder !== '0'){ up.placeholder='0'; }   // 안내문 원복
```
**호기줄이 실제로 그려져 있을 때만** 헤더를 덮는다. 아니면 사용자가 직접 쓰는 칸이므로 건드리지 않는다.

## 3. 원인 ② — 복원이 '값'만 되돌리고 '화면 상태'는 안 되돌렸다

`qfRestore()` 가 부르던 것 / 안 부르던 것:

| 화면 상태 함수 | 복원 시 호출 | 안 부르면 |
|---|---|---|
| `qToggleFx` `qCalcParts` `qFormSyncLabel` `qSyncShip` `qBuildUnits` `qUnitSum` | ✅ | |
| **`qSyncPoType`** | ❌ **누락** | **PO유형='추가'인데 관리번호 칸이 `disabled`+`display:none` 인 채로 남음** |
| `qManualToggle` | ❌ 누락 | 수동발행 체크는 복원되나 입력칸이 안 열림 · 검증기록(`_qManualOK`) 없어 제출 거부 |
| `qUnitDueSync` | ❌ 누락 | 납기 일괄적용 체크 복원돼도 호기 납기 잠금 안 맞음 |

→ 대표가 말한 **"관리번호를 입력할 수가 없게 된다"** 가 정확히 이것.
값은 되살아나는데 그 값에 딸린 화면이 안 따라와서 **모순된 상태로 굳는다** = "갇힌 느낌".

### 수정
복원 4단계 뒤에 추가:
```js
qManualToggle();                       // 수동발행 체크 → 입력칸 열기/닫기
if(수동코드 있음) qManualReset();       // 검증기록은 복원 안 되므로 '다시 [검증]' 안내
qSyncPoType();                         // PO유형 → 관리번호 칸 잠금/해제 (내부에서 qBuildUnits 재평가)
...(호기줄 복원 후)...
qUnitDueSync();                        // 납기 일괄적용 반영
```

## 4. 근본 대책 — 복원됐다는 걸 눈에 보이게

사용자가 **복원됐다는 사실 자체를 몰라서** 이상하게 느낀 것이 문제의 뿌리였다.

`qfShowRestoredBar()` 신설:
```
✏️ 이전에 쓰다 만 내용을 불러왔습니다. 새로 작성하시려면 오른쪽 버튼을 누르세요.  [🗑 지우고 새로 시작]
```
- 폼 맨 위(오류 표시줄 자리)에 파란 안내 띠
- 버튼 = `qfClear()` + `location.reload()` → 임시저장·값·안내띠 전부 초기화
- **빈 껍데기면 안 띄운다** — 프로젝트명·모델·장비·관리번호·고객사·단가·금액·발주일·납기·비고 또는 호기값 중 **실제로 적힌 게 있을 때만** 표시(클릭만 하다 나간 경우까지 잔소리하지 않도록)

## 6. 알아둘 것

- **임시저장 키는 사업부별로 따로**다 (`knk.qf.draft.T`, `...M` 등). 검사기 탭에서 쓰다 만 내용은 자동화 탭에 안 뜬다.
- 임시저장은 **수정 모드(`QF_ED`)에선 동작하지 않는다** — 신규 등록 폼 전용.
- **제출 성공 시 자동 삭제**되고, 클라 검증에 막힌(preventDefault) 경우엔 **보존**된다(입력 날아감 방지).
- `qCalcAmount`(단가×수량=금액)와 `qUnitSum`이 같은 칸(`qAmount`·`qUnitPrice`)을 건드린다. 이번 수정으로 **역할이 갈렸다** — 호기줄 있으면 `qUnitSum`, 없으면 `qCalcAmount`. 앞으로 이 두 함수를 손댈 땐 반드시 같이 볼 것.

## 7. 남은 후속
- 같은 '값 복원 vs 화면 상태' 문제는 **다른 폼에도 있을 수 있다.** 임시저장을 쓰는 폼이 더 있으면 동일 점검 필요(현재 확인된 건 간편등록 폼 1개).
- 안지연 프로께 **수정 완료 + 새로고침 한 번** 안내 필요(옛 탭은 예전 화면일 수 있음).
