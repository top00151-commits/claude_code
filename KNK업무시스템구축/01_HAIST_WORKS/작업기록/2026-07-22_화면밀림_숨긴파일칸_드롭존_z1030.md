## 1. 원인 — LIVE 실측으로 증명

### 페이지가 창보다 길었다
```
창 높이            666px
페이지 실제 높이    812px   ← 146px 초과
```

### 초과분의 정체
화면 틀(`.app`) **바깥**, `<body>` 맨 아래에 붙은 **130px 짜리 '파일 넣는 상자'**.

그 상자만 잠시 숨겨보니:
```
숨기기 전 : 812px (넘침 146)
숨긴 직후 : 666px (넘침 0)   ← 원인 확정
```

### 상자는 어디서 왔나
`project_detail.html:2489~2493` — 업로드 버튼용 파일칸을 **숨겨서 body에 직접 붙인다**:
```js
f.style.display = 'none';       // 안 보이게 만들고
document.body.appendChild(f);   // 페이지 맨 밑(화면 틀 바깥)에 붙임
```
그런데 전역 `dragdrop.html` 의 `autoWrap()` 이 **숨긴 칸까지 감싸서** 보이는 상자로 만들었다.

> 대표가 전에 *"아래 파일 넣는 건 어떤 기능인가요?"* 라고 물었던 **바로 그 상자**다.
> **정체불명 상자와 화면 깨짐이 같은 원인**이었다.

### 밀리는 순간 — `overflow:hidden` 이 못 막는 것
셸은 `.app{height:100vh; overflow:hidden}` 이라 **일반 스크롤은 막힌다.** 실측:

| 시도 | 결과 |
|---|---|
| `window.scrollTo(0,500)` | **안 밀림** ✅ (overflow:hidden 이 막음) |
| **화면 밖 상자를 보이게 하기**(scroll-into-view) | **138.5px 밀림** ❌ |

**브라우저가 "화면 밖 요소를 보여주려고" 끌어올리는 동작은 `overflow:hidden` 으로 못 막는다.**
그 상자를 **클릭**하거나, 브라우저 찾기(Ctrl+F)·키보드 이동으로 그쪽에 초점이 가면
**화면 전체가 끌려 올라간다.**

안지연 프로가 자주 겪은 이유 = **그 상자가 뭔지 몰라 눌러보셨기 때문**일 가능성이 크다
(실제로 용도를 물어보셨다).

## 2. 수정

`dragdrop.html` `autoWrap()` 앞에 **`isHiddenTrigger()` 게이트** 추가.

```js
function isHiddenTrigger(inp){
  if (/display\s*:\s*none/i.test(inp.getAttribute('style')||'')) return true;
  if (inp.hidden) return true;
  if (getComputedStyle(inp).display === 'none') return true;
  return false;
}
function autoWrap(inp){
  if (inp.closest('.knk-dropzone')) return;
  if (isHiddenTrigger(inp)) return;     // ← 숨긴 방아쇠는 감싸지 않음
  ...
```

**원칙**: `display:none` 인 파일칸은 **버튼 뒤에 숨겨둔 프로그램용 방아쇠**다.
드롭 대상이 아니므로 감싸면 안 된다. (숨긴 채로는 어차피 끌어다 놓을 수도 없었다.)

### ⚠️ `visibility` 는 검사하지 않는다
`visibility` 는 **상속**되므로, 탭·접이식 안의 **정상 칸까지 오탐**한다.
`display` 는 상속되지 않아 `'none'` 이면 **그 칸 자체가 숨겨진 것이 확실**하다.

## 5. 배운 것 (다음에 같은 함정 피하기)

1. **`overflow:hidden` 은 만능이 아니다.** 일반 스크롤은 막지만
   **scroll-into-view(브라우저가 요소를 보여주려는 동작)** 는 못 막는다.
   → 셸이 `100vh` 고정인 구조에서는 **`<body>` 직속에 보이는 요소를 붙이면 안 된다.**
2. **전역 자동 처리(auto-wrap)는 "숨긴 것"을 존중해야 한다.**
   개발자가 일부러 숨긴 요소를 전역 헬퍼가 되살리면, 원래 의도와 다른 부작용이 난다.
3. **"이게 뭐예요?" 질문은 버그 신호일 수 있다.** 이번 건은 미관 질문으로 접수됐다가
   실제로는 화면 깨짐의 원인이었다.

## 6. 남은 것
- 같은 패턴(`document.body.appendChild` 로 보이는 요소 추가)이 다른 화면에도 있는지는 미점검.
  필요하면 `check_standards.py` 에 "body 직속 요소로 페이지가 창보다 길어지는지" 항목 추가 검토.
