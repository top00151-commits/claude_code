### 3.1 리허설이 잡은 결함 1건 (배포 전 수정)
새 DB 인데 **"기존 DB 보정"이 실행**됐다.

- 원인: `sqlite_master` 는 CREATE TABLE 을 **주석까지** 보관한다. 구버전 판정을
  `"DEFAULT 'KOR'" in sql` 로 하다가 같은 CREATE 문의 설명 주석
  (`기본값(DEFAULT 'KOR')을 두면 …`)에 스스로 걸렸다.
- 결과: 방금 만든 표를 즉시 재작성하고 **'고쳤다'고 사실과 다르게 보고**(빈 표라 데이터 피해는 없음).
- 수정: 판정을 **스키마 메타데이터**(`PRAGMA table_info` 의 `dflt_value`)로 교체.
- ⚠ **같은 방식(DDL 글자 검색)으로 확인하던 테스트는 그 결함 덕에 통과**하고 있었다 → 테스트도 교체.

## 5. 🔴 LIVE 에서 발견한 사항 — 대표 계정이 '시스템 관리자'로 잡힘

**사실**: 호기 화면에 `🛠 시스템 관리자 비상복구` 배너가 대표 계정에 표시된다.
이 배너는 `role == 'admin'` 일 때만 나오므로, **대표 계정의 role 이 `admin`** 이다.

**영향**: 승인된 계약은 *"기술영업팀·대표·임원의 정상 업무에는 관리자 비상복구 사유를 요구하지 않는다"* 인데,
현재 대표가 호기 업무를 하려면 **매번 '요청 부서·요청자'와 '우회 사유'를 입력**해야 하고
안내 문구도 *"호기 업무는 기술영업팀 담당입니다. 대신 수행하려면…"* 으로 대표에게 어색하다.

**실측**: `main.py` 전체에서 `role == 'admin'` 만 허용하는 곳은 **없고**(WP-03 제외),
`role in ("ceo","admin","executive")` 로 **동급 취급하는 곳이 9군데**다.
→ WP-03 이 코드 전체에서 유일하게 `admin` 과 `ceo` 를 다르게 다룬다.

**선택지**

| 안 | 내용 | 위험 |
|---|---|---|
| A | 대표 계정 role 을 `ceo` 로 변경 | 낮음 — 다른 9곳이 동급이라 기능 변화 없음. 전산 관리자만 `admin` 으로 남아 의도대로 갈림 |
| B | WP-03 에서 대표를 사번으로 예외 처리 | 하드코딩 — 비권장 |
| C | 그대로 둠 | 대표도 매번 사유 입력(계약과 불일치) |

**권장 = A** · ⛔ 대표 지시 없이는 변경하지 않음(LIVE 사용자 데이터 + 게이트가 WP-03 범위 동결).
