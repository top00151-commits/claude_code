## 2. 고친 것

### P-1 / P-2 — 구매검토의 핵심 5열이 통째로 버려지던 것

```
사내 재고 · 베트남 재고 · 발주 수량   →  버림
재고 금액                          →  amount 로 잘못 매핑
발주 금액 · AMOINT 합계             →  버림
```

신설 필드: `stock_qty_kor` · `stock_ref_vn` · `order_qty` · `stock_amount` · `order_amount`

⭐ **넓은 별칭보다 앞에 배치했습니다.** `_HEADER_ALIASES` 는 왼쪽 열부터 훑으며 **첫 매칭 필드**를 잡고 그 필드를 `used` 처리합니다. 그래서 `발주 수량`이 `"수량"`(unit_count)에, `재고 금액`이 `"금액"`(amount)에 먼저 잡히면 **원본이 영영 사라집니다.** 실제로 그랬습니다.

⚠ **`stock_ref_vn` 은 이름부터 `ref`(참고)입니다.** 대표 판정대로 본사 가용재고·원장·자동 구매량 계산에 넣지 않으며, 운영수량과 섞이지 않도록 이름으로 구분했습니다.

### P-3 — 원본에 적힌 금액이 있으면 계산하지 않는다

```python
# 전: amount 가 0이기만 하면 무조건 단가 × 수량으로 덮어씀
# 후: 합계 열 자체가 없을 때만 계산 + 계산했다는 사실을 표시
if "amount" not in _mapped and it["unit_price"]:
    ...
    it["amount_is_calculated"] = True
```

| | 전 | 후 |
|---|---|---|
| 구매팀 최종본 합계 | 103,266,661.32 (계산값) | **103,521,961.32 (원본)** |
| 차이 | **255,300원 틀림** | 0 |

⚠ **이 결함이 설계팀 파일에서는 드러나지 않았습니다.** 그 파일은 단가·금액이 전부 비어 있어 계산 분기를 타지 않았기 때문입니다. 그래서 제가 "완벽히 읽는다"고 잘못 보고했습니다.

### P-4 — 화살표가 두 번인 줄

```
MFMCA0030RJD -> ELM-PWR3M0-A1 -> E-CASP3M-N     (단종 → 대체 → 재대체)
```

`maxsplit=1` 이라 첫 화살표만 잘리고 **뒤쪽 화살표가 새 품번 안에 통짜로 남아** 5줄이 잘못된 품번을 가졌습니다.

`_split_arrow_chain()` 을 신설해 **처음 값 → 마지막 값**으로 잡고, 중간 단계를 `chain` 에 보존합니다. 기존 `_split_arrow()` 는 호환을 위해 남겼습니다.

### P-5 — 자재가 아닐 수 있는 줄에 **의심 표시**만

`해외 출장비 (VINA)` · `프로그램 개발비` 가 **단위 EA** 로 자재와 똑같은 모양으로 들어옵니다.

⛔ **시스템이 자동으로 걸러내지 않습니다.** `is_service_suspect` 로 **표시만** 하고 판정은 사람이 합니다. 임의 추정 금지 원칙 때문입니다.
