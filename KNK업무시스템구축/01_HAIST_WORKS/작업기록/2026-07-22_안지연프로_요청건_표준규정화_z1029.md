## 2. 공용 코드로 강제 — `_v5_partials/knk_rowflag.html`

`styles.html` 전역 include. **클래스만 붙이면 규정이 자동으로 지켜진다.**

```html
<tr class="knk-row-flag">                        <!-- 기본 amber = "확인해 보세요" -->
  <td>… <span class="knk-flag-badge">중복 2</span></td>
```
톤: `--info`(파랑) · `--ok`(초록) · `--danger`(빨강 · **정말 잘못된 값에만**)

### 왜 덧칠인가 (z1026 실제 사고)
부품표의 매입·마진 칸은 **인라인 style 로 원가색(`#fff7ed`)** 을 갖는다.
줄 강조를 `background: … !important` 로 주면 **그 색까지 덮어써 원가 열 구분이 사라진다.**
`box-shadow: inset 0 0 0 9999px rgba(...)` 는 배경을 **지우지 않고 위에 얹으므로**
줄무늬·원가열·상태색이 그대로 비쳐 보인다.

### 함께 정리
z1026 의 `dup-spec` → `knk-row-flag` 로 교체하고 **`project_detail.css` 의 중복 정의를 제거**했다.
같은 규칙이 두 곳에 있으면 반드시 어긋난다.

## 3. 자동검사 — `deploy/check_standards.py`

```
python deploy/check_standards.py            # 전체
python deploy/check_standards.py --changed  # 변경분만
종료코드 0=통과 / 1=위반
```

검사 3종:
1. **인라인 `<script>` JS 문법**(esprima) — WORKS엔 검사기가 없어 **문법 오류 하나가 화면 전체를 죽일** 수 있었다(메신저의 `check_js_syntax.py` 에 대응)
2. **표 줄/셀 `background !important`**
3. **스크롤표 `100vh` 매직넘버**

### ⭐핵심 설계 — BASELINE 방식
처음엔 전량 차단으로 만들었더니 **143건**이 나왔다. 이러면 아무도 안 본다.

| | 건수 |
|---|---|
| 처음(전량 차단) | 143건 |
| 정밀화 후 | **15건** |
| BASELINE 등재 후 | **0건** (새 위반만 잡음) |

정밀화 내용:
- 미사용 레거시/백업 폴더 제외(`_legacy_base`·`_v4_backup`) — 지적된 JS 4건은 전부 여기였고 **실제로는 정상 코드**(내 Jinja 제거 과정의 오탐)
- `!important` — **표의 줄/셀**만. hover·drag·선택·인쇄는 정당하므로 제외
- `100vh` — **스크롤 컨테이너의 max-height**만. 셸 레이아웃(`.main{height:calc(100vh-topbar)}`)은 정상

**BASELINE = 기존 것은 개수만큼 면제, 늘어나면 잡는다.** 지금 잘 도는 화면을 무리해서
바꾸지 않으면서(대표 방침) **새로 생기는 위반은 반드시 걸린다.**
