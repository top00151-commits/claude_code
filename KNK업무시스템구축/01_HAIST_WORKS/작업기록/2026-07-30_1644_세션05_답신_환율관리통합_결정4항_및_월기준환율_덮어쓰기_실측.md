## 3. 🔴 실측 — 자재구매 입력이 매출 월 기준환율을 **조용히 덮는다**

### 3-1. 원인 (코드)

`app/main.py:20594` `_fx_load_rates` 가 읽는 문장입니다.

```sql
SELECT UPPER(from_currency) AS ccy, substr(rate_date,1,7) AS ym, rate
FROM exchange_rates
WHERE COALESCE(to_currency,'KRW')='KRW' AND rate>0
```

- **날짜 조건이 없습니다.** 그 달의 **아무 날짜** 행이나 전부 읽습니다.
- 읽은 뒤 `rates[통화][YYYY-MM] = rate` 로 넣습니다 → **같은 달에 여러 행이면 나중에 읽힌 행이 이깁니다.**
- `ORDER BY` 가 없어 **어느 행이 이길지 보장되지도 않습니다.**

반면 `/admin/fx-rates/save` 는 `rate_date='YYYY-MM-01'`(그 달 1일)로 저장합니다.
`/rates/new` 는 **사용자가 고른 아무 날짜**로 저장합니다. → 같은 달에 두 행이 공존합니다.

### 3-2. 재현 (로컬 임시 DB · 운영 무접촉)

```
① 매출이 /admin/fx-rates 로 2026-07 기준환율 입력 (2026-07-01, USD 1,527.30)
   → 2026-07 USD 기준환율 = 1527.3        ✅ 정상

② 구매팀이 /rates/new 로 2026-07-15 에 USD 1,400.00 입력
   → 2026-07 USD 기준환율 = 1400.0        🔴 매출 기준환율이 바뀜

   2026-07 USD 행 수 = 2 (둘 다 살아 있음 · 삭제된 것 아님)
```

**아무 경고도 없고, 매출 화면에는 그대로 1,400 이 적용됩니다.**

### 3-3. 금액으로 보면

| 기준환율 | 1억 원을 USD 로 |
|---|---|
| 1,527.30 (매출이 정한 값) | **65,473 USD** |
| 1,400.00 (구매팀이 넣은 값) | **71,428 USD** |
| **차이** | **5,955 USD** |

### 3-4. 영향 범위 — 🔴 **어제 신설한 메신저 환율 기능도 포함됩니다**

`_fx_load_rates` 를 부르는 곳 (`origin/main` = `f4a2cdc7` 기준):

| 위치 | 무엇 |
|---|---|
| `main.py:9124` | 수주·매출 금액 원화 환산 |
| **`main.py:20693`** | **`/api/fx/monthly` — 메신저 금액 원화 환산 (z1071 · 대표 지시 2026-07-30)** |
| `main.py:20732` | `/admin/fx-rates` 월 기준환율 격자 화면 |
| `main.py:21074` | 소모품 매출 금액 표시 (z900) |

`_fx_pick`(`main.py:20611`, z1071 신설)도 `_fx_load_rates` 의 결과를 그대로 받습니다.

> **어제 대표님이 지시하신 "메신저에서 $ 금액을 눌러 원화로 보기"가 같은 결함을 물려받았습니다.**
> 구매팀이 `/rates/new` 에 임의 환율을 넣으면 **메신저에 보이는 원화 금액까지 바뀝니다.**
> z1071 은 주석에 *"인터넷 시세를 따로 가져오면 회계 숫자와 어긋나므로 쓰지 않는다"*고
> 적어 두었는데, **정작 사내 다른 입력 경로 때문에 어긋날 수 있는 상태**입니다.

이 때문에 §4-A(날짜 조건 넣기)의 우선순위가 올라간다고 봅니다 —
고칠 곳은 **`_fx_load_rates` 한 함수**이고, 그 한 곳을 고치면 위 네 곳이 함께 지켜집니다.

### 3-5. ⛔ 아직 확인하지 못한 것 (정직하게)

- **운영에 실제로 그런 행이 있는지는 확인하지 않았습니다.** 위는 **로컬 재현**입니다.
- 확인하려면 운영 DB **읽기 전용 조회 1회**가 필요합니다(아래 §5).
- *"칸이 있다 ≠ 누가 쓴다"* 는 제가 WP-04 에서 두 번 지적받은 원칙이라, 세어 보기 전에는 "이미 사고가 났다"고 말하지 않겠습니다.

## 4. 그래서 제안이 어떻게 바뀌는가

원문의 방향(입력을 매출 한 곳으로)은 **그대로 맞습니다.** 다만 할 일이 하나 늘어납니다.

| 순서 | 할 일 | 담당 |
|---|---|---|
| **A** | **`_fx_load_rates` 에 날짜 조건 넣기** — 월 기준환율은 **그 달 1일 행만** 읽도록. (`substr(rate_date,9,2)='01'` 등) · **한 함수만 고치면 §3-4 네 곳이 함께 지켜집니다(메신저 포함)** | **세션 01** (`main.py:20594` 소유) |
| **B** | 자재구매 입력 3경로 잠금 — `/rates/new` · `/rates/upload` · **`/fx/rates`** | 세션 05 + `/fx/rates` 는 소유 확정 필요 |
| **C** | `/rates` 를 조회 전용으로 · 안내 문구 + 매출 월 기준환율 링크 | 세션 05 |
| **D** | 사이드바 `💱 환율(조회)` 로 라벨 변경 | 세션 05 |
| **E** | 한국은행 API 는 **A 가 끝난 뒤에** 단일 소스에만 | 세션 01 |

> **A 를 B 보다 먼저** 하시길 권합니다.
> B 만 하면 *앞으로* 들어올 오염은 막지만, **이미 들어와 있는 행은 계속 이깁니다.**
> A 를 하면 과거 행이 있어도 월 기준값이 지켜집니다.

### `/fx/rates`(#3) 소유는 누구입니까

원문 소유표에 없습니다. 주석상 "외부 시스템 통합용"이라 **자재구매 것도 매출 것도 아닌 것으로 보입니다.**
`_fx_guard` 에 **관리팀(team_id=3)** 이 들어 있어, 닫으면 관리팀이 쓰던 길이 사라질 수 있습니다.
→ **대표께서 소유와 존치 여부를 정해 주시면** 그대로 따르겠습니다.

## 5. 착수 전 요청 — 운영 **읽기 전용** 조회 1회

아래만 확인하면 §3 이 "가능성"인지 "이미 일어난 일"인지 확정됩니다.

```
1) 같은 (통화, 월) 에 행이 2개 이상인 경우가 있는가 · 몇 건인가
2) 그중 1일이 아닌 행이 이기고 있는 (통화, 월) 은 어디인가
3) exchange_rates.source 별 건수 — '월기준' / '수동' / 'CSV' / 그 외
   → /fx/rates·/rates/upload 를 실제로 쓰는 사람이 있는지 판단
```

- **읽기만 합니다.** `mode=ro` 로 열고, 쓰기·수정은 하지 않습니다.
- ⛔ 데이터 정정이 필요해지면 **SSH 가 아니라 앱 정식 화면**으로 하겠습니다(대표규정).
- 결과는 별도 짧은 보고서로 올리겠습니다.

**승인해 주시면 바로 확인하겠습니다.**
