# [메신저 세션 요청서] KNK Eum MAIL 을 SSO 새 소비자로 등록

- 작성: 빅터(01) · 2026-06-14 · 지시: 김정락 대표
- 목적: 독립 메일 앱(`mail.knknara.co.kr`)이 **메신저 SSO로 로그인**하고 **직원명부를 동기화**하도록 메신저 측 설정/확인
- 배경: 메일을 WORKS에서 분리(별도 서버·별도 DB). 메일은 자체 audience `knk-mail` 로 토큰을 검증함.

## 1. 메일을 SSO SP(소비자)로 등록 — 필수
- **audience = `knk-mail`** 토큰 발급(메일 진입 시). WORKS 는 `haist-works`, 메일은 `knk-mail`.
- **redirect_uri allowlist** 에 추가: `https://mail.knknara.co.kr/sso/land`
- 토큰 규격은 WORKS 와 동일(RS256·iss `https://haist.knknara.co.kr/msg/`·sub=사번·claim: name_kr/en/vi·dept·entity·email·pwv 등)
- 메일 로그인 흐름(WORKS와 동일 계약):
  `메일 /login → build_login_url(redirect_uri=…/sso/land) → 메신저 → redirect_uri?token=<JWT>`

## 2. 직원명부 API 확인 — `GET /api/sso/directory`
- 메일이 **별도 DB**라 직원명부를 동기화로 미러링함(`sync_directory_from_messenger`).
- 헤더 `X-SSO-Service-Key: <KNK_SSO_SERVICE_KEY>` 로 호출 → `{"users":[{employee_no,name_kr,name_en,name_vi,dept,position,entity,email,phone,is_admin}, …]}`
- **이 API가 이미 있으면** 즉시 동작. **없으면** 구현 요청(WORKS 도 동일 인터페이스 사용).
  - (대안) API 준비 전까지는 메일 첫 로그인 시 토큰 payload 로 본인만 upsert 되어 사용에는 지장 없음.

## 3. 공유키 `KNK_SSO_SERVICE_KEY`
- 메신저 ↔ 메일 서버 공유(전산담당자가 메일 `.env` 에 동일 값 등록).

## 4. (후속) 메신저 📧 메일 아이콘 목적지 변경
- 현재 메신저의 📧 메일 아이콘은 WORKS(`works.knknara.co.kr/mail`) 로 감.
- **전환(cutover) 시점에** `https://mail.knknara.co.kr/sso/login` (또는 `/mail/app`) 로 변경.
- ⚠ 전환 전까지는 **그대로 두기**(현 메일 정상 동작 유지).

## 5. 안전
- 메일주소·MX·기존 메일 라우팅 무관(웹 SSO 설정만).
- 권한: 현재 모든 인증 직원 입장 허용. 필요 시 메신저가 `mail_access` claim 추가하면 메일이 게이트 강화 가능.
