## 1. 한 줄 요약

`내 프로필`(`/me`) 언어 고르는 칸에 **「Tiếng Việt(vi)」 선택지가 없다.** 서버는 `vi` 를 받고, 실제로 **52명이 `vi`** 인데 화면에는 **한국어·English 둘뿐**이다.

## 2. 🔴 지금 실제로 벌어지는 일 (이게 핵심)

`app/templates/profile.html` 99~102줄:

```html
<select name="lang">
  <option value="ko" ...>한국어</option>
  <option value="en" ...>English</option>
</select>
```

`user.lang == 'vi'` 인 사람이 이 화면을 열면 **맞는 선택지가 없다** → 브라우저는 **첫 항목(한국어)** 을 보여 준다.
그 상태로 이메일·전화만 고치고 **「💾 변경사항 저장」** 을 누르면 `lang=ko` 가 함께 전송된다
→ **본인도 모르게 언어가 한국어로 바뀐다.** (반대로 베트남 직원은 베트남어를 **고를 수가 없다**.)

## 3. 실측 사실 (2026-10-10 · 운영 DB)

| | |
| --- | --- |
| 재직자 `lang='vi'` | **52명** (전원 베트남 법인) |
| 재직자 `lang='ko'` | 105명 (본사 77 · 베트남 법인 28) |
| 🔴 한국 직원인데 `vi` 로 된 분 | **최소 3명** — 이용식(법인장) · 권혁인 · 박지만 (대표 확인) |
| `users` 표의 말 관련 칸 | **`lang` 하나뿐** |
| 직원 동기화가 `lang` 을 덮나 | **아니다** — `lang` 을 쓰는 곳은 아래 두 창구뿐 |

🔵 **이음 메신저 「내 상태」의 언어와는 전혀 다른 설정이다.** 이음은 4가지(中文 포함), WORKS 는 3가지(`i18n.py LANGS` = ko·vi·en). 서로 연결돼 있지 않다 — 이음에서 한국어로 바꿔도 WORKS 값은 그대로다.

🔵 **지금은 티가 안 난다** — WORKS 화면 **366개 중 번역을 쓰는 것이 5개뿐**(견적서 인쇄·이슈 목록·QMS 2·재고 이슈). 그래서 `vi` 여도 대부분 한국어로 보인다. **⏭ 곧 달라진다 — 아래 6번.**

## 4. 고쳐 주실 것

### ① `profile.html` — 선택지에 베트남어 추가
```html
<option value="vi" {% if user.lang == 'vi' %}selected{% endif %}>Tiếng Việt</option>
```
순서는 `i18n.py` 의 `LANGS`(ko · vi · en)와 같게.

### ② 🔴 두 창구의 기준이 다르다 — 통일
| 창구 | 지금 받는 값 | 문제 |
| --- | --- | --- |
| `POST/GET /api/set-lang` (main.py 7287~) | `LANGS` 안의 것만 = **ko·vi·en** | 기준에 맞음 |
| `POST /me` (main.py 13442~) | `("ko","en","vi","zh")` | 🔴 **`zh` 를 받는다** — `i18n.py` 에 `zh` 가 없어 받아도 한국어로 떨어진다(죽은 값) |

→ `/me` 도 **`LANGS` 를 기준으로** 판정하게 바꿀 것. 두 곳이 같은 한 곳을 보게.

### ③ 🔴 모르는 값이 와도 **조용히 덮어쓰지 말 것**
`user.lang` 이 선택지에 없는 값(예: 옛 `zh`)일 때, 저장하면서 말없이 바꾸지 말고 **그 값을 그대로 두거나** 화면에 「지금 설정: zh(목록에 없음)」처럼 보여 줄 것.
(지금 구조에서 제일 위험한 자리 = ①을 고치면 `vi` 는 해결되지만 **다른 모르는 값이 또 생기면 같은 사고가 난다**.)

## 5. 🔵 이미 있는 것 — 새로 만들 필요 없음

- 번역 장치 `app/i18n.py` — 키 466개 · `t(key, lang)` · `get_all_translations(lang)`
- `main.py` `ctx()` 가 **모든 화면에** `i`(번역 사전)와 `lang` 을 이미 넣어 준다
- 말 고르는 순서: `users.lang` → 세션 → `ko`
- `/api/set-lang` 창구는 **이미 잘 돈다**(POST JSON · GET 쿼리 둘 다)

## 6. 왜 지금 필요한가 (⏭ 곧 오는 변화)

세션 16 이 **회의록 화면을 베트남어로** 만들 예정입니다(대표 지시 2026-10-10 「중국어 빼고 베트남어만」 · 583개 글).
그러면 지금 잠자던 `lang` 이 **깨어납니다.**
- `vi` 로 잘못 설정된 한국 직원(최소 3명)은 **회의록이 베트남어로 보입니다**
- 그때 **스스로 되돌릴 길이 있어야** 합니다 ← 이 지시서의 목적
- ①이 없으면 틀린 사람이 나올 때마다 **서버에서 손으로 고쳐야** 합니다

## 7. 🔴 경계 — 건드리지 마실 것

- **회의록·음성 메모 화면 번역은 세션 16(저) 몫**입니다. `meeting_form.html` · `meetings.html` · `voice_note*.html` 에 손대지 마십시오(제가 583개를 작업 중입니다).
- **사람들의 `lang` 값을 일괄로 바꾸지 마십시오.** 누가 어느 나라 사람인지는 이름으로 판단할 수 없습니다 — **대표가 짚어 주셔야** 합니다. 이용식·권혁인·박지만 세 분도 **대표 지시가 나오면** 바꿉니다.

## 8. 검증 요건 (완료 판정)

1. `vi` 인 계정으로 `/me` 를 열면 **「Tiếng Việt」이 선택된 채** 보인다
2. 그 화면에서 **이메일만 고쳐 저장해도 `lang` 이 `vi` 그대로**다 ← 🔴 지금 깨져 있는 바로 그것
3. 한국어 계정에서 베트남어로 바꾸고 다시 한국어로 **되돌릴 수 있다**
4. `/api/set-lang` 과 `/me` 가 **같은 기준**(LANGS)으로 판정한다 — `zh` 를 보내면 둘 다 같게 거절
5. 번역을 쓰는 화면 5개(견적서 인쇄 등)에서 말이 실제로 바뀐다
6. 🔴 **운영 데이터 무접촉** — 시험은 시험 계정으로. 남의 `lang` 을 바꾸지 말 것
