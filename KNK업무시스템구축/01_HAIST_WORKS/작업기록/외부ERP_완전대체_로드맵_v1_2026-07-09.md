## 0. 목표 (한 문장)

**12개월 내에 외부 ERP를 완전 종료**하고, 구매·자재·회계·세무 전 업무를 HAIST WORKS로 이관.

## 1. 원칙 (5조 · 위험 관리)

| # | 원칙 | 이유 |
|---|---|---|
| ① | **병행 기간 필수** (최소 6개월) | 마감·세무 오류는 국세청·회계 문제 직결 → 검증 없이 전환 금지 |
| ② | **회계사·세무사 검토 필수** | 매 마감 단계마다 외부 전문가 검증 · 자문료 예산 확보 |
| ③ | **롤백 가능해야** | 언제든 외부 ERP로 되돌릴 수 있어야 (데이터 무결성 유지) |
| ④ | **한 사람만 아프면 안 됨** | 병행 입력 부담을 자동화·최소화 (담당자 번아웃 방지) |
| ⑤ | **직원 교육 병행** | 새 시스템 학습 시간 = 정규 업무 시간 인정 · 교재 준비 |

**위반 시 즉시 대표 보고 → 일정 재조정.**

## 2. 4 Phase 로드맵

### 🟢 Phase 1 · 엑셀 대체 + 안정화 (지금 ~ 3개월)

**목표**: 엑셀로 처리하던 일상 업무를 HAIST WORKS로 이관. 외부 ERP는 그대로.

| 구현 | 산출물 |
|---|---|
| 자재 마스터 안정화 | 3,218건 → 완결 (이원화·단가 완성) |
| 발주(PO) 실사용 | 구매 담당자 매일 사용 |
| 재고 관리 실사용 | 자재 담당자 매일 사용 |
| 자재 요청·신규검토 | 관련부서(설계·전장·SW) 참여 |
| 3역할 홈 대시보드 | 구매·자재·요청부서 각 홈 |

**성공 기준**:
- ✅ 매일 활성 사용자 ≥ 5명 (구매·자재·관련부서)
- ✅ 엑셀 사용 감소 확인 (파일 수 · 사용 빈도)
- ✅ 데이터 정확도 = 외부 ERP와 일치 (샘플 검증)

**위험**:
- 🟠 직원이 익숙한 엑셀을 계속 쓸 수도 → **주간 사용률 모니터링** 필수
- 🟠 자재 마스터 오류 = 모든 후속 오류 원인 → 초기 데이터 정합성 확보 최우선

---

### 🟡 Phase 2 · 매입/매출 마감 개발 (3~6개월)

**목표**: 외부 ERP의 마감 기능을 HAIST WORKS에서 병행 실행. 결과 대조 검증.

| 구현 | 산출물 |
|---|---|
| **매입 마감** 화면 | 월별 매입 확정 · 미수불 대사 |
| **매출 마감** 화면 | 월별 매출 확정 · 미수금 대사 |
| **재고 자산 평가** | FIFO 기반 원가 계산 |
| **회계 계정 매핑** | item_account → 회계 계정 매핑표 (회계사 협의) |
| **병행 검증 도구** | 외부 ERP 결과 vs HAIST WORKS 결과 자동 비교 리포트 |

**성공 기준**:
- ✅ 3개월 연속 마감 차이 0원 (완전 일치)
- ✅ 회계사 승인 (매입/매출 결과 감사)

**위험**:
- 🔴 마감 차이 발생 → **원인 규명 전까지 절대 이관 X** (차이가 곧 세무 리스크)
- 🟠 병행 입력 부담 → 자동 매핑·복사 도구로 최소화

---

### 🟠 Phase 3 · 세금계산서 · 부가세 · 재무 리포트 (6~9개월)

**목표**: 세무 신고 기능 완성. 홈택스·은행 연동.

| 구현 | 산출물 |
|---|---|
| **세금계산서 발행** | 홈택스 API 연동 (개별 · 묶어발행 · 3차 분할) |
| **부가세 신고 자료** | 매입/매출 부가세 자동 집계 · 신고 파일 생성 |
| **재무 리포트** | 손익계산서 · 재무상태표 · 현금흐름표 |
| **계정 원장** | 매입처·매출처별 원장 |
| **외부 시스템 연동** | 홈택스 · 은행 (선택) |

**성공 기준**:
- ✅ 세무사 승인 (신고 파일 검증)
- ✅ 부가세 신고 실제 진행 성공 (분기 신고 1회 이상)

**위험**:
- 🔴 홈택스 API 규격 변경·인증 문제 → 세무사·전산 협조 필요
- 🟠 회계 계정 매핑 오류 → 회계사 검증 반복

---

### 🟢 Phase 4 · 외부 ERP 종료 (9~12개월)

**목표**: 병행 검증 완료 후 외부 ERP 계약 해지·데이터 백업·완전 이관.

| 진행 | 산출물 |
|---|---|
| 마지막 병행 3개월 결과 검증 | 완전 일치 확인 |
| 이력 데이터 이관 | 3~5년치 매입·매출·재고 이력 이관 |
| 외부 ERP 백업 | 원본 데이터 안전 보관 (법정 보존 기간 준수) |
| 계약 해지 | 외부 ERP 종료 |
| 사용자 교육 마무리 | 전 직원 새 시스템 활용 |

**성공 기준**:
- ✅ 외부 ERP 사용 완전 종료
- ✅ 전 직원 새 시스템 활용도 100%
- ✅ 회계·세무 무사고 마감 3개월 이상

**위험**:
- 🔴 외부 ERP 종료 후 문제 발견 → **롤백 불가** · 사전 검증 완벽해야
- 🟠 이력 데이터 이관 실수 → 백업 원본 반드시 보관

## 3. 데이터 이관 계획

### 이관 대상
| 종류 | 규모 (추정) | 이관 시점 |
|---|---|---|
| 자재 마스터 | ~5,000건 | ✅ 이미 진행 중 (3,218 등록됨) |
| 협력사 마스터 | ~300건 | Phase 1 완료 |

### 이관 원칙
- **항상 백업 후 이관** (원본 안전 확보)

- **매핑표 기록** (외부 ERP ID ↔ HAIST WORKS ID)
- **롤백 스크립트 필수** (문제 시 즉시 원복)

## 4. 병행 운영 계획

### 병행 기간의 부담 최소화
| 상황 | 해결책 |
|---|---|
| 두 시스템에 같은 데이터 입력 | **일방향 자동 복사** (HAIST WORKS → 외부 ERP 또는 반대) |
| 마감 시 결과 대조 | **자동 비교 리포트** (일별 · 월별) |
| 어느 게 진실? | **HAIST WORKS 우선** (외부 ERP는 검증용) |
| 직원 혼란 | **화면 상단에 "병행 기간" 명확 표시** |

### 최소 병행 기간
- **Phase 2 → Phase 3**: 3개월 이상
- **Phase 3 → Phase 4**: 3개월 이상 (분기 마감 검증)
- 총 **6개월 이상** 병행 확정

## 7. 롤백 계획

**어느 Phase에서든 문제 발생 시 안전하게 되돌리기.**

| Phase | 롤백 방법 |
|---|---|
| 1 (엑셀 대체) | 엑셀 파일 원본 유지 → 즉시 복귀 가능 |
| 2 (마감 병행) | 외부 ERP 계속 사용 · HAIST WORKS 결과만 참고 |
| 3 (세무 병행) | 실제 신고는 외부 ERP · HAIST WORKS 결과 대조만 |
| 4 (완전 대체 후) | **롤백 불가** → 이 단계 진입 전 완벽 검증 필수 |

## 10. 앞으로 원칙 (필독)

1. **모든 신규 개발은 이 로드맵의 어느 Phase에 해당하는지 명시.**
2. **회계·세무 관련 코드는 회계사·세무사 승인 없이 배포 금지.**
3. **병행 결과 차이 발견 시 즉시 개발 중단 → 원인 규명.**
4. **매월 대표 보고 필수** (Phase 진행률 · KPI · 위험 항목).
5. **직원 피드백 상시 수렴** — 새 화면 만들 때마다 실제 사용자 검증.
