## 0. 목표 (한 문장)

**3개월 안에 매일 발생하는 로스(오구매·추가구매·잘못된 구매)를 실제로 감소시킨다.**

완전 대체 · 마감 이관은 목표 아님. 로스만 멈춤.

## 1. 왜 이 스프린트인가

### 대표가 말한 실제 통증 (원문)
> "지금 업무 방식으로 실수가 너무 많아. 업무 공유들도 안 되고. 변경점 관리도 즉시 되지 않아 부품을 추가 구매, 오 구매 등 많은 로스가 발생되고 있어."

### 로스 3원인 분류
| 원인 | 예상 로스 유형 |
|---|---|
| **A. 실수** | 오입력·중복발주·재고 있는 자재 재구매 |
| **B. 업무 공유 안 됨** | 다른 사람이 이미 발주 · 정보 못 받음 |
| **C. 변경점 관리 안 됨** | 설계 변경 후 이미 발주한 부품 못 취소 · 잘못된 부품 조달 |

### 판단 필터 통과 확인 (5조 전체 Y)
| 필터 | 이 스프린트 | 근거 |
|---|---|---|
| ① 실무자 하루 짧아짐 | Y | 재작업·확인 시간 감소 |
| ② 놓치던 걸 자동으로 잡음 | Y | 변경 알림·중복 감지 |
| ③ 반복 작업 없어짐 | Y | 매번 확인하던 걸 시스템이 |
| ④ 새 입력 요구 X | Y | 기존 화면에 방지 로직 추가만 |
| ⑤ 안 만들면 힘든가 | Y | **매일 로스 발생 중** |

**✅ 스프린트 자체가 판단 필터 통과. 개별 기능은 아래에서 재확인.**

## 2. 3개월 스프린트 상세

### 🔴 1개월차 · 실수 방지 (Sprint 1)

**목표**: 오입력·중복발주 즉시 차단.

| # | 기능 | 판단필터 | 실무자 이득 | 예상 개발 |
|---|---|---|---|---|
| 1-1 | **중복 발주 자동 감지** — 이미 진행 중 PO 있는 자재를 또 발주하려 하면 발주 화면에서 경고 | 5/5 Y | 오구매 방지 · 즉시 확인 | 3일 |
| 1-2 | **재고 있는 자재 붉게 표시** — 발주 화면에서 현재 재고량 즉시 표시 (0 아니면 경고) | 5/5 Y | 불필요 구매 방지 | 2일 |
| 1-3 | **유사 자재 자동 매칭 확장** — 신규 요청 시 이미 등록된 유사 자재 자동 추천 (기존 신규검토 강화) | 5/5 Y | 자재 중복 등록 방지 | 4일 |
| 1-4 | **오입력 방지 검증 확장** — 수량·단가·통화 오류 저장 전 차단 (기존 z643~ 확장) | 5/5 Y | 데이터 오류 방지 | 3일 |
| 1-5 | **부적합 자재 재구매 차단** — 반품·폐기 이력 있는 자재를 재구매 시 경고 | 5/5 Y | 반복 실수 방지 | 3일 |

**1개월차 총**: 15일 개발 · 5개 기능

**실무자 검증**: 배포마다 구매 담당자에게 확인 → "이거 도움 됩니까?"

---

### 🟡 2개월차 · 업무 공유 (Sprint 2)

**목표**: 다른 사람이 이미 했는지 · 지금 어디까지 됐는지 자동 공유.

| # | 기능 | 판단필터 | 실무자 이득 | 예상 개발 |
|---|---|---|---|---|
| 2-1 | **관련부서 요청 실시간 상태** — 요청자 화면에서 요청→검토→발주→입고 자동 갱신 (Eum 봇 알림) | 5/5 Y | 전화·이메일 문의 감소 | 4일 |
| 2-2 | **자재 이력 통합 뷰** — 한 자재의 모든 활동(요청·발주·입고·출고·변경) 시간순 한 화면 | 5/5 Y | 무슨 일이 있었는지 즉시 파악 | 5일 |
| 2-3 | **발주·입고 상태 자동 통보** — 관련자에게 상태 변경 즉시 Eum 봇 알림 | 5/5 Y | 놓침 방지 · 확인 부담 감소 | 3일 |
| 2-4 | **누가 뭘 하고 있는지 · 진행 중 발주 대시보드** ⚠ | ④ 재검토 | 관리자용이면 안 만듦 · 담당자용이면 만듦 | 검토 후 결정 |
| 2-5 | **자재 요청→발주 자동 연결** — 요청서 클릭 → 관련 PO 즉시 표시 | 5/5 Y | 왕복 감소 | 3일 |

**2개월차 총**: 15일 · 2-4는 필터 재검토 후 확정

---

### 🔴 3개월차 · 변경점 관리 (Sprint 3) — 가장 큰 로스 원인

**목표**: 설계·BOM·프로젝트 변경 발생 시 관련자에게 즉시 자동 알림. 이미 진행 중인 발주 자동 검토.

| # | 기능 | 판단필터 | 실무자 이득 | 예상 개발 |
|---|---|---|---|---|
| 3-1 | **프로젝트 변경 → 관련 자재 담당자 자동 알림** — 프로젝트 사양·수량·납기 변경 시 관련 부품 담당자에게 Eum 봇 통보 | 5/5 Y | 잘못된 구매 원천 차단 | 5일 |
| 3-2 | **진행 중 발주 자동 검토 알림** — 프로젝트 변경 발생 시 관련 PO에 "검토 필요" 표시 · 담당자에게 알림 | 5/5 Y | 오구매 회수 기회 | 4일 |
| 3-3 | **변경 이력 자동 기록·조회** — 언제 누가 뭘 바꿨는지 자동 기록 (수동 입력 X) | 5/5 Y | 원인 추적 · 재발 방지 | 4일 |
| 3-4 | **설계·전장·SW팀 변경 → 구매팀 자동 통보** — 관련부서 변경 요청 시 구매팀 Eum 봇 알림 (부서별 라우팅) | 5/5 Y | 정보 흐름 자동화 | 4일 |
| 3-5 | **BOM 변경 → 미결 요청·발주 자동 재검토** — BOM 갱신 시 미완 요청 자동 재계산 · 담당자 알림 | 5/5 Y | 사후 발견 X · 사전 대응 | 5일 |

**3개월차 총**: 22일 · 가장 큰 임팩트

## 3. 성공 기준 (실측)

3개월 뒤 다음을 대표에게 보고:

| 지표 | 측정 방법 | 목표 |
|---|---|---|
| **오구매 사고 건수** | 실무자 자체 보고 (반품·폐기 이력) | 감소 추세 |
| **중복 발주 자동 차단 건수** | 시스템 로그 | 실제 발생 확인 |
| **BOM 변경 → 담당자 통보 소요 시간** | 로그 기록 | 즉시 (수 분 이내) |
| **관련부서 요청 → 처리 리드타임** | 요청·완료 시각 | 감소 추세 |
| **실무자 만족도** | 배포 2주 후 짧은 청취 | "이거 있으면 안 놓쳐요" 응답 |

**KPI 대시보드는 만들지 않음.** 대표는 월 1회 이 지표를 문서로 보고 받음 (판단 필터 지킴).

## 4. 스프린트 진행 원칙 (5조)

1. **매주 금요일 실무자 확인** — 개발한 것 실제 사용해봤는지 · 도움 됐는지
2. **도움 안 되면 즉시 폐기·수정** — "아까워서" 유지 X
3. **배포 후 1주일 사용률 저조 → 회수** — 안 쓰는 화면 X
4. **판단 필터 5조 유지 확인** — 매 배포마다
5. **12개월 완전 대체 로드맵과 병행** — 이 스프린트는 로드맵 Phase 1 안에 포함 · 별도 프로젝트 X
