## 1. 결론 먼저

- **할 수 있다. 다만 한 번에 끊으면 위험하고, 대표님만 하실 수 있는 일이 4가지 있다**(AWS 계정 · 가비아 DNS · 하이웍스 계약 · 직원 확인).
- 받기는 **AWS SES 서울**이 맞다(Cloudflare 는 회사 도메인의 네임서버를 통째로 옮겨야 해서 위험이 더 큼).
- **권하는 첫걸음 = 「보내기만 먼저 독립」**. 받는 길(MX)은 건드리지 않아 거래처 메일이 끊길 위험이 없고, 문제가 생기면 설정 하나로 하이웍스 발송으로 되돌릴 수 있다.
- 🔴 **그대로 받는 길만 바꾸면 사고가 난다**: 지금 이음웍스는 「누구 것인지 모르는 수신 주소」를 **대표님 메일함**으로 넣게 되어 있다. 전 직원 주소 연결 없이 받는 길을 바꾸면 **직원 메일이 대표님 메일함으로 들어간다**. 받는 길 전환 전에 반드시 고쳐야 할 것 1순위.

| | 지금 | 근거 |
|---|---|---|
| 메일이 도착하는 곳 | 하이웍스 | 공개 DNS: `knknara.co.kr` MX = `mailapp.hiworks.co.kr` 한 곳 |

→ 이음웍스 메일은 지금 **하이웍스 위의 창**이다. 하이웍스 계약 종료·비밀번호 변경·장애 때 받기·보내기가 같이 멈춘다.

## 3. 떼어 내려면 바뀌어야 하는 것 4가지

1. **받는 길(MX)** — 회사 도메인의 배달 주소를 하이웍스 → 우리 받는 서비스로.
2. **보내는 길** — 하이웍스 발송 서버 → 우리 발송 서비스 + 「이 서비스가 우리 회사 메일을 보내도 된다」는 인증 기록(SPF·DKIM·DMARC)을 가비아 DNS에.
3. **메일함** — 전 직원(약 90명)이 이음웍스 메일을 쓰고, **하이웍스에 쌓인 과거 메일**(받은·보낸)을 옮겨 옴.
4. **하이웍스 계약** — 메일만 끊고 전자결재는 유지(규정: 결재는 별도 유지).

메일 주소(@knknara.co.kr)는 **바뀌지 않는다**(영구 불변 규정 그대로 지킴). 거래처는 아무것도 바꿀 필요 없음.

## 4. 받는 길 — 두 가지 비교

| | **AWS SES 받기 (서울)** ⭐ | Cloudflare 이메일 라우팅 |
|---|---|---|
| 회사 도메인에서 바꾸는 것 | **MX 기록 하나**(가비아에서) | **네임서버 자체를 Cloudflare 로 이전**(DNS 전부 옮김) — 홈페이지·다른 기록까지 영향 |
| 서울 지역 | 지원(`inbound-smtp.ap-northeast-2.amazonaws.com`) | — |
| 한 통 최대 크기 | 40MB(S3 보관 방식) | 25MB(넘으면 거절) |
| 이음웍스(NAS)가 꺼져 있을 때 | 메일은 **S3 보관함에 쌓여 있다가** 켜지면 가져옴 → 분실 없음 | 이음웍스로 바로 넘기는 구조라 그 순간 못 받을 수 있음(6월 시험 때 지메일 안전망을 따로 붙였던 이유) |
| 스팸·바이러스 | **검사 결과를 머리글로 붙여 줌**(`X-SES-Spam-Verdict` · `X-SES-Virus-Verdict` · `Authentication-Results`) → 어제 만든 스팸·피싱 판별이 그대로 읽음 | 별도 없음 |
| 아웃룩·휴대폰 기본 메일 앱 | **안 됨**(받는 서비스일 뿐, IMAP 서버 없음) | 안 됨 |
| 이음웍스로 들여오는 길 | 이음웍스가 S3에서 **가져옴**(지금 하이웍스에서 가져오는 것과 같은 방식) → 외부에서 이음웍스로 밀어 넣는 입구가 필요 없음 | Worker 가 이음웍스 수신 입구(`/api/mail/inbound`)로 밀어 넣음 |

→ **SES 권장.** 도메인에서 바꾸는 게 MX 한 줄이고, 우리 서버가 잠깐 꺼져도 메일이 안 사라지며, 바이러스 검사 결과까지 받는다.

출처: AWS SES 공식 문서(지역·받기 개념) · Cloudflare 이메일 라우팅 제한 문서.

## 5. 보내는 길 — AWS SES 서울 발송

- 발송 서버: `email-smtp.ap-northeast-2.amazonaws.com` (이음웍스 `mail_send.py` 는 SMTP 설정만 바꾸면 됨 — 6월 Day1 분석과 같음).
- 가비아 DNS에 추가: SPF 에 SES 허용 한 줄 · DKIM 기록 3개(SES 가 만들어 줌) · DMARC 새로(처음엔 「보고만」 모드).
  - 하이웍스 SPF 는 **전환 기간 내내 그대로 둠**(둘 다 허용) → 직원들이 하이웍스로 보내는 메일도 계속 정상.
- 🔴 새 AWS 계정은 처음에 **하루 200통·초당 1통** 제한(「샌드박스」) → 해제 신청을 해야 실제 업무에 쓸 수 있음(AWS 공식 기본값).
- 네이버·다음 등 국내 포털에 스팸으로 안 가는지는 **실측 없음** → 1단계에서 대표님 메일로 먼저 확인.

## 7. 단계안 (권장 순서 · 각 단계 끝에 대표 확인)

| 단계 | 하는 일 | 회사 도메인에서 바뀌는 것 | 되돌리기 |
|---|---|---|---|
| **1. 보내기 독립** | AWS 계정 · SES 서울 · 도메인 인증(DNS 추가) · 대표님 메일 보내기를 SES 로 · 국내 포털 도착 확인 | 기록 **추가만**(SPF 한 줄·DKIM 3개·DMARC). MX 무접촉 | 이음웍스 설정에서 하이웍스 발송으로 되돌림(즉시) |
| **2. 받기 준비** | SES 받기+S3 · 이음웍스 「S3에서 가져오기」 · 위 ①②③ 고치기 · 시험용 하위 주소(예: `test.knknara.co.kr`)로 실제 메일 받아 보기 | 시험용 하위 주소의 MX 만(본 주소 MX 무접촉) | 시험 기록 삭제 |
| **3. 병행 사용** | 전 직원이 이음웍스 메일 사용(지금처럼 하이웍스에서 사본 가져오기) · 과거 메일 이전 · 아웃룩 사용자 정리 · 백업 | 없음 | 하이웍스 그대로 |
| **4. MX 전환** | 며칠 전 DNS 갱신 시간(TTL) 낮추기 → 주말 밤 MX 를 SES 로 → 24시간 지켜보기 · 하이웍스는 읽기용으로 남김 | **MX 변경**(규정상 대표 결재 사안) | MX 원복(TTL 만큼 지나면 하이웍스로 다시) |
| **5. 하이웍스 메일 해지** | 결재만 남기는 계약 가능 여부 확인 후 | SPF 에서 하이웍스 빼기 | 재가입 |

- 정의서(6월) 로드맵과 같은 순서다. 「베트남법인 5명 → 본사 리더 → 전 직원」 순서도 3단계 안에서 그대로 쓸 수 있다.
- 기간은 직원 조사·과거 메일 용량을 재야 정할 수 있어 **이 문서에서 날짜를 약속하지 않는다**.

## 8. 대표님만 하실 수 있는 것 (제가 할 수 없는 것)

1. **AWS 계정 만들기·결제 수단 등록** — 계정·결제·비밀번호는 제가 만들거나 입력할 수 없음. 계정이 생기면 이후 설정 순서는 화면 단위로 안내.
2. **가비아 DNS 관리 권한** — 누가 들어갈 수 있는지(대표님/전산 담당). 기록 추가·MX 변경은 그분이 하시거나 승인.
3. **하이웍스 계약** — 메일만 해지하고 결재만 남길 수 있는지, 해지 조건·만료일, 지금 월 비용(정의서의 「월 50~100만원」은 **추정치였음 · 실측 없음**).
4. **직원 확인** — 아웃룩·휴대폰 기본 메일 앱을 쓰는 직원이 몇 명인지, 그룹 주소 목록(누가 받는지).

## 9. 비용 (대략 · 확정 아님)

- SES 발송·받기 모두 **통 단위 소액 과금** + S3 보관 용량 요금. 90명 규모면 정의서 추정은 월 3~4만 원 수준 — **AWS 요금표로 1단계 때 다시 계산**.
- 하이웍스 쪽 절감액은 계약을 봐야 앎(위 8-3).

## 10. 권고

- **지금 결정하실 것은 하나**: 「1단계(보내기 독립)를 할지」. 하신다면 대표님이 AWS 계정을 만드시는 것부터 시작한다.
- 받는 길(MX) 전환은 위 ①~⑤가 끝나고 직원 병행 사용을 거친 뒤에 다시 결재받는다.
- 1단계를 안 하더라도, **①(모르는 주소 → 대표님 메일함)** 은 지금 구조에서도 고쳐 두는 것이 안전하다(현재는 하이웍스에서 대표님 계정만 가져오므로 실제 사고는 없음 — 그래서 급하지는 않음).
