- **확정 범위(질문 2건)**: ①이음 메신저까지 완전 동일 ②부서 + **개별 인원**도 추가.
- **커밋/미러**: (배포 확인란)

## 왜 소모품 필터가 비었나
`/prod-requests` 목록은 `prod_requests JOIN projects JOIN orders`. 소모품은 별도 테이블(consumable_orders)이고 제작요청 발행을 거치지 않아 그 소스에 없음 → C 탭 0건.

## 구현 (핵심 `_prod_request_notify_core`·기존 목록 쿼리 무변경 = 회귀 0)
1. **마이그레이션**(database.py ~2867): consumable_orders에 `notify_recipients / notify_dept_names / notify_user_ids / notify_team_ids / notify_at / notify_by_name`(TEXT) + `notify_sent_to / notify_dept_count / notify_msg_sent`(INT) 추가.
2. **통보 코어 헬퍼 `_consumable_notify_send`**(main.py, consumables_notify 앞):
   - 수신자 = 부서(team_ids 전체 활성 구성원) + 개별(user_ids), 발신자 제외.
   - **WORKS 벨** 알림 INSERT(kind=`consumable_request`→📋) · 본문 = 제작요청 ■-포맷 미러(`📋 소모품 요청서 · 관리번호 · 모델` + 고객사/품목·수량/일정·수주). **⛔가격 제외**(제작요청 규약·가격 게이트).
   - **이음(KNK Eum)** 카드 푸시 = `notify_via_messenger(emp_nos, title, body, link, card=type:prod_request)` → 제작요청과 **동일 카드 렌더**(biz='소모품'). 발행자 본인에게도 확인 카드.
   - 수신부서/명단 스냅샷을 consumable_orders에 저장.
   - 엔드포인트 `/consumables/{id}/notify`: `{team_ids, user_ids}` 수신(개별 추가).
3. **소모품 상세**(consumable_detail.html):
   - 통보 모달에 **개별 인원**(팀별 ▸개별 펼치기·knkp user 항목) 추가 → doNotify가 user_ids도 전송. 라우트에 team_members 전달.
   - 상세 상단에 **'📣 통보 완료 — N부서·M명 · 📱이음 · 📋받는 사람 …'** 표시(co.notify_* · 제작요청 상세 미러). 통보 후 자동 새로고침으로 갱신.
4. **제작요청서목록**(main.py `prod_requests_list_page` + prod_requests_list.html):
   - biz가 '전체' 또는 'C'일 때 consumable_orders를 카드 dict로 매핑해 **덧붙임**(projects.html 병합 패턴). qty=라인 qty 합·status_ko 맵·biz_label='소모품'·`_kind='consumable'`.
   - 카드 href 분기: 소모품→`/consumables/{co_id}`, 제작요청서→기존 편집 링크. 기존 prod_requests 쿼리·카드는 불변.
   - notifications.html 아이콘: `consumable_request`→📋.
