# WORKS '월 기준환율'은 관리자 화면(/admin/fx-rates)이 단일 기준 — 대표규정

- **작성**: 2026-07-29 (수) 18:37 KST
- **지시**: 대표 — *"WORKS에서 월 기준환율은 (관리자·월 기준환율 입력) 화면이 무조건 기준이 됨. 이걸 규정으로 확정해."*
- **성격**: **절대준수 규정** · 현황판 §4 **규칙 48**
- **상태**: 규정 확정·기록. 구현은 **이미 z900로 존재**(이 규정은 '단일 기준'을 못 박아 다른 환율 소스 도입을 금지).

---

## 1. 규정

WORKS에서 **외화(USD·EUR·JPY·CNY·VND)를 원화(KRW)로 환산**할 때 쓰는 **'월 기준환율'은 오직 관리자 화면 `/admin/fx-rates`(= `exchange_rates` 테이블)의 값**이 단일 기준이다.

- ⛔ **다른 환율 소스 금지**: 실시간 환율 API·코드 하드코딩·개별 입력 화면의 임의 환율 등으로 원화 환산하지 않는다.
- ⭐ **환산 기준월 = 각 건의 납품월**(due_date의 'YYYY-MM'): 매출은 건별 **납품월**의 기준환율로 외화를 원화 환산해 합산한다(미출하 여부 무관·z900 대표 지시).
- ⭐ **입력 단위**: USD·EUR = **1통화당 원**, JPY·CNY·VND = **100단위당 원**(1단위가 작아). 예) USD 1=1,380 · 100엔=900 · 100위안=19,000 · 100동=5.6. 내부 저장은 항상 **'1 통화당 KRW'**로 환산해 보관.
- ⭐ **결측 대체**: 특정 (월·통화) 환율이 없으면 **직전 달**로 대체(그 달 이하 최신), 그것도 없으면 가장 이른 입력월. 통화가 아예 없으면 **0원 처리 + 경고**(진단 화면에 '기준환율 없음' 목록 + 입력 링크).
- ⭐ **빈칸 저장 = 삭제**: 입력칸을 비워 저장하면 그 (월·통화) 환율이 삭제된다.
- ⚠ **신규기능 준수**: 외화→원화 환산이 필요한 **모든 신규 기능**은 자체 환율 산정 없이 공용 헬퍼(`_fx_load_rates`/`_fx_to_krw`)를 통해 이 월 기준환율을 써야 한다. 지원 통화 = USD·EUR·JPY·CNY·VND(기준통화 KRW).

## 2. 왜 (배경)

- 매출·소모품매출 등은 여러 통화가 섞이는데, **환산 기준이 흩어지면 매출 숫자가 달라진다**(z1051 소모품 117억=통화 오등록 사례처럼). 기준을 **한 화면·한 테이블**로 못 박아 "이 숫자는 이 환율로 나온 것"을 항상 재현·설명할 수 있게 한다.
- 대표가 매월 이 화면에 기준환율을 넣으면, 그게 곧 전 시스템의 원화 환산 기준이 된다(단일 진실).

## 3. 구현 (이미 존재 · z900)

| 요소 | 위치 |
|---|---|
| 입력 화면 | `GET /admin/fx-rates`(admin/ceo) → `admin_fx_rates.html`(최근 13개월 × 통화 그리드) |
| 저장 | `POST /admin/fx-rates/save` → `exchange_rates`(from_currency·rate_date='YYYY-MM-01'·to_currency='KRW'·rate=1통화당 KRW) |
| 로드 | `_fx_load_rates(c)` → {CCY: {'YYYY-MM': rate}} |
| 월별 환율 | `_fx_rate_for(rates, ccy, ym)` — 그달 없으면 직전 달, 그것도 없으면 최이른 |
| 환산 | `_fx_to_krw(rates, amount, ccy, ref_ym, missing)` — 환율 없으면 0 + missing 기록 |
| 사용처 | 매출 홈·소모품 매출 등(main.py ~20586·`ref_ym=납품월`) |
| 상수 | `FX_KRW_CURRENCIES`(USD·EUR·JPY·CNY·VND) · `FX_INPUT_UNIT`(JPY·CNY·VND=100) |

- 코드 변경 없음(규정·문서만). 위 헬퍼가 규정의 **강제 지점**이다 — 새 환산은 반드시 여기를 거친다.
