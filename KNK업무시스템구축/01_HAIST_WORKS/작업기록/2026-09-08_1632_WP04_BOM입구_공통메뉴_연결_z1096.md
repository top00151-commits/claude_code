## 2. 넣은 두 줄

```jinja
{# 자재·구매 그룹 — 기존 M-02-28 자리 #}
{% if can_bom_purchase %}{{ a('/bom/tools?mode=purchase', '🛠 구매 서류 만들기', 'M-02-28') }}{% endif %}

{# 공통 그룹 — 자재 요청서 다음 #}
{% if can_bom_design and not can_bom_purchase %}{{ a('/bom/tools?mode=design', '🛠 설계 BOM 만들기', 'M-00-25') }}{% endif %}
```

**왜 설계 입구를 '공통'에 두는가**: 공통 그룹은 **세 허브(통합·매출영업·자재구매) 어디서나** 보인다.
→ 판정 문서 완료조건 *"설계는 구매센터를 거치지 않고 설계 작업으로 진입"* 이 성립한다.
새 허브 탭을 만들거나 메뉴 체계를 바꾸지 않아 변경이 가장 작다.

## 3. ⭐ 세션01이 정한 것 — 구매 담당자에게는 입구 하나

세션05가 넘긴 판단 사항: 구매 담당자는 두 변수가 **모두 참**이라 그대로 두면 메뉴가 **두 개** 보인다.

**→ `and not can_bom_purchase` 로 설계 입구를 감췄다.**

- 근거: 메신저 정의서 최상위 원칙 *"카톡만큼 쉬운가?"* — **입구가 둘이면 "뭘 눌러야 하지"가 된다.**
- 기능 손실 없음: 세션05 확인대로 **구매 입구 안에 여섯 작업이 다 들어 있다**.
- 결과: 설계자 → 설계 입구 하나 · 구매자 → 구매 입구 하나 · **각자 자기 입구 하나**.
