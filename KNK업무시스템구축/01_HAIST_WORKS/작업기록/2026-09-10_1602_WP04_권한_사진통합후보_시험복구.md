## 2. 헛돌던 시험 두 개를 실제로 잡히게 고쳤다

### ① 스키마 확인기 — 6건 → **13건**

**실패를 일부러 만들어** 본다. `bom_tool_runs` 의 칸 추가만 예외를 던지는 연결로 바꿔
`init_db()` 를 돌린다(다른 표는 그대로).

| 새 확인 | 무엇을 잡나 |
|---|---|
| 05·06 | 한 칸만 있는 DB(반쪽 마이그레이션 뒤 재기동) — 모자란 칸만 추가 · 값 보존 |
| 07 | 표 없는 DB = **정상 생성**(실패 사례로 세지 않음) |
| 08 | 실패하면 **사유가 기록된다**(`OperationalError` 포함) |
| 09 | 실패 기록에 **기존 건수**가 함께 남는다 |
| 10 | 칸 검증이 **모자람을 돌려준다** |
| 11 | 실패해도 **기존 기록 5건 그대로** |
| 12 | 실패해도 **기동이 죽지 않는다** — 이제 `True` 가 아니라 `init_db` 가 예외를 밖으로 내보내지 않았다는 사실로 확인 |
| 13 | **역검사** — 실패를 안 만들면 같은 자리에서 칸이 생긴다 |

⛔ 이걸 이유로 WORKS 전체 기동정책은 바꾸지 않았다(메일 오류로 38분 전면 다운 전례 유지).

### ② 단가 시험 — 13건 중 1실패 → **17건 / 0**

그 시험은 **개인 임시 폴더(scratchpad)** 의 특정 파일을 찾고 있었다. 폴더가 지워져 실패했고,
그 실패를 「단가 이상 없음」의 근거로 쓸 수 없다 — **해당 사례 검증 미완료**였다.

신설 `_검증/_표본/make_price_fixtures.py` — **언제 돌려도 똑같은 비식별 표본**을 코드로 만든다.

⛔ 고객명·실제 단가·협력사명·도면·장비 사진이 **하나도 들어가지 않는다.**
⛔ 실제 거래파일을 저장소에 커밋하지 않았다.

기존 시험 **목적은 그대로**다 — 협력사가 미정이면 단가를 채우지 않고 과거 실적을 참고로만 남긴다.

| 확인 | 값 |
|---|---|
| 채움 | **0건** (판단을 대신하지 않는다) |
| 과거 실적 참고 | **14건** |
| 수불부에 없는 형번 | 참고에도 안 뜸 |
| 뼈대 기존단가(P) | 전부 빈칸 유지 |
| **역검사** | 협력사를 확정하면 같은 자리에서 **14줄이 실제로 채워진다** |

> 실패를 삭제하거나 SKIP 으로 바꿔 통과시키지 않았다. 원래 확인하던 동작을 새 표본으로 실제 시험한다.

## 6. ⏳ 아직 막혀 있는 것 — 미분류 원본

지시안은 **「나안의 제한형」을 권고**하면서, 동시에
*"실제 운영 예외 적용은 대표가 이 제한형을 선택한 뒤 진행한다"*,
*"결정 전에는 예외를 임의로 확대·축소하지 마세요"* 라고 못박았다.

→ **대표 선택을 받기 전이므로 손대지 않았다.** 예외 코드는 이 후보에 **없다.**

선택하시면 반영할 범위(지시안 §3 그대로):

**여는 것** — 서버가 기록한 사용자 ID 로 **직접 업로더임이 확인된** 사람이,
양식 미지원으로 분류 못 한 **그 입력 원본을 가공 없이 그대로** 되받는 것 하나.

**열지 않는 것** — 산출물 · 보고문 · 구매 관리본 · 남이 올린 원본 ·
구매 실행권한 · 단가/구매처 전체 열람 · 같은 관리번호의 다른 파일 · 인계받은 파일.

**승인 기록에 나눠 적어야 할 것** — ①일반 경로(기본 조회 + 두 열람권한) **유지 여부**와
②본인 예외 **추가**는 별개다. 본인 예외만 승인하고 다른 사용자 범위는 바꾸지 않는다.

⚠ 실제 발생 빈도는 **실측 없음** (보관함 기록 6건 · 원본 재다운로드 시도 기록 없음).
