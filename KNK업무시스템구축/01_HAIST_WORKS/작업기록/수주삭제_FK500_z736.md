# 수주 삭제 "Unexpected token '<'" (500) 수정 — z736 (2026-06-30 · 대표 지시)

## 신고
005M2511(BIM LINE·수출·251라인) 수주 삭제 시 모달에 **"⚠ 실행 실패: Unexpected token '<', "<!DOCTYPE "... is not valid JSON"**. + 대표 질문: "비밀번호 메신저 비밀번호로 연동되는 거 아니야?"

## 진단
삭제 흐름(`password_confirm.html`): ①`/auth/verify-password`(본인 비번 검증·`users.password` 해시) → ②통과 시 onConfirm = `fetch('/sales/orders/{oid}/delete')` → `r.json()`.
- 에러 메시지가 **"실행 실패"**(onConfirm catch)지 "비밀번호 불일치"가 아님 → **비번 검증은 통과**(메신저 로그인과 연동된 계정이라 그 비번이 맞음). 문제는 **삭제 응답이 JSON이 아니라 HTML**.
- HTML 출처: **전역 예외 핸들러**(`main.py` `_v5_global_exception_handler` ~463) 가 unhandled 예외에 `<!DOCTYPE html>…` 반환.
- 죽은 이유: `delete_order`(`project_workflow.py`)가 `order_id` 참조 자식 중 **일부만**(order_items·shipments·invoices·receipts_payment·order_status_history) 삭제. **생산지시 `production_orders`·세금계산서묶음 `tax_invoice_lines`·수출헤더 `export_orders` 등은 안 지움** → `PRAGMA foreign_keys=ON`에서 `DELETE FROM orders`가 **FK IntegrityError** → 500. (order_items 삭제는 try/except로 감싸 있어 실패해도 조용히 넘어가던 구조도 한몫.)

## 수정
1. `project_workflow.py: delete_order` — 자식 정리를 **'order_id 컬럼이 있는 모든 테이블 동적 스윕'**으로 교체: `sqlite_master`에서 테이블 목록 → 각 `PRAGMA table_info`에 `order_id` 있으면 `DELETE … WHERE order_id=?`(각 try/except). 테이블이 추가돼도 FK로 안 죽음. 프로젝트 복원(mgmt_code 회수)도 try/except로 best-effort.
2. `main.py: /sales/orders/{oid}/delete` — `delete_order` 호출을 **try/except로 감싸 항상 JSON 반환**(예외여도 `{ok:False, message:'수주 삭제 실패: …'}`). 더 이상 HTML→'Unexpected token <' 안 남·실패 사유 표면화.

## 검증 (임시 DB·FK ON)
- 옛 로직 모사: production_orders/tax_invoice_lines 남긴 채 orders 삭제 → **IntegrityError 재현**(=500 원인 확인).
- 새 `delete_order`: orders·order_items(251)·production_orders·tax_invoice_lines **전부 삭제** + 프로젝트 복원(mgmt_code=NULL·status 수주예정·stage 제안작성) → **PASS**. AST OK.
