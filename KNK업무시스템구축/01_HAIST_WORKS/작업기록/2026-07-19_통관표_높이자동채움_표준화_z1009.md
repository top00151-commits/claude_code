# z1009 — 통관 입력 표 '화면 남은 높이 자동 채움' (모니터 크기 자동 적응) · Phase A

- **일자**: 2026-07-19
- **지시(대표)**: 통관 입력 화면의 품목 데이터 입력 표(`M-260707-1 · PARTS_EXPORT · 12품목`)가 노트북에서 너무 작아 1~2줄만 보임. **모니터 크기(노트북 12~14"·데스크탑 24~27"·일부 30")에 따라 자동 조정**되게 하고, **다른 페이지도 같은 문제 전수 조사·수정**, **표준화 규정으로 등재**.
- **승인**: 옵션 ① — 통관 먼저 고쳐 배포 → 대표 노트북 확인 → 확정 후 공용 표준+나머지 일괄(Phase B).

## 1. 원인 (핵심)

- WORKS 공용 셸: `.app{height:100vh; overflow:hidden}` 격자 + `.main{display:flex; flex-direction:column; overflow:hidden}` → **본문은 화면 높이에 고정**, 표준 스크롤 영역은 `.main-body{flex:1; overflow:auto}` (남은 세로공간 자동 채움). ([design_v2.html] `.app`=445행, `.main`=349행)
- **통관 화면은 `.main-body`를 안 쓰고** 모든 내용을 `.main`에 직접 넣음. 표 위 도구모음(제목·버튼줄 + `일괄 적용`바 + `🧾 신고 서류` + `📦 박스별` + `⚙ 컬럼 설정`바 + 수주 제목)이 항상 펼쳐져 화면 상당 부분을 차지.
- 표 래퍼(`.tbl-wrap`)는 `overflow:auto`라 **flex-shrink 대상**(스크롤 컨테이너는 min-height:auto가 0으로 풀림) → flexbox가 표를 **'남은 공간'만큼 짓눌러** 노트북에선 1~2줄. 큰 모니터는 남는 공간이 커서 여러 줄 → **모니터 크기에 따라 제멋대로**.
- 기존 `max-height:calc(100vh - 290px)`의 290은 실제 도구모음 높이(≈500px)와 안 맞는 **추측값**이라 도움 안 됨. **최소 높이도 없어** 얼마든지 작아짐.

## 2. 해결 = 'data-knk-fill' 화면 남은 높이 자동 채움 헬퍼 (이 파일 인라인 — Phase A)

`app/templates/export_prep_detail.html` 한 파일에만 적용(격리):
- **JS 헬퍼**: `[data-knk-fill]` 요소의 **실제 시작위치(getBoundingClientRect().top)를 재서** `height = 화면높이 − top − (여백 + 안내문 높이)`로 지정. `flex:none`으로 flex 눌림 제거. → **12"~30" 어디서든 자동 적응**.
  - 최소 높이 **FLOOR=340px** 보장(작은 노트북에서도 ≥약 11줄), 그보다 커야 할 땐 페이지 스크롤로.
  - 재계산 트리거: `load`·`resize`·`orientationchange`·**`<details>` 펼침/접힘(도구모음)**·`fonts.ready`. `requestAnimationFrame` 디바운스. `window.knkFill()` 수동 호출 노출.
- **CSS 폴백(JS 실패 시 안전)**: `.tbl-wrap.ex-fill{ min-height:340px; max-height:calc(100vh-210px) }` + `.app>.main{ overflow-y:auto }`(넘치면 페이지 스크롤=잘림 방지). min-height는 flex-shrink보다 우선하므로 **JS 없이도 1~2줄 눌림은 사라짐**.
- **업무 로직·기존 컬럼 폭조절/순서/숨김 JS·저장 함수 무변경**. 표 래퍼에 `class="... ex-fill" data-knk-fill`만 추가하고 인라인 `max-height:290` 제거.

## 4. 대표 확인 요청 (노트북에서)

열린 통관 탭은 자동 새로고침됨(안 되면 새로고침 1회):
1. 품목 표가 **화면 아래까지 크게** 채워지는가(1~2줄 → 넉넉).
2. 창을 줄이거나 큰 모니터로 옮기면 **표 높이가 따라 조정**되는가.
3. `🧾 신고 서류`/`📦 박스별`을 펼치면 표가 그만큼 **다시 계산**되는가.
4. 컬럼 폭조절·숨김·저장 등 기존 기능 정상인가.

## 6. Phase B 실행 (대표 "진행하자" 확인 후 · 안전 opt-in 방식)

⭐**핵심 판단**: 공용 `.tbl-sticky`(약 45개 화면)를 **일괄 자동 전환**하려 했으나, 사내 브라우저 렌더 차단으로 내가 45개를 실측 검증할 수 없고, 오늘 잘 도는 표를 미검증 자동 변경하는 건 **"잘 되는 건 안 건드린다"(절대준수) 위반** → **opt-in 방식으로 좁힘**: 매직넘버로 손튜닝돼 있던(=잠재 문제) 화면만 명시 전환, 기본 `.tbl-sticky` 페이지는 그대로(원하면 한 줄 `data-knk-fill`로 opt-in).

- **공용 헬퍼 신설** `_v5_partials/knk_autofill.html` → `styles.html`에 1줄 include(전 200화면 도달). **opt-in 전용**(`[data-knk-fill]`만 대상). 두 모드:
  - **기본(max-height)**: `maxHeight = 화면높이 − 시작위치 − 20`. 내용 적으면 줄어듦(빈 공간 없음). 목록·표.
  - **grow**: `[data-knk-fill="grow"]` = 지정 높이 + `flex:none` (flex 눌림 화면). 뒤 형제(안내문 등) 높이 자동 확보. 페이지 스크롤 컨테이너 `overflow-y:auto` 필요.
  - 재계산: resize·orientationchange·load·**fullscreenchange**·**details 펼침/접힘**·fonts.ready(rAF 디바운스). `window.knkFill()` 노출. FLOOR=340. JS 실패 시 CSS 폴백(`[data-knk-fill]{min-height:340}`).
- **전환**: ①통관(export_prep_detail)=인라인 헬퍼 제거→공용 grow로 통일 ②HS사전(export_hs_dict)=`.hsd-wrap` opt-in ③연락처(contacts_list)·④고객사(customers_list)=`!important` 매직넘버 제거 + 표 opt-in.
- **의도적으로 안 건드림(그대로 정상)**: `projects`(전용 전체화면 오프셋 로직) · `sales_orders`(이미 `.list-scroll flex:1` 올바른 2단) · `sales_shipments_receipts`(z922 사용자 높이조절 기능) · 나머지 ~35개 기본 `.tbl-sticky` 목록.
- **검증**: 6파일 Jinja parse·esprima(헬퍼 포함 전 스크립트)·CSS 균형·편집 정확 전부 통과(`scratchpad/verify_z1009b.py`). 배포=(Phase B 커밋 해시 기입).
