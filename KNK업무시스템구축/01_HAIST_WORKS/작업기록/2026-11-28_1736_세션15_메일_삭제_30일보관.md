## 3. 「누가 이것을 쓰나」(스킬 3절) — 코드로 확인한 것
- **첨부 파일(디스크)**: `mail_attachments.sha256` + 내용 지문 경로 — 같은 내용은 파일 1개를 여러 메일이 함께 쓴다. 예전 완전 삭제도, 이번 밤 정리도 **첨부 줄만** 지우고 디스크 파일은 건드리지 않는다(`os.remove` 없음) → 다른 메일 첨부가 깨지지 않는다. 대신 아무도 안 쓰는 파일이 디스크에 남는다(예전과 같음).
- **첨부 BLOB(DB 안)**: 줄마다 따로 들고 있어 공유 없음 → 줄과 함께 지움.
- **본문 보관함**(`mail_body_store`, `html_sha`): 여러 메일이 같은 본문을 함께 쓸 수 있음 → 밤 정리 뒤 기존 공용 `gc_store`(어느 메일도 안 쓰는 것만 지움)를 부름. 대기 중인 메일은 `html_sha` 를 그대로 들고 있어 지워지지 않는다.
- **보낸 메일 「답 기다림」**(`mail_messages.wait_reply_id`): 보낸 메일이 받은 답 메일 번호를 잡고 있음 → 잡혀 있으면 밤 정리가 **지우지 않고 남김**(이력 `night_keep` + 까닭).
- **👉 맡기기**(`mail_delegations.mail_id`, 처리 중 `working`·`review`): 원문은 이음에 복사로 넘어가지만, 상태 띠가 메일 번호를 씀 → 처리 중이면 남김.
- **큰 파일 링크**(`mail_large_files`): 메일 번호를 갖지 않음(토큰·올린 사람·기한만) → 메일을 지워도 링크·파일은 따로 기한대로. 영향 없음.
- **대화 흐름**(`mail_thread`): 질의가 `is_deleted=0` 만 봄 → 대기 메일은 흐름에서 빠짐. 번호 참조 표 없음.
- **그 밖의 옆 표**(`mail_reply_marks`·`mail_from_guess`·`mail_body_pack_log` 등): 메일 번호를 적어 두지만 화면을 그리지 않는 기록 — 예전 완전 삭제 때도 남기던 것과 같음(이번에도 손대지 않음).
- **다시 들여오기**: 아웃룩 옛 메일 가져오기·하이웍스 옮기기의 중복 검사(`dedup_hash`)는 대기 메일도 「이미 있음」으로 본다(휴지통 메일과 같은 동작) → 대기 중에는 같은 메일을 다시 들여오지 않고, 30일 뒤 지워진 다음엔 다시 들여올 수 있다.
- **목록·검색·세기**: 화면 질의가 모두 `is_deleted=0`(목록·검색·폴더 숫자·안 읽음) 또는 `=1`(휴지통)로 거른다 → 값 2 는 어디에도 안 잡힌다. `is_deleted<>0`·`NOT is_deleted` 같은 비교는 코드에 없음(전수 grep). 메일 열기(`get_mail`)도 `is_deleted=0` 만. 저장 공간 화면(`mail_storage`)은 아직 디스크를 차지하므로 대기 메일도 센다(밤에 지워지면 빠짐).
- 이 일과 별개로 남은 「바로 지우는」 곳: 중복 사본 자동 정리 `dedup_inbox(hard=True)`(원본 1통은 남기고 같은 사본만 지움) — 이번 세 곳에 들지 않아 그대로 둠.
