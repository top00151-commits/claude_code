## 1. 첫째 — 구매 작업은 **시작하기 전에** 본다

### 무엇이 문제였나

구매 서류를 만드는 네 가지 작업(단가 채우기·견적요청서·발주서·설계변경 반영)은
**시작할 때는 「구매 실행권한」만** 봤습니다. 단가·구매처를 볼 수 있는지는
**다 만든 뒤 내려받는 자리에서야** 확인했습니다.

그래서 이런 일이 생길 수 있었습니다.

| 순서 | 예전 |
|---|---|
| ① | 사람이 파일을 올리고 작업을 누른다 |
| ② | 서버가 엑셀을 만든다 (시간·자원 소모) |
| ③ | 보관함에 기록과 파일이 남는다 |
| ④ | **내려받기를 누르면 그제서야 「열람 권한 필요」** |

즉 **일을 다 시켜놓고 결과만 못 받게** 했습니다. 만든 파일은 보관함에 그대로 남았습니다.

### 어떻게 고쳤나

`/bom/tools/run/{step}` 에서 실행권한 관문 **바로 다음**에 정보권한을 함께 봅니다.

```python
if step in _BT_PURCHASE_STEPS:            # price · rfq · po · revise
    _pol0 = load_field_access_policy(...)
    _lack = []
    if not can_view_field(u, "purchase_price", _pol0):  _lack.append("구매단가")
    if not can_view_field(u, "supplier_info",  _pol0):  _lack.append("구매처")
    if _lack:
        return RedirectResponse("/bom/tools?err=...", 303)   # 만들기 전에 되돌린다
```

화면에 나오는 말:

> ⛔ 이 작업은 **구매단가 · 구매처** 열람 권한이 있어야 시작할 수 있습니다.
> 만들고 나서 받지 못하는 일을 막기 위해 미리 확인합니다 — 구매팀에 문의해 주십시오.

- 네 작업 **모두** 단가와 협력사를 다루므로 **둘 다** 요구합니다.
- **새 권한을 만들지 않았습니다.** 2026-07-05 부터 쓰던 `field_access_policy` 를 그대로 읽습니다.
  달라진 것은 **보는 시점**뿐입니다(끝 → 시작).

### 실제로 몇 명이 막히나 — 운영 DB 읽기 전용 실측

⭐ **0명**입니다.

| 구분 | 인원 | 단가 열람 | 구매처 열람 | 이번 변경으로 막히나 |
|---|---|---|---|---|
| 구매 실행권한 보유 | **16명** | 16명 | 16명 | **0명** |
| └ 본사 (팀 1·10·11·15) | 14명 | 정책으로 보유 | 정책으로 보유 | 아니오 |
| └ 법인 (팀 19·24) | 2명 | `role='admin'` 로 통과 | `role='admin'` 로 통과 | 아니오 |

→ **지금 일하는 사람 중 새로 막히는 사람은 없습니다.** 앞으로 권한 구성이 바뀔 때
헛수고를 막아 주는 안전장치로 작동합니다.

## 2. 둘째 — DB 칸 추가 실패를 조용히 넘기지 않는다

### 무엇이 문제였나

등급 칸(`bom_tool_runs.has_price` · `has_vendor`) 을 만드는 코드가 `except: pass` 였습니다.

만약 이 칸이 안 생기면 → 등급이 **늘 「불명」** → **모든 파일이 제한**됩니다.
안전한 쪽이긴 하지만 **업무는 멈추는데 아무도 그 사실을 모릅니다.**

이건 제 자신이 어긴 규칙이기도 합니다 (`except:pass` 금지). 실제로 같은 자리에서
`import re` 누락이 조용히 삼켜져 등급 판정이 통째로 작동하지 않은 적이 있습니다.

### 어떻게 고쳤나

`app/database.py` 의 해당 블록을 다음처럼 바꿨습니다.

| 상황 | 남기는 말 |
|---|---|
| 칸을 새로 추가함 | `[WP-04] bom_tool_runs 등급 칸 추가: ['has_price','has_vendor'] · 기존 기록 6건 보존(6건)` |
| 추가했는데도 칸이 없음 | `🔴 등급 칸 없음 … 등급 판정이 늘 '불명'이 되어 모든 파일이 제한됩니다. 확인 필요.` |
| 행 수가 달라짐 | `🔴 행 수가 바뀜: 6 → N — 확인 필요` |
| 통째로 실패 | `🔴 마이그레이션 실패: <오류종류>: <내용> (기존 기록 N건) — 등급이 불명 처리되어 파일이 제한됩니다.` |

⛔ **기동은 막지 않습니다(예외를 다시 던지지 않음).**
근거: 메일 모듈 기동 오류(`4829f1da`)로 **WORKS 전체가 38분 동안 멈춘** 전례가 있습니다.
메일·메신저·WORKS 가 컨테이너 하나를 같이 쓰기 때문에, 여기서 죽으면 회사 전체가 멈춥니다.
그래서 **크게 남기되 살려 둡니다.**

### 배포 전 확인기 신설 — `deploy/check_bom_schema.py`

빈 DB 로 하는 시험은 의미가 없습니다(`CREATE TABLE IF NOT EXISTS` 는 기존 표에 칸을 안 만듭니다).
그래서 **운영과 같은 조건** — 옛 스키마 표 + 기존 6행 — 을 임시 폴더에 만들어 확인합니다.

|---|---|---|
| 1 | 등급 칸 두 개가 생긴다 | OK |
| 2 | 기존 기록 6건이 그대로 있다 | OK |
| 3 | 옛 행의 등급은 불명(NULL) — 제한 대상 | OK |
| 4 | 두 번 돌려도 안전하다(멱등) | OK |
| 5 | 표가 없던 DB 에서도 칸이 갖춰진다 | OK |

→ **확인 6건 / 실패 0건**

## 3. 곁들여 고친 것 1건 — 안내문도 권한을 따라가게

시험 화면을 찍다가 발견했습니다. 「전체 흐름 보기」 안내문이 **설계 담당자에게**
*"이미 합쳐 둔 BOM이 있으면 단가·견적·발주서로 바로 들어가시면 됩니다"* 라고 말하고 있었습니다.
권한을 나누기 **전에 쓰인 글**이라, 이제는 **할 수 없는 일을 하라고 안내**하는 셈이었습니다.

- 구매 담당자 → 예전 문장 그대로
- 설계·조회 → *"이 가운데 단가·견적요청서·발주서는 구매 담당자가 맡습니다 — 설계에서는 간이 양식과 합치기까지 하시면 됩니다."*

기능 변경이 아니라 **말과 실제를 맞춘 것**입니다(한 개념 = 여섯 층 중 「안내문」 층).
불필요하다고 보시면 이 한 건만 되돌리면 됩니다.

## 5. 🔴 대표님 판단이 필요한 1건 — 미분류 원본 열람

### 확인 결과: **기존 승인 근거가 없습니다.**

찾아본 곳: 2026-09-08 구현기준 문서 §5, 그 이전 WP-04 문서 전체.
나오는 것은 **제가 2026-09-08 에 적은 두 줄뿐**이고, 대표님이나 구매팀의 승인 기록은 없습니다.

> `### 원본 불명 처리 — 아무도 못 보게 막지는 않는다`
> `불명이면 가장 보수적인 등급(단가·구매처 둘 다 필요)으로 본다.`

즉 **제 판단으로 정한 규칙**입니다. 그대로 두는 것이 맞는지 판단을 청합니다.

### 지금 어떻게 동작하나

올린 **원본 파일**을 내려받을 때, 그 파일이 우리 PART LIST 양식으로 읽히지 않으면
(양식이 아니거나 읽기 실패) → **단가·구매처가 둘 다 든 파일로 간주**합니다.

| 사람 | 우리 양식 원본 | **양식 아닌 원본** |
|---|---|---|
| 구매팀 (둘 다 열람) | 받음 | **받음** |
| 설계 (단가만 열람) | 내용대로 판단 | **못 받음** |
| 조회 전용 (둘 다 열람) | 받음 | **받음** |

### 무엇이 걸리나

좋은 점 — 정체를 모르는 파일로 단가·거래처가 새는 것을 막습니다.

걸리는 점 — **설계 담당자가 자기가 올린 원본을 되받지 못할 수 있습니다.**
인벤터에서 뽑은 파일이나 협력사가 준 양식이 우리 양식과 다르면 그렇습니다.
대표님이 *"인계받은 자료까지 못 보게 막지는 마세요"* 라고 하신 취지와 부딪힐 소지가 있습니다.

⚠ **실측 없음** — 지금 보관함 실행 기록은 6건뿐이고 원본 재다운로드 시도 기록이 없어,
실제로 이 일이 몇 번 일어나는지는 **측정된 바 없습니다.** 짐작으로 "영향 없음"이라 적지 않습니다.

### 고를 수 있는 길

| | 안 | 내용 | 위험 |
|---|---|---|---|
| **가** | **지금 그대로** | 양식 아니면 둘 다 필요 | 설계가 자기 원본을 못 받는 경우 발생 가능 |
| **나** | **올린 본인은 예외** | 그 파일을 올린 사람은 언제나 받을 수 있음 | 낮음 — 자기가 올린 파일임 (⛔ 남의 파일은 그대로 제한) |
| **다** | 설계까지 열어줌 | 양식 아닌 원본은 BOM 권한자면 받음 | 단가·거래처 유출 소지 |

제 의견은 **(나)** 입니다. 새는 것을 막으면서, *"인계받은 자료까지 못 보게 막지 말라"* 는
취지도 지킬 수 있습니다. 다만 **이번 지시 범위 밖이므로 손대지 않았고**, 승인해 주시면 그때 만들겠습니다.
