## 5. 번호 ↔ 발주일 어긋남 (대표 첫 지적)

### 규칙은 정상 작동했다
관리번호와 수주번호는 **같은 기준일(`_co_ref`)** 로 발번한다([consumables.py:660,667](../app/consumables.py)):
```python
co_no     = generate_co_no("C", _co_ref)       # 수주번호
mgmt_code = generate_mgmt_code("C", _co_ref)   # 관리번호  ← 같은 _co_ref
```
`_co_ref` = 발주일. **없으면 등록한 날**로 폴백.

⭐ `110C2605`(26년 5월)와 `C-260507-1`(5월 7일)이 **같은 날**을 가리킨다 → **발번 순간 발주일이 비어 있었다.** 발주일이 04-15였다면 `110C2604` / `C-260415-1` 이 나왔어야 한다.
**번호는 발번 때 굳으므로 나중에 발주일을 채워도 안 따라간다.**

### 왜 발주일이 비었나 (정황 · 미확정)
파서는 정보란 라벨이 **정확히 `발주일`** 일 때만 읽는다:
```python
elif meta["order_date"] is None and tn == "발주일":                    # 1개만
elif meta["due_date"]  is None and tn in ("납품일","납기","납기일"):    # 3개 허용
```
`발주 일자`·`수주일`·`ORDER DATE` 로 적혔거나 `2026/04/15` 형식이면 못 읽는다. 납기(4/27)는 들어왔는데 발주일만 빠진 화면 상태와 앞뒤가 맞는다.
⚠ **확정하려면 그때 올린 원본 파일을 봐야 한다.**
