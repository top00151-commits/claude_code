## 1. 진짜 문제 — 보여주기만 하고 **고칠 자리가 없었다**

```
프로젝트 상세 화면
  ├── PO유형 : 추가        ← 프로젝트 한 줄만 표시
  └── 수주 내역 4건        ← PO유형 칸이 아예 없음
                              ↓
              고치려면 [프로젝트 정보 수정] 말고 갈 곳이 없다
                              ↓
              거기서 고치면 자기 값 없는 수주가 **통째로** 바뀐다
```

z1033 에서 **수주별 PO유형**을 만들었지만, 고칠 수 있는 곳은 **작업일정표 한 곳뿐**이었다.
안지연 프로가 서 있던 화면(프로젝트 상세)에는 없었다.

> **⭐보여주는 곳에는 고치는 자리도 같이 있어야 한다.**
> 없으면 직원은 **더 큰 범위를 고치는 엉뚱한 진입점**으로 간다.

### 고친 것
| | |
|---|---|
| 수주 카드 | `PO유형` 선택칸 — 고른 즉시 **그 수주만** 저장 (`so_oid` 동봉·변경 이력) |
| 참고(추가) 수주 카드 | 표시만 (z650b 규정 유지) — 수주번호 클릭 → 작업일정표에서 수정 |
| 프로젝트 정보 | `PO유형 (기본값)` 으로 표기 + "수주마다 다르면 아래 수주 내역에서" |
| [프로젝트 정보 수정] 버튼 | `(전체 4건)` 표시 — **들어가기 전에** 범위를 알린다 |

`orders.po_type` 을 `get_project_orders` 의 조회 컬럼에 추가(z981 모델명·장비명과 같은 방식).

## 2. '6대' — 안지연 프로 말이 맞았다

| | |
|---|---|
| 화면 | 단가 ₩241,900,000 × **6대** = ₩3,144,700,000 |
| 산수 | 241,900,000 × 6 = **14억** ≠ 31억 |
| 실제 | **13대** (같은 화면 아래 '총 수량 13대'와도 안 맞음) |

**원인**: 수량은 `projects.unit_qty`(**등록할 때 적은 예상 수량**, 추가발주가 붙어도 안 늘어남)인데
금액은 `_displayed_amt`(**실제 수주 합계**)였다. **예상과 확정을 한 문장에 섞었다.**

### 고친 것
- 수주 발행 후에는 **실제 호기 수**를 쓰고, 단가도 그 수로 나눈다 → 문장이 **항상 맞는다**
- 호기 단가가 서로 다르면 **`(평균)`** 이라고 밝힌다
- ⭐**산수가 안 맞으면 그 줄을 아예 숨긴다** (부품·소모품처럼 '대' 단위가 아닌 프로젝트)
  → 금액 자체는 바로 위 '수주액'에 이미 정확히 나와 있다
- 수정 폼 ③도 `확정 금액` 으로 바뀌고 실제 수량·금액 표시 (`so_qty`/`so_amount`/`so_count`)

## 3. ◆ 와 파란 글씨 — **정상 동작이었다**

**◆ + 파란 글씨 = 그 호기만 따로 지정한 값** (수주번호 값을 물려받지 않음).
설명은 표 아래 작은 글씨로 이미 있었지만 눈에 안 띄었다.

→ 마우스를 올리면 뜨는 말을 **사람 말로** 바꿨다(5곳).
`호기 override` → **`◆ 이 호기만 따로 지정한 발주일입니다 (수주번호 값을 물려받지 않음)`**

> 캡처의 **노란 칠**은 화면 기능이 아니다(코드 전체에 없음 — 확인함). 신고자가 표시한 것으로 보인다.
