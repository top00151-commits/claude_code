# 비고 "67"(사번) 오염 사건 — 원인 규명·차단·청소 (z978)

- **일자**: 2026-07-15
- **신고**: 김정락 대표 — "수주 내역 비고 칸에 '67'이 적혀 있고, 여러 페이지에 이런 게 많다. 67은 안지연 프로 사번인데 왜 이런 거지?"
- **결론 한 줄**: 시스템 코드가 사번을 쓴 것이 아니라, **엑셀 일괄등록 파서가 헤더를 못 읽으면 경고 없이 '옛 양식 열 위치'로 추측 저장**하던 설계 결함 때문에, 열 구성이 다른 파일의 엉뚱한 열 값(사번 '67' 등)이 비고 칸에 통째로 들어간 것. z978에서 원인 폐지 + 청소 도구 배포 완료.

---

## 1. 증상
- 프로젝트 상세 수주 내역(호기/부품 줄)의 **비고 칸에 "67"** — 업무와 무관한 값.
- 한 곳이 아니라 **여러 페이지·여러 건**에 동일하게 "67".
- 67 = 안지연 프로 사번. (현재 WORKS 실사용자가 사실상 안지연 프로 1인)

## 2. 원인 조사 (전수 추적)
### 2-1. 시스템 코드는 결백
비고(line_note)를 쓰는 **모든 저장 경로를 전수 추적** — 행 편집(items/{iid}/edit), 부품 추가(add-unit), 업로드 5종(import-parts-lines·consumable-lines·상품양식·일괄등록·추가발주), 보드 셀 편집(/unit-field·/cell), 상태 변경(row-status) 등:
- **사용자 번호(사번/users.id)를 비고에 기록하는 코드는 없음.**
- 전부 "사람이 입력한 값(폼 비고칸 또는 엑셀 비고열)"만 저장.

### 2-2. 진짜 원인 — 일괄등록 엑셀 파서의 '침묵 위치 폴백'
[main.py](../app/main.py) 일괄등록 파서(구 27038행 부근):
```python
if "name" not in colmap and not _is_new_flat:   # 헤더 인식 실패 → 구 위치기반 폴백
    colmap = {"name": 0, "mgmt_code": 1, ..., "pm": 12, "sales": 13, "ship_to": 14, "note": 15}
```
- 정상 동작: 3행 **헤더 이름**으로 열을 매핑(z172 — 열 순서 무관·견고).
- 문제 동작: 헤더 인식에 실패하면 **아무 경고 없이** 위 고정 위치(0~15)로 추측.
- 결과: 자체 관리 엑셀에서 붙여넣는 등 **열 구성이 다른 파일**을 올리면, 그 파일의 15번째 열(예: 담당자 사번)이 **비고로**, 13번째 열이 **영업담당으로** … 조용히 대량 저장됨.
- 한 번의 일괄 업로드가 수십 건을 만들므로 "여러 페이지에 똑같이 67"과 정확히 부합.
- 저장 경로: 엑셀 비고열 → `add_followup_order(note=…)` → 제품/부품 1줄(`order_items.line_note`) — 사진의 T-260427-3(제품 1줄·수량4)이 이 경로.
- 이는 우리 규정 **[데이터 연결성 안전]("자동 연결은 명확할 때만·애매하면 중단")** 위반 구조였음.

### 2-3. 남은 확인(추정→100% 확정, 선택)
- 안지연 프로의 일괄등록 **원본 엑셀**에서 비고/담당 근처 열에 67(사번)이 있는지 확인하면 확정.
- 단, 아래 z978로 재발은 이미 원천 차단됨.

## 3. 조치 (z978 · 대표 승인 "둘 다 진행")
### ① 침묵 폴백 폐지 (재발 차단)
- 헤더(3행) 인식 실패 시 → 그 시트는 **파싱하지 않고 실패 목록으로 표면화**:
  > "시트 '○○' 전체 — 3행 헤더를 인식하지 못해 이 시트는 건너뛰었습니다 — '양식 다운로드'로 최신 양식을 받아 값을 옮긴 뒤 다시 올려주세요. (예전처럼 열 위치를 추측해 저장하지 않습니다)"
- 조용한 '0건 등록'도, 조용한 오염 저장도 불가능해짐.
- **규정화**: 앞으로 만드는 모든 엑셀 파서는 위치 추측 폴백 금지 — 헤더 매핑 실패 = 중단 + 안내. (메모리 `knk_bulk_import_header_strict` 기록)

### ② 청소 도구 — `/admin/note-sweep` (대표·관리자 전용)
- 주소: **works.knknara.co.kr/admin/note-sweep** (기본 검색값 67 · `?v=값`으로 다른 오염값도 재사용)
- 스캔 대상(비고류 5칸 · 값이 **트림 후 정확히 일치**하는 것만):
  1. `order_items.line_note` — 수주 호기/부품 비고 (이번 사건 위치)
  2. `projects.logi_note` — 작업일정표 기타사항
  3. `projects.note` — 프로젝트 비고
  4. `orders.unit_note` — 수주 메모 ⚠PO번호 겸용 칸이라 목록 확인 필수
  5. `consumable_orders.note` — 소모품 발주 비고
- 흐름: 목록(관리번호·수주번호·항목명) 확인 → **[🧹 전부 비우기]**(확인창) → NULL 처리 + 건수 서버 로그.
- 비로그인/일반 사용자 접근 시 홈으로 차단(게이트 검증 완료).
