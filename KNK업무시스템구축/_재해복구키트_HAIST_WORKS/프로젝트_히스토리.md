## 2. 주요 결정 이력

### 2.1 기술 스택 선택 — FastAPI + SQLite
- **왜 FastAPI**: 비동기·자동 API 문서·타입 힌트. 메신저(Flask)와 다른 스택으로 격리.
- **왜 SQLite**: 130명 규모는 SQLite 충분. 백업·이동 단순. PostgreSQL 부담 회피.
- **단점**: 동시 init 시 database is locked → `KNK_WORKERS=1` 필수.

### 2.2 메신저와의 관계 — 같은 컨테이너, 별도 서비스
- 2026-05-28: 대표 지시 "같은 컨테이너에서 두 서비스를 돌리기 원한다 / /opt 밑에 모든 프로그램"
- 메신저 = `/opt/knk_messenger/` (Flask · 시스템 Python 3.8 · port 5050)
- HAIST WORKS = `/opt/knk_haist/` (FastAPI · Python 3.11.9 pyenv · port 8081)
- 양쪽 영향 0 (별도 supervisor program · 별도 venv · 별도 nginx location)

### 2.3 외부 진입 — 서브도메인 분리

## 5. 실패·복구 이력 (교훈)

### 5.1 git add -A 사고 (2026-05-28 NAS 배포 중)
- `.gitignore` 없이 `git add .` 실행 → credentials.csv·DB 파일 1391개 staged
- 다행히 push 전 발견 → `git rm --cached -r` + `--amend` 로 정리
- 333 파일로 축소, 보안 노출 0
- **교훈**: 메모리 룰 "git add -A 금지" 강화

### 5.2 nginx duplicate server (2026-05-29)
- install 스크립트가 nginx 백업을 `sites-enabled/` 안에 만듦 → nginx 가 추가 설정으로 읽음
- 자동 롤백 동작했음 (nginx -t 실패 감지)
- **교훈**: 백업은 항상 `/root/nginx-backups/` 처럼 nginx 가 안 읽는 곳에

### 5.3 Python 3.8 PEP 604 미지원 (2026-05-29)
- HAIST WORKS 코드는 PC(3.10+)에서 개발 → `str | None` 51곳
- 메신저 컨테이너 Python 3.8 → TypeError
- pyenv로 3.11.9 별도 빌드 (10~15분), 메신저는 3.8 그대로 유지
- **교훈**: 베이스 이미지 Python 버전 먼저 확인

### 5.4 SQLite database is locked (2026-05-29)
- `KNK_WORKERS=2` 시 두 워커가 동시에 `init_db()` 호출
- **교훈**: SQLite + uvicorn 은 workers=1 표준
